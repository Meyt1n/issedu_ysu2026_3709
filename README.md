# 多模态智能医疗家庭助手

面向 8 周软件工程实训的多模态 AI 项目，计划整合药物图像识别、带引用的医疗知识问答、家庭健康资料管理和可观测后台。

> 本项目目前处于**启动准备阶段，尚未开始功能开发**。仓库中的架构、接口、模型和验收内容均为待评审方案，不代表已经实现或达到医疗应用上线条件。

## 项目边界

本项目只用于教学、工程训练和受控演示：

- 提供健康知识检索、风险提示和家庭照护辅助；
- 不进行临床诊断、处方生成、药量调整或自动用药决策；
- 不使用未经授权的真实患者数据训练、调试或演示；
- 模型结果必须展示不确定性、来源和人工核对提示；
- 高风险症状由确定性规则触发就医升级，不能只依赖大模型判断。

## 课程要求

课程材料规定实训周期为 8 周、40 个工作日、320 学时，覆盖：

1. Python 数据处理与可视化；
2. 机器学习和深度学习基础；
3. OpenCV、CNN 和目标检测；
4. 药物识别与视频演示；
5. Flask/FastAPI Web 服务；
6. 多模态模型 API 与本地大模型部署；
7. RAG、LoRA/LLaMA Factory 微调和模型评估；
8. 系统集成、测试、文档和项目答辩。

课程学习不等于项目功能完成。每项能力必须通过 Story、代码提交、测试用例、缺陷记录、评审记录和演示证据进入项目基线。

## 计划能力

| 模块       | MVP 目标                               | 安全边界                             |
| ---------- | -------------------------------------- | ------------------------------------ |
| 药物识别   | 返回候选类别、边界框、置信度和模型版本 | 低置信度拒识别，不给用药决定         |
| 医疗问答   | 多轮文本/图片问答，回答带可定位来源    | 证据不足拒答，高风险症状建议立即就医 |
| RAG 知识库 | 授权资料入库、权限检索和引用           | 检索前鉴权，公共与个人知识域隔离     |
| 健康资料   | 家庭成员、过敏史、体检指标和事件管理   | 最小采集、加密、审计、可导出删除     |
| 管理后台   | 用户、知识、模型、任务和服务状态       | RBAC，敏感操作二次确认               |

完整范围见[需求规格说明书](docs/vibe-coding/01-需求规格说明书.md)。

## 候选技术基线

以下内容仍需在第 1 周通过 ADR、原型和资源评估确认：

- Web：Vue 3 + TypeScript + Vite；
- API：Python 3.11 + FastAPI；课程要求的 Flask 作为独立教学/管理端候选；
- 数据：PostgreSQL、ChromaDB、对象存储、Redis；
- AI：PyTorch、OpenCV、经复现实验确认的 YOLO、可替换 LLM 网关；
- RAG：薄编排层，按需采用 LangChain；
- 测试：pytest、httpx、Playwright、模型固定回归集；
- 部署：Docker Compose，本地模型优先使用 Ollama，GPU 服务按资源评估选择。

选型理由、替代方案和退出条件见[技术方案](docs/vibe-coding/02-技术方案.md)。

## 启动前流程

1. 项目经理组织需求、范围、风险和数据来源评审。
2. 各模块负责人用小型原型验证候选技术，不直接建立完整系统。
3. 测试组先建立验收矩阵和固定评估集。
4. 资料组建立 Story、实验、测试、缺陷和评审证据目录。
5. 所有成员确认 Git、分支、PR、AI 使用和敏感数据规则。
6. 只有达到[启动就绪门禁](docs/vibe-coding/16-一期开发实施方案.md)后才进入功能开发。

## 协作原则

- 一个 Story 对应一个可验证用户价值、一个负责人和一个主要 PR；
- 先写清验收条件，再让 AI 规划和实现；
- AI 生成内容必须由人阅读、测试和负责；
- 需求、设计、实现、测试和证据使用同一编号追踪；
- 不以代码行数、模型能返回内容或页面可打开作为“完成”；
- 不提交密钥、真实医疗数据、模型权重、缓存和本地产物；
- 架构、模型、数据、阈值、公开 API 或安全规则变化必须记录 ADR/实验报告。

协作细节见 [CONTRIBUTING.md](CONTRIBUTING.md)。
