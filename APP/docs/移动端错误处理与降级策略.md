# 移动端错误处理与降级策略

> 本文档是家健镜随身版的错误处理与降级策略完整指南，覆盖错误分类、错误处理流程、降级策略、用户反馈、日志记录。面向移动端开发者，作为错误处理的权威依据。

## 1. 错误分类

### 1.1 按来源分类

| 类别 | 说明 | 示例 |
| --- | --- | --- |
| 网络错误 | 网络连接问题 | 无网络、DNS 失败、连接超时 |
| 服务端错误 | 服务器返回错误 | 500、502、503 |
| 客户端错误 | 请求参数问题 | 400、401、403、404 |
| 业务错误 | 业务逻辑错误 | 任务已确认、授权已撤销 |
| 设备错误 | 设备能力问题 | 不支持语音、相机不可用 |
| 未知错误 | 未分类错误 | 未捕获异常、内存溢出 |

### 1.2 按严重程度分类

| 级别 | 说明 | 用户感知 | 处理方式 |
| --- | --- | --- | --- |
| Fatal | 应用崩溃 | 白屏/闪退 | 错误边界 + 重新加载 |
| Critical | 核心功能不可用 | 页面无法使用 | 错误页 + 重试 |
| Warning | 部分功能受限 | 功能降级提示 | 降级 + 提示 |
| Info | 轻微问题 | 无感知或轻微提示 | 日志记录 |

### 1.3 按可恢复性分类

| 类型 | 说明 | 处理 |
| --- | --- | --- |
| 瞬时错误 | 网络抖动、服务端临时不可用 | 自动重试（指数退避） |
| 持久错误 | 资源不存在、权限不足 | 不重试，显示错误信息 |
| 用户可修复 | 网络未连接、服务器地址错误 | 引导用户操作 |
| 系统不可修复 | 设备不支持、浏览器过旧 | 提示升级或使用其他设备 |

## 2. 错误处理原则

### 2.1 核心原则

1. **不吞错误**：所有错误必须处理或向上传递
2. **用户友好**：错误信息用用户能理解的语言
3. **可操作**：告诉用户能做什么（重试、检查网络、联系管理员）
4. **不暴露细节**：不显示堆栈跟踪、内部错误码
5. **可追溯**：所有错误记录日志，含 request_id
6. **优雅降级**：功能不可用时提供替代方案
7. **幂等安全**：重试不会产生重复数据

### 2.2 错误信息规范

```typescript
interface UserFacingError {
  title: string           // 简短标题（如「网络连接失败」）
  message: string         // 详细说明（如「请检查网络后重试」）
  action?: ErrorAction    // 建议操作
  requestId?: string      // 用于排查
}

type ErrorAction =
  | { type: 'retry'; label: string }
  | { type: 'navigate'; label: string; path: string }
  | { type: 'contact'; label: string }
  | { type: 'none' }
```

**好的错误信息：**
- 「网络连接失败，请检查网络后重试」
- 「服务器暂时不可用，请稍后再试」
- 「该任务已被其他人确认，请刷新页面」

**不好的错误信息：**
- 「Error: 500 Internal Server Error」
- 「undefined is not a function」
- 「操作失败」（无任何说明）

## 3. 网络错误处理

### 3.1 网络状态检测

```typescript
// composables/useNetworkStatus.ts
export function useNetworkStatus() {
  const isOnline = ref(navigator.onLine)
  const connectionType = ref<string>('unknown')

  const updateOnline = () => { isOnline.value = navigator.onLine }
  const updateConnection = () => {
    const conn = (navigator as any).connection
    connectionType.value = conn?.effectiveType || 'unknown'
  }

  onMounted(() => {
    window.addEventListener('online', updateOnline)
    window.addEventListener('offline', updateOnline)
    updateConnection()
  })

  onUnmounted(() => {
    window.removeEventListener('online', updateOnline)
    window.removeEventListener('offline', updateOnline)
  })

  return { isOnline, connectionType }
}
```

### 3.2 请求超时

```typescript
const requestWithTimeout = async <T>(
  fn: () => Promise<T>,
  timeout = 15000
): Promise<T> => {
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), timeout)

  try {
    return await fn()
  } catch (error) {
    if (error.name === 'AbortError') {
      throw new TimeoutError('请求超时，请检查网络后重试')
    }
    throw error
  } finally {
    clearTimeout(timer)
  }
}
```

### 3.3 自动重试

```typescript
const RETRYABLE_CODES = ['NETWORK_ERROR', 'TIMEOUT', '502', '503', '504']

const requestWithRetry = async <T>(
  fn: () => Promise<T>,
  maxRetries = 3,
  baseDelay = 1000
): Promise<T> => {
  let attempt = 0

  while (true) {
    try {
      return await fn()
    } catch (error) {
      attempt++
      if (attempt > maxRetries || !isRetryable(error)) {
        throw error
      }
      const delay = baseDelay * Math.pow(2, attempt - 1)  // 指数退避
      await sleep(delay)
    }
  }
}
```

## 4. HTTP 错误处理

### 4.1 状态码处理

```typescript
const handleHttpError = (status: number, data: any): UserFacingError => {
  switch (status) {
    case 400:
      return { title: '请求参数错误', message: data?.error?.message || '请检查输入' }
    case 401:
      sessionStore.clear()
      router.push('/login')
      return { title: '登录已过期', message: '请重新登录' }
    case 403:
      return { title: '无权限访问', message: '您没有权限执行此操作' }
    case 404:
      return { title: '资源不存在', message: '该内容可能已被删除' }
    case 409:
      return { title: '操作冲突', message: '数据已被修改，请刷新后重试' }
    case 429:
      return { title: '请求过于频繁', message: '请稍后再试' }
    case 500:
      return { title: '服务器错误', message: '服务器暂时不可用，请稍后重试' }
    case 502:
    case 503:
    case 504:
      return { title: '服务不可用', message: '服务暂时不可用，请稍后重试' }
    default:
      return { title: '请求失败', message: '请检查网络后重试' }
  }
}
```

### 4.2 401 处理

```typescript
// ApiClient 中统一处理
if (response.status === 401) {
  // 清除会话
  sessionStore.clear()
  // 跳转到登录页（如果不是登录请求）

    router.push('/login')
  }
  throw new ApiError('UNAUTHORIZED', '登录已过期')
}
```

### 4.3 409 冲突处理


## 5. 业务错误处理

### 5.1 任务操作错误

```typescript
const handleTaskError = (error: ApiError, task: TodayTask) => {
  switch (error.code) {
    case 'TASK_ALREADY_CONFIRMED':
      showToast('该任务已被确认')
      task.status = 'confirmed'
      break
    case 'TASK_NOT_FOUND':
      showToast('任务不存在，请刷新')
      break
    case 'ACTION_NOT_ALLOWED':
      showToast('当前状态不允许此操作')
      break
    case 'MISSED_GRACE_EXPIRED':
      showToast('已超过记漏服时间窗口')
      break
    default:
      showToast(error.message || '操作失败')
  }
}
```

### 5.2 授权错误

```typescript
const handleAuthError = (error: ApiError) => {
  switch (error.code) {
    case 'AUTHORIZATION_REVOKED':
      showToast('授权已被撤销')
      // 刷新成员列表，移除该成员
      break
    case 'AUTHORIZATION_EXPIRED':
      showToast('授权已过期')
      break
    case 'FIELD_NOT_AUTHORIZED':
      showToast('您没有权限查看该字段')
      break
  }
}
```

### 5.3 视觉识别错误

```typescript
const handleVisionError = (error: ApiError) => {
  switch (error.code) {
    case 'VISION_SERVICE_UNAVAILABLE':
      showToast('识别服务暂时不可用，请稍后重试或手动录入')
      break
    case 'INVALID_IMAGE':
      showToast('图片格式不支持，请重新拍摄')
      break
    case 'IMAGE_TOO_LARGE':
      showToast('图片过大，请压缩后重试')
      break
    case 'TASK_CANCELLED':
      showToast('识别已取消')
      break
  }
}
```

## 7. 降级策略

### 7.1 功能降级矩阵

| 功能 | 正常 | 降级 1 | 降级 2 | 不可用 |
| --- | --- | --- | --- | --- |
| 今日任务 | 实时数据 | 缓存数据 | 空状态 + 提示 | 错误页 |
| 拍药盒 | 拍照识别 | 文件选择 | 手动录入 | 提示不可用 |
| 语音助手 | 语音+文字 | 仅文字 | 提示不支持 | 隐藏入口 |
| 风险提醒 | 实时推送 | 手动刷新 | 空状态 | 提示稍后查看 |
| 知识检索 | 在线检索 | 缓存结果 | 提示不可用 | 隐藏入口 |
| 环境行动卡 | 真实天气 | 静态建议 | 隐藏卡片 | 不影响主功能 |

### 7.2 演示模式降级

当服务器不可用时，可切换到演示模式体验功能：

## 9. 日志记录

### 9.1 日志级别

```typescript

const logger = {
  debug: (msg: string, data?: any) => log(LogLevel.DEBUG, msg, data),
  info: (msg: string, data?: any) => log(LogLevel.INFO, msg, data),

  error: (msg: string, data?: any) => log(LogLevel.ERROR, msg, data),
```

### 9.2 错误日志格式

```typescript
const logError = (error: Error, context: Record<string, any> = {}) => {
  const entry = {
    timestamp: new Date().toISOString(),
    level: 'ERROR',
    message: error.message,
    stack: error.stack,
    context: {
      userId: sessionStore.user?.id,
      page: router.currentRoute.value.path,
      ...context,
    },
  }
  console.error(entry)
  // 生产环境可发送到日志服务（家庭自部署）

```

### 9.3 请求日志

```typescript
// ApiClient 中记录
const request = async (path: string, options: RequestInit) => {
  const startTime = Date.now()
  const requestId = generateId()

  logger.info('API 请求', { path, method: options.method, requestId })

  try {
    const response = await fetch(...)
    const duration = Date.now() - startTime
    logger.info('API 响应', { path, status: response.status, duration, requestId })
    return response
  } catch (error) {
    const duration = Date.now() - startTime
    logger.error('API 失败', { path, error: error.message, duration, requestId })
    throw error
  }
}
```

## 12. 错误处理检查清单

开发时逐项检查：

- [ ] 所有 API 调用有 try-catch
- [ ] 所有异步操作有错误处理
- [ ] 错误信息用户友好，不含技术细节
- [ ] 错误有明确的可操作建议
- [ ] 网络错误有重试机制
- [ ] 401 自动跳转登录
- [ ] 表单错误内联显示
- [ ] 加载状态和错误状态互斥
- [ ] 空状态有引导
- [ ] 长辈模式下错误有语音播报
- [ ] 错误有日志记录
- [ ] 关键操作有撤销机制
- [ ] 不使用 alert/confirm（用自定义模态框）
- [ ] 不把错误堆栈显示给用户
- [ ] 不吞错误（catch 后必须处理或重新抛出）

---

*错误处理是用户体验的重要组成部分。好的错误处理让用户在出问题时也能感到安心和可控。*
