# MOB-148 移动端最终发布门禁

本门禁只为移动端 PWA / APK 的发布结论提供可追溯裁决，**不新增业务功能，也不替代各 Story 的验收**。模型权重、OCR/视觉 worker 与人工网页复核均在家庭服务器或网页端；APP 不内置模型、不直连模型，且不得把健康数据发送至外部云。

## 1. 两条独立结论

| 结论 | 可声明的范围 | 额外前置条件 |
| --- | --- | --- |
| `RUNTIME_RELEASE` | APP/PWA/APK 能在受控运行时使用；视觉入口只消费获权、可追溯结果 | 本文第 2 节的全部运行时项均为 `VERIFIED`，并且回滚演练完成 |
| `FULL_VISION_PRODUCTION` | 可声明生产视觉闭环 | `RUNTIME_RELEASE` 已通过，且 HCT-201 / #48 和 HCT-409 / #72 的固定集、模型、后端 R3 与全产品发布门禁也均通过 |

任何一项缺证据、依赖未满足或记录不一致时，结论必须为 `BLOCKED`。仅用于课堂或受控演示时可标为 `DEMO_ONLY`，不得表述为家庭生产可用或生产视觉闭环。

## 3. 视觉能力的诚实降级

HCT-201 / #48 与 HCT-409 / #72 不阻塞非视觉 APP 运行时发布候选，但它们未通过时必须同时满足：

1. 最终记录把 `FULL_VISION_PRODUCTION` 写为 `BLOCKED`。
2. `RUNTIME_RELEASE` 写为 `DEMO_ONLY`，或在能力接口未提供视觉能力时禁用视觉入口。
3. 不伪造识别结果；界面必须说明视觉能力受限，并保留安全网页复核交接。

## 4. 裁决步骤

1. 从 [mob148-final-release-record.template.json](mob148-final-release-record.template.json) 复制记录到未跟踪目录。不得提交 URL、令牌、Cookie、真实设备标识、健康数据、APK 或签名材料。
2. 将每个矩阵项填为 `VERIFIED`、`BLOCKED` 或 `NOT_APPLICABLE`。`NOT_APPLICABLE` 只能由维护者写明理由并附审核人。
3. 对每条结论执行裁决：所有必需项 `VERIFIED` 才允许通过；任一 `BLOCKED` 或缺失记录即为 `BLOCKED`。
4. 维护者人工复核记录、复跑关键命令并验证回滚包后，才可把相应结论记为 `APPROVED`。
5. 发布后发现不一致时，撤回候选版本、恢复上一份已验证产物与配置，并在本 Issue 补充阻塞原因和新的脱敏证据索引。

## 5. 与 MOB-147 的关系

MOB-147 的 `controlled-release-record` 证明某一受控环境候选的版本与合成数据指纹；本门禁汇总各 Story、真机与后端契约的发布裁决。两份记录的 `app_commit`、`server_commit`、PWA shell 和 Android 版本必须一致，否则最终结论为 `BLOCKED`。
