# 移动端测试策略与用例设计

> 本文档是家健镜随身版的完整测试策略，覆盖测试分层、测试环境、用例设计、自动化测试、真机验收、性能测试、安全测试、无障碍测试和发布验收。面向测试人员和开发者，作为测试执行和验收的权威依据。

## 1. 测试策略概述

### 1.1 测试目标

- 确保移动端功能符合需求规格
- 确保在各种设备、网络、系统版本下稳定运行
- 确保无障碍功能符合 WCAG 2.1 AA 标准
- 确保性能满足预算要求
- 确保安全和隐私保护到位
- 确保发布质量达到门禁标准

### 1.2 测试分层

```
┌─────────────────────────────────────┐
│         真机验收（人工）              │  10%
│   TalkBack / 弱网 / 升级 / 回滚      │
├─────────────────────────────────────┤
│         E2E 测试（Playwright）       │  10%
│      关键用户流程端到端验证           │
├─────────────────────────────────────┤
│       集成测试（Vitest + MSW）       │  20%
│    组件组合、API 集成、状态管理       │
├─────────────────────────────────────┤
│         单元测试（Vitest）           │  60%
│   工具函数、组件逻辑、Provider、API   │
└─────────────────────────────────────┘
```

**测试金字塔原则：** 大量快速的单元测试，适量的集成测试，少量的 E2E 测试，必要的人工真机验收。

### 1.3 测试环境矩阵

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| 开发环境 | 开发调试 | 演示数据 |
| 本地后端联调 | API 对接 | SQLite + 合成数据 |
| Docker Compose | 集成测试 | MySQL + 合成数据 |
| PWA（Chrome） | 浏览器测试 | 演示/联调数据 |
| Android 真机 | 真机验收 | 演示/联调数据 |
| 低端设备模拟 | 性能测试 | 演示数据 |

### 1.4 测试数据原则

- 测试使用虚构数据，不使用真实健康数据
- 合成数据覆盖各种边界情况（空列表、超长文本、特殊字符）
- 测试数据可复现（固定种子）
- 测试后清理数据，不残留
- 不提交包含真实数据的测试文件

#### 2.4.2 API 客户端测试

```typescript
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { ApiClient } from '../api/client'

describe('ApiClient', () => {
  let client: ApiClient

  beforeEach(() => {
    client = new ApiClient({ baseUrl: 'http://localhost:18800' })
    vi.stubGlobal('fetch', vi.fn())
  })

  it('应该在请求头中携带 Authorization token', async () => {
    client.setToken('test-token')
    await client.get('/health')
    const [, options] = (fetch as any).mock.calls[0]
    expect(options.headers.Authorization).toBe('Bearer test-token')
  })

  it('应该在 401 时触发 onUnauthorized 回调', async () => {
    const onUnauthorized = vi.fn()
    client.onUnauthorized = onUnauthorized
    ;(fetch as any).mockResolvedValue({ status: 401, json: async () => ({}) })
    await client.get('/protected').catch(() => {})
    expect(onUnauthorized).toHaveBeenCalled()
  })

  it('应该将网络错误标准化为 ApiError', async () => {
    ;(fetch as any).mockRejectedValue(new TypeError('Failed to fetch'))
    await expect(client.get('/health')).rejects.toMatchObject({
      code: 'NETWORK_ERROR',
    })
  })
})
```

```typescript
import { test, expect } from '@playwright/test'

test.describe('今日任务流程', () => {
  test('用户可以确认今日任务', async ({ page }) => {
    // 登录
    await page.goto('http://localhost:5173/#/login')
    await page.fill('[data-testid="username"]', 'testuser')
    await page.fill('[data-testid="password"]', 'TestPass123')
    await page.click('[data-testid="login-btn"]')

    // 确认第一个任务
    const firstTask = page.locator('[data-testid="task-card"]').first()
    await firstTask.locator('[data-testid="confirm-btn"]').click()

    // 验证状态更新
    await expect(firstTask).toContainText('已确认')
  })

  test('弱网下显示骨架屏和超时提示', async ({ page }) => {
    // 模拟慢网络

      setTimeout(() => route.continue(), 10000)
    })

    await page.goto('http://localhost:5173/#/today')

    // 验证骨架屏
    await expect(page.locator('.skeleton-line').first()).toBeVisible()

    // 等待超时
    await expect(page.locator('[data-testid="timeout-error"]')).toBeVisible({ timeout: 20000 })
  })
```

## 6. 性能测试

### 6.1 性能测试类型

| 类型 | 工具 | 指标 |
| --- | --- | --- |
| 产物体积 | Vite 构建统计 | JS/CSS gzip 大小 |
| 加载性能 | Lighthouse / 自定义脚本 | FCP, LCP, TTI |
| 运行时性能 | Chrome DevTools | 帧率、内存、CPU |
| 低端模拟 | Chrome DevTools 4x CPU + Slow 3G | 加载、路由、断网 |
| 真机性能 | Android Profiler | 启动时间、内存、帧率 |

### 6.2 性能预算测试

`npm run perf:budget` 自动执行：

1. 构建生产版本
2. 启动本地服务器
3. 用 Playwright 加载页面
4. 测量 FCP、TTI、路由切换、断网恢复
5. 与预算对比，超预算则失败

`npm run perf:budget:low-end` 在 4x CPU + Slow 3G 下重复测量。

### 6.3 性能回归测试

`npm run test:perf-budget` 对比当前构建与基线：

- JS gzip 增长 >5% → 警告
- TTI 增长 >20% → 失败
- 路由切换增长 >20% → 失败

- 3 个家庭成员（老人、子女、照护者）
- 5 种药品（含过敏冲突示例）
- 10 条健康事件
- 3 条风险（不同等级）
- 2 个服药计划
- 5 篇知识文档

所有数据明确标注「演示」，不含真实健康信息。

### 10.2 联调造数

`npm run seed:live -- --base <url>` 向联调后端注入合成数据：

- 创建测试家庭和成员
- 添加药品和计划
- 生成风险事件
- 注入知识文档

造数使用固定种子，可复现。测试后可清理。

### 10.3 测试数据清理

- 单元测试：每个用例后重置 mock 和状态
- 集成测试：MSW server 重置
- E2E 测试：测试前重新造数
- 真机测试：使用演示模式或联调环境，不影响生产

## 11. 缺陷管理

### 11.1 缺陷分级

| 级别 | 定义 | 修复时限 |
| --- | --- | --- |
| P0 阻塞 | 核心功能不可用、崩溃、数据丢失 | 立即修复 |
| P1 严重 | 主要功能异常、无替代方案 | 24 小时内 |
| P2 一般 | 次要功能异常、有替代方案 | 下一版本 |
| P3 轻微 | UI 瑕疵、文案错误 | 按需修复 |
