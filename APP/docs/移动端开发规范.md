# 移动端开发规范

> 本文档是家健镜随身版的开发规范，覆盖代码风格、目录规范、组件开发、状态管理、API 调用、Git 工作流、代码评审。面向移动端开发者，作为日常开发的权威依据。

## 1. 技术栈规范

### 1.1 核心技术

| 类别 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 框架 | Vue | 3.5+ | Composition API + `<script setup>` |
| 语言 | TypeScript | 5.7+ | 严格模式 |
| 构建 | Vite | 6+ | 开发和生产构建 |
| 路由 | vue-router | 4+ | hash 模式 |
| 状态 | Pinia-style | - | 轻量 store |
| 测试 | Vitest | - | 单元测试 |
| 原生 | Capacitor | 8+ | Android 打包 |
| 包管理 | npm | - | 不混用 yarn/pnpm |

### 1.2 禁止使用

- 不使用 Vue 2 语法（Options API 仅限旧代码）
- 不使用 JavaScript 编写新文件（全部 TypeScript）
- 不使用 Element Plus、Vant 等 UI 组件库
- 不使用 jQuery
- 不使用 moment.js（用原生 Date 或 dayjs）
- 不使用 lodash 整库（按需引入或原生方法）
- 不使用自定义 Web Font（系统字体）

## 2. 代码风格

### 2.1 命名规范

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 组件文件 | PascalCase.vue | `TaskCard.vue` |
| 组合式函数 | useCamelCase.ts | `useSpeechRecognition.ts` |
| 工具函数 | camelCase.ts | `formatDateTime.ts` |
| 类型/接口 | PascalCase | `interface HealthEvent` |
| 类型前缀 | I 前缀可选 | `interface IProps`（不强制） |
| 常量 | UPPER_SNAKE_CASE | `const MAX_RETRY = 3` |
| 变量/函数 | camelCase | `const taskList = []` |
| CSS 类 | kebab-case | `.task-card-title` |
| 事件名 | kebab-case | `@task-confirm` |
| Props | camelCase（JS）/ kebab-case（模板） | `:task-id` |
| Emits | camelCase | `emit('taskConfirm')` |

### 2.2 文件结构

每个组件一个目录或文件：

```
# 简单组件
components/
  TaskCard.vue
  LevelTag.vue

# 复杂组件（带测试和子组件）
components/
  AssistantEvidencePanel/
    index.vue
    EvidenceItem.vue
    index.test.ts
```

### 2.3 Vue 组件规范

#### 2.3.1 必须使用 `<script setup>`

```vue
<script setup lang="ts">
import { ref, computed, onMounted } from 'vue'

// Props
const props = defineProps<{
  task: TodayTask
  disabled?: boolean
}>()

// Emits
const emit = defineEmits<{
  (e: 'confirm', taskId: string): void
  (e: 'defer', taskId: string, reason: string): void
}>()

// 响应式状态
const isLoading = ref(false)

// 计算属性
const statusText = computed(() => {
  return props.task.status === 'confirmed' ? '已确认' : '待确认'
})

// 方法
const handleConfirm = async () => {
  isLoading.value = true
  try {
    emit('confirm', props.task.task_id)
  } finally {
    isLoading.value = false
  }
}
</script>
```

#### 2.3.2 Props 定义

```typescript
// 好：类型明确，有默认值
const props = withDefaults(defineProps<{
  title: string
  count?: number
  disabled?: boolean
}>(), {
  count: 0,
  disabled: false,
})

// 不好：any 类型
const props = defineProps<any>()
```

#### 2.3.3 模板规范

```vue
<template>
  <!-- 指令顺序：v-if → v-for → :key → 其他属性 → 事件 -->
  <div
    v-if="visible"
    v-for="item in items"
    :key="item.id"
    class="task-card"
    :class="{ 'is-active': item.active }"
    @click="handleClick(item)"
  >
    {{ item.title }}
  </div>
</template>
```

- 模板中不写复杂逻辑，用 computed
- 不使用 `v-html`（除非经过 DOMPurify 清洗）
- 列表必须有 `:key`
- 事件处理函数名：handleXxx / onXxx

## 3. 组件开发规范

### 3.1 组件设计原则

| 原则 | 说明 |
| --- | --- |
| 单一职责 | 一个组件只做一件事 |
| 可复用 | 通用逻辑抽离为组件或 composable |
| 可测试 | 组件逻辑可独立测试 |
| 可访问 | 支持 ARIA、键盘导航、焦点管理 |
|  props 向下，events 向上 | 不直接修改 props，通过 emit 通知父组件 |

### 3.2 组件分类

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| 基础组件 | `components/base/` | 按钮、输入框、标签等 |
| 业务组件 | `components/` | 任务卡、风险卡等 |
| 页面组件 | `views/` | 完整页面 |
| 布局组件 | `components/layout/` | 底部导航、页面容器 |

### 3.3 组件测试

```typescript
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import TaskCard from './TaskCard.vue'

describe('TaskCard', () => {
  it('renders task title and time', () => {
    const wrapper = mount(TaskCard, {
      props: {
        task: { id: '1', title: '阿司匹林', time: '08:00', status: 'pending' },
      },
    })
    expect(wrapper.text()).toContain('阿司匹林')
  })

  it('emits confirm when button clicked', async () => {
    const wrapper = mount(TaskCard, {
      props: { task: { id: '1', status: 'pending' } },
    })
    await wrapper.find('[data-testid="confirm"]').trigger('click')
    expect(wrapper.emitted('confirm')).toBeTruthy()
  })
})
```

## 4. 状态管理规范

### 4.1 Store 设计

```typescript
// stores/accessibility.ts
import { defineStore } from 'pinia'

export const useAccessibilityStore = defineStore('accessibility', {
  state: () => ({
    elderMode: false,
    theme: 'system' as 'light' | 'dark' | 'system',
    fontSize: 'standard' as 'standard' | 'large' | 'xlarge',
    highContrast: false,
    reducedMotion: false,
    voiceFeedback: false,
  }),

  getters: {
    effectiveTheme: (state) => {
      if (state.theme === 'system') {
        return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
      }
      return state.theme
    },
  },

  actions: {
    toggleElderMode() {
      this.elderMode = !this.elderMode
      if (this.elderMode) {
        this.fontSize = 'xlarge'
        this.voiceFeedback = true
      }
      this.persist()
    },
    persist() {
      localStorage.setItem('hct-a11y', JSON.stringify(this.$state))
    },
  },
})
```

### 4.2 状态使用原则

- 全局状态（无障碍、会话、运行时）放 Store
- 页面级状态放组件内
- 临时状态（loading、input）放组件内
- 不把 API 响应直接放 Store（按需获取）
- Store 变更必须通过 actions

## 5. API 调用规范

### 5.1 ApiClient 使用

```typescript
// api/client.ts
export class ApiClient {
  private baseUrl: string
  private token: string | null = null

  constructor(baseUrl: string) {
    this.baseUrl = baseUrl
  }

  setToken(token: string | null) {
    this.token = token
  }

  async request<T>(path: string, options: RequestInit = {}): Promise<T> {
    const headers: Record<string, string> = {
      'Content-Type': 'application/json',
      ...(options.headers as Record<string, string>),
    }

    if (this.token) {
      headers['Authorization'] = `Bearer ${this.token}`
    }

    const controller = new AbortController()
    const timeout = setTimeout(() => controller.abort(), 15000)

    try {
      const response = await fetch(`${this.baseUrl}${path}`, {
        ...options,
        headers,
        signal: controller.signal,
      })

      if (response.status === 401) {
        this.onUnauthorized?.()
        throw new ApiError('UNAUTHORIZED', '会话已过期')
      }

      if (!response.ok) {
        const data = await response.json().catch(() => ({}))
        throw new ApiError(data.error?.code || 'REQUEST_FAILED', data.error?.message || '请求失败')
      }

      return response.json()
    } catch (error) {
      if (error instanceof ApiError) throw error
      if (error.name === 'AbortError') {
        throw new ApiError('TIMEOUT', '请求超时')
      }
      throw new ApiError('NETWORK_ERROR', '网络连接失败')
    } finally {
      clearTimeout(timeout)
    }
  }

  get<T>(path: string) {
    return this.request<T>(path, { method: 'GET' })
  }

  post<T>(path: string, body: unknown) {
    return this.request<T>(path, {
      method: 'POST',
      body: JSON.stringify(body),
    })
  }
}
```

### 5.2 调用规范

- 所有 API 调用通过 DataProvider，不直接在组件中 fetch
- 写操作必须带幂等键
- 错误必须处理，不吞异常
- loading 状态必须管理
- 请求失败有重试机制（指数退避，最多 3 次）
- 记录请求日志（request_id、状态、耗时）

### 5.3 错误处理

```typescript
try {
  await api.confirmTask(taskId)
  showToast('已确认')
} catch (error) {
  if (error.code === 'UNAUTHORIZED') {
    router.push('/login')
  } else if (error.code === 'TIMEOUT') {
    showToast('请求超时，请重试')
  } else if (error.code === 'IDEMPOTENCY_KEY_CONFLICT') {
    showToast('操作已提交，请刷新')
  } else {
    showToast(error.message || '操作失败')
  }
}
```

## 6. Git 工作流

### 6.1 分支策略

| 分支 | 用途 | 命名 |
| --- | --- | --- |
| master | 主分支，生产代码 | master |
| feature | 功能开发 | `feat/xxx-描述` |
| fix | Bug 修复 | `fix/xxx-描述` |
| docs | 文档更新 | `docs/xxx-描述` |
| refactor | 重构 | `refactor/xxx-描述` |

### 6.2 提交规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type：**

| type | 说明 |
| --- | --- |
| feat | 新功能 |
| fix | Bug 修复 |
| docs | 文档 |
| style | 格式（不影响代码运行） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试 |
| chore | 构建/工具 |

**示例：**

```
feat(mob): add missed dose action to task card

- Add missed dose button with required reason
- Fix button text truncation on 1272px screens
- Add unit tests for new action

Closes #521
```

### 6.3 PR 规范

- 每个 PR 关联一个 Issue
- PR 标题清晰描述变更
- PR 描述包含：变更内容、验收方式、风险、回滚方式
- 小步提交，单个 PR 不超过 500 行（文档除外）
- CI 通过后才能合并
- 至少一个人 review（维护者合并即代表复核）

### 6.4 代码评审检查清单

- [ ] 功能符合需求
- [ ] 代码风格符合规范
- [ ] TypeScript 类型完整
- [ ] 无 any 类型
- [ ] 无控制台输出（console.log）
- [ ] 无硬编码（魔法数字、URL）
- [ ] 错误处理完整
- [ ] 无障碍支持（ARIA、焦点、键盘）
- [ ] 测试覆盖关键逻辑
- [ ] 无安全隐患（XSS、敏感信息泄露）
- [ ] 性能考虑（列表虚拟化、防抖节流）

## 7. 测试规范

### 7.1 测试要求

- 新功能必须伴随单元测试
- Bug 修复必须添加回归测试
- 工具函数覆盖率 ≥90%
- 组件覆盖率 ≥70%
- 测试文件与源文件同目录，`.test.ts` 后缀

### 7.2 测试命名

```typescript
describe('模块名', () => {
  describe('函数/组件名', () => {
    it('应该在什么条件下做什么', () => {
      // 测试
    })
  })
})
```

### 7.3 测试原则

- 测试行为，不测试实现细节
- 每个测试独立，不依赖执行顺序
- 使用真实数据结构，不过度 mock
- 测试边界条件（空、null、undefined、最大值）
- 测试错误路径

## 8. 性能规范

### 8.1 渲染性能

- 列表 >50 条使用虚拟滚动
- 大列表项使用 `v-memo`
- 图片使用 `loading="lazy"`
- 避免在模板中调用方法（用 computed）
- 避免深层响应式（大对象用 shallowRef）

### 8.2 网络性能

- 独立请求并行（Promise.all）
- 不常变化数据短期缓存
- 搜索输入防抖 300ms
- 分页加载，默认 20 条
- 不重复请求相同数据

### 8.3 体积控制

- 路由级代码分割
- 第三方库按需引入
- 不使用整库（如 lodash）
- 图标内联 SVG，不用 icon font
- 定期检查 bundle 分析

## 9. 无障碍规范

### 9.1 必须做到

- 所有可交互元素可通过 Tab 聚焦
- 焦点环可见
- 图标按钮有 `aria-label`
- 图片有 `alt`
- 表单有 `label`
- 动态内容在 `aria-live` 区域
- 模态框有焦点陷阱
- 颜色不是唯一信息传递方式
- 所有文字对比度 ≥4.5:1
- 触控目标 ≥48px

### 9.2 检查方法

- 自动化：axe-core
- 手动：键盘操作、TalkBack、系统大字号
- 工具：Chrome DevTools Lighthouse

## 10. 安全规范

### 10.1 必须做到

- 不使用 `v-html` 渲染用户输入
- 不把 token 存 localStorage
- 不在 URL 传递敏感参数
- 不在 console 输出敏感信息
- 不硬编码密钥
- 文件上传校验 MIME 和大小
- 所有写操作有幂等键
- 授权在服务端校验，不依赖客户端

### 10.2 依赖安全

- 定期运行 `npm audit`
- 不安装来源不明的包
- 锁定依赖版本（package-lock.json）
- 生产构建不包含 devDependencies
