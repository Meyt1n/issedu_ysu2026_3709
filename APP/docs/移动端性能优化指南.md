# 移动端性能优化指南

> 本文档是家健镜随身版性能优化的完整指南，覆盖加载性能、运行时性能、网络性能、存储性能、低端设备适配、性能预算与监控。面向前端开发者，作为性能优化和验收的权威依据。

## 1. 性能目标与预算

### 1.1 为什么性能重要

移动端用户对性能的容忍度远低于桌面端：
- 加载超过 3 秒，53% 的用户会放弃
- 动画掉帧会被用户直接感知为「卡顿」
- 低端设备（Android Go、老旧手机）占用户基数的 30%+
- 弱网环境（2G/3G、地铁、地下室）是常态

家健镜的核心用户是老年人，使用的设备往往是中低端安卓机，网络环境也不稳定。性能不是锦上添花，而是产品可用性的基础。

### 1.2 性能预算

#### 1.2.1 产物体积预算

| 指标 | 基线预算 | 低端设备预算 | 测量方式 |
| --- | --- | --- | --- |
| JS gzip | ≤ 170 KiB | ≤ 200 KiB | `npm run build` 后统计 |
| CSS gzip | ≤ 30 KiB | ≤ 40 KiB | 同上 |
| HTML | ≤ 5 KiB | ≤ 5 KiB | 同上 |
| 首屏资源总数 | ≤ 10 个 | ≤ 15 个 | Network 面板 |
| 图片总数（首屏） | ≤ 3 个 | ≤ 5 个 | Network 面板 |
| 字体文件 | 0 个（系统字体） | 0 个 | 不使用自定义字体 |

**当前实测：** JS gzip 159.29 KiB（基线通过）

#### 1.2.2 加载性能预算

| 指标 | 基线（4G） | 低端（Slow 3G + 4x CPU） | 测量方式 |
| --- | --- | --- | --- |
| 首屏可交互（TTI） | ≤ 1500ms | ≤ 3000ms | `npm run perf:budget` |
| 首次内容绘制（FCP） | ≤ 800ms | ≤ 2000ms | Lighthouse |
| 最大内容绘制（LCP） | ≤ 2000ms | ≤ 4000ms | Lighthouse |
| 路由切换 | ≤ 300ms | ≤ 800ms | 自定义脚本 |
| 断网恢复 | ≤ 500ms | ≤ 1000ms | 自定义脚本 |

**当前实测（低端模拟）：** 可交互 841ms、路由最慢 133ms、断网恢复 177ms（全部通过）

#### 1.2.3 运行时性能预算

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 页面滚动帧率 | ≥ 55fps | Chrome DevTools Performance |
| 动画帧率 | ≥ 55fps | 同上 |
| 输入响应延迟 | ≤ 100ms | 同上 |
| 内存占用（PWA） | ≤ 100MB | Chrome Task Manager |
| 内存占用（WebView） | ≤ 150MB | Android Profiler |
| 长时间运行内存泄漏 | 无增长 | 多次路由切换后对比 |

### 1.3 性能门禁

`npm run mobile:ready` 包含性能预算检查，超预算则构建失败：

```
perf:budget          # 基线性能（普通设备）
perf:budget:low-end  # 低端设备模拟（4x CPU + Slow 3G）
test:perf-budget     # 性能回归测试
```

**注意：** `perf:budget` 和 `perf:budget:low-end` 都会重建 `dist/`，必须顺序执行，不能并行（并行会导致不同构建产物混杂，体积报告失真）。

## 2. 加载性能优化

### 2.1 代码分割

#### 2.1.1 路由级懒加载

```typescript
// router/index.ts
import { createRouter, createWebHashHistory } from 'vue-router'

const routes = [
  {
    path: '/today',
    component: () => import('../views/TodayView.vue'),  // 懒加载
  },
  {
    path: '/scan',
    component: () => import('../views/ScanView.vue'),
  },
  // ...
]
```

**效果：** 首屏只加载 TodayView 的代码，其他页面按需加载。首屏 JS 体积减少约 40%。

#### 2.1.2 组件级懒加载

大组件（如助手证据面板、知识详情）使用异步组件：

```vue
<script setup>
import { defineAsyncComponent } from 'vue'

const AssistantEvidencePanel = defineAsyncComponent(() =>
  import('../components/AssistantEvidencePanel.vue')
)
</script>

<template>
  <Suspense>
    <template #default>
      <AssistantEvidencePanel v-if="showEvidence" />
    </template>
    <template #fallback>
      <div class="loading">加载中...</div>
    </template>
  </Suspense>
</template>
```

#### 2.1.3 第三方库分割

- Vue、vue-router 等基础库打包到 vendor chunk
- 工具函数按需引入，不整库导入
- 不使用 moment.js（用原生 Date 或 dayjs）
- 不使用 lodash 整库（用按需引入或原生方法）

### 2.2 Tree Shaking

- 所有 import 使用 ES Module 语法，确保 Vite 能 tree shake
- 不使用 `import * as` 整命名空间导入
- 组件库（如有）使用按需引入
- 生产构建自动启用 tree shaking 和压缩

### 2.3 资源优化

#### 2.3.1 图片优化

- 装饰层（极光、萤火）纯 CSS 绘制，不使用图片
- 图标使用内联 SVG，不使用 icon font 或 PNG 图标
- 用户上传的图片在服务端压缩，客户端不处理大图
- PWA 图标使用 192px 和 512px 两个尺寸，maskable 图标单独提供
- 图片使用 `loading="lazy"` 懒加载

#### 2.3.2 字体优化

- 不使用自定义字体，全部使用系统字体栈
- 标题使用系统衬线字体回退：`Georgia, 'Times New Roman', serif`
- 正文使用系统无衬线字体：`-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`
- 中文使用系统中文字体，不加载 Web Font

**字体栈：**

```css
:root {
  --font-sans: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC',
    'Hiragino Sans GB', 'Microsoft YaHei', sans-serif;
  --font-serif: Georgia, 'Times New Roman', 'Songti SC', 'SimSun', serif;
  --font-mono: 'SF Mono', Consolas, 'Liberation Mono', Menlo, monospace;
}
```

#### 2.3.3 CSS 优化

- 使用 CSS 自定义属性（变量），避免重复声明
- 未使用的样式通过构建工具移除
- 媒体查询按需加载
- 不使用 `@import`（会增加请求瀑布）
- 关键 CSS 内联在 HTML 中

### 2.4 预加载与预获取

```html
<!-- 预加载首屏关键资源 -->
<link rel="preload" href="/src/main.ts" as="script" />

<!-- 预获取下一个可能的页面 -->
<link rel="prefetch" href="/assets/TodayView.js" />
```

- 首屏 JS 使用 `preload`
- 用户可能访问的页面使用 `prefetch`（浏览器空闲时加载）
- 不滥用 prefetch，避免浪费流量

### 2.5 Service Worker 缓存

`public/sw.js` 实现 App Shell 缓存：

| 资源 | 策略 | 缓存版本 |
| --- | --- | --- |
| index.html | Network First，回退缓存 | v4 |
| JS/CSS | Cache First | v4 |
| 图标/图片 | Cache First | v4 |
| API 请求 | Network Only（不缓存） | - |
| 跨域请求 | Network Only | - |

**缓存更新：**
- 新版本发布时，Service Worker 版本号递增（v3 → v4）
- 新 SW 激活后清除旧版本缓存
- 用户确认后刷新页面

## 3. 运行时性能优化

### 3.1 渲染性能

#### 3.1.1 动画优化

只动画 `transform` 和 `opacity`，不动画 `width`、`height`、`top`、`left` 等触发重排的属性：

```css
/* 好：只触发合成层 */
.card {
  transition: transform 0.2s ease-out, opacity 0.2s ease-out;
}
.card:hover {
  transform: translateY(-4px);
}

/* 不好：触发重排 */
.card {
  transition: margin-top 0.2s;  /* 触发重排 */
}
```

#### 3.1.2 列表虚拟滚动

事件时间线超过 50 条时启用虚拟滚动：

```vue
<template>
  <div ref="container" class="event-list" @scroll="onScroll">
    <div :style="{ height: totalHeight + 'px' }">
      <div
        v-for="item in visibleItems"
        :key="item.id"
        :style="{ transform: `translateY(${item.offset}px)` }"
      >
        <EventCard :event="item" />
      </div>
    </div>
  </div>
</template>
```

#### 3.1.3 避免布局抖动

批量读取和写入 DOM，避免读写交替导致强制同步布局：

```typescript
// 好：先读所有，再写所有
const heights = elements.map(el => el.offsetHeight);  // 批量读
elements.forEach((el, i) => {
  el.style.height = heights[i] + 'px';  // 批量写
});

// 不好：读写交替
elements.forEach(el => {
  const h = el.offsetHeight;  // 读
  el.style.height = h + 'px'; // 写（触发强制同步布局）
});
```

### 3.2 响应式优化

#### 3.2.1 防抖与节流

```typescript
// 防抖：搜索输入
function debounce<T extends (...args: any[]) => void>(fn: T, delay: number) {
  let timer: number;
  return (...args: Parameters<T>) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// 节流：滚动监听
function throttle<T extends (...args: any[]) => void>(fn: T, limit: number) {
  let inThrottle = false;
  return (...args: Parameters<T>) => {
    if (!inThrottle) {
      fn(...args);
      inThrottle = true;
      setTimeout(() => (inThrottle = false), limit);
    }
  };
}

// 使用
const search = debounce((query: string) => fetchResults(query), 300);
const onScroll = throttle(() => updateHeader(), 16);
```

#### 3.2.2 IntersectionObserver

懒渲染、无限滚动、图片懒加载使用 `IntersectionObserver`，不使用 scroll 事件 + getBoundingClientRect：

```typescript
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      // 加载内容
      observer.unobserve(entry.target);
    }
  });
}, { rootMargin: '200px' });

observer.observe(document.querySelector('#lazy-content')!);
```

### 3.3 计算优化

- 复杂计算（视频抽帧、图片处理）在 Web Worker 中执行
- 大列表使用 `v-memo` 缓存渲染结果
- 避免在 `computed` 中做复杂计算，必要时缓存
- 日期格式化等高频操作缓存结果
- 视频抽帧使用 `requestAnimationFrame` 节流

### 3.4 内存管理

- 组件卸载时清除定时器、事件监听器、IntersectionObserver
- 大对象（图片数据、视频帧）不再使用时置 null
- 全局状态不存储不必要的数据
- 路由切换时清除页面级临时状态
- 定期检查内存泄漏（多次路由切换后 heap 大小稳定）

```typescript
// 组件卸载清理
onUnmounted(() => {
  clearInterval(timer);
  window.removeEventListener('resize', onResize);
  observer.disconnect();
  abortController.abort();
});
```

## 4. 网络性能优化

### 4.1 请求优化

#### 4.1.1 减少请求数

- 合并相关请求（如成员状态 + 今日任务一次返回）
- 使用 GraphQL 风格的字段选择（如后端支持）
- 静态资源合并（JS/CSS 打包）
- 图标内联 SVG，不发起请求

#### 4.1.2 请求并发

- 独立请求并行发起（Promise.all）
- 不串行请求可以并行的接口
- 依赖请求使用 Promise 链

```typescript
// 好：并行
const [member, tasks, risks] = await Promise.all([
  api.getMember(id),
  api.getTodayTasks(id),
  api.getRisks(id),
]);

// 不好：串行
const member = await api.getMember(id);
const tasks = await api.getTodayTasks(id);  // 不依赖 member
const risks = await api.getRisks(id);       // 不依赖 member
```

#### 4.1.3 请求缓存

- 不常变化的数据（知识文档、成员列表）短期缓存
- 使用 `stale-while-revalidate` 策略：先显示缓存，后台更新
- 缓存键包含授权范围，避免越权
- API 响应不进 Service Worker 缓存（安全考虑）

### 4.2 数据传输优化

- 列表分页，默认 20 条，最大 100 条
- 列表项只返回摘要字段，详情按需加载
- 使用 gzip/brotli 压缩（服务端配置）
- 时间使用 ISO 8601 字符串，不发送冗余字段
- 空字段不发送（null 而非空字符串）

### 4.3 弱网适配

#### 4.3.1 超时与重试

```typescript
const DEFAULT_TIMEOUT = 15000;  // 15 秒

async function fetchWithTimeout(url: string, options: RequestInit, timeout = DEFAULT_TIMEOUT) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);

  try {
    return await fetch(url, { ...options, signal: controller.signal });
  } finally {
    clearTimeout(timer);
  }
}

// 重试策略：指数退避，最多 3 次
async function fetchWithRetry(url: string, options: RequestInit, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      return await fetchWithTimeout(url, options);
    } catch (e) {
      if (i === retries - 1) throw e;
      await new Promise(r => setTimeout(r, 1000 * Math.pow(2, i)));
    }
  }
}
```

#### 4.3.2 骨架屏

加载中显示骨架屏，不显示空白：

```vue
<template>
  <div v-if="loading" class="skeleton">
    <div class="skeleton-line" v-for="i in 5" :key="i" />
  </div>
  <div v-else class="content">
    <!-- 实际内容 -->
  </div>
</template>

<style>
.skeleton-line {
  height: 16px;
  margin-bottom: 12px;
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
  border-radius: 4px;
}
@keyframes shimmer {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
</style>
```

**减少动效模式下：** 骨架屏不使用 shimmer 动画，显示静态灰色块。

#### 4.3.3 离线降级

- 已加载的页面在断网时可查看（App Shell 缓存）
- API 请求失败时显示「网络不可用」，保留旧数据
- 不支持离线写入（P0 不做离线队列）
- 重新联网后提示「网络已恢复」

### 4.4 网络状态检测

```typescript
// 监听在线/离线状态
window.addEventListener('online', () => {
  showToast('网络已恢复');
  // 刷新数据
});
window.addEventListener('offline', () => {
  showToast('网络已断开，部分功能不可用');
});

// 检测有效网络类型
const connection = (navigator as any).connection;
if (connection) {
  console.log('网络类型:', connection.effectiveType);  // 4g, 3g, 2g, slow-2g
  console.log('下行带宽:', connection.downlink);       // Mbps
}
```

## 5. 存储性能

### 5.1 存储策略

| 数据 | 存储位置 | 原因 |
| --- | --- | --- |
| 会话 token | 内存 | 安全，XSS 无法窃取 |
| 无障碍设置 | localStorage | 小数据，需持久化 |
| 服务器地址 | localStorage | 小数据，需持久化 |
| 演示数据 | 内存（模块变量） | 不需要持久化 |
| API 响应 | 内存（短期缓存） | 安全，不持久化健康数据 |
| 静态资源 | Service Worker Cache | 离线可用 |
| 健康数据 | 不存储 | 隐私，每次从服务端获取 |

### 5.2 localStorage 限制

- 总存储量 ≤ 100KB
- 不存储健康数据、会话 token、密码
- 只存储 UI 偏好和服务器地址
- 提供「清除本地数据」入口，逐键校验删除

### 5.3 内存缓存

- 成员状态、今日任务等短期缓存（5 分钟）
- 缓存键包含 household_id + member_id + 授权范围
- 切换家庭/成员时清除相关缓存
- 登出时清除全部缓存

## 6. 低端设备适配

### 6.1 设备分级

| 等级 | 特征 | 适配策略 |
| --- | --- | --- |
| 高端 | 多核 CPU、≥4GB RAM、Chrome 最新版 | 全部功能、全部动效 |
| 中端 | 4 核 CPU、2-4GB RAM | 减少装饰节点、简化动画 |
| 低端 | 双核 CPU、≤2GB RAM、Android 7-9 | 停用装饰层、简化动画、虚拟滚动 |

### 6.2 自动检测

```typescript
function isLowEndDevice(): boolean {
  const cores = navigator.hardwareConcurrency || 4;
  const memory = (navigator as any).deviceMemory || 4;
  return cores <= 2 || memory <= 2;
}

// 低端设备自动减少装饰
if (isLowEndDevice()) {
  document.documentElement.setAttribute('data-low-end', 'true');
}
```

```css
[data-low-end="true"] .aurora-layer { display: none; }
[data-low-end="true"] .firefly-layer { display: none; }
[data-low-end="true"] * {
  animation-duration: 0.01ms !important;
  transition-duration: 0.01ms !important;
}
```

### 6.3 低端设备行为

- 极光/萤火装饰层不渲染
- 页面切换无过渡动画
- 列表超过 20 条启用虚拟滚动
- 图片加载使用 `loading="lazy"` + `decoding="async"`
- 不使用模糊、阴影等耗性能效果
- 触摸反馈使用颜色变化，不使用缩放动画

## 7. 性能监控

### 7.1 核心指标

| 指标 | 说明 | 采集方式 |
| --- | --- | --- |
| FCP | 首次内容绘制 | Performance API |
| LCP | 最大内容绘制 | PerformanceObserver |
| FID | 首次输入延迟 | PerformanceObserver |
| TTI | 可交互时间 | 自定义计算 |
| CLS | 累积布局偏移 | PerformanceObserver |
| 路由切换时间 | 页面切换耗时 | 路由守卫计时 |
| API 响应时间 | 接口耗时 | 请求拦截器计时 |
| JS 错误 | 运行时错误 | window.onerror |

### 7.2 本地日志

性能数据记录在内存，可在「我的 → 最近请求与回执」查看：

```typescript
interface RequestLog {
  request_id: string;
  url: string;
  method: string;
  start_time: number;
  end_time: number;
  duration_ms: number;
  status: number;
  error?: string;
}
```

- 最多保留 50 条请求记录
- 不记录请求体和响应体（隐私）
- 可导出为文本，用于问题排查

### 7.3 性能回归测试

`npm run test:perf-budget` 自动对比当前构建与基线：

- JS gzip 体积增长超过 5% → 警告
- 首屏 TTI 增长超过 20% → 失败
- 路由切换时间增长超过 20% → 失败

## 9. 常见性能问题

### 9.1 白屏时间长

**原因：** JS 体积过大、首屏请求过多、渲染阻塞

**解决：**
- 代码分割，首屏只加载必要代码
- 关键 CSS 内联
- 使用 Service Worker 缓存 App Shell
- 预加载首屏资源

### 9.2 列表卡顿

**原因：** 一次性渲染大量 DOM、每个 item 有复杂计算

**解决：**
- 虚拟滚动
- `v-memo` 缓存渲染
- 列表项组件 memo 化
- 图片懒加载

### 9.3 动画掉帧

**原因：** 动画了触发重排的属性、同时有大量动画、低端设备

**解决：**
- 只动画 transform/opacity
- 减少同时运行的动画数量
- 低端设备停用装饰动画
- 使用 `will-change` 提示浏览器

### 9.4 输入延迟

**原因：** 主线程阻塞、事件处理函数计算量大

**解决：**
- 复杂计算移到 Web Worker
- 事件处理防抖/节流
- 避免在事件处理中操作 DOM
- 使用 `requestIdleCallback` 处理非紧急任务

### 9.5 内存泄漏

**原因：** 定时器未清除、事件监听器未移除、全局状态累积

**解决：**
- 组件卸载时清理所有副作用
- 使用 WeakMap/WeakSet 存储关联数据
- 定期检查 heap snapshot
- 路由切换后对比内存
