# 移动端设计模式与最佳实践

> 本文档是家健镜随身版的设计模式与最佳实践指南，覆盖常见场景的解决方案、组件复用模式、状态管理模式、性能优化模式。面向移动端开发者，作为开发时的参考手册。

## 1. 架构模式

### 1.1 分层架构

```
┌─────────────────────────────────────┐
│           表现层 (Views)             │
│  页面组件、布局组件、交互组件         │
├─────────────────────────────────────┤
│         组合式函数层 (Composables)    │
│  useSpeech、useVision、useTasks 等   │
├─────────────────────────────────────┤
│          状态层 (Stores)             │
│  accessibility、session、runtime     │
├─────────────────────────────────────┤
│         数据层 (Data Providers)      │
│  DemoDataProvider、ServerDataProvider│
├─────────────────────────────────────┤
│          基础设施层 (Infra)          │
│  ApiClient、Storage、Logger、Toast   │
└─────────────────────────────────────┘
```

**依赖规则：**
- 上层依赖下层，下层不依赖上层
- 表现层 → 组合式函数 → 状态层 → 数据层 → 基础设施
- 同层之间不直接依赖，通过事件或 props 通信
- 数据层通过接口抽象，可切换实现（演示/联机）

### 1.2 依赖注入模式

```typescript
// 数据提供者接口
interface DataProvider {
  getTodayTasks(memberId: string): Promise<TodayTask[]>
  confirmTask(taskId: string): Promise<void>
  // ...
}

// 演示实现
class DemoDataProvider implements DataProvider {
  // 返回模拟数据
}

// 联机实现
class ServerDataProvider implements DataProvider {
  constructor(private api: ApiClient) {}
  // 调用真实 API
}

// 运行时注入
const runtime = useRuntimeStore()
const dataProvider = computed(() =>
  runtime.mode === 'demo' ? new DemoDataProvider() : new ServerDataProvider(api)
)
```

**优点：**
- 演示和联机模式无缝切换
- 单元测试可注入 Mock
- 新增数据源只需实现接口

### 1.3 组合式函数模式

```typescript
// composables/useVisionTask.ts
export function useVisionTask() {
  const task = ref<VisionTask | null>(null)
  const isPolling = ref(false)
  let pollTimer: number | null = null

  const createTask = async (file: File) => {
    // 上传文件 → 创建任务 → 开始轮询
  }

  const pollStatus = async (taskId: string) => {
    // 轮询任务状态，直到终态
  }

  const cancelTask = async (taskId: string) => {
    // 取消任务，停止轮询
  }

  const cleanup = () => {
    if (pollTimer) clearInterval(pollTimer)
  }

  return { task, isPolling, createTask, cancelTask }

```

**原则：**
- 每个 composable 负责一个功能域
- 返回响应式状态和操作方法
- 在 onUnmounted 中清理资源（定时器、事件监听）
- 不直接操作 DOM，通过 ref 绑定

## 3. 状态管理模式

### 3.1 全局状态 vs 局部状态

| 状态类型 | 存储位置 | 示例 |
| --- | --- | --- |
| 全局状态 | Pinia Store | 无障碍设置、会话、运行时模式 |
| 页面状态 | 页面组件 | 当前筛选条件、分页 |
| 组件状态 | 组件内部 | loading、input value、展开/折叠 |
| 临时状态 | 函数内变量 | 计算中间值 |

**原则：**
- 状态尽量下沉到最低层级
- 只有多组件共享的状态才放 Store
- 表单状态不放 Store（除非跨页面）

### 3.2 乐观更新模式

```typescript
const confirmTask = async (taskId: string) => {
  // 1. 乐观更新
  const task = tasks.value.find(t => t.task_id === taskId)
  const originalStatus = task?.status
  if (task) task.status = 'confirmed'

  try {
    // 2. 调用 API
    await api.confirmTask(taskId)
    showToast('已确认')
  } catch (error) {
    // 3. 失败回滚
    if (task && originalStatus) task.status = originalStatus
    showToast('确认失败，请重试')
  }
}
```

### 3.4 状态机模式

用于复杂交互（如视觉识别流程）：

```typescript
type VisionState = 'idle' | 'uploading' | 'queued' | 'processing' | 'matched' | 'conflict' | 'failed'

const state = ref<VisionState>('idle')

const transitions: Record<VisionState, VisionState[]> = {
  idle: ['uploading'],
  uploading: ['queued', 'failed'],
  queued: ['processing', 'failed'],
  processing: ['matched', 'conflict', 'failed'],
  matched: ['idle'],
  conflict: ['idle'],
  failed: ['idle'],
}

const transition = (next: VisionState) => {
  if (transitions[state.value].includes(next)) {
    state.value = next
  } else {
    console.warn(`Invalid transition: ${state.value} → ${next}`)
  }
}
```

### 7.1 Promise 化模态框

// composables/useConfirmDialog.ts
export function useConfirmDialog() {
  const open = (options: ConfirmOptions): Promise<boolean> => {
    return new Promise((resolve) => {
      dialogStore.show({
        ...options,
        onConfirm: () => resolve(true),
        onCancel: () => resolve(false),
      })
    })
  }
  return { open }
}

### 7.2 焦点陷阱

```typescript
const trapFocus = (el: HTMLElement) => {
  const focusable = el.querySelectorAll<HTMLElement>(
    'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
  )
  const first = focusable[0]
  const last = focusable[focusable.length - 1]

  const handleKeydown = (e: KeyboardEvent) => {
    if (e.key !== 'Tab') return
    if (e.shiftKey && document.activeElement === first) {
      e.preventDefault()
      last.focus()
    } else if (!e.shiftKey && document.activeElement === last) {
      e.preventDefault()
      first.focus()
    }
  }

  el.addEventListener('keydown', handleKeydown)
  first.focus()
  return () => el.removeEventListener('keydown', handleKeydown)
}
```

## 8. 错误处理模式

### 8.1 全局错误边界

```vue
<!-- ErrorBoundary.vue -->
<script setup>
const error = ref<Error | null>(null)
const handleError = (err: Error) => {
  error.value = err
  console.error(err)
}
</script>
<template>

    <slot v-if="!error" />
    <div v-else class="error-boundary">
      <h2>出错了</h2>
      <p>{{ error.message }}</p>
      <button @click="error = null">重试</button>
    </div>
  </ErrorBoundary>
</template>
```

### 8.2 错误重试

```typescript
const fetchWithRetry = async <T>(
  fn: () => Promise<T>,
  retries = 3,
  delay = 1000
): Promise<T> => {
  try {
    return await fn()
  } catch (error) {
    if (retries <= 0 || !isRetryable(error)) throw error
    await sleep(delay)
    return fetchWithRetry(fn, retries - 1, delay * 2)
  }
}
```

### 8.3 错误分类

```typescript
class ApiError extends Error {
  constructor(public code: string, message: string) {
    super(message)
  }
}

class NetworkError extends Error {}
class TimeoutError extends Error {}
class ValidationError extends Error {
  constructor(public fields: Record<string, string>) {
    super('表单校验失败')
  }
}

// 使用
try {
  await api.submit(form)
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldErrors(error.fields)
  } else if (error instanceof NetworkError) {
    showToast('网络连接失败')
  } else if (error instanceof TimeoutError) {
    showToast('请求超时')
  } else {
    showToast('操作失败，请重试')
  }
}
```
