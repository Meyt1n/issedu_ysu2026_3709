# 移动端自动化验证复盘

## 1. 复盘范围

本复盘对应 MOB-145（#233）和 MOB-148（#234）的自动化部分，记录 2026-08-27 在本机完成的性能预算修复与验证。复盘只覆盖浏览器 PWA 和 Capacitor 工程，不覆盖 Android 真机或生产后端。

## 2. 发现的问题

性能预算脚本为每个场景创建新的浏览器 context。应用在首次进入时会显示“隐私告知”弹层；如果脚本直接点击“提醒”导航，弹层会拦截点击，导致路由场景超时。这个失败是测试路径没有完成真实用户前置步骤，而不是性能超预算。

## 3. 修复方式

在 `APP/scripts/perf-budget.mjs` 增加统一的 `acknowledgePrivacyNotice(page)` 辅助函数，并在每个新 context 的导航、离线和恢复场景开始前调用。函数只点击页面已有的“我已阅读并知晓”按钮，不修改应用状态、不注入数据，也不关闭隐私告知逻辑。

## 4. 验证结果

| 检查 | 结果 |
| --- | --- |
| `npm run perf:budget` | 通过；基线冷启动、交互、路由、离线外壳、恢复和资源体积在预算内 |
| `npm run perf:budget:low-end` | 通过；4× CPU / Slow 3G 模拟在预算内 |
| `npm run test:perf-budget` | 通过 |
| `npm run check` | 通过 |
| `npm run test` | 通过，31 个文件 / 282 tests |
| `npm run build` | 通过 |

性能脚本报告的代表性结果为：基线 FCP 132ms、交互 208ms、最差路由 42ms；低端模拟 FCP 340ms、交互 636ms、最差路由 97ms。数值仅代表本机浏览器模拟，不可当作 Android 真机承诺。

## 5. 回归边界

- 隐私告知仍由应用 UI 呈现，自动化没有绕过或伪造同意。
- 脚本不读取 Cookie、令牌或真实健康数据。
- 测试使用仓库内虚构演示数据；不上传真实设备标识或日志。
- 性能通过不等于后端联调、APK 安装、系统权限、TalkBack、TTS 或回滚通过。

## 6. 后续动作

维护者在受控环境中应重新执行同一组预算命令，并把设备型号、WebView、网络配置、APK 哈希和回滚结果写入未提交记录。若真机或受控环境结果超预算，应保留失败证据并将对应门禁恢复为 `BLOCKED`，不得用本机模拟结果覆盖。
