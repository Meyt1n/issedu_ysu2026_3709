# 移动端部署与运维手册

> 本文档是家健镜随身版的部署与运维完整手册，覆盖开发环境搭建、PWA 部署、Android APK 构建、发布流程、监控告警、备份恢复、常见问题排查。面向运维人员和开发者，作为部署和运维的权威依据。

## 1. 部署概述

### 1.1 部署形态

| 形态 | 交付物 | 适用场景 |
| --- | --- | --- |
| PWA | 静态文件（HTML/CSS/JS） | 快速迭代、演示、浏览器直接访问 |
| Android APK | app-debug.apk / app-release.apk | 正式发布、真机能力（通知、安全区） |
| 企业内部分发 | APK + 下载页 | 家庭内部使用，不上应用商店 |

### 1.2 部署架构

```
┌──────────────┐     HTTPS/HTTP      ┌──────────────┐
│  移动端 APP   │ ◄──────────────────►│  Nginx 静态   │
│ (PWA/APK)    │                     │  资源服务器   │
└──────┬───────┘                     └──────────────┘
       │
       │  API 请求
       ▼
┌──────────────┐
│  FastAPI     │
│  后端服务    │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  MySQL/      │
│  SQLite      │
└──────────────┘
```

- PWA 静态资源由 Nginx（或任意静态服务器）托管
- API 请求转发到 FastAPI 后端
- 移动端不直接访问数据库
- 所有服务部署在家庭局域网内

### 3.3 Nginx 部署

#### 3.3.1 配置示例

```nginx
server {
    listen 443 ssl http2;
    server_name homecare.example.com;

    ssl_certificate /etc/nginx/ssl/homecare.crt;
    ssl_certificate_key /etc/nginx/ssl/homecare.key;

    root /var/www/homecare/dist;
    index index.html;

    # PWA 静态资源缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Service Worker 不缓存
    location = /sw.js {
        add_header Cache-Control "no-cache";
    }

    # manifest 不缓存
    location = /manifest.webmanifest {
        add_header Cache-Control "no-cache";
    }

    # index.html 不缓存
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 安全头
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options DENY;
    add_header Referrer-Policy no-referrer;
}
```

#### 3.3.2 部署步骤

```bash
# 1. 构建
cd APP
npm run build

# 2. 上传到服务器
scp -r dist/* user@server:/var/www/homecare/dist/

# 3. 重载 Nginx
sudo nginx -t
sudo systemctl reload nginx
```

### 3.4 PWA 安装

- Chrome/Edge：地址栏显示安装图标，点击安装
- Android：Chrome 菜单 → 添加到主屏幕
- iOS：Safari 分享 → 添加到主屏幕
- 安装后表现类似原生应用，全屏、独立任务、离线可用

### 3.5 Service Worker 更新

1. 新版本发布后，sw.js 内容变化
2. 浏览器检测到新 SW，进入 waiting 状态
3. 页面显示更新提示「有新版本可用」
4. 用户确认后，新 SW 激活，页面刷新
5. 旧缓存（v3 及更早）被清除

**强制更新（紧急情况）：**
- 修改 sw.js 中的版本号
- 用户清除站点数据

## 4. Android APK 构建

### 4.1 环境准备

#### 4.1.1 Windows

```powershell
# 安装 JDK 21
winget install Microsoft.OpenJDK.21

# 设置环境变量
$env:JAVA_HOME = "C:\Program Files\Microsoft\jdk-21"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:PATH += ";$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\cmdline-tools\latestin"

# 安装 Android SDK（通过 Android Studio 或 sdkmanager）
sdkmanager "platforms;android-34" "build-tools;34.0.0" "platform-tools"
```

#### 4.1.2 macOS

```bash
brew install openjdk@21
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
# 安装 Android Studio，通过 SDK Manager 安装 SDK
```

#### 4.1.3 Linux

```bash
sudo apt install openjdk-21-jdk
# 下载 Android command-line tools，配置 ANDROID_HOME
sdkmanager "platforms;android-34" "build-tools;34.0.0" "platform-tools"
```

### 4.2 同步 Capacitor

```bash
cd APP

# 构建前端
npm run build

# 同步到 Android 工程
npm run android:sync
# 等价于：npx cap sync android
```

同步内容：
- 复制 dist/ 到 android/app/src/main/assets/public/
- 同步插件配置
- 更新 capacitor.config.ts 到 Android 工程

### 4.3 构建 Debug APK

#### 方式一：一键脚本（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-apk.ps1
```

产物：`android/app/build/outputs/apk/debug/app-debug.apk`

#### 方式二：手动构建

```bash
cd APP/android

# Windows
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat assembleDebug --no-daemon --console=plain

# macOS/Linux
./gradlew assembleDebug --no-daemon
```

### 4.4 构建 Release APK

#### 4.4.1 生成签名密钥

```bash
keytool -genkey -v -keystore homecare-release.keystore   -alias homecare -keyalg RSA -keysize 2048 -validity 10000
```

**重要：** 密钥文件和密码必须安全保存，丢失则无法更新应用。

#### 4.4.2 配置签名

创建 `android/app/release-signing.properties`（不提交到版本控制）：

```properties
storeFile=homecare-release.keystore
storePassword=your-password
keyAlias=homecare
keyPassword=your-password
```

#### 4.4.3 构建

```bash
cd APP/android
./gradlew assembleRelease --no-daemon
```

产物：`android/app/build/outputs/apk/release/app-release.apk`

### 4.5 安装到设备

```bash
# 确认设备连接
adb devices

# 安装
adb install -r android/app/build/outputs/apk/debug/app-debug.apk

# 启动
adb shell am start -n com.homecaretwin.companion/.MainActivity
```

**Windows 注意：** 荣耀设备可能需要 `$env:ADB_LIBUSB=1` 才能稳定枚举。

### 4.6 APK 验证

```bash
# 检查 APK 信息
aapt dump badging app-debug.apk | head -20

# 检查权限
aapt dump permissions app-debug.apk

# 检查签名
apksigner verify --verbose app-release.apk

# 计算 SHA-256
Get-FileHash app-debug.apk -Algorithm SHA256
```

### 4.7 构建产物清单

```bash
npm run release:manifest -- --out release
```

生成 `release/manifest.json`，含每个文件的 SHA-256，用于发布验证。

### 5.1 发布检查清单

### 5.2 版本号规则

采用语义化版本：`MAJOR.MINOR.PATCH`

- MAJOR：不兼容的架构变更
- MINOR：新增功能，向下兼容
- PATCH：bug 修复，向下兼容

示例：`1.0.0` → `1.1.0`（新增功能）→ `1.1.1`（修复 bug）

### 5.3 发布步骤

```bash

# 修改 APP/public/manifest.webmanifest 的 version
```

## 6. 监控与告警

### 6.1 应用监控

#### 6.1.1 前端监控（PWA）

- **错误监控**：`window.onerror` + `unhandledrejection`，记录到内存，可在「我的 → 诊断」查看
- **性能监控**：Performance API 采集 FCP、LCP、TTI
- **请求监控**：每个 API 请求记录耗时、状态、request_id
- **离线状态**：监听 online/offline 事件

#### 6.1.2 后端监控

- API 响应时间
- 错误率
- 数据库连接池状态
- outbox worker 积压
- 视觉任务队列长度

### 6.2 日志

#### 6.2.1 移动端日志

- 不持久化日志（隐私考虑）
- 内存中保留最近 50 条请求记录
- 可在「我的 → 最近请求与回执」查看
- 可导出为文本用于排查

#### 6.2.2 后端日志

- 结构化 JSON 日志
- 每个请求含 request_id
- 日志级别：DEBUG / INFO / WARNING / ERROR
- 日志轮转：按天切割，保留 30 天

### 6.3 告警规则

| 指标 | 阈值 | 级别 | 通知方式 |
| --- | --- | --- | --- |
| API 错误率 | >5% 持续 5 分钟 | P1 | 邮件 |
| API 响应时间 | P95 > 3s 持续 5 分钟 | P2 | 邮件 |
| 数据库连接失败 | 任意一次 | P0 | 短信+邮件 |
| outbox 积压 | >100 条持续 10 分钟 | P2 | 邮件 |
| 磁盘使用率 | >80% | P2 | 邮件 |
| 证书过期 | <30 天 | P1 | 邮件 |

## 7. 备份与恢复

### 7.1 数据备份

#### 7.1.1 数据库备份

```bash
# MySQL
mysqldump -u root -p homecare > backup_$(date +%Y%m%d).sql

# SQLite
cp homecare.db backup_$(date +%Y%m%d).db
```

#### 7.1.2 文件备份

```bash
# 视觉证据文件
tar -czf files_backup_$(date +%Y%m%d).tar.gz /var/homecare/files/

# 向量索引
tar -czf vector_backup_$(date +%Y%m%d).tar.gz /var/homecare/vector/
```

#### 7.1.3 备份策略

- 全量备份：每天一次，保留 7 天
- 增量备份：每小时一次（如支持）
- 备份加密：AES-256
- 异地备份：每周一次到外部存储

### 7.2 恢复流程

```bash
# 1. 停止服务
sudo systemctl stop homecare-api

# 2. 恢复数据库
mysql -u root -p homecare < backup_20260903.sql

# 3. 恢复文件
tar -xzf files_backup_20260903.tar.gz -C /var/homecare/files/

# 4. 重启服务
sudo systemctl start homecare-api

# 5. 验证
curl http://localhost:8000/health
curl http://localhost:8000/api/v1/meta/capabilities
```

### 7.3 移动端数据恢复

- 移动端不持久化健康数据，无需恢复
- 重新登录后从服务端获取最新数据
- 无障碍设置可通过备份 localStorage 恢复（非必须）
- PWA 重新安装后 Service Worker 重新缓存

## 8. 升级与回滚

### 8.1 PWA 升级

1. 构建新版本，上传到服务器
2. 用户打开应用时检测到新 SW
3. 显示更新提示，用户确认后刷新
4. 旧版本缓存自动清除

**回滚：** 上传旧版本文件，用户清除站点数据或等待 SW 更新。

### 8.2 APK 升级

1. 构建新版本 APK
2. 用户下载覆盖安装（versionCode 必须递增）
3. 应用数据保留

**回滚：** 卸载新版本，安装旧版本 APK（可能丢失本地设置）。

### 8.3 后端升级

1. 备份数据库
2. 拉取新代码
3. 运行数据库迁移：`alembic upgrade head`
4. 重启服务
5. 验证健康检查和核心接口

**回滚：**
1. 停止服务
2. 回滚数据库：`alembic downgrade <previous_revision>`
3. 回滚代码到上一版本
4. 重启服务

## 9. 常见问题

### 9.1 开发环境

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| npm install 失败 | 网络问题 | 使用国内镜像 |
| 端口被占用 | 其他程序占用 5173 | 修改 vite.config.ts 端口 |
| API 请求 404 | 后端未启动或代理配置错 | 启动后端，检查代理 |
| CORS 错误 | 后端 CORS_ORIGINS 不包含前端地址 | 添加前端地址到 CORS_ORIGINS |
| 热更新不生效 | 文件监听问题 | 重启 dev server |

### 9.2 Android 构建

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| JAVA_HOME 未设置 | 环境变量未配置 | 设置 JDK 路径 |
| Gradle 下载慢 | 网络问题 | 配置国内镜像 |
| SDK 未找到 | ANDROID_HOME 未设置 | 设置 Android SDK 路径 |
| 构建失败：minSdk | 依赖要求更高版本 | 升级 compileSdk |
| 安装失败：签名冲突 | 已安装不同签名的 APK | 卸载旧版本 |
| adb 找不到设备 | 驱动问题或未开调试 | 安装驱动，开启 USB 调试 |

### 9.3 运行时

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 白屏 | JS 加载失败或运行时错误 | 检查控制台，清除缓存 |
| 页面空白 | 路由错误或数据加载失败 | 检查 API 响应 |
| 图片不显示 | 路径错误或 CORS | 检查图片路径 |
| 语音不可用 | 浏览器不支持 Web Speech | 使用文字输入 |
| 通知不显示 | 权限未授予或 PWA 未安装 | 授予权限，安装 PWA |
| 横屏布局错乱 | CSS 响应式问题 | 检查媒体查询 |

### 9.4 性能

| 问题 | 原因 | 解决 |
| --- | --- | --- |
| 启动慢 | JS 体积大或网络慢 | 检查产物体积，启用 gzip |
| 滚动卡顿 | 列表渲染过多 | 启用虚拟滚动 |
| 动画掉帧 | 动画了重排属性 | 只动画 transform/opacity |
| 内存增长 | 内存泄漏 | 检查组件卸载清理 |

## 10. 运维脚本

### 10.1 健康检查脚本

```bash
#!/bin/bash
# check-health.sh
API_URL="http://localhost:8000"

echo "=== 健康检查 ==="
echo "时间: $(date)"

# API 健康
if curl -sf "$API_URL/health" > /dev/null; then
  echo "[OK] API 健康检查通过"
else
  echo "[FAIL] API 健康检查失败"
  exit 1
fi

# 数据库
if curl -sf "$API_URL/api/v1/health/db" > /dev/null; then
  echo "[OK] 数据库连接正常"
else
  echo "[FAIL] 数据库连接失败"
  exit 1
fi

# 能力探测
CAPABILITIES=$(curl -sf "$API_URL/api/v1/meta/capabilities")
if echo "$CAPABILITIES" | grep -q "manual-health-event"; then
  echo "[OK] 能力探测正常"
else
  echo "[WARN] 能力探测异常"
fi

echo "=== 检查完成 ==="
```

### 10.3 日志清理脚本

```bash
#!/bin/bash
# cleanup-logs.sh
LOG_DIR="/var/log/homecare"

# 清理 30 天前的日志
find "$LOG_DIR" -name "*.log" -mtime +30 -delete

# 压缩 7 天前的日志
find "$LOG_DIR" -name "*.log" -mtime +7 -exec gzip {} \;

echo "日志清理完成"
```

## 11. 安全运维

### 11.1 定期安全检查

- 每周：`npm audit` 检查依赖漏洞
- 每月：Android 安全配置审计
- 每季度：渗透测试
- 每次发布：隐私扫描

### 11.2 密钥管理

- 不将密钥提交到版本控制
- 使用环境变量或密钥管理服务
- 定期轮换 API key 和数据库密码
- 签名密钥离线保存，多份备份

### 11.3 访问控制

- 服务器 SSH 使用密钥认证，禁用密码登录
- 数据库只监听本地地址
- API 服务只监听家庭局域网
- 管理后台需要额外认证
