# 移动端架构设计详解

> 本文档详细描述家健镜随身版（HomeCare Twin Companion）的架构设计、模块划分、数据流、状态管理、与后端的交互方式，以及关键技术决策。面向后端与移动端开发者，作为代码阅读、功能扩展和问题排查的权威参考。

## 1. 产品定位与架构目标

### 1.1 产品定位

随身版是家健镜系统的移动端入口，定位为「随身照护端」。老人和照护者用手机完成每天高频的照护动作：今日任务确认、拍药盒录入、查看风险提醒、家人健康概览、语音助手问答、紧急求助。管理、复核、大屏和模型实验室等重度操作由网页端承担。

### 1.2 架构目标

| 目标 | 说明 |
| --- | --- |
| 本地优先 | 健康数据默认不出网；演示模式完全离线可用；联机模式仅与家庭局域网内的 FastAPI 通信 |
| 端云同构 | 与网页端共享同一套 API 契约、术语和业务语义；移动端不维护第二套业务规则 |
| 渐进增强 | 核心功能在低端设备和弱网下可用；视觉动效、语音等高级能力可降级 |
| 可访问性优先 | 从架构层面支持长辈模式、高对比、大字号、减少动效、TalkBack |
| 安全可信 | 会话凭据仅存内存；密码不上传明文；授权范围在服务端强制校验 |
| 可测试 | 数据层抽象为 Provider 接口，演示数据与真实 HTTP 可互换；组件纯函数化 |

### 1.3 非目标

- 不做离线优先的 PWA 数据同步（P0 不支持离线写入后同步）
- 不做原生 iOS 开发（P0 仅 Android + PWA）
- 不做后端业务逻辑的客户端重复实现（风险计算、授权判断均在服务端）
- 不做跨设备实时协作（P0 不支持多端实时同步）

## 2. 技术栈选型与理由

### 2.1 核心框架

| 技术 | 版本 | 选型理由 |
| --- | --- | --- |
| Vue | 3.5 | Composition API 适合复杂状态管理；与网页端同栈，降低维护成本 |
| TypeScript | 5.7 | 类型安全；API 契约可从后端 OpenAPI 生成类型 |
| Vite | 6 | 极速 HMR；构建产物体积小；支持 PWA 插件 |
| vue-router | 4 | hash 路由，任意静态托管可用；Capacitor WebView 兼容好 |
| Pinia-style stores | - | 轻量状态管理；无障碍设置、会话、能力探测等全局状态 |

### 2.2 为什么不用组件库

项目选择不使用 Element Plus、Vant、Ant Design Mobile 等组件库，原因：

1. **视觉一致性**：暖阳纸笺设计语言需要深度定制，组件库默认样式覆盖成本高于从零构建
2. **无障碍**：组件库的 ARIA 实现往往不符合项目严格的可访问性要求
3. **体积控制**：移动端对产物体积敏感，完整组件库会显著增加 JS gzip 体积
4. **可控性**：所有交互行为可精确控制，避免组件库内部行为导致的边界问题

基础组件（TabBar、TaskCard、LevelTag、Switch 等）均在 `src/components/` 下手写实现，单一职责，可独立测试。

### 2.3 原生壳选型

| 方案 | 选型 | 理由 |
| --- | --- | --- |
| Capacitor | 8 | 与 Vue/Vite 生态集成好；WebView 渲染一致性高；插件体系成熟 |
| React Native | 否 | 需要维护两套 UI 代码；与网页端无法共享组件 |
| Flutter | 否 | Dart 语言栈不匹配；无法复用现有 Web 技术积累 |
| 纯原生 | 否 | 开发成本高；PWA 无法复用 |

Capacitor 允许同一套 Web 代码同时以 PWA 和原生 APK 两种形态交付，PWA 用于快速迭代和演示，APK 用于发布和真机能力（通知、安全区）。

### 3.2 分层架构

移动端采用经典的四层架构，依赖方向严格单向：

```
┌─────────────────────────────────────────┐
│              Views（页面层）              │
│  今日 / 拍药盒 / 家人 / 提醒 / 知识 / 助手  │
│  求助 / 我的 / 登录                       │
└───────────────┬─────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────┐
│           Components（组件层）            │
│  TaskCard / LevelTag / TabBar / Switch   │
│  AssistantEvidencePanel / AlertCard      │
└───────────────┬─────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────┐
│        Data / Stores（数据与状态层）       │
│  DataProvider 接口                        │
│  ├─ DemoProvider（演示数据）              │
│  └─ HttpDataProvider（真实后端）          │
│  Stores: accessibility / auth / runtime  │
└───────────────┬─────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────┐
│             API（接口层）                 │
│  ApiClient / AuthApi / 类型定义            │
│  请求拦截 / 响应解析 / 错误标准化          │
└─────────────────────────────────────────┘
```

**依赖规则：**
- Views 只能依赖 Components、Data、Stores，不能直接依赖 API
- Components 只能依赖 utils 和类型，不能依赖 Data/Stores（通过 props/events 通信）
- Data 层依赖 API 层，API 层不依赖 Data
- Stores 可以依赖 API 和 Data，但 Views 通过 Stores 获取状态

### 3.3 关键模块职责

#### 3.3.1 API 层（`src/api/`）

| 文件 | 职责 |
| --- | --- |
| `client.ts` | ApiClient 封装：baseURL、超时、请求拦截、Bearer token 注入、响应解析、错误标准化、请求 ID 追踪 |
| `auth.ts` | 登录、注册、修改密码、会话续验、登出；会话凭据仅存内存 |
| `types.ts` | 从后端 OpenAPI 契约派生的 TypeScript 类型；事件、风险、计划、视觉任务等接口定义 |
| `vision.ts` | 视觉任务创建、证据上传、融合、状态轮询、取消 |
| `assistant.ts` | 助手对话（普通/流式）、工具调用状态解析 |
| `knowledge.ts` | 知识文档列表、检索、详情 |

**错误标准化：** 所有 API 错误统一转换为 `ApiError` 对象，包含 `code`、`message`、`requestId`、`status` 字段。UI 层根据 `code` 展示用户友好提示，不直接显示 HTTP 状态码。

#### 3.3.2 数据层（`src/data/`）

数据层是移动端架构的核心抽象，通过 `DataProvider` 接口解耦演示数据与真实后端：

```typescript
interface DataProvider {
  // 家庭与成员
  getHouseholds(): Promise<Household[]>
  getMembers(householdId: string): Promise<Member[]>

  // 健康事件与状态
  getEvents(householdId: string, memberId: string): Promise<HealthEvent[]>
  getMemberState(householdId: string, memberId: string): Promise<MemberState>

  // 风险与提醒
  getRisks(householdId: string, memberId: string): Promise<RiskEvent[]>
  acknowledgeRisk(householdId: string, riskId: string, payload: RiskAckPayload): Promise<void>

  // 照护计划
  getTodayTasks(householdId: string, memberId: string): Promise<Task[]>
  confirmTask(householdId: string, taskId: string): Promise<void>
  deferTask(householdId: string, taskId: string, reason: string): Promise<void>
  skipTask(householdId: string, taskId: string, reason: string): Promise<void>
  missTask(householdId: string, taskId: string, reason: string): Promise<void>
  getPlanWorkbench(householdId: string, memberId: string): Promise<PlanWorkbench>

  // 知识
  getKnowledgeDocuments(): Promise<KnowledgeDoc[]>
  searchKnowledge(query: string): Promise<KnowledgeSearchResult>
  getKnowledgeDocument(docId: string): Promise<KnowledgeDocDetail>

  // 视觉
  createVisionTask(householdId: string, memberId: string, file: File): Promise<VisionTask>
  getVisionTask(taskId: string): Promise<VisionTask>
  cancelVisionTask(taskId: string): Promise<void>

  // 助手
  chat(payload: ChatRequest): Promise<ChatResponse>
  chatStream(payload: ChatRequest): AsyncIterable<StreamChunk>

  // 能力探测
  getCapabilities(): Promise<Capabilities>
}
```

**DemoProvider**：内置虚构家庭数据，完全离线，用于演示、教学和 UI 开发。数据结构与真实 API 响应保持一致，确保切换到 HttpProvider 时无需修改 UI 代码。

**HttpDataProvider**：通过 ApiClient 调用真实 FastAPI 后端。所有请求携带 `X-Access-Purpose`（非 Owner 时），响应按授权范围过滤。

**Provider 切换**：在「我的 → 数据来源」中切换，切换后清除当前会话状态，重新加载数据。默认使用 DemoProvider。

#### 3.3.3 状态管理（`src/stores/`）

| Store | 职责 | 持久化 |
| --- | --- | --- |
| `accessibility.ts` | 长辈模式、主题（浅/深/系统）、字号（标准/大/特大）、高对比、减少动效、语音播报开关 | localStorage（仅本机） |
| `auth.ts` | 当前会话 token、用户信息、家庭/成员选择；登录/登出/会话续验 | 内存（不持久化） |
| `runtime.ts` | 能力探测结果（capabilities）、服务器地址、连接状态 | 内存 |

**为什么会话不持久化：** 安全设计要求会话凭据仅存内存。页面刷新后需要重新登录，避免 XSS 窃取长期凭据。PWA 的 Service Worker 只缓存静态资源，不缓存 API 响应或会话数据。

#### 3.3.4 路由（`src/router/`）

- 使用 hash 路由（`#/today`、`#/scan`），兼容 Capacitor WebView 和任意静态托管
- 联机页面（需要真实后端的页面）配置路由守卫，未登录或未配置服务器时重定向到登录/配置页
- 演示模式下所有页面可直接访问，无需登录
- 路由切换时清除页面级临时状态（如助手输入草稿不清除，由组件自行管理）

#### 3.3.5 视图层（`src/views/`）

| 页面 | 路由 | 职责 |
| --- | --- | --- |
| `TodayView` | `#/today` | 今日任务、进度环、风险概览、最近变化、健康资讯 |
| `ScanView` | `#/scan` | 拍药盒、质量门控、视觉任务状态回查、取消 |
| `FamilyView` | `#/family` | 授权成员列表、成员详情（按授权范围显示字段） |
| `AlertsView` | `#/alerts` | 风险列表（四级筛选）、风险详情、证据展示、知晓回写 |
| `KnowledgeLibraryView` | `#/knowledge` | 知识条目列表、检索、只读详情 |
| `AssistantView` | `#/assistant` | 语音助手对话、流式回复、证据面板、停止生成 |
| `HelpView` | `#/help` | 紧急求助（大按钮）、语音播报提醒、联系家人 |
| `MeView` | `#/me` | 无障碍设置、数据来源、修改密码、隐私声明、本地数据管理、最近请求诊断 |
| `LoginView` | `#/login` | 服务器配置、登录、注册 |

### 4.2 装饰层（极光与萤火）

`App.vue` 中渲染两层纯 CSS 装饰：

- **极光层**：3 个径向渐变节点，通过 `ambient-aurora-drift` 动画缓慢漂移（周期 30s），透明度 0.08
- **萤火层**：8 个小圆点，通过 `ambient-firefly-rise` 动画上升（周期 15-25s 随机），透明度 0.12

两层均设置 `pointer-events: none`，不拦截点击。开启减少动效时（`data-motion="reduced"`），两层均 `display: none`。

**性能考量：** 装饰层使用 `transform` 和 `opacity` 动画，不触发重排；节点数量控制在 11 个以内，低端设备也能保持 60fps。

### 4.3 响应式布局

移动端采用移动优先的响应式设计，断点：

| 断点 | 宽度 | 布局调整 |
| --- | --- | --- |
| 默认 | < 480px | 单列，底部导航 |
| `--breakpoint-tablet` | ≥ 480px | 卡片最大宽度限制，内容居中 |
| 横屏 | 高度 < 宽度 | 任务卡横向排列，减少垂直滚动 |

**横屏适配关键规则：**
- 根容器 `max-width: 100vw`，禁止横向溢出
- 底部导航在横屏仍固定底部，但高度减小
- 今日页的进度环在横屏移至左侧，任务列表在右侧
- 长文案按钮（如「记漏服」）在 1272px 宽屏下保持完整文字不截断（提交 `e3b8093` 修复）

## 5. 数据流与状态管理

### 5.1 页面数据加载流程

```
用户进入页面
  → 路由守卫检查（登录状态/数据来源）
  → 页面 onMounted 调用 DataProvider 方法
  → DataProvider 判断当前模式（Demo/Http）
    → Demo: 直接返回内置数据（同步/微任务）
    → Http: ApiClient 发起请求，携带 token 和 X-Access-Purpose
  → 响应解析为类型化对象
  → 页面本地 state 更新，视图渲染
  → 错误时显示降级 UI（骨架屏→错误提示→重试按钮）
```

### 5.2 写操作流程（以任务确认为例）

```
用户点击「确认」
  → 按钮进入 loading 状态，禁用重复点击
  → 生成幂等键（`confirm:<taskId>`）
  → 调用 DataProvider.confirmTask
    → Http: POST /api/v1/households/{id}/plans/confirm
      → 服务端按幂等键去重，返回 200 或已有结果
    → Demo: 更新本地演示数据
  → 成功：更新任务状态为「已确认」，显示 Toast + 触觉震动
  → 失败：恢复按钮状态，显示错误提示，不更新本地状态
  → 任务操作历史追加一条记录（从服务端事件投影推导）
```

### 5.3 会话生命周期

```
登录成功
  → ApiClient 保存 token 到内存（auth store）
  → 后续请求自动携带 Authorization: Bearer <token>
  → 401 响应 → 清除会话 → 跳转登录页 → 显示「会话已过期」

修改密码成功
  → 服务端撤销全部旧会话，签发新会话
  → 客户端采纳新 token，旧 token 立即失效
  → 密码输入框立即清除

登出
  → 调用 /auth/logout 撤销当前会话
  → 清除内存 token 和所有页面状态
  → 跳转登录页

页面刷新
  → 内存 token 丢失 → 需要重新登录（安全设计）
```

### 5.4 能力探测与降级

应用启动时调用 `GET /api/v1/meta/capabilities`，获取服务端能力声明。结果存储在 `runtime store`，各功能模块根据能力声明决定行为：

| 能力 | 可用时 | 不可用时 |
| --- | --- | --- |
| `knowledge-store` | 知识检索正常发请求 | 显示「知识库暂不可用」，不发请求 |
| `risk-acknowledgement` | 风险「已知晓」按钮可点击 | 按钮置灰，说明需服务端支持 |
| `vision-inference` | 视觉任务正常创建 | 显示「视觉识别暂不可用」 |
| `external-web` | 助手联网搜索开关可开启 | 开关禁用，说明默认关闭 |
| `plan-workbench` | 任务动作按服务端策略展示 | 按钮置灰，保持只读 |

**诚实降级原则：** 能力不可用时如实提示，不冒充可用，不静默失败。

### 6.2 请求头约定

| 头 | 说明 |

### 6.3 错误处理

| HTTP 状态 | 错误码 | 客户端行为 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 显示字段级错误提示 |
| 401 | `UNAUTHORIZED` | 清除会话，跳转登录 |
| 403 | `ACCESS_DENIED` | 显示「无权限访问该成员/字段」 |
| 404 | `RESOURCE_NOT_FOUND` | 显示「资源不存在」（统一不区分不存在/无权限） |
| 409 | `IDEMPOTENCY_KEY_CONFLICT` | 显示「操作已提交，请刷新」 |
| 409 | `AUTHORIZATION_VERSION_CONFLICT` | 提示授权已变更，重新加载 |
| 429 | `RATE_LIMITED` | 显示「操作过于频繁」，禁用重试 |
| 500 | `INTERNAL_ERROR` | 显示「服务器错误」，提供重试 |
| 503 | `SERVICE_UNAVAILABLE` | 显示「服务暂不可用」，保留旧数据 |

**网络错误：** 区分超时（15s）、DNS 失败、连接拒绝，分别给出针对性提示。弱网下显示骨架屏和「正在加载...」，超时后显示「网络较慢，可重试」。

### 6.4 流式响应（助手对话）

助手流式对话使用 `fetch` + `ReadableStream` 解析 SSE：

```
POST /api/v1/assistant/chat/stream
  → 响应 Content-Type: text/event-stream
  → 客户端逐块解析：
    - agent_stage: 多智能体阶段状态（路由/检索/推理/校验）
    - evidence_preview: 脱敏证据预览
    - content_delta: 文本增量
    - tool_call: 工具调用记录
    - done: 最终结果（含完整引用）
    - error: 流错误
  → 普通流错误回退到 /assistant/chat（非流式）
```

停止生成：客户端调用 `AbortController.abort()`，同时发送停止请求到服务端（`POST /api/v1/assistant/chat/stop`），服务端取消生成并返回已生成内容。

## 7. 视觉识别流程

### 7.1 拍药盒完整流程

```
用户点击「拍药盒」
  → 调用系统文件选择器（image/* 或 video/*）
  → 客户端预检：
    - 图片：MIME 白名单、大小 ≤10MiB、像素 ≥800×600
    - 视频：时长 ≤30s、大小 ≤10MiB
  → 创建视觉任务（POST /vision-tasks），获取 taskId
  → 上传文件（安全文件引用，非 multipart）
  → 进入「识别中」状态，启动轮询：
    - 间隔：2s → 3s → 5s → 8s（退避）
    - 上限：30 次或 120s
  → 状态变化：
    - QUEUED → PREPROCESSING → INFERENCING → FUSING
    - 终态：MATCHED / CONFLICT / UNKNOWN / REVIEW / FAILED
  → 排队中/处理中可「取消本次识别」（复用 taskId）
  → 终态展示：
    - MATCHED: 展示候选，引导去网页端复核确认
    - CONFLICT: 展示多候选冲突，提示人工复核
    - UNKNOWN: 提示未识别，建议手动录入
    - REVIEW: 待人工复核
    - FAILED: 显示失败原因，提供重试
```

### 7.2 视觉任务状态机

```
QUEUED ──→ PREPROCESSING ──→ INFERENCING ──→ FUSING ──→ MATCHED
   │            │                │              │          │
   │            │                │              │          ├→ CONFLICT
   │            │                │              │          ├→ UNKNOWN
   │            │                │              │          └→ REVIEW
   │            │                │              │
   └────────────┴────────────────┴──────────────┴──→ FAILED
                                                       ↑
CANCELLED ←── 任意非终态调用 cancel ────────────────────┘
```

**取消语义：** 取消复用同一 taskId，不重新上传、不新建任务。取消后任务进入终态，界面展示取消时间。已完成/失败/超时的任务不显示取消入口。

### 7.3 客户端质量门控

在上传前进行基础质量检查，减少无效请求：

| 检查项 | 阈值 | 不通过时 |
| --- | --- | --- |
| 图片模糊度 | Laplacian 方差 ≥ 100 | 提示「图片模糊，请重拍」 |
| 图片亮度 | 平均亮度 30-220 | 提示「光线不足/过曝」 |
| 图片尺寸 | 长边 ≥ 800px | 提示「分辨率过低」 |
| 文件大小 | ≤ 10 MiB | 提示「文件过大」 |
| 视频时长 | ≤ 30s | 提示「视频过长」 |

**注意：** 客户端质量门控是前置过滤，服务端仍会执行 OpenCV 质量门控，两者不互相替代。

## 9. PWA 与离线策略

### 9.1 Service Worker 缓存策略

`public/sw.js` 实现离线外壳缓存（App Shell）：

| 资源 | 策略 | 说明 |
| --- | --- | --- |
| HTML/CSS/JS/图标 | Cache First | 版本化缓存（`hct-mobile-shell-v4`），更新时替换 |
| 氛围底图 | Cache First | 静态资源 |
| `/api/*` | Network Only | 绝不缓存 API 响应和健康数据 |
| `/health` | Network Only | 绝不缓存健康检查 |
| 其他跨域请求 | Network Only | 不缓存第三方资源 |

### 9.2 更新生命周期

1. 新版本发布后，Service Worker 检测到新资源，进入 `waiting` 状态
2. 页面显示可关闭、可读屏的更新提示：「有新版本可用，点击刷新」
3. 用户确认后，`serviceWorker.controller.postMessage({type: 'SKIP_WAITING'})`
4. 新 Service Worker 激活，页面刷新
5. 旧缓存（`hct-mobile-shell-v3` 及更早）被清除

**用户体验：** 更新提示不强制、不阻塞，用户可继续使用当前版本，下次打开时自动更新。

### 9.3 离线行为

- 已缓存的应用外壳和静态资源可正常加载
- API 请求失败时显示「当前离线，健康数据不可用」
- 不支持离线写入（P0 不做离线队列和同步）
- 「我的 → 清理离线外壳缓存」可手动清除缓存（两步确认）

## 11. 性能架构

### 11.1 产物体积预算

| 指标 | 基线预算 | 低端设备预算 |
| --- | --- | --- |
| JS gzip | ≤ 170 KiB | ≤ 200 KiB |
| CSS gzip | ≤ 30 KiB | ≤ 40 KiB |
| HTML | ≤ 5 KiB | ≤ 5 KiB |
| 首屏可交互 | ≤ 1500ms | ≤ 3000ms |
| 路由切换 | ≤ 300ms | ≤ 800ms |
| 断网恢复 | ≤ 500ms | ≤ 1000ms |

`npm run perf:budget` 和 `npm run perf:budget:low-end` 自动测量，超预算则 CI 失败。

### 11.2 性能优化手段

1. **代码分割**：路由级懒加载，首屏只加载今日页
2. **Tree Shaking**：Vite 生产构建自动移除未使用代码
3. **CSS 优化**：CSS 自定义属性避免重复，未使用的样式通过 PurgeCSS 移除
4. **图片优化**：装饰层纯 CSS 绘制，不使用图片；图标使用内联 SVG
5. **虚拟列表**：事件时间线超过 50 条时启用虚拟滚动
6. **防抖节流**：搜索输入防抖 300ms，滚动监听节流 16ms
7. **懒渲染**：页面下方内容使用 `IntersectionObserver` 懒渲染
8. **避免重排**：动画只使用 `transform` 和 `opacity`

### 11.3 低端设备适配

- 装饰层节点数在低端设备自动减少（通过 `navigator.hardwareConcurrency` 判断）
- 减少动效模式下完全停用装饰层
- 图片加载使用 `loading="lazy"`
- 复杂计算（如视频抽帧）在 Web Worker 中执行

## 15. 常见问题排查

### 15.1 白屏

- 检查 Service Worker 是否缓存了旧版本 → 清除站点数据
- 检查 JS 是否有运行时错误 → Chrome DevTools remote debugging
- 检查 CSS 变量是否正确注入 → 审查 `:root` 计算样式

### 15.2 API 请求失败

- 检查服务器地址是否正确（「我的 → 数据来源」）
- 检查家庭服务器是否启动（`curl http://<addr>:18800/health`）
- 检查 CORS 配置（后端 `CORS_ORIGINS` 需包含移动端地址）
- 检查会话是否过期（401 → 重新登录）
- 检查 `X-Access-Purpose` 是否与授权匹配（403）

### 15.3 横屏布局溢出

- 检查根容器 `max-width: 100vw`
- 检查是否有元素设置了固定宽度大于视口
- 运行 `npm run audit:responsive` 自动检测
- 长文案按钮使用 `white-space: normal` 或缩短文案

### 15.4 TalkBack 朗读异常

- 检查元素是否使用语义化标签
- 检查图标按钮是否有 `aria-label`
- 检查动态内容是否在 `aria-live` 区域
- 检查焦点顺序是否与视觉顺序一致

### 15.5 APK 安装失败

- 检查是否允许安装未知来源应用
- 检查 Android 版本是否 ≥ 7.0
- 检查是否有签名冲突（先卸载旧版本）
- 检查存储空间是否充足

## 16. 术语表

| 术语 | 含义 |
| --- | --- |
| 随身版 | 移动端应用（HomeCare Twin Companion） |
| 演示模式 | 使用内置虚构数据，完全离线，不连接后端 |
| 联机模式 | 连接家庭局域网内的 FastAPI 后端，使用真实数据 |
| 暖阳纸笺 | 产品视觉设计语言，暖纸背景 + 松绿主色 + 陶土强调色 |

| 幂等键 | 写操作的去重标识，相同键重复提交只生效一次 |
| 能力探测 | 调用 `/meta/capabilities` 获取服务端可用能力声明 |
| 离线外壳 | Service Worker 缓存的静态资源（HTML/CSS/JS/图标），不包含 API 数据 |
