# 移动端安全设计与隐私保护

> 本文档是家健镜随身版安全设计与隐私保护的完整规范，覆盖认证授权、数据安全、网络安全、存储安全、隐私保护、Android 安全配置、安全测试与应急响应。面向后端和移动端开发者，作为安全设计和验收的权威依据。

## 1. 安全原则

### 1.1 核心安全原则

| 原则 | 说明 |
| --- | --- |
| 本地优先 | 健康数据默认不出网，所有处理在家庭局域网内完成 |
| 最小权限 | 每个角色、每个授权只授予必要的最小权限 |
| 纵深防御 | 多层安全控制，一层被突破仍有其他层保护 |
| 默认安全 | 默认配置是安全的，需要显式开启才能降低安全等级 |
| 失败关闭 | 安全检查失败时默认拒绝，不默认放行 |
| 可审计 | 所有关键操作有审计日志，可追溯 |
| 诚实透明 | 向用户明确说明数据收集范围和用途，不隐瞒 |

### 1.2 威胁模型

#### 1.2.1 资产

| 资产 | 敏感度 | 说明 |
| --- | --- | --- |
| 健康事件 | 极高 | 用药、过敏、疾病、指标等个人健康信息 |
| 家庭成员关系 | 高 | 家庭结构、照护关系 |
| 账号凭据 | 极高 | 用户名、密码哈希、会话 token |
| 授权配置 | 高 | 谁能看什么数据 |
| 药品主数据 | 中 | 药品名称、成分、规格 |
| 视觉证据 | 高 | 药盒照片、OCR 结果（可能含个人信息） |
| 使用日志 | 中 | 操作记录、请求时间 |

#### 1.2.2 威胁

| 威胁 | 来源 | 风险 |
| --- | --- | --- |
| 越权访问 | 恶意家庭成员 | 查看未授权的健康数据 |
| 会话劫持 | 网络中间人 | 窃取会话 token 冒充用户 |
| XSS | 输入注入 | 窃取 token、篡改页面 |
| 数据泄露 | 设备丢失 | 本地存储的健康数据被提取 |
| 网络嗅探 | 公共 WiFi | 明文传输健康数据 |
| 重放攻击 | 截获请求 | 重复提交操作 |
| 恶意 APK | 第三方分发 | 植入后门、窃取数据 |
| 依赖漏洞 | 开源组件 | 已知漏洞被利用 |

#### 1.2.3 信任边界

- **家庭局域网内**：API、数据库、文件存储、Ollama 互信
- **家庭局域网外**：默认不可信，需要 HTTPS 和认证
- **移动端 WebView**：不可信环境，不存储敏感数据
- **第三方服务**：天气 API 只接收城市编码，不接收健康数据

## 2. 认证与授权

### 2.1 认证机制

#### 2.1.1 账号密码

- 用户名：3-32 字符，字母数字下划线
- 密码：≥8 位，同时含字母和数字
- 密码存储：bcrypt 哈希，cost factor ≥ 12
- 密码不传输明文（HTTPS 传输）
- 连续失败 5 次锁定 15 分钟
- 不提供密码找回（本地系统，通过 Owner 重置）

#### 2.1.2 会话管理

- 短期 Bearer token，有效期 1 小时
- 无 refresh token，过期后重新登录
- 移动端 token 仅存内存，不写 localStorage
- 页面刷新后需重新登录
- 修改密码后撤销全部旧会话，签发新会话
- 登出时撤销当前会话
- 服务端维护会话黑名单，支持主动撤销

#### 2.1.3 家庭 PIN

- 6 位数字 PIN，用于敏感操作二次确认
- 服务端只存哈希，不下发、不回显
- 连续失败 5 次锁定 5 分钟
- 用于：删除成员、撤销授权、修改家庭设置等

### 2.2 授权模型

#### 2.2.1 角色

| 角色 | 权限 |
| --- | --- |
| Owner | 家庭创建者，拥有全部权限，可管理授权 |
| 照护者 | 被授权访问特定成员的特定字段，可执行被授权的动作 |
| 成员本人 | 可查看自己的全部数据（P0 简化，P1 细化） |

#### 2.2.2 字段级授权

授权粒度到「成员 × 数据字段 × 动作 × 目的 × 期限」：

```
授权 = {
  grantee: 照护者用户ID,
  member: 成员ID,
  data_fields: ["medications", "vitals", "risks"],
  actions: ["read", "confirm_task", "acknowledge_risk"],
  purpose: "care_daily_check",  // ASCII 目的代码
  valid_from: 开始时间,
  valid_until: 结束时间,
  status: active / revoked / expired
}
```

#### 2.2.3 授权校验

- 每次 API 请求校验：用户身份 → 家庭归属 → 成员授权 → 字段权限 → 动作权限 → 目的匹配 → 有效期
- 非 Owner 必须携带 `X-Access-Purpose` 头，值与授权 purpose 精确匹配
- 跨家庭、未授权、字段越权统一返回 404（不泄露资源存在性）
- 授权版本使用乐观锁，并发修改返回 409
- 授权变更立即生效，旧请求在下一次校验时被拒绝

### 2.3 访问审计

- 所有非 Owner 访问记录审计日志：时间、用户、成员、动作、目的、结果
- 审计日志只存元数据，不存健康正文或证据
- Owner 可查询授权和访问审计
- 审计记录不可修改、不可删除（追加写）
- 家庭删除时审计日志同步清除

## 3. 数据安全

### 3.1 数据分类

| 分类 | 示例 | 保护要求 |
| --- | --- | --- |
| 极敏感 | 健康事件、药品、过敏、指标 | 加密存储、授权访问、不出网 |
| 敏感 | 家庭成员、授权配置、审计日志 | 授权访问、不出网 |
| 内部 | 药品主数据、规则配置、模型版本 | 家庭内可见 |
| 公开 | 健康资讯、产品说明 | 可公开 |

### 3.2 传输安全

- 家庭局域网内默认 HTTP（可信网络）
- 公网访问必须 HTTPS（TLS 1.2+）
- Release APK 禁止明文流量（`cleartextTrafficPermitted="false"`）
- Debug APK 仅允许家庭局域网 HTTP，拒绝公网 HTTP
- API 请求不包含敏感信息在 URL 中（用 POST body）
- 响应头不泄露服务器版本、堆栈信息

### 3.3 存储安全

#### 3.3.1 服务端存储

- MySQL 数据库文件权限限制（仅服务进程可读）
- 敏感快照（before/after）最小化并加密
- 数据库备份加密存储
- 不提交 .env、真实数据、密钥到版本控制

#### 3.3.2 客户端存储

| 数据 | 存储位置 | 加密 |
| --- | --- | --- |
| 会话 token | 内存 | 不持久化 |
| 密码 | 不存储 | - |
| 健康数据 | 不存储 | - |
| 无障碍设置 | localStorage | 明文（非敏感） |
| 服务器地址 | localStorage | 明文（非敏感） |
| 演示数据 | 内存 | 虚构数据 |

**关键规则：移动端不持久化任何健康数据或认证凭据。**

### 3.4 数据最小化

- API 响应只返回请求的字段，不返回多余数据
- 列表接口返回摘要，详情接口返回完整数据
- 审计日志只存元数据，不存正文
- 视觉证据在处理完成后可配置保留期限
- 不收集用户行为分析数据（无 Google Analytics、无埋点 SDK）

### 3.5 数据删除

#### 3.5.1 家庭删除

Owner 可触发完整删除传播（`DELETE /households/{id}`）：

1. 数据库：家庭、成员、事件、授权、审计、风险、计划全部删除
2. 文件存储：相关图片、视频、视觉证据全部删除
3. 向量索引：相关文档切片全部删除
4. 缓存：Redis/内存缓存全部清除
5. 会话：该家庭全部会话撤销
6. 审计：审计日志同步删除（不保留）

#### 3.5.2 成员删除

- 删除成员的全部健康事件、状态投影、风险、计划
- 保留家庭审计日志中该成员的访问记录（脱敏）
- 相关视觉证据标记删除

#### 3.5.3 本地数据清除

移动端「我的 → 本地数据管理」提供：
- 查看本机保存的数据清单
- 逐项清除（localStorage 键）
- 全部清除（恢复初始状态）
- 清除后需重新配置服务器和登录

## 4. 网络安全

### 4.1 网络边界

- 默认拒绝所有出网请求
- 仅允许的出网：
  - 家庭局域网内的 API 服务器
  - 天气 API（仅发送 6 位城市编码）
  - 知识文档来源（如配置了外部知识源）
- 健康数据、成员信息、视觉证据不出网
- 云端 LLM 只能作为独立扩展，不能作为默认 fallback

### 4.2 CORS 策略

- 后端配置 `CORS_ORIGINS` 白名单
- 移动端地址必须在白名单中才能访问 API
- 不使用 `Access-Control-Allow-Origin: *`
- 允许的方法：GET, POST, PATCH, DELETE（按接口）
- 允许的头：Authorization, Content-Type, X-Access-Purpose, Idempotency-Key, X-Request-ID

### 4.3 请求安全

- 所有写操作支持幂等键（`Idempotency-Key`）
- 相同幂等键重复提交返回原结果，不重复执行
- 幂等键冲突（相同键不同内容）返回 409
- 请求体大小限制：JSON ≤ 1MB，文件上传 ≤ 10MB
- 内容类型校验：只接受 `application/json` 和白名单 MIME 的文件

### 4.4 响应安全

- 安全响应头：
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Content-Security-Policy`（限制脚本来源）
  - `Referrer-Policy: no-referrer`
- 错误信息不泄露堆栈、SQL、文件路径
- 404 统一不区分「不存在」和「无权限」

## 5. 隐私保护

### 5.1 隐私原则

- **不收集**：不收集位置、通讯录、相机胶卷、麦克风（除用户主动触发）
- **不共享**：不向第三方共享任何健康数据
- **不分析**：不做用户行为分析、不嵌入追踪 SDK
- **不广告**：不展示广告、不做商品推荐
- **可控制**：用户可查看、导出、删除自己的数据
- **透明**：明确告知数据收集范围和用途

### 5.2 权限最小化

#### 5.2.1 Android 权限

| 权限 | 是否申请 | 用途 |
| --- | --- | --- |
| INTERNET | 是 | 与家庭服务器通信 |
| CAMERA | 否 | 通过系统文件选择器拍照，不直接申请相机权限 |
| READ_EXTERNAL_STORAGE | 否 | 通过系统文件选择器，不申请存储权限 |
| POST_NOTIFICATIONS | 否（P0） | P0 不做本地通知，P1 按需申请 |
| CALL_PHONE | 否 | 用 `tel:` 链接打开拨号界面，不直接拨号 |
| RECORD_AUDIO | 否 | 语音输入用浏览器 Web Speech API，不申请麦克风权限 |
| ACCESS_FINE_LOCATION | 否 | 天气用城市编码，不用精确位置 |
| READ_CONTACTS | 否 | 紧急联系人手动输入，不读通讯录 |

**P0 只申请 INTERNET 一个权限。**

#### 5.2.2 Web API 使用

| API | 用途 | 隐私保护 |
| --- | --- | --- |
| Web Speech API | 语音输入/播报 | 音频不上传，本地识别（浏览器支持时） |
| navigator.vibrate | 触觉反馈 | 不收集数据 |
| localStorage | UI 偏好 | 只存非敏感设置 |
| Service Worker | 离线缓存 | 只缓存静态资源，不缓存 API 数据 |
| IntersectionObserver | 懒加载 | 不收集数据 |

### 5.3 隐私告知

首次使用展示可朗读的隐私告知：

1. 我们收集什么：不收集个人健康数据到云端
2. 数据存在哪里：家庭本地服务器
3. 谁能看到：只有被授权的家庭成员
4. 我们不做什么：不广告、不分析、不共享
5. 你的权利：查看、导出、删除数据
6. 如何联系：家庭管理员

用户必须确认后才能使用。

### 5.4 语音隐私

- 语音输入使用浏览器/系统 Web Speech API
- 音频不上传到家庭服务器
- 不保存音频文件
- 语音识别文本作为普通消息处理，不特殊存储
- 语音播报使用系统 TTS，不发送文本到云端

### 5.5 视觉隐私

- 药盒照片只上传到家庭本地服务器
- 照片用于 OCR 识别后，可配置保留期限
- 照片不用于模型训练（除非用户显式授权）
- 困难样本进入审核池前脱敏
- 不使用人脸识别作为认证方式（P0 不做人脸识别）

## 6. Android 安全配置

### 6.1 Manifest 配置

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- 只申请 INTERNET -->
    <uses-permission android:name="android.permission.INTERNET" />

    <application
        android:allowBackup="false"
        android:usesCleartextTraffic="false"
        android:networkSecurityConfig="@xml/network_security_config"
        android:exported="false">
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
    </application>
</manifest>
```

### 6.2 网络安全配置

**Release：**

```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <base-config cleartextTrafficPermitted="false">
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </base-config>
</network-security-config>
```

**Debug（仅家庭局域网 HTTP）：**

```xml
<network-security-config>
    <base-config cleartextTrafficPermitted="false">
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </base-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="false">10.0.0.0/8</domain>
        <domain includeSubdomains="false">172.16.0.0/12</domain>
        <domain includeSubdomains="false">192.168.0.0/16</domain>
        <domain includeSubdomains="false">localhost</domain>
    </domain-config>
</network-security-config>
```

**应用层校验：** 即使 Debug 允许局域网 HTTP，APP 仍校验地址——公网 HTTP 地址被拒绝，只允许私有 IP 段或 localhost。

### 6.3 备份禁止

`android:allowBackup="false"`：
- 禁止 Android 11 及以下的 full-backup
- 禁止 Android 12+ 的 cloud-backup 和 device-transfer
- 应用私有域全部排除在备份之外
- 防止通过 ADB 备份提取应用数据

### 6.4 WebView 安全

```java
WebSettings settings = webView.getSettings();
settings.setJavaScriptEnabled(true);              // 应用需要 JS
settings.setDomStorageEnabled(true);              // localStorage
settings.setAllowFileAccess(false);               // 禁止文件访问
settings.setAllowContentAccess(false);            // 禁止 content URI
settings.setAllowUniversalAccessFromFileURLs(false); // 禁止跨域
settings.setMixedContentMode(WebSettings.MIXED_CONTENT_NEVER_ALLOW); // Release
// Debug: MIXED_CONTENT_ALWAYS_ALLOW（仅家庭局域网）
settings.setCacheMode(WebSettings.LOAD_DEFAULT);

// 不启用 setSavePassword（已废弃，默认不保存）
// 不启用 setGeolocationEnabled（不需要位置）
```

### 6.5 深度链接安全

- 不注册自定义 scheme（如 `homecare://`），避免恶意应用调用
- 不使用 `intent://` 链接
- 不导出不必要的组件
- MainActivity 的 launchMode 为 singleTask，防止重放攻击

## 7. 前端安全

### 7.1 XSS 防护

- 使用 Vue 模板语法，默认转义 HTML
- 不使用 `v-html` 渲染用户输入
- 必要时使用 `v-html`，内容必须经过 DOMPurify 清洗
- API 响应中的文本作为纯文本渲染，不作为 HTML
- 内容安全策略（CSP）限制脚本来源

```vue
<!-- 好：自动转义 -->
<p>{{ userInput }}</p>

<!-- 不好：可能 XSS -->
<p v-html="userInput"></p>

<!-- 如必须用 v-html -->
<p v-html="sanitize(userInput)"></p>
```

### 7.2 CSRF 防护

- 使用 Bearer token（非 Cookie），天然免疫 CSRF
- 不使用 Cookie 存储会话
- 关键操作（删除、撤权）需要二次确认（家庭 PIN）

### 7.3 依赖安全

- 定期运行 `npm audit` 检查依赖漏洞
- 不安装来源不明的 npm 包
- 锁定依赖版本（package-lock.json）
- 生产构建不包含 devDependencies
- Capacitor 插件只使用官方或可信来源

### 7.4 敏感信息保护

- 密码输入框 `type="password"`，不显示明文
- 密码提交后立即清除输入框
- 不在 URL 中传递敏感参数
- 不在 console.log 中输出 token、密码、健康数据
- 错误提示不泄露具体原因（如「用户名或密码错误」而非「用户名不存在」）

### 7.5 本地数据隔离

- 不同家庭的数据不共享本地缓存
- 切换家庭时清除上一个家庭的缓存
- 登出时清除全部内存状态
- 多用户共用设备时，后登录者看不到前登录者的数据

## 8. 安全测试

### 8.1 自动化安全检查

| 检查项 | 工具 | 命令 |
| --- | --- | --- |
| Android 权限审计 | 自定义脚本 | `npm run audit:android-security` |
| 隐私扫描 | 自定义脚本 | `npm run privacy:scan` |
| 依赖漏洞 | npm audit | `npm audit` |
| CORS 配置 | 后端测试 | pytest |
| 授权越权 | 集成测试 | pytest |
| 输入校验 | 单元测试 | Vitest |

### 8.2 隐私扫描内容

`npm run privacy:scan` 检查：

- [ ] 代码中无硬编码的密钥、token
- [ ] 无外部分析 SDK（Google Analytics、Sentry 等）
- [ ] 无不必要的网络请求（遥测、错误上报）
- [ ] localStorage 不存储健康数据或 token
- [ ] 无 `v-html` 渲染用户输入（或已清洗）
- [ ] 无 console.log 输出敏感信息
- [ ] Android Manifest 权限最小化
- [ ] 网络安全配置正确
- [ ] Service Worker 不缓存 API 响应

### 8.3 渗透测试清单

- [ ] 越权访问：尝试访问其他家庭/成员的数据
- [ ] 字段越权：尝试访问未授权的字段
- [ ] 会话劫持：窃取 token 后能否使用
- [ ] 重放攻击：重复提交相同请求
- [ ] XSS：在输入框注入脚本
- [ ] SQL 注入：在搜索框注入 SQL
- [ ] 文件上传：上传恶意文件
- [ ] 暴力破解：连续尝试登录
- [ ] 中间人：HTTP 环境下嗅探数据
- [ ] 本地存储：Root 设备提取应用数据

### 8.4 安全回归

每次 PR 合并前运行：
- `npm run privacy:scan`
- `npm run audit:android-security`
- 后端授权集成测试
- 后端输入校验测试

## 9. 应急响应

### 9.1 安全事件分级

| 级别 | 定义 | 响应时间 |
| --- | --- | --- |
| P0 严重 | 健康数据泄露、系统被入侵 | 立即响应，24 小时内修复 |
| P1 高危 | 越权漏洞、认证绕过 | 24 小时内响应，72 小时内修复 |
| P2 中危 | 信息泄露、配置错误 | 72 小时内响应，一周内修复 |
| P3 低危 | 最佳实践缺失 | 下一版本修复 |

### 9.2 响应流程

1. **发现**：用户报告、安全测试、监控告警
2. **评估**：确认漏洞、影响范围、严重程度
3. **遏制**：临时措施（关闭功能、撤销会话）
4. **修复**：开发补丁、测试验证
5. **通知**：受影响用户（如涉及数据泄露）
6. **复盘**：根因分析、改进措施、更新文档

### 9.3 漏洞披露

- 安全问题通过 Issue 报告，标记 `security` 标签
- 不公开披露未修复的漏洞细节
- 修复后在 Release Notes 中说明
- 感谢报告者（如适用）
