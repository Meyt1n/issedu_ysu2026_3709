# MOB-148 发布前置条件证据台账

本台账配合 [MOB-148 移动端最终发布门禁](MOB-148-移动端最终发布门禁.md) 使用，用于如实记录发布前置条件的完成情况、待补证据和复核入口。它**不是发布批准记录**，不因填写本台账而解除任何门禁。

## 使用规则

1. 初始状态统一为 `BLOCKED`；只有维护者在受控环境中复核完整脱敏证据后，才可改为 `VERIFIED`。
2. `Issue closed`、页面截图、mock 成功或本地单次运行均不能单独作为通过证据。
3. 证据路径只可填写脱敏报告、CI 链接、测试记录或受控环境记录编号；不得写入真实地址、令牌、Cookie、设备序列号、健康数据或 APK 签名材料。
4. 每次状态改变必须同步填写执行日期、APP/服务端提交、复核人和回滚产物位置；任一字段缺失，维持 `BLOCKED`。

## 2026-08-28 本机补充证据（不改变状态）

本次在最新 `master`（源码基线 `c0640ca`）上顺序复跑了移动端自动化，并用 JDK 21 + Android SDK 生成了 debug APK。类型检查、32 个测试文件共 290 个测试、生产构建、Capacitor 同步、隐私扫描、Android 静态安全审计、PWA 审计和两套性能预算均通过；基线 JS gzip 为 159.29 KiB，低端模拟可交互 841 ms。发布清单显示版本 `0.1.0`、55 个产物且提交一致性为 true。

同一候选 APK 在荣耀 AAP-AN00（Android 16、WebView 138.0.7204.179、1272×2800）完成 USB 安装和启动烟测，设备序列号未记录。由于未启动受控后端，`verify:linkage` 仍失败；无障碍/语音证据校验器仍因缺少完整真机矩阵拒绝空记录，升级、后台恢复、权限和 PWA/APK/API 回滚也未演练。因此以下状态继续保持 `BLOCKED`：

- `MOB148-E01`：本机自动化通过，但缺维护者在受控环境中的完整签收；
- `MOB148-E02`：已生成候选 APK，但缺上一版本指纹和回滚演练；
- `MOB148-E06`：仅完成一次安装/启动烟测，缺更新、缓存恢复、网络和权限矩阵；
- `MOB148-E07`：缺 TalkBack、TTS、触觉、高对比、减少动效和小屏证据；
- `MOB148-E09`：浏览器/低端模拟通过，缺受控 Android 后台恢复和崩溃烟测；
- `MOB148-E03`、`E04`、`E05`、`E08`、`E10` 以及 `V01`、`V02`：仍缺受控后端或正式视觉生产证据。

## 裁决

- `RUNTIME_RELEASE` 只能在 MOB148-E01 至 MOB148-E10 全部为 `VERIFIED`、版本信息一致且回滚演练成功时由维护者批准。
- 任一 E 项为 `BLOCKED` 时，不得把 APP/PWA/APK 描述为可运行时发布；如仅作课堂演示，应明确为 `DEMO_ONLY`。
- `FULL_VISION_PRODUCTION` 还要求 MOB148-V01、MOB148-V02 均为 `VERIFIED`；否则视觉能力必须禁用或明确受限，不得伪造识别结果。
