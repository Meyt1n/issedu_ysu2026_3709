## 3. 可复跑自动化

在 `APP/` 目录执行：

```powershell
npm run mobile:ready
npm run check
npm run test
npm run build
npm run android:sync
npm run privacy:scan
npm run audit:android-security
npm run audit:pwa
npm run perf:budget
npm run perf:budget:low-end
npm run test:perf-budget
npm run test:privacy-scan
npm run release:manifest -- --out release
```

`npm run mobile:ready` 会按正确顺序串行执行上述主要代码门禁、两套性能预算和 Capacitor Android 资源同步；需要检查本机 APK 时追加 `-- --apk <路径> --require-apk`。单项命令仍保留，便于定位失败原因。

本次复核结果为：`check`、测试（32 个文件 / 290 tests）、构建、Capacitor 同步、隐私、安全、PWA、基线性能、低端设备性能、两个回归测试和产物清单均通过。基线性能 JS gzip 为 159.29 KiB；低端模拟可交互 841 ms、路由最慢 133 ms、断网恢复 177 ms。`release/` 只用于本机临时产物，不提交仓库。

性能脚本会在每个新的浏览器 context 中先按真实用户路径确认首次隐私告知，再进入提醒、设置和断网恢复场景。这样既保留隐私告知语义，也避免自动化绕过真实 UI。

性能命令必须顺序执行：`perf:budget` 和 `perf:budget:low-end` 都会重建 `dist/`，并行执行会造成不同构建产物混杂，导致体积报告失真。
