# HCT-458 后端风险告警合并与预算审计元数据

- Issue：[#480](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/480)
- 上游需求：[#477 HCT-457](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/477)
- 关联需求：FR-05、NFR-03、NFR-07
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为家庭照护后端维护者，我希望每条风险告警都带有服务器计算的合并和预算审计信息，这样客户端能够解释提醒为何合并、是否被每日预算暂缓以及依据来自多少条脱敏事件，而不需要在本地重新运行规则或读取健康正文。

## 验收标准

- [x] 风险列表和助手 `get_risk_alerts` 为每条告警返回 `deduplication_key`、`merged_count`、`budget_status`、`budget_reason`、`next_visible_at`、`evidence_summary`。
- [x] 相同规则和来源事件的重复告警累计合并数量，并生成稳定、无正文的分组键。
- [x] 严重告警和预算内告警标记 `VISIBLE`；超出普通预算的告警标记 `DEFERRED`，带原因和下一次 UTC 预算重置时间，且不再静默丢失。
- [x] `suppressed_count` 仍准确统计暂缓条目；规则等级、风险指纹、确认和默认预算语义保持不变。
- [x] 证据摘要只返回来源事件数量，不包含事件 payload、药品/疾病正文或原始查询。

## 实现与证据

1. 扩展规则引擎 `Alert` 元数据，在去重阶段累计合并数量，在预算阶段标注可见性、原因和下一周期时间。
2. 扩展风险 API Schema、风险详情、风险确认路径和本地助手工具序列化，确保不同入口使用同一服务端元数据。
3. 增加规则单元测试、风险列表契约测试、助手工具回归测试和隐私字段断言。

## 回滚

回滚应用代码和 API 文档即可移除新增元数据；不涉及数据库迁移，不改变已有风险规则、授权或确认数据。
