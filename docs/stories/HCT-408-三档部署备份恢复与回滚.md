## 目标与价值

交付三档可复现部署，并证明数据库、文件、索引、配置和版本组合可备份、恢复和回滚。

## 范围

### 三档 Compose Profile

| 档位 | Profile 名 | 服务 | 能力边界 |
|------|-----------|------|----------|
| 基础档 | `basic` | db + api + web | 结构化事实、规则卡、授权、事件、文件上传。不启 Ollama，AI 能力返回 `unavailable` |
| 增强档 | `enhanced` | db + api + web + ollama | 基础档全部 + 本地 Ollama（Qwen2.5:7B Q4_K_M，回环 HTTP），工具调用与结构化输出 |
| 研发档 | `dev` | 增强档全部 + 调试 | 热重载（uvicorn --reload）、源码挂载、调试端口 5678、前端 Vite dev server |

### 备份恢复

- `scripts/backup.ps1` / `scripts/backup.sh`：mysqldump + 文件目录清单 + 版本组合 JSON 清单（含各组件版本、哈希、迁移 head）
- `scripts/restore.ps1` / `scripts/restore.sh`：恢复数据库 dump → 运行迁移 → 验证文件引用 → 健康检查

### 回滚

- 关闭新流量入口
- 回退 Compose 镜像 tag 和配置版本
- 数据库迁移反向执行（若适用）或恢复到上一备份
- 保留审计日志和已提交事件

## 明确不做

- 不依赖未登记云服务
- 不把开发机临时目录或未锁定模型权重当正式制品
- 不实现增量备份（一期只做全量）
- 不自动上传备份到云端
- 不在基础档暴露任何 AI/LLM 能力

## 2026-08-24 implementation evidence

- `scripts/hct408_validate_backup.py` validates the version manifest, non-empty MySQL dump, file manifest schema, path traversal, migration-head binding, and file size/SHA-256 references without modifying the database or files.
- `scripts/backup.ps1` writes configuration hashes (file contents only, never `.env` values), refuses a full backup when `FILE_ROOT` is missing, and runs the validator before reporting success.
- `scripts/restore.ps1` and `scripts/restore.sh` run the validator before the destructive database operation, run migrations, verify file references when present, and fail on migration/health-check errors instead of printing a warning and claiming success.
- `scripts/backup.sh` and `scripts/hct408_file_inventory.py` provide the equivalent Linux path.
- Automated evidence: `tests/unit/test_hct408_backup_validation.py`, `tests/deploy/test_hct408_deploy.py`; PowerShell and Bash syntax checks pass.

The Story remains `In Progress`: no destructive restore was executed in this development workspace. The controlled backup → disposable restore → data comparison → rollback drill, three-profile health run, and independent R3 review are still required before closure.
