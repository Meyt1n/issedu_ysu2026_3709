## 用户价值

网页端流式助手已有阶段反馈、停止按钮与请求取消（HCT-430），`end-reply` 也随 PR #490 落地。移动端已具备基础入口，但停止后的气泡没有可持久化的终态标记，普通停止、结束回复和网络中断的语义也不够清晰，用户无法判断内容是否完整。

## 范围

- 流式回复过程中的停止按钮：点击后通过 AbortSignal 取消上游请求，不只是前端停止渲染。
- 「结束回复」与「被用户停止」两种终态的显式标记与文案区分，并保留已显示内容供复核。
- 被停止的回答标记为不完整，并提供重新提问入口；不进入引用校验通过态。
- 阶段反馈（检索中、联网中、生成中）在移动端的呈现与可访问性。

## 非目标

- 不改服务端流式协议、取消语义与限速（属 HCT-430）。
- 不做断点续答或部分回答的再生成拼接。
- 不改助手安全策略与医疗硬边界。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 回复正在流式生成，When 点击停止，Then 服务端请求被取消（含联网检索），前端标记该回答为用户已停止且不完整。
2. Given 回答自然结束，When 展示终态，Then 标记为已完成，与「被停止」文案明显不同。
3. Given 回答被停止，When 查看该条消息，Then 不展示「已通过引用校验」之类完整性结论，并提供重新提问入口。
4. Given 网络中断导致流式提前结束，When 展示，Then 归入可恢复错误并说明内容不完整，不冒充正常结束。
5. Given TalkBack 与减少动效，When 流式进行中，Then 阶段反馈以文本状态可朗读，且不依赖动画传达进度。

## 安全、隐私与回滚

- 停止必须真正取消上游请求，避免用户以为已停止而联网检索仍在进行。
- 不完整回答不得参与「有真实引用」的结论展示。
- 回滚：回退本次 APP 提交即可恢复原有流式收尾逻辑；不涉及服务端协议、数据迁移或模型策略。

## 实现与验证证据

- `APP/src/views/AssistantView.vue`：流式气泡增加 `streaming/completed/ended/stopped/incomplete` 终态；普通停止与结束回复都会保留部分回答并标注不完整，隐藏引用完整性信息，提供「重新提问」入口；网络中断和非流式回退失败归入可恢复不完整态。
- `APP/src/api/client.ts`：显式调用方取消统一返回 `CANCELLED`，与计时器触发的 `REQUEST_TIMEOUT` 分离，确保停止动作不会被误报成网络超时。
- `APP/src/utils/assistantReply.ts`：从现有 sessionStorage 的 `degraded/degradeReason` 字段恢复中断终态，兼容旧会话。
- 自动验证：`cd APP && npm run check`、`npm run test`（39 个测试文件、356 项通过）、`npm run build`、`git diff --check` 均通过。2026-09-02 在最新 `master` 复核了流式取消、SSE `cancelled` 事件和中止读取期间的 `CANCELLED` 错误区分。
- Issue 保持打开，待维护者在 Android/PWA 上验证真实流式取消、服务端请求停止、TalkBack 状态播报、减少动效和网络中断恢复路径。
