- 背景：HCT-451（PR #456）已交付助手全幅画布、左侧会话历史栏与设置抽屉。用户随后反馈（附截图）：对话气泡与消息流本身仍不够精致，希望向主流 AI 对话前端（ChatGPT / Claude / Gemini 风格）看齐。本 Story 只做气泡/对话流的视觉与密度打磨，不动 HCT-451 的画布骨架。

## 用户价值

家庭管理员与照护者在健康助手页获得与主流 AI 助手一致的阅读体验：消息集中在舒适的阅读列宽内，用户提问是随文字自动收缩的右侧气泡，助手回答使用轻量暖纸气泡，引用、风险提示与追问建议收纳为紧凑的次级信息块，长辈更容易聚焦「回答本身」而不是处理过程卡片。

## 设计系统（单一连贯体系，Claude 式，适配家健镜暖纸/松绿主题）

1. 阅读列：全幅画布保留，消息内容居中收进 `min(820px, 100%)` 的阅读列（`.chat-thread`），不再从左端铺到右端。
2. 用户消息：右对齐软填充气泡（松绿 tint、圆角 19px、行高 1.7），宽度由实际文字决定并限制最大宽度；消息正文单独承担 `pre-wrap`，模板缩进不得把短消息撑成竖条。
3. 助手消息：左侧小头像 + 暖纸主题轻气泡，衬线正文 15.5px / 行高 1.8；保留流式插入符，但不在回答正文上方叠加行内「结束回复」按钮或处理卡片。
4. 次级信息块：生成过程中只显示轻量动态状态；证据预览、分流、引用和外部参考不占据回答前的空间。回答完成后统一折叠到默认关闭的「查看依据」，展开后仍保留原有安全文案和可核验引用。
5. 追问建议：「接下来可以问」以轻量提示卡只挂在最后一条助手消息下方，开放对话模式同样展示服务端安全建议；点击只填入输入框并聚焦，由用户修改或确认后再发送。每条助手消息保留一行纤细操作（朗读 / 按用药安全再查一次）。
6. 空状态：吉祥物 + 一句短提示 + 建议胶囊，压缩纵向留白；法律边界文案保留在页脚细字（`.assistant-footnote`）。
7. 输入框：与阅读列同宽居中、大圆角（22px）、发送为输入框右下角的圆形主按钮（↑ 图标，aria-label「发送」）；「联网搜索」保持紧凑开关，语音按钮为次级样式；设置仍在右上角齿轮抽屉。
8. 动效：新消息和助手纸面气泡轻抬淡入，思考态保留本机生成波形，追问卡悬停轻抬；`prefers-reduced-motion` 下关闭入场和位移动效，平滑滚动到底保留。
9. 历史栏：仅轻打磨（active 左侧松绿指示条、hover/排版微调），结构不变。

## Given / When / Then

- Given 管理员打开健康助手且无历史消息；When 页面加载；Then 空状态为吉祥物 + 一句提示 + 建议胶囊的紧凑布局，页脚保留教学免责细字。
- Given 管理员发送短问题 `nihao`；When 消息渲染；Then 用户消息为右对齐且随文字收缩的松绿软气泡，不出现窄而高的竖条；助手回答为左侧小头像 + 暖纸轻气泡，两者都收在居中阅读列内。
- Given 助手正在分析；When 收到路由或证据预览事件但回答尚未完成；Then 对话流只显示轻量思考状态，不显示大块证据预览或行内结束回复按钮。
- Given 助手回答带引用与追问建议；When 回答完成；Then 默认只显示「查看依据」，展开后 `details.chat-citation` 仍可查看片段正文；「接下来可以问」只出现在最后一条助手消息下，点击后写入输入框而不自动发送。
- Given 系统开启「减少动态效果」；When 新消息进入；Then 无入场动画，内容立即完整呈现。
- Given 视口在 1440/1280/1024 宽度间切换；When 查看助手页；Then 纵向滚动仍收在 `.chat-window` 内，页面无整体滚动（hct418 既有用例保持通过）。
- Given 用户使用键盘操作；When 聚焦输入框并按 Enter；Then 行为与改版前一致（发送）；圆形发送按钮可聚焦且 accessible name 为「发送」。
