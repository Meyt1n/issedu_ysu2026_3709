## 1. 用户价值与目标

视频任务是 HCT-414 服务端能力的入口。当前质量检查已经区分图片和视频，但视觉任务只保存文件和任务类型，质量凭证也没有把媒体类型纳入签名载荷。这样会让图片凭证被重放到视频任务，或者让任务记录无法回答“本次任务按哪一种媒体策略创建”。本切片为任务和凭证补齐媒体类型契约，先建立可供后续抽帧 worker、移动端和发布验收复用的安全边界。

## 2. 范围与非目标

本切片实现：

1. `VisionTask` 持久化 `media_type`，允许值为 `image` 或 `video`，旧记录迁移为兼容默认值 `image`；
2. `VisionTaskCreate`/`VisionTaskRead` 和 OpenAPI 同步媒体类型字段；
3. 质量凭证 v2 将媒体类型加入签名载荷，验证时绑定调用者、文件摘要、配置版本和媒体类型；旧 v1 凭证只按图片兼容；
4. 创建任务时校验请求媒体类型、文件扩展名和质量凭证三者一致，冲突以可识别 409 返回且不落库；
5. 覆盖图片/视频匹配、错配、凭证重放、幂等冲突、非法媒体类型和旧记录迁移默认值测试。

不做：

- 视频 worker、抽帧算法、容器时长/编码限制、临时文件留存清理和性能报告；
- 移动端或网页端上传 UI；
- OCR、条码、候选融合、人工复核、健康事件和模型发布逻辑；
- 真实视频、药品图片、模型权重、运行日志或任何敏感数据。

## 3. Given / When / Then 验收

- [ ] Given 质量检查签发图片凭证；When 创建 `.png`/`.jpg` 图片任务；Then 返回 `media_type=image` 并进入原有队列。
- [ ] Given 质量检查签发视频凭证；When 创建 `.mp4`/`.mov` 视频任务；Then 返回 `media_type=video` 并进入原有队列。
- [ ] Given 凭证、请求字段或文件扩展名媒体类型不一致；When 创建任务；Then 返回 409 `MEDIA_TYPE_MISMATCH` 或明确凭证错误，不创建任务。
- [ ] Given 同一文件、成员、媒体类型和幂等键重试；When 重复提交；Then 返回同一任务，不产生第二条记录；媒体类型变化视为幂等冲突。
- [ ] Given 迁移前已有视觉任务；When 升级数据库并读取；Then 任务可正常读取，`media_type=image`，历史结果和状态不变。
