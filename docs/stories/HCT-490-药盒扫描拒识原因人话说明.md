# HCT-490：药盒扫描拒识原因的人话说明

- Issue：[ #561 ](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/561)
- 绑定：FR-03、NFR-03、NFR-04、NFR-07
- 前置：HCT-201、HCT-202、HCT-205-D1、HCT-206、HCT-416
- 状态：实现完成，待 PR/CI 与维护者人工验收
- 风险：R2；人话说明只帮助补证据或交给家人复核，不确认药品身份、不提供用药结论

## 目标

把药盒扫描的拒识、冲突、依据不足和需要复核等结果，转换为普通家庭成员能理解的说明。用户应能知道是“图片不清楚”“多个候选很接近”“不同依据不一致”还是“资料不足”，并得到可执行的补拍或人工核对建议，而不需要理解模型、推理、worker 或本机文件路径。

## 实现范围

- `src/web/src/vision/visionReasons.ts` 将视觉失败码、融合状态和 finding 码集中映射为稳定的中文标题、原因和下一步建议；未登记的内部码使用中性兜底文案。
- `VisionResultViewer.vue` 将 `MATCHED`、`CONFLICT`、`UNKNOWN`、`REVIEW` 与 `READY_FOR_FUSION` 的状态提示、候选依据和发现事项转换为人话；保留版本信息用于审计，但不把内部码作为家庭主提示。
- `ScanView.vue` 与详情侧栏共享同一套映射，确保列表、详情和失败任务的说明一致。
- 识别结果仍明确标记为候选，只有人工确认后才进入健康记录；冲突或未知状态建议补拍、补充条码或交给家人核对。

## 验收条件

- 常见图片/视频/识别失败有明确标题、原因和下一步，原始模型堆栈和本机路径不泄漏。
- 四状态均有可理解的提示：一致也要人工确认，冲突要核对，不足要补证据，复核状态要交给家人决定。
- finding 与候选理由显示为“条码与资料一致”“图片文字与资料不一致”等可读文本；未知码不回显内部标识。
- 单元测试覆盖失败码、融合状态、finding 映射和敏感内部文本不泄漏；浏览器测试覆盖失败任务和复核交接。

## 非目标与回滚

本切片不改变 OCR、条码、YOLO、候选融合阈值、服务端状态机或人工确认权限。回滚时删除文案映射和展示层调用即可，保留后端结构化证据及既有四状态判定。
