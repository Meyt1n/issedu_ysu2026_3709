# HCT-418 完整网页 E2E 验收矩阵

## 1. Story

作为项目维护者，我希望用一组可重复的网页端 E2E 用例验收主要业务路径和异常状态，以便在演示或发布前确认页面编排没有越过后端权限、证据和人工确认边界。

## 2. 需求与边界

- 关联 Issue：[#260](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/260)
- 依赖：HCT-405/#70 核心 E2E；HCT-412/#210 语音；HCT-413/#247 风险回写；HCT-415/#252 助手体验；HCT-416/#256 视觉扫描；HCT-417/#258 Web 会话。
- 关联 FR：FR-01、FR-02、FR-03、FR-05、FR-07、FR-08、FR-09、FR-10
- 关联 NFR：NFR-01、NFR-02、NFR-03、NFR-04、NFR-06、NFR-07
- 风险等级：R2；浏览器合成 API 用例不能替代真实本地 API、隐私、安全、性能和人工走查。
- 所有测试数据均为合成家庭、成员、事件、识别候选、知识文档和模型元数据；不提交截图、日志、音频、图片或真实健康数据。

## 3. 验收矩阵

| 路径 | 关键断言 | 失败/降级断言 |
|---|---|---|
| 登录→家庭→成员 | 身份进入后加载家庭和成员，成员切换只请求当前作用域 | 空家庭显示创建入口，不显示健康摘要 |
| 图片→质量门控→任务→复核 | 质量通过后创建任务，候选在人工确认前不成为健康事实 | 质量失败阻止任务创建并说明原因 |
| 任务→确认/修正 | 复核动作刷新总览、风险和时间线 | 401/409/超时不展示旧上下文，提供重试/重新进入 |
| 健康事件→风险解释 | 风险页面显示规则、证据来源和版本 | 无风险/无证据/接口失败有明确空态 |
| 助手→引用→追问 | 回答显示引用和追问，追问只填草稿不自动发送 | 模型或知识库不可用时显示降级状态 |
| 知识新增→检索→引用 | 新文档可见、检索结果显示标题/版本/片段 | 未授权和检索失败不泄露文档内容 |
| 管理后台研发入口 | 侧栏与命令面板不出现模型实验室、演示造数 | 家庭大屏与知识文档仍在「家庭与研发」 |
| 离线/未授权/空数据/超时 | 四类状态都有可理解的恢复入口 | 不保留旧家庭或旧成员健康上下文 |

## 4. 实现与证据

- 浏览器测试：`tests/browser/hct418-web-e2e.spec.ts`。
- 既有专项测试：`hct405-visible-workflows.spec.ts`、`hct405-real-api.spec.ts`、`hct409-accessibility.spec.ts`、HCT-412 语音测试及对应专项 PR。
- 合成路由只验证前端状态机和请求边界；真实 API 贯通必须在 `REAL_API_E2E=1`、临时本地数据库和人工验收条件满足时单独执行。

## 5. 回滚

回滚本 Story 的 PR 只移除新增浏览器测试和矩阵记录，不改动业务 API、数据库、模型、知识文档或健康事件。
