## 用户价值

后端已有健康资讯缓存降级与配置指纹隔离（HCT-445、HCT-454），移动端只会把缓存内容照原样显示，用户分不清看到的是今天的还是上周的。补明确的过期提示与一键刷新，让「旧内容」这件事在界面上无法被误读。

## 范围

- 资讯区展示新鲜度状态：实时、缓存（含缓存时间）、缓存已过期、完全不可用四态。
- 一键刷新：触发服务端重新取数，展示进行中/成功/失败，失败保留旧内容并说明原因。
- 配置指纹变化时丢弃旧缓存呈现，不把不同配置下的资讯混在一起。
- 刷新的节流与重复点击保护，复用 MOB-113 的请求防重复策略。

## 非目标

- 不在 APP 内实现资讯抓取或本地持久缓存策略（属后端）。
- 不做后台定时静默刷新。
- 不改缓存 TTL 与指纹规则（属 HCT-445/HCT-454）。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 服务端返回缓存内容，When 展示资讯，Then 明示这是缓存并给出缓存时间，不出现暗示实时的措辞。
2. Given 缓存已超过有效期，When 展示，Then 显著提示内容可能已过期并突出刷新入口。
3. Given 点击刷新且服务端取数成功，When 返回，Then 更新内容与新鲜度状态，并给出成功反馈。
4. Given 刷新失败或超时，When 返回，Then 保留旧内容、说明失败原因，不清空列表也不谎报成功。
5. Given 缓存配置指纹变化，When 加载，Then 不展示旧指纹下的缓存内容。
6. Given 连续点击刷新，When 请求仍在进行，Then 不发起重复请求，按钮进入禁用/进行中态。

## 安全、隐私与回滚

- 任何缓存呈现都必须带时间，不允许无标注的旧内容。
- 刷新只调家庭服务器，不直连外部资讯源。
- 回滚：移除刷新入口并保留静态资讯展示；过期提示可独立保留。

## 实现与验证证据

- `APP/src/utils/healthNews.ts` 新增 `presentHealthNewsFreshness()`，把「这份内容有多新」独立算出来，返回 `fromCache` / `expired` / `whenLabel` / `notice` / `tone` / `emphasizeRefresh`，覆盖实时、缓存有效、缓存过期、本地季节四态（范围第 1 条）。
- 验收 1：`presentHealthNews()` 现在会读 `cache_status`。**缓存内容的状态标签不再复用 `status` 的「已更新」**，`fresh` 显示「缓存资讯」、`stale` 显示「缓存已过期」；说明句一律写明是家庭服务器缓存并带抓取时间。
- 安全边界「任何缓存呈现都必须带时间」：服务端**没有**返回 `fetched_at` 时不静默展示无标注旧内容，而是显式说「服务端未返回缓存时间，无法判断新鲜度」并要求刷新。
- 验收 2：`cache_status === 'stale'` 时用 `role="alert"` 的告警条呈现过期说明，刷新按钮同时从 `btn-quiet` 提升为 `btn-secondary`（`emphasizeRefresh`），做视觉突出。
- 验收 3/4：新增 `refreshOutcomeMessage()`。刷新成功且本轮实时取回才说「新取回的内容」；服务端仍只能给缓存时明确说「仍是有效期内的缓存 / 仍只能提供过期缓存」，**不出现「最新」字样**。刷新失败保留 `news` 不清空，内联提示带上 `loadError.message` 说明失败原因。
- 验收 5：APP 侧不做任何本机持久化（健康资讯只存在组件 `ref` 里，无 localStorage/sessionStorage 落盘），刷新时整份替换而非合并，因此服务端换缓存配置指纹后旧指纹内容不会残留。指纹判定本身仍在服务端（HCT-454），移动端不复制该逻辑。
- 验收 6：沿用 `loadInFlight` 门闩，请求进行中不发起重复请求；刷新按钮 `:disabled="loading"` + `:aria-busy="loading"`，文案切到「刷新中…」。
- 刷新只调 `activeProvider().getHealthNews()`（即家庭服务器 `/api/v1/health-news`），不直连外部资讯源。
- `cd APP && npx vue-tsc --noEmit` 通过；`npx vitest run` 通过（35 个测试文件、330 项，`src/utils/healthNews.test.ts` 从 3 项扩到 10 项）；`npx vite build` 通过；`node scripts/privacy-scan.mjs` 通过；`git diff --check` 通过。
- `APP/scripts/mob171-weak-network-fixture.mjs` 现支持 `news-stale` 与 `news-error` 两个受控场景：前者返回带过期时间和旧内容的 `cache_status: stale`，后者返回带 `request_id` 的 503 错误；两者均可通过 `POST /__control` 在同一设备上切换，便于复跑刷新与失败保留旧内容验收。

## 与既有测试的行为变更

- `healthNews.test.ts` 里 MOB-159 的断言 `statusLabel: '缓存资讯'`（`cache_status: 'stale'`）按验收 2 改为 `'缓存已过期'`。这是本 Story 有意收紧的措辞，不是回归。

## 未完成证据

- 验收 2/3/4 只在响应契约层面做了自动验证（构造 `cache_status` 的四种取值）。真实 TTL 走到过期、真实刷新成功/超时/失败三条链路需要在联机环境按 HCT-445 的 `health_news_cache_ttl_seconds` / `stale_ttl_seconds` 实跑一遍。
- 验收 5 只验证了「移动端不落盘 + 整份替换」这一侧；服务端指纹变化时的实际表现属 HCT-454，需联机联调确认移动端拿到的是 `miss` 而不是旧指纹缓存。
- Android/PWA 上的 TalkBack 播报（`role="alert"` 过期告警与 `aria-busy` 刷新态）、长辈模式与特大字号下告警条与按钮的排版走查仍需维护者在真机执行；在此之前 Issue 保持打开。

## 2026-09-02 受控夹具补充

- 为避免等待真实资讯提供方才能复现边界，复用 MOB-171 的本地夹具增加了 `news-stale`/`news-error`。夹具只返回虚构资讯，不写磁盘、不访问外部站点，默认绑定回环地址；真机联调需显式使用可信局域网并在完成后停止。
- 运行示例：`node scripts/mob171-weak-network-fixture.mjs --host 127.0.0.1 --port 8000 --mode news-stale`；切换失败态：`Invoke-RestMethod http://127.0.0.1:8000/__control -Method Post -ContentType 'application/json' -Body '{"mode":"news-error"}'`。
- 受控夹具覆盖了验收 2（过期告警/突出刷新）与验收 4（503 失败、保留旧内容、显示原因）的可复跑输入；真实 TTL、真实 provider 成功链路、TalkBack/特大字号和发布门禁仍需维护者签收。
