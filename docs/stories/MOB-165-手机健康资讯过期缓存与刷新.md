## 用户价值

后端已有健康资讯缓存降级与配置指纹隔离（HCT-445、HCT-454），移动端只会把缓存内容照原样显示，用户分不清看到的是今天的还是上周的。补明确的过期提示与一键刷新，让「旧内容」这件事在界面上无法被误读。

## 范围

- 资讯区展示新鲜度状态：实时、缓存（含缓存时间）、缓存已过期、完全不可用四态。
- 一键刷新：触发服务端重新取数，展示进行中/成功/失败，失败保留旧内容并说明原因。
- 配置指纹变化时丢弃旧缓存呈现，不把不同配置下的资讯混在一起。
- 刷新的节流与重复点击保护，复用 MOB-113 的请求防重复策略。

## 非目标

- 不在 APP 内实现资讯抓取或本地持久缓存策略（属后端）。
- 不做后台定时静默刷新。
- 不改缓存 TTL 与指纹规则（属 HCT-445/HCT-454）。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 服务端返回缓存内容，When 展示资讯，Then 明示这是缓存并给出缓存时间，不出现暗示实时的措辞。
2. Given 缓存已超过有效期，When 展示，Then 显著提示内容可能已过期并突出刷新入口。
3. Given 点击刷新且服务端取数成功，When 返回，Then 更新内容与新鲜度状态，并给出成功反馈。
4. Given 刷新失败或超时，When 返回，Then 保留旧内容、说明失败原因，不清空列表也不谎报成功。
5. Given 缓存配置指纹变化，When 加载，Then 不展示旧指纹下的缓存内容。
6. Given 连续点击刷新，When 请求仍在进行，Then 不发起重复请求，按钮进入禁用/进行中态。

## 安全、隐私与回滚

- 任何缓存呈现都必须带时间，不允许无标注的旧内容。
- 刷新只调家庭服务器，不直连外部资讯源。
- 回滚：移除刷新入口并保留静态资讯展示；过期提示可独立保留。
