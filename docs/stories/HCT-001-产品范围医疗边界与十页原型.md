- 风险：R2；范围或页面口径漂移会导致 API、Schema、前后端和验收返工
- 前置依赖：无
- 预计范围：1 个文档与契约测试增量
- 允许修改：`docs/vibe-coding/01-需求规格说明书.md`、`docs/vibe-coding/12-需求追踪矩阵.md`、`docs/vibe-coding/18-产品信息架构与页面设计.md`、`docs/stories/HCT-001-*.md`、`docs/reviews/HCT-001-*.md`、`tests/unit/test_hct001_scope_baseline.py`

## 用户价值

团队在开始架构、API、数据库和页面开发前，共享唯一的 P0 产品范围、十页结构、页面状态、医疗边界和无导流承诺，避免各组按不同假设实现。

## 范围与非目标

必须完成：

- 冻结 FR-01 至 FR-10、NFR-07、角色、产品硬承诺和非目标；
- 冻结十个核心页面名称、页面职责和主链演示顺序；
- 为每个核心页面定义正常、加载、空、错误、离线、未授权和低置信状态；
- 记录本次桌面推演的接受项、延期项、责任人、证据和回滚方式；
- 用自动测试保护十页名称、状态矩阵和六项硬承诺。

明确不做：

- 不实现页面、API、数据库或模型；
- 不决定具体医疗规则、药物相互作用、剂量或治疗方案；
- 不把页面原型、Mock、截图或文档描述宣称为已实现能力；
- 不引入买药、问诊、广告、佣金或健康消费导流。

## 输入、输出、状态和异常

- 输入：综合研究报告、需求规格、页面设计、生命周期流程和 Issue #38；
- 输出：统一需求基线、十页页面与状态矩阵、Story、评审记录和契约测试；
- 状态：Story 在 PR 合并前保持“进行中”，合并动作代表范围复核完成；
- 异常：发现需求、页面或硬承诺冲突时停止扩展范围，在评审记录中明确裁决或延期。

## Given / When / Then

- Given 团队读取需求和页面设计；When 核对 P0 页面；Then 只能得到十个名称一致的核心页面，授权设置作为跨页面支撑视图而非第十一个核心页面。
- Given 任一核心页面；When 核对交互状态；Then 均能找到正常、加载、空、错误、离线、未授权和低置信的安全表现。
- Given 识别、授权、提醒、AI 或商业边界相关文案；When 对照六项硬承诺；Then 本地不出网、人工确认、字段授权、分级提醒、证据解释和无导流口径一致。
- Given 后续提交修改需求或页面设计；When 运行 HCT-001 契约测试；Then 删除核心页面、状态或硬承诺会使测试失败。

## 隐私、授权、医疗和模型边界

- 健康数据默认留在家庭可信域，家庭版不允许云端 LLM 回退；
- 未确认、冲突、未知或低质量识别不能进入正式健康状态和风险计算；
- 子女或照护者只查看被授权的成员、字段、动作、目的和期限；
- 风险等级由版本化规则决定，LLM 只解释有权限的证据；
- 不诊断、处方、停药、换药或判断剂量，不设置买药、问诊和广告入口。
