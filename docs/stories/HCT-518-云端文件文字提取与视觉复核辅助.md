# HCT-518 云端文件文字提取与视觉复核辅助

- Issue：待维护者登记（当前 agent 无 Issue 创建权限）
- 关联：HCT-205-D1、HCT-206、HCT-207、HCT-208、HCT-416、HCT-517
- FR/NFR：FR-03、FR-08；NFR-02（健康数据出网边界）、NFR-03（可追溯）、NFR-04（依赖故障降级）、NFR-07（可理解交互）
- 风险等级：R3（文件文字、药盒 OCR 可能包含健康信息；云端发送必须由运维配置显式开启）
- 状态：实现中，待 Issue、PR、门禁和维护者人工复核

## 1. Story

作为使用云端大模型的操作员，我希望在大模型聊天中上传文件并把其中可读文字交给当前对话，也希望视觉扫描的 OCR 词条能交给云端模型做药品名称、包装规格和成分候选判断，以减少手工录入；系统仍必须保留原图、OCR 证据、人工修正和人工确认边界。

## 2. 范围与产品决定

| 范围 | 决定 |
|---|---|
| 聊天附件 | 浏览器上传一个附件到 `POST /assistant/files/extract`；文本、CSV/JSON/YAML/XML/HTML、PDF、DOCX 走本地提取；图片优先走本地 PaddleOCR，没有本地 OCR 时只有显式开启云端视觉模型才可发送图片。提取结果只在内存中转成文字，不写入 `FILE_ROOT`、知识库或健康事件。 |
| 聊天上下文 | 浏览器只把提取后的文字和文件名附在本轮用户消息；服务端把它标记为不可信文件内容，不能覆盖系统策略或身份上下文。原文件不会作为长期对象保存。 |
| 视觉扫描 | `POST /vision-tasks/{id}/llm-assist` 只读取已保存的 OCR/条码证据和已有批准主数据候选，返回药品名称、包装规格/含量和成分的辅助建议，不修改视觉任务、复核任务或健康事件。 |
| 药品字段 | “剂量”按药盒包装上的规格/含量处理，例如 `0.25g×24粒`，不处理个体用药剂量、频次、诊断、处方或治疗建议。成分只能从被选中的本地主数据记录补全，模型不能凭常识创造。 |
| 人工闸门 | AI 建议会带入“人工修正”表单；只有操作员提交人工修正或确认，才进入既有复核事务和健康事件链路。点击“云端 AI 判断”才触发视觉 OCR 外发，页面不自动静默发送。 |
| 云模型 | `LLM_PROVIDER=cloud`、HTTPS endpoint、API key 和 `LLM_API_VISION_ENABLED=true` 是独立运维配置。当前 `deepseek-chat` 为文本模型，不能直接处理图片；图片能力需替换为服务商明确支持 `image_url` 的模型。 |

## 3. 非目标与安全边界

- 不把任意云端生成的药品、规格或成分直接写入健康事件。
- 不把 OCR 词条当成事实；OCR/条码仍是证据，候选仍须经过人工确认。
- 不支持把任意二进制文件“魔法识别”为文字；当前对不受支持的格式返回可操作错误。可安全扩展格式时，应增加对应解析器和测试，不应静默把二进制内容送给模型。
- 不改变 HCT-205 OCR-first 证据契约、HCT-206 候选融合状态机、HCT-207 复核事务或 HCT-208 修正/训练同意流程。
- 不提交 API key、真实健康文件、模型权重、OCR 缓存或运行日志。

## 4. Given / When / Then 验收

1. Given 已登录用户在助手页；When 选择 TXT、DOCX、PDF 或常见图片并点击发送；Then 系统先提取文字，再把提取文字附到本轮对话，页面显示文件名和发送失败原因；临时附件不出现在永久文件列表。
2. Given 文本附件含伪装成系统指令的内容；When 模型回答；Then 文件文字只能作为用户提供的材料，不能改写服务端系统策略或身份范围。
3. Given 云端未显式启用视觉能力或当前模型为文本模型；When 上传图片；Then 返回 `503` 和明确的视觉不可用原因，不把图片字节发送给文本模型。
4. Given 已完成的视觉任务含 OCR 词条和本地主数据候选；When 用户点击“云端 AI 判断”；Then 云端只收到必要 OCR/条码/批准候选，响应只保留有证据或有批准主数据来源的药品名、包装规格和成分，并在页面展示辅助建议。
5. Given 云端模型输出不存在于 OCR 或批准候选中的药名、规格、成分；When 服务端归一化响应；Then 幻觉字段被丢弃，返回 `REVIEW_REQUIRED` 或保留可落地的批准候选字段，并给出警告。
6. Given AI 已给出建议；When 用户点击“带入人工修正表单”并提交；Then 字段进入既有人工修正 API，保存 before/after、修正原因和人工身份；AI 请求本身不创建健康事件。
7. Given 云端超时、鉴权失败或返回非法 JSON；When 调用任一新接口；Then 文件聊天显示可操作失败，视觉扫描保留人工修正入口，不泄露 key，不破坏既有本地 OCR/复核链路。

## 5. 允许修改范围与证据

- API：`src/api/app/config.py`、`cloud_llm.py`、`file_extract.py`、`cloud_vision_assist.py`、`routes.py`、`schemas.py`。
- Web：助手附件选择/发送、复核页云端辅助建议和人工修正字段；不改变扫描任务的确认闸门。
- 配置：`.env.example` 仅提供占位项，不改本机 `.env` 中的真实密钥。
- 测试：文件提取、云端视觉请求形状、模型幻觉字段过滤、前端类型/构建和既有后端回归。

## 6. 验证、部署影响与回滚

- 自动验证：`uv run ruff check src/api tests migrations`、`uv run pytest`、`npm run check:web`、`npm run test:web`、`npm run build:web`、`git diff --check`。
- 部署：新增 `pypdf` 依赖；文本附件和本地图片 OCR无需云端出网。要使用图片云 OCR，必须配置 HTTPS、视觉模型和 `LLM_API_VISION_ENABLED=true`，并重新构建/重启 API。
- 回滚：将 `LLM_PROVIDER` 改回 `local` 或将 `LLM_API_VISION_ENABLED=false` 立即关闭云端路径；代码回滚删除两个新接口和对应 UI，不影响既有 OCR、复核任务和已确认健康事件。

## 7. 已知限制

- 当前实现是“提取文字后聊天”，不是把任意原文件作为多模态上下文长期存储；图片识别质量取决于本地 PaddleOCR 或配置的云端视觉模型。
- PDF 扫描件若没有文本层，需要图片渲染/OCR扩展；当前不会把无文本 PDF 静默当作已识别。
- 云端建议的置信度是辅助信号，不是医学准确率或安全保证；正式发布仍需要批准主数据、真实固定集和 R3 人工验收。
