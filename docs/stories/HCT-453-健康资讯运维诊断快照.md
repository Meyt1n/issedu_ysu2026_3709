# HCT-453 健康资讯运维诊断快照

- Issue：[#463](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/463)
- 关联需求：NFR-01、NFR-02、NFR-03
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为本地健康资讯适配器维护者，我希望通过受保护的运维接口查看适配器是否启用、白名单是否配置、活动来源和缓存状态，从而定位资讯降级原因，同时不接触新闻正文或任何家庭健康数据。

## 验收标准

- [x] 新增 `/api/v1/health-news/ops`，返回 adapter 模式、白名单配置状态、活动来源 ID、缓存状态/年龄/条目计数和 TTL。
- [x] 响应只包含配置与缓存元数据，不返回新闻标题、摘要、文章正文、家庭/成员标识或请求内容。
- [x] 非管理员访问被拒绝；开发环境允许本地运维调试，配置管理员名单后严格按名单授权，生产环境无名单时默认拒绝。
- [x] 读取快照不触发外网请求、不改变缓存，也不影响 `/health-news` 的本地/远程降级行为。

## 实现与证据

1. 在健康资讯适配器中新增 `health_news_ops_snapshot`，从当前配置和进程缓存计算无正文诊断数据。
2. 新增 Owner/管理员边界的运维路由，复用 `knowledge_admin_actors` 的本地运维 allowlist。
3. 补充缓存快照字段、响应最小化和管理员授权契约测试。

## 回滚

回滚应用代码即可移除诊断入口；健康资讯抓取、重定向校验和缓存数据结构不受影响。
