# HCT-206：候选融合、阈值校准与四状态判定

- GitHub Issue：[#53](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/53)
- Story：HCT-206
- FR/NFR：FR-03、NFR-05、NFR-06
- 阶段：P0-W4
- 风险：R3（视觉身份与健康事实边界）
- 前置依赖：HCT-205-D1 OCR-first 证据契约与离线归一化
- 当前状态：技术验收完成（候选融合 API、版本化状态规则、可复跑技术固定集和人工复核记录已完成；生产药品固定集仍受 HCT-201 授权门禁约束）

## 用户价值与边界

对 HCT-205 已存在的 OCR、条码、包装和本地主数据候选进行可解释排序，并把结果明确分为 `MATCHED`、`CONFLICT`、`UNKNOWN`、`REVIEW`。每个候选保留各通道的支持、冲突、缺失、分数和版本，避免用一个总分掩盖证据缺口。

本增量不运行 OCR/条码模型，不创建健康事件，不把最高分当作确认，不从主数据之外生成身份。`MATCHED` 也必须继续人工确认；全部结果返回 `health_event_allowed=false`。

## 验收条件

- [x] 候选评分使用版本化 OCR、条码、包装和元数据权重，并输出每通道证据。
- [x] 冲突、未知、关键字段缺失、候选间隔不足和依赖不可用时不会输出 `MATCHED`。
- [x] `POST /api/v1/vision-tasks/{task_id}/fusion` 只消费已完成的本地证据结果和批准主数据快照，不写健康事件。
- [x] 校准函数仅接受验证集与独立测试集，输出阈值、接受率、误匹配率、拒识率、覆盖率和样本哈希。
- [x] 单元与 API 契约测试覆盖一致证据、冲突、未知和安全降级。
- [x] 在获批的 HCT-206 技术固定验证集和独立测试集（仓库合成夹具，非生产药品数据）上完成正式规则阈值校准及人工复核证据；生产药品固定集校准仍由 HCT-201 门禁管理，不宣称生产准确率。

## 回滚

移除融合 API 与 `candidate-fusion-v1` 规则，视觉任务继续保留 HCT-205 证据并降级到 `REVIEW`/`UNKNOWN`；不得绕过人工确认或直接写入健康事件。

## 2026-08-22 验收补充

生产固定集的融合验收使用 `scripts/hct205_accuracy_report.py` 的状态准确率和失败样本报告，并继续受
`scripts/hct201_fixed_set_gate.py` 的授权、unknown 和 conflict 门禁约束。仓库现有技术固定集结果不代表生产药品准确率。
