## 1. Story

用户反馈「似乎不能正确进入前台」。根因多为入口误用，而非服务挂掉：

1. 只起了 `web` / `web-admin`，未起 `web-member`；
2. 在成员前台（5173/8080）用管理员（`Household.created_by`，演示常为 `demo-parent`）登录，被 HCT-453 入口锁登出；
3. 在成员前台「创建家庭」后创建者成为管理员，立刻被锁出，误以为建家失败。

本 Story 把**正确进入成员前台**的三步写进欢迎页、冲突提示、启动脚本与 README，不削弱入口锁。

## 2. 正确进入逻辑（产品基线）

| 步骤 | 动作 |
|---|---|
| 1 | `scripts/start.sh\|ps1 api` |
| 2 | `scripts/start.sh\|ps1 web-member` → http://127.0.0.1:5173（Compose：8080） |
| 3 | 用**家庭成员**账号刷脸 / PIN（演示如 `grandma-demo` / `grandpa-demo`） |

管理员用 `web-admin` → 5174/8081 + 账号密码。`scripts/start web` 是 auto 调试单入口，不是产品前台。

## 3. 方案

- `portalEntry.ts`：冲突文案补充端口、web-member、演示成员账号；建家后专用 `afterCreate` 文案；导出 `MEMBER_PORTAL_ENTRY_STEPS`。
- `store.ts`：成员前台建家触发 `need-admin-entry` 时改写为「家庭已创建…」。
- `WelcomeView.vue`：成员入口展示进入清单；开发演示 placeholder 改为 `grandma-demo`；建家空态预警。
- `scripts/start.sh|ps1`：`web` 打印黄字提醒改用 `web-member`；`web-member`/`web-admin` 打印入口地址。
- README / 本地部署指南：增加「正确进入成员前台」清单。

## 4. 非目标

- 不改 `portalEntryConflict` 判定；不让 owner 留在成员前台。
- 不改服务端授权、会话、PIN、人脸契约。
- 不拆应用、不改 Compose 端口约定。

## 5. 验收标准

1. Given 成员前台欢迎页，When 未处于冲突/建家空态，Then 可见「正确进入成员前台」三步清单且含 `web-member`。
2. Given 成员前台，When 管理员账号登录，Then 登出并提示改去管理后台或换成员账号（含 grandma-demo）。
3. Given 成员前台建家成功，When 入口锁触发，Then 提示「家庭已创建」而非含糊失败。
4. Given `scripts/start.sh web`，When 启动，Then stderr/控制台提示应改用 `web-member`。
5. Given 既有入口锁单测与 hct453 浏览器用例，When 跑测试，Then 通过（文案断言已对齐）。
