## 用户价值与范围

让支持触觉反馈的设备在关键操作后获得轻提示，同时让不支持 `navigator.vibrate` 的设备静默降级、不报错、不阻断操作；求助页的急救和家人拨号均必须先展示安全提示并由用户二次确认。本 Story 不判断病情、不替用户决定是否就医，也不新增后端能力。

## Given / When / Then

- Given 设备支持 `navigator.vibrate`，When 打开或确认求助拨号，Then 触发短振动/确认振动，拨号流程继续。
- Given 设备不支持 `navigator.vibrate`，When 触发同样操作，Then `tapFeedback` 返回 `false` 且不抛错，确认、取消和拨号流程不受阻断。
- Given 用户点按“拨打急救电话 120”或“联系家人”，When 尚未确认，Then 不立即跳转电话界面，而是展示带 `role="dialog"`、`aria-modal="true"`、标题、描述和取消按钮的二次确认。
- Given 急救确认对话框，When 用户阅读提示，Then 明确“仅在真实紧急情况下拨打 120”“应用不会判断病情”，并提示以急救服务和医生判断为准。
- Given 用户取消或按 Escape，When 对话框关闭，Then 返回原拨号按钮焦点，不发生拨号。
- Given 用户确认，When 对话框提交，Then 进入对应 `tel:` 链接；应用不缓存、不上传电话数据。

## 真机对比记录

执行环境：开发机 Android SDK 内存在 `adb`，但当前 `adb devices -l` 没有已连接设备，未发现可用模拟器；以下不能替代真机验收。

| 场景 | 支持振动设备 | 不支持振动设备 | 当前结果 |
|---|---|---|---|
| 打开急救确认 | 应短振动一次并显示确认对话框 | 无振动、无错误，仍显示确认对话框 | 自动逻辑通过；真机待验 |
| 取消/按 Escape | 关闭对话框并回到原按钮焦点 | 同左 | 代码路径已覆盖；真机待验 |
| 确认拨打急救 | 确认振动后进入 `tel:120` | 无振动、仍进入 `tel:120` | 自动逻辑通过；真机待验 |
| 联系家人 | 同样先确认，显示联系人和升级提示 | 同样先确认，无错误 | 自动逻辑通过；真机待验 |

真机复核步骤：准备一台支持振动的 Android 设备和一台不支持振动或禁用振动权限的设备；安装同一 APK，分别进入“求助”，验证四个场景，记录设备型号、Android 版本、是否支持振动、TalkBack 状态和结果。完成前不得把 Story 状态改为“已验证”。
