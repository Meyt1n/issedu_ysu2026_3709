## 用户价值

家人拍完药盒后，不用再猜"识别到底完成没有"：拍药盒页会按有上限的退避节奏回查家庭服务器上的任务状态，排队中、处理中、完成、失败、超时都如实展示对应的时间和下一步；完成时可以收到一条不含健康数据的本地提醒。失败或超时给出结构化原因和"重试回查"入口，重试只回查同一个任务，绝不重复创建。

## 范围

- `ApiClient.getVisionTask`：`GET /api/v1/vision-tasks/{task_id}`（actor 由会话承载，走正式鉴权）；
- `DataProvider.fetchVisionTaskStatus(taskId)`：把服务端 `VisionTaskRead` 映射为移动端状态快照（状态、错误码/错误消息、模型版本、创建时间、下一步说明）；
- `useVisionTaskPolling`：有上限的指数退避轮询（初始 1s、×1.6、封顶 8s、最多 12 次）；到达终态、`stop()`、页面离开、切换会话/成员、切到后台时停止并清理，回前台立即回查一次再续轮询；
- 终态本地提醒（可选）：仅系统通知权限可用且用户显式开启；文案不含任务编号与健康数据，无权限时只保留页面内状态，不声称已发送远程推送；
- 拍药盒页"任务状态回查"卡片：状态标签、最近回查时间、已回查次数、下一步说明；失败/超时/取消展示服务端 `error_code`/`error_message` 与"重试回查"。

## 非目标

- 不在移动端执行识别、融合或复核（属于网页端人工复核中心）；
- 不新增后端接口或状态语义；后端状态枚举为 `queued/running/succeeded/failed/cancelled/timeout`，未知状态原样展示并停止轮询，不猜测为成功；
- 不做远程推送；通知不携带健康数据、任务编号或照片信息；
- 不改变 MOB-103 的任务创建与网页交接语义；"重试回查"绝不重新创建任务。

## 服务端契约（HCT-204，已在 master）

```text
GET /api/v1/vision-tasks/{task_id}   -> VisionTaskRead
{ id, household_id, member_id, file_id, task_type,
  status: queued|running|succeeded|failed|cancelled|timeout,
  error_code, error_message, result, model_version, created_by, created_at }
```

终态 = `succeeded | failed | cancelled | timeout`。回查经过 `activeProvider()`，自动获得 MOB-133 的 fail-closed 边界：未登录/会话失效/撤权时拒绝并提示重新登录，不回退开发期身份。

## Given / When / Then

- Given 视觉任务已创建；When 任务处于 queued/running；Then 拍药盒页按退避节奏回查并展示"排队中/处理中"、最近回查时间与下一步，不把 queued 当作成功。
- Given 任务到达 succeeded/failed/cancelled/timeout；When 回查返回终态；Then 停止轮询并展示终态、服务端时间、失败原因（error_code/error_message）与下一步；若用户开启了本地提醒且系统允许，发一条不含健康数据的通知。
- Given 轮询期间切后台/离开页面/切换会话或成员；When 对应事件发生；Then 立即停止并清理定时器，回前台先立即回查一次再续轮询。
- Given 回查持续失败或到达次数上限；When 展示结果；Then 给出结构化错误与"重试回查"入口；重试只复用同一 taskId，不重复创建任务、不重新上传照片。
- Given 系统不支持通知或用户未授权；When 任务到达终态；Then 只保留页面内状态与语音播报，界面如实标注"未开启"，不声称已发送任何推送。

## 安全、隐私与回滚

- 轮询、通知与本地状态不写入健康数据；通知文案只有"任务已结束，请回到应用查看"，不含药品名、任务编号、成员或照片信息；
- 回查走正式会话与授权边界，不绕过能力探测；未提供视觉任务能力时入口本来就禁用；
