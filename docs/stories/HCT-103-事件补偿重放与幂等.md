## 用户价值

健康事实以不可覆盖的事件形式存储，系统从重复请求、投影失败和进程中断中确定性恢复，保证"一条事实 = 一条事件 + 补偿更正"始终可审计。

## 范围与非目标

**范围：**
- 事件追加写（已有基础）
- 幂等键（同键重复提交 → 同一结果，冲突 payload 拒绝）
- 补偿事件（`COMPENSATION` 类型，通过 `compensates_event_id` 关联原事件）
- 事务 outbox（已有基础，补重试 + 幂等投递）
- 投影 checkpoint + 确定性重放
- 中断恢复（重复投递、乱序消息、进程中断）

**明确不做：**
- 不直接 UPDATE/DELETE 已有历史事件
- 不通过删除事件来修复错误

## Given / When / Then

- Given 客户端使用相同 `idempotency_key` 重复提交；When 第一次已成功；Then 返回已有结果，不创建新事件。
- Given 客户端使用相同 `idempotency_key` 但不同 payload 提交；When 两次 payload 不一致；Then 返回 `IDEMPOTENCY_CONFLICT` 拒绝。
- Given 已确认的健康事件需要更正；When 提交 `COMPENSATION` 事件并带 `compensates_event_id`；Then 原事件保留，投影状态更新为补偿后的值。
- Given outbox 消息发布失败；When 消费者重试；Then 同一条 outbox 消息不会被重复投递。
- Given 投影进程中断后重启；When 从 checkpoint 重放事件；Then 重建的投影与在线状态一致。
