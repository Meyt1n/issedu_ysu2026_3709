## 用户价值

MOB-112 统一了错误展示、MOB-113 定了防重复与刷新策略，但弱网下的中间态仍很粗糙：列表在加载时是空白，超时后的文案与「本来就没有数据」看起来一样。补骨架屏与分层的超时/重试文案，让「在加载」「加载失败」「确实为空」三种状态互不混淆。

## 范围

- 今日任务、成员、风险、时间线等主要列表的骨架屏（尊重减少动效设置）。
- 三态区分：加载中、失败可重试、空数据，文案与图示互不相同。
- 超时分层文案：连接超时、服务端慢、部分数据失败，分别给出可执行动作。
- 重试的节流与幂等，复用 MOB-113 的防重复策略，不新造机制。

## 非目标

- 不改错误码到文案的映射规则（属 MOB-112）。
- 不改请求防重复与刷新时机（属 MOB-113）。
- 不做离线写队列或本地乐观更新。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 弱网首次加载列表，When 请求未返回，Then 展示骨架屏而非空白或「暂无数据」。
2. Given 减少动效开启，When 展示骨架屏，Then 不播放闪烁/位移动画，改用静态占位。
3. Given 请求超时，When 展示错误，Then 文案区分连接超时与服务端处理慢，并给出对应动作。
4. Given 服务端返回空集合，When 展示，Then 明确显示「确实没有数据」，与失败态视觉和文案都不同。
5. Given 连续点击重试，When 上一次请求仍在进行，Then 不发起重复请求。
6. Given TalkBack，When 状态在加载→失败→成功之间变化，Then 每次变化都有可朗读的状态播报。

## 安全、隐私与回滚

- 骨架屏只是占位，不得展示任何伪造的示例数据。
- 错误文案不得透露服务端内部实现或其它家庭是否存在。
- 回滚：移除骨架屏组件回到既有加载态，错误文案分层可独立保留。

## 实现与验证证据

- 新增 `ListLoadingState.vue` 统一列表加载态：骨架卡片只作为布局占位，使用 `role=status`、`aria-busy` 和可读状态文字；`SkeletonCard.vue` 在减少动效设置或系统减少动效时关闭扫光动画。
- `FamilyView.vue`、`AlertsView.vue`、`TodayView.vue`、`ScanView.vue`、`MeView.vue`、`MemberDetailView.vue` 和 `AlertDetailView.vue` 接入统一加载态；新增 `ListStatusAnnouncer.vue` 在加载完成后播报成功/空列表状态。
- `ErrorNotice.vue` 增加列表刷新期间的忙碌锁定、部分数据的警示样式和状态标题，避免连续点击重试；各列表加载入口增加请求中守卫。
- `presentListApiError()` 在不改变 MOB-112 通用映射的前提下补充列表上下文：连接等待超时、服务端 504/慢处理、部分数据保留分别给出下一步动作。
- 今日页使用 `Promise.allSettled` 保留已成功的任务/风险数据，趋势失败时单独提示并支持“重试补齐”；提醒页在风险列表成功但汇总失败时同样保留列表。
- `cd APP && npm run check` 通过；`npm run test` 通过（31 个测试文件、285 项）；`npm run build` 通过；`git diff --check` 通过。
