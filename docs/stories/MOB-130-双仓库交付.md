# MOB-130：双仓库交付

- 需求：NFR-04、NFR-06、NFR-07；《双仓库同步提交说明》
- Issue：[ #183 ](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/183)
- 状态：进行中
- 负责人：ry12-20
- 复核人：维护者在合并时完成最终复核
- 风险：R2。同步身份、提交边界或双端哈希不一致时，禁止向内部仓库手动补推、强推或伪造交付完成。
- 允许修改目录：`APP/`、相关测试、`docs/stories/`

## 用户价值

作为项目交付负责人，我需要让移动端变更通过 GitHub PR、Required Checks 和合并后的自动同步进入内部仓库，并能核对两个 `master` 的提交 SHA，才能在不重复提交或错配成员身份的前提下保留可审计的双仓库交付记录。

## 范围

- 所有移动端后续任务从 GitHub `master` 创建分支，通过 GitHub PR 合并；普通成员不直接推送任一远端的 `master`。
- PR 必须绑定单一 Issue、单一负责人和本 Story；PR 作者及其全部提交身份必须映射为同一成员。
- 合并前确认 Required Checks：`Mandatory development docs`、`Backend lint, migration and tests`、`Frontend typecheck and build`、`Secret scan`，以及 `Sync identity preflight` 的身份预检结果。
- 合并后由 `.github/workflows/sync-original-cloud.yml` 触发自动同步；该工作流对每个合并 PR 校验快进路径、PR 边界、身份映射、Token Secret 和推送后 SHA。
- 用 `git ls-remote` 分别读取 GitHub 与内部云端 `master`，仅当两个 SHA 完全一致时记录同步成功。
- 记录失败状态、Actions 运行链接、GitHub SHA、内部 SHA 与阻塞原因；日志和文档不记录 Token、真实健康数据或其他密钥。

## 非目标

- 不向内部云端重复创建对应提交，不手动双推同一分支。
- 不修改或重写 GitHub/内部 `master` 历史；不使用 `--force`。
- 不在本 Story 中变更健康数据、授权、诊疗规则、模型或正式鉴权能力。
- 不把 Actions 未运行、同步失败、SDK 缺失或真机未测描述为已完成。

## Given / When / Then

- 正常：Given PR 由 `ry12-20` 创建，且 PR 内全部提交均关联 `ry12-20`，When Required Checks 与 `Sync identity preflight` 通过并合并到 GitHub `master`，Then 自动同步工作流按该成员映射推送同一提交对象，随后两个远端 `master` SHA 完全一致。
- 边界：Given 内部云端 `master` 已包含目标 GitHub SHA，When 自动同步运行，Then 工作流记录“已同步/无需重复同步”，不重建提交、不重新归属作者。
- 失败：Given 内部云端 SHA 不在 GitHub `master` 第一父链、PR 引入跨 PR 提交、身份映射不唯一、缺少对应 Secret 或推送后 SHA 不一致，When 工作流预检，Then 在任何 push 前失败并输出可定位原因；维护者先处理分叉或配置后再重跑。
- 未授权：Given PR 作者或提交作者不属于已配置成员映射，When `Sync identity preflight` 或合并后同步运行，Then 拒绝同步，绝不退回使用其他成员 Token。

验收记录必须附上本 PR 链接、Required Checks 结果、同步 Actions 运行结果和上述两端 SHA；若任何项尚未产生或失败，Story 保持“进行中”或“阻塞”。

## 回滚

PR 未合并前关闭 PR 并删除分支。PR 合并后使用 `git revert` 生成新的 GitHub PR；由正常合并后的自动同步工作流镜像该 revert。禁止为回滚直接向内部云端推送或强制覆盖。
