# HCT-446 健康资讯重定向链白名单校验

- Issue：[#437](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/437)
- 关联需求：NFR-01、NFR-02、NFR-03
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为本地健康资讯适配器维护者，我希望服务端在跟随资讯源重定向时校验每一跳 URL，确保请求始终停留在 HTTPS 白名单内；当跳转越界时系统应立即阻断并回退到季节卡片，避免未授权出站和远端内容进入缓存。

## 验收标准

- [x] 初始列表地址、重定向链中间地址和最终响应地址都必须使用 HTTPS 并通过健康资讯域名白名单。
- [x] 跳转到未授权域名时不解析、不缓存响应正文，返回 `status=egress_blocked` 和季节性降级卡片。
- [x] 合法的白名单内 HTTPS 重定向仍可正常解析、去重和写入缓存。
- [x] 现有本地模式、白名单 RSS/HTML 抓取、fresh/stale 缓存和错误降级语义保持不变。

## 实现与证据

1. 新增响应重定向链校验，逐跳检查 `response.history` 与最终 `response.url`。
2. 新增结构化 `HealthNewsEgressBlockedError`，将越界跳转映射为安全降级状态。
3. 补充安全测试，覆盖最终地址越界、中间跳转越界和合法白名单重定向。

## 回滚

回滚应用代码即可移除重定向链校验；HCT-444/HCT-445 的本地季节卡片和缓存数据结构不变。
