# HCT-103：健康事件追加与状态投影

- 需求：FR-02、NFR-03
- 状态：进行中
- 负责人：Meyt1n（仓库维护者，需项目组确认）
- 复核人：待项目组指定；必须复核事件不可覆盖、事务一致性和删除传播
- 风险：高；错误的历史覆盖会破坏健康事实可追溯性
- 允许修改：`src/api/app/models.py`、`src/api/app/routes.py`、`src/api/app/schemas.py`、`migrations/`、`tests/`

## 用户价值

家庭成员手工确认一条健康事实后，系统以不可覆盖事件保存，并在同一事务中创建 outbox 消息和成员状态投影。

## 范围与非目标

本 Story 只接受已确认的手工事件，支持事件列表和最小状态投影。视觉识别、药品主数据、风险规则和自动状态推断不在本 Story 内。

## Given / When / Then

- Given 成员属于当前家庭且操作者有写入权限；When 提交 `CONFIRMED` 手工事件；Then 生成不可覆盖 `health_event`、outbox 消息和状态投影。
- Given 事件已经创建；When 查询事件时间线；Then 原始 payload、证据、操作者、确认状态和时间可见。
- Given 未确认识别结果；When 尝试通过该接口提交；Then Schema 拒绝，不能进入正式健康状态。

见 `tests/integration/test_event_chain.py`。后续必须补充事件重放、补偿事件和数据库事务失败回滚测试，完成前不得标记为已验证。
