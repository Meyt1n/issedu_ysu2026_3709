## 用户价值

家庭成员确认的健康事实以不可覆盖事件保存；重复请求、下游失败、worker 中断或投影损坏不会造成重复业务结果或历史丢失，维护者可以从空状态或受校验 checkpoint 确定重建当前状态。

## 范围与非目标

本 Story 交付成员内单调事件序号、幂等写入、补偿事件、事务 outbox、自动 worker、失败/锁状态、状态哈希、checkpoint 和重放。`UNCONFIRMED` 事件仍只进入待复核 outbox，不更新正式状态。视觉识别、药品主数据、风险规则、关系图谱、删除传播和自动医学判断不在本 Story 内。

## 冻结契约

- `health_event` 只追加；数据库触发器拒绝直接 `UPDATE/DELETE`，更正追加带 `supersedes_event_id` 的已确认补偿事件并保留原事件。
- 每个成员的 `sequence_no` 单调递增；投影按已确认事件序号处理，检测到缺失的已确认前序时返回 `OUT_OF_ORDER`，不跨过缺口。
- 写请求可携带最长 128 位 `Idempotency-Key`；同家庭、同 key、同操作者和同 payload 返回原事件，不同请求指纹返回 `409 IDEMPOTENCY_KEY_CONFLICT`。
- 事件、最小 outbox 消息和在线投影在同一事务提交；投影异常时三者一起回滚。outbox 不复制健康 payload。
- outbox 状态为 `PENDING/PROCESSING/FAILED/DISPATCHED`，保存尝试次数、锁、稳定错误码和时间；worker 自动回收过期 `PROCESSING` 锁并重试。
- 投影保存 `last_sequence`、`version` 和规范 JSON SHA-256；checkpoint 保存状态快照与哈希，哈希不匹配时拒绝重放。
- MySQL Compose 显式启用 `log_bin_trust_function_creators=1`，允许受限项目库迁移账号建立不可变触发器；已有健康事件时禁止破坏性 downgrade，生产使用前滚修复。

## Given / When / Then

- Given 同一幂等键和相同请求；When 重复提交；Then 只存在一个事件、一个 outbox 和一个投影效果，并返回同一事件 ID。
- Given 同一幂等键但 payload 或操作不同；When 提交；Then 返回 `409`，不追加任何事实。
- Given 已确认事件需要更正；When 提交补偿；Then 原事件保持不变，新事件引用原事件，当前投影反映修正值。
- Given 投影更新抛错；When 追加事件；Then 事件、outbox 和投影全部回滚。
- Given worker 下游失败或进程中断；When 下次轮询；Then 失败/过期锁可观察且可重试，重复投递不重复改变投影版本。
- Given 空投影或有效 checkpoint；When 按序重放；Then 状态哈希与在线投影一致；乱序消息在缺失前序完成前保持失败状态。

## 风险与回滚

- 停止 `outbox-worker` 后可保持事实写入和在线投影；未派发消息留在 outbox，恢复 worker 后按成员序号重试。
- 应用回滚不得删除事件、outbox 或 checkpoint；先停止 worker，保全表和状态哈希，再使用兼容应用版本或前滚修复。
- 只在空事件库允许 migration downgrade；存在事件时迁移主动拒绝，避免丢失序号、幂等、补偿和可重放语义。
- worker 日志只输出计数和稳定错误码，不输出 payload、evidence、成员状态或异常正文。
