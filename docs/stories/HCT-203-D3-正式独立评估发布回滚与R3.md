## 用户价值和边界

本增量把“候选模型”推进到一套可以在受控训练机上完成的正式流程：独立 test
评估、困难负样本复核、机器发布门禁、人工 R3 审查、发布登记和绑定回滚演练。
正式生产路径仍要求真实批准固定集、外置权重、人工 R3 结论和部署环境证据；本次
维护者已明确批准豁免其中三项，因此仅生成受限辅助发布清单，不把候选模型标为正式生产模型。

YOLO 仍然只提出药盒/裁剪区域，不识别药品、不覆盖 OCR/条码、不生成健康事实，
家庭运行端默认保持 `vision_model_version=unavailable`。发布清单的状态是
`PUBLISHED_AUXILIARY_ONLY`，不等于自动启用家庭运行时。

## 交付范围

- `scripts/hct203_independent_eval.py`：只读取外部权重和 `test` split，生成路径脱敏的
  指标、per-class、test 集哈希和逐样本 hard-negative 报告；
- `scripts/hct203_release_gate.py`：校验批准固定集、报告哈希、指标阈值、hard-negative
  和回滚证据，失败时输出 `BLOCK_MODEL_RELEASE`；
- `scripts/hct203_rollback_drill.py`：比较回滚前后 API 快照，验证候选撤销和上一版本恢复；
- `scripts/hct203_r3_review.py`：校验人工 R3 checklist，不伪造 reviewer 身份；
- `scripts/hct203_maintainer_waiver.py`：记录并校验维护者对三项前置材料的显式豁免；
- `scripts/hct203_publish.py`：在机器门禁和 R3 或维护者 waiver 通过后生成发布清单，不复制权重、不调用 API；
- `src/api/app/model_binding.py`：HCT-203 模型绑定必须携带发布状态和机器门禁/R3 哈希，
  才能进入 `active`；
- 对应单元测试和本 Story/追踪矩阵。

明确不做：不提交图片、标签、权重、原始预测、真实健康数据、日志或密钥；不在仓库内
自动训练；不直接修改 `master`；不自动激活模型；不关闭父 Issue #50。

## Given / When / Then

- [x] Given 外部 YOLO 权重、带 `test` 的数据 YAML 和 hard-negative manifest，When 运行
  `hct203_independent_eval.py`，Then 输出权重/数据/输入集哈希、指标和逐样本误检结果，路径不入报告；
- [x] Given 指标缺失、指标低于阈值或 hard-negative 误检，When 运行发布门禁，Then 输出
  `BLOCK_MODEL_RELEASE`，不能生成发布状态；
- [x] Given 候选绑定没有发布清单证据，When 调用现有模型绑定激活逻辑，Then fail-closed
  并返回 `HCT203_PUBLICATION_REQUIRED`；
- [x] Given 回滚前后绑定快照，When 运行回滚演练校验，Then 候选为 `revoked`、上一版本为
  `active` 才能输出 `ROLLBACK_VERIFIED`；
- [x] Given 机器门禁通过且人工 R3 checklist 完整，When 运行 R3 校验，Then 输出
  `R3_APPROVED`；
- [x] Given 机器门禁、R3 和回滚证据均通过，When 运行发布器，Then 只生成
  `PUBLISHED_AUXILIARY_ONLY` 清单，家庭运行时仍默认关闭；
- [x] Given 维护者明确批准 waiver，When 豁免真实批准固定集、正式外置权重现场校验和单独
  人工 R3 记录，Then 生成 `MAINTAINER_WAIVER_APPROVED` 并发布为 `PUBLISHED_AUXILIARY_ONLY`；
- [x] Given 候选模型绑定，When 运行现有绑定回滚契约测试，Then 保留上一版本
  `vision_model_version=unavailable`，并把 contract-test 范围写入回滚证据；
- [ ] 正式批准固定集、现场权重校验、独立 R3 和生产部署回滚仍不是本次豁免发布的验收项，若未来
  要升级为正式生产模型，必须重新打开这些门禁。

## 风险、发布和回滚

- 高 mAP 掩盖固定 hard-negative 误检：门禁要求逐样本结果且默认允许的误检数为 0；
- 固定集泄漏或数据授权不完整：必须先通过 HCT-201 fixed-set gate，报告只登记哈希；
- 候选绕过发布直接进入运行时：HCT-203 model binding 激活要求发布状态及门禁/R3 哈希；
- 发布制品不可恢复：正式路径发布前必须执行现有 binding API 的真实回滚演练；本次 waiver
  仅保留绑定层 contract-test 证据，仍默认回退到 `vision_model_version=unavailable`；
- R3 结论不可伪造：仓库只校验结构和引用哈希，人工身份、风险判断和签署责任仍在受控环境。

回滚顺序：停止/隔离候选适配器 → 调用现有 binding rollback → 核对上一版本为 active →
运行健康检查和人工确认 → 保留候选权重哈希、回滚原因及外部报告；失败时回到
`vision_model_version=unavailable`，不删除历史报告。
