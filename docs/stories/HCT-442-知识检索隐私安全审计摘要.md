# HCT-442 知识检索隐私安全审计摘要

- Issue：[#407](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/407)
- 关联需求：FR-08、NFR-01、NFR-02、NFR-03
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为家庭照护系统维护者，我希望知识检索审计能够证明查询发生过、属于哪个授权范围以及返回了多少结果，但不保留用户输入的健康问题原文，从而兼顾排障可追溯性和本地隐私最小留存。

## 背景与边界

原有 `retrieval_query.query_text` 直接保存最多 1000 个字符的查询内容。用户可能在问题中输入药品、症状或成员健康信息，即使数据库仅用于本地审计，明文留存仍扩大了泄露面。本切片将查询文本替换为规范化 SHA-256 摘要和长度元数据，并清理历史明文；检索结果、助手引用、权限过滤和降级语义保持不变。

不保存模型思考链、完整回答、原始知识片段或未授权健康数据；摘要不能作为认证凭据或权限判断依据。

## 验收标准

- [x] 新检索记录的 `query_text` 为空，`query_digest` 为 64 位摘要，`query_length` 记录规范化后的字符长度。
- [x] 仅空白和 Unicode 兼容格式差异的同一查询产生相同摘要，摘要不可逆且不用于授权。
- [x] `0022_hct442_knowledge_query_privacy` 升级时为历史记录生成摘要并清空 `query_text`，保留审计 ID、范围、结果数量和时间。
- [x] `GET /api/v1/knowledge/query-audit` 只返回当前 actor 的摘要、长度、家庭/成员范围、结果计数和时间，不返回查询原文、chunk ID 或正文。
- [x] 检索失败、助手降级和现有知识权限边界不因审计摘要改造而改变。

## 实现设计

1. `RetrievalQuery` 增加 `query_digest`、`query_length`，保留可空的旧 `query_text` 列用于迁移兼容；新写入永远置空原文。
2. 规范化使用 Unicode NFKC 和连续空白折叠，再计算 SHA-256；只保留摘要和长度。
3. Alembic 迁移逐行回填历史摘要后清空旧文本，并为摘要建立索引；降级不尝试恢复不可逆的原文。
4. 新增 actor-scoped 审计摘要接口，按创建时间倒序并限制批量，响应计算 `top_chunk_count` 但不暴露存储的 chunk 列表。

## 测试与证据

- `tests/unit/test_hct442_knowledge_privacy.py`：规范化摘要、明文不落库、actor 隔离、响应字段最小化和摘要不可逆边界。
- 知识库/助手既有契约回归：检索结果、引用校验、无授权文档降级和本地模型不可用降级。
- 静态检查：`uv run ruff check .`；迁移：临时 SQLite `uv run alembic upgrade head`。

## 回滚

回滚应用代码只会隐藏新审计入口，不恢复历史明文；若必须回退迁移，仍保持 `query_text` 为空并以摘要字段作为事实源，禁止伪造或恢复已清除的健康查询原文。
