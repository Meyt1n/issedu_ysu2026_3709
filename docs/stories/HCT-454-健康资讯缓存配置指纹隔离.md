# HCT-454 健康资讯缓存配置指纹隔离

- Issue：[#465](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/465)
- 关联需求：NFR-01、NFR-02、NFR-03
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为健康资讯适配器维护者，我希望缓存与生成它时的来源和白名单配置绑定，这样运行中修改出站范围后，旧配置产生的远端资讯不会继续被复用，确保配置变更能够立即生效。

## 验收标准

- [x] 缓存指纹覆盖 adapter 模式、允许域名、活动来源 ID/地址/类型/路径和展示条目上限等影响内容或出站范围的配置。
- [x] 运行中修改来源或白名单后，旧缓存不再以 fresh/stale 形式返回；系统重新抓取或回退到本地季节卡片。
- [x] 配置未变化时，原有 fresh/stale TTL 行为保持不变。
- [x] 运维快照能够区分缓存为空、fresh、stale、expired 和 config_mismatch。
- [x] 缓存指纹只用于隔离，不包含查询、家庭、成员或新闻正文。

## 实现与证据

1. 为进程缓存条目增加配置指纹，生成时记录活动来源和展示配置的哈希。
2. 读取 fresh、限流 stale 和 provider-failure stale 前校验指纹；配置不一致时强制重新抓取。
3. 运维快照返回 `cache_scope_matches` 和 `config_mismatch`，并补充来源变更回归测试。

## 回滚

回滚应用代码即可恢复旧缓存读取逻辑；不涉及数据库迁移，不影响 HCT-445/HCT-446 的白名单和重定向安全校验。
