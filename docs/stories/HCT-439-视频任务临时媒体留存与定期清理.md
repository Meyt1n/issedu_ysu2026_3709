# HCT-439 视频任务临时媒体留存与定期清理

- Issue：[#389](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/389)（父任务 [#246](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/246)，承接 HCT-414-D1/#264 与 HCT-414-D2/#332）
- 负责角色：后端组
- 阶段：P1-W8
- 风险：R2
- 状态：已合并；清理接口、留存上限和保护规则已有自动化证据，父任务发布门禁仍单独追踪

## 用户故事

作为家庭 Owner 和系统维护者，我希望视觉任务产生的临时视频不会无限期保留，能够先预览、再按安全规则批量清理，从而降低隐私暴露和磁盘占用风险，同时不破坏仍在处理或等待人工复核的任务。

## 背景与边界

HCT-414-D1/D2 已完成图片/视频媒体类型契约、质量凭证绑定、视频抽帧 worker、30 秒时长上限和能力声明，但父任务明确把“视频/帧留存与定期清理策略”留给后续增量。本切片处理上传文件树（正文以及既有 thumbnail/cache/index 派生文件），不删除视觉任务数据库行、OCR/融合结果、健康事件或人工复核记录。

本切片只针对 `media_type=video`，因为视频是该父任务的临时采集载荷；图片留存策略不在本次范围内。

## 验收标准

- [x] Given 终态视频任务超过留存期，When Owner 以默认 `dry_run=true` 调用清理接口，Then 只返回扫描、候选、保护和文件统计，不删除任何文件。
- [x] Given 终态视频任务超过留存期且没有待复核任务/共享引用，When Owner 执行清理，Then 删除正文及 thumbnail/cache/index 派生文件，保留任务行和结果元数据。
- [x] Given 任务处于 queued/running，When 执行清理，Then 任务不在清理候选中，原文件保持不变。
- [x] Given 任务有 `PENDING_REVIEW` 关联，When 执行清理，Then 任务和文件都被保护，报告返回保护计数。
- [x] Given 同一文件被多个视觉任务引用，When 执行清理，Then 文件保持不变，避免删除其他任务仍需的输入。
- [x] Given 文件已被上一次执行删除，When 再次执行，Then 返回幂等的 `missing_files` 统计，不返回 500。
- [x] Given 请求者不是家庭 Owner 或家庭已擦除，When 调用清理接口，Then 返回隐藏式 404，不泄露家庭/文件是否存在。
- [x] Given 定时任务运行脚本，When 未提供 `--execute`，Then 默认只做 dry-run；只有明确传入 `--execute` 才删除文件。

## 实现设计

1. `Settings` 增加 `VISION_VIDEO_RETENTION_SECONDS`（默认 24 小时，允许运维延长）和 `VISION_VIDEO_CLEANUP_BATCH_SIZE`（默认 100）。配置缩短留存期不能绕过终态、待复核和共享引用保护。
2. `cleanup_expired_video_files` 只查询指定家庭的终态视频任务，并按完成时间升序处理批次。终态包括 succeeded、failed、timeout、cancelled；缺少 `finished_at` 时回退到 `updated_at/created_at`。
3. 对候选任务查询待人工复核关联和文件引用数量。所有保护判断在删除前完成，清理过程不修改数据库记录。
4. 新增 Owner-only `POST /api/v1/households/{household_id}/vision-tasks/retention-cleanup`，请求支持 `dry_run` 和批量上限，返回截止时间、候选数、保护数和删除/缺失/失败统计。
5. 新增 `scripts/vision_task_retention.py`，默认预览，可按家庭执行；用于本地定时任务或发布环境的受控调度。

## 数据与隐私

- 不把文件路径、原始 OCR 文本、视频内容或候选结果写入清理日志。
- 任务数据库行保留用于审计、重试状态查询和家庭删除传播；原始视频文件及派生文件按文件存储层清理。
- 文件不存在视为幂等结果，不通过错误信息暴露路径或原始文件名。

## 测试计划

- 单元测试：截止时间计算、dry-run 不变更、终态筛选、待复核保护、共享引用保护、缺失文件幂等和失败计数。
- 契约测试：Owner 权限、家庭边界、默认 dry-run、execute 响应字段和批量上限。
- 静态检查：`ruff check`；相关 pytest 回归。

## 回滚

将 `VISION_VIDEO_RETENTION_SECONDS` 调大或停止调度脚本即可暂停实际删除；API 的 dry-run 仍可用于观察。回滚代码只影响清理入口，不改变视频 worker、图片任务、融合、人工复核和健康事件链路。
