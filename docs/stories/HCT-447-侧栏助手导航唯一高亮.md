# HCT-447 侧栏助手导航唯一高亮

- Issue：待开（本 Story 与 PR 先行绑定，Issue 创建后回填）
- 关联需求：FR-08（本地证据型助手入口）、NFR-07（可用性与一致导航）
- 负责角色：前端组
- 风险：R1（纯前端导航展示缺陷修复，不涉及数据、权限、模型或网络出口）
- 状态：实现中（待 PR、维护者复核）

## 用户故事

作为家庭管理员或成员，我打开侧栏的健康助手时，希望侧栏只出现一条助手入口且只有这一条被高亮，避免「健康助手」和「本地助手」同时选中造成导航混乱。

## 缺陷根因

HCT-444 为成员前台加入「健康助手」（`view: 'assistant'`，组「我的照护」）时，管理员的「本地助手」（同 `view: 'assistant'`，组「安全与洞察」）仍保留在 `src/web/src/App.vue` 的 `NAV_ITEMS` 中。`assistant` 属于 `SHARED_VIEWS`（`src/web/src/store.ts`）：

- 成员过滤 `MEMBER_VIEWS.includes(view) || SHARED_VIEWS.includes(view)` 放行两条；
- 管理员过滤 `!MEMBER_VIEWS.includes(view)` 也放行两条；

因此两个门户的侧栏都渲染两条 `assistant` 条目，模板 `:class="{ active: session.currentView === item.view }"` 按 view 精确匹配，两条同时高亮。

## 验收标准

- [x] Given 管理员门户，When 打开助手，Then 侧栏只有一条助手导航（标签「健康助手」，组「安全与洞察」）且仅该条高亮。
- [x] Given 成员门户，When 打开助手，Then 仅「我的照护」组的「健康助手」一条高亮。
- [x] 任一门户下，`visibleNavItemsFor` 结果中不存在重复 view。
- [x] `npm run check:web`、`npm run build:web`、`npm run test:web` 通过。

## 实现与证据

1. 新增 `src/web/src/ui/navigation.ts`：把 `NAV_ITEMS`、门户过滤、分组和 active 选择从 `App.vue` 抽为纯函数；助手两条定义分别用 `portals: ['member']` / `portals: ['admin']` 显式限定；管理员条目标签统一为「健康助手」；`visibleNavItemsFor` 末尾按 view 去重防御，保证即使未来条目配置出错，active 高亮仍唯一。
2. `src/web/src/App.vue` 改为消费上述纯函数，删除组件内重复的导航定义与过滤逻辑；active 判定保持按 view 精确匹配（无标签模糊匹配）。
3. 新增 `src/web/src/ui/navigation.test.ts`（12 个用例）：断言 admin/member 下 `assistant` 恰好一条、标签「健康助手」、分组正确、任意组合下无重复 view、`activeNavItem` 唯一命中与回落。

## 修订注（2026-08-31）

管理员侧栏「登录设置」原与「授权管理」共用钥匙、与「用药安全」易混淆。改为 `lock`（锁），并增加与授权钥匙、用药盾牌不重复的单测。冻结正文不改。
