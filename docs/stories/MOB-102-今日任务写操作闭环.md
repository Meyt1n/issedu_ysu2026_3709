## 用户价值

让老人最常做的"确认 / 延期 / 跳过"在弱网、重复点击、后端暂不可用时仍能给出准确、可恢复的反馈，不产生重复事件。

## 范围

- 确认、延期、跳过的防重复提交（幂等键 + 加载态锁定按钮）；
- 失败后的重试与准确的成功/失败反馈；
- 操作成功后任务列表、趋势图、时间线刷新一致；
- 跳过必填原因、延期带明确时长的交互校验。

## 非目标

- 服务端幂等逻辑（复用主仓库既有事件中心幂等，本 story 只做移动端防重复与展示）；
- 将"近 7 天完成率"包装为医疗依从性结论。

## Given / When / Then

- Given 用户点击确认；When 请求进行中再次点击；Then 按钮锁定，不发起第二次请求，不产生重复事件。
- Given 写回成功；When 页面刷新；Then 任务列表、趋势、时间线同步更新，与后端回执一致。
- Given 写回失败（网络/超时）；When 用户重试；Then 显示可重试的失败提示，成功后状态以服务端回执为准。
- Given 用户跳过任务；When 未填原因；Then 阻止提交并提示必填，不写入事件。

## 测试

- 确认/延期/跳过的防重复提交
- 幂等键生成与复用
- 失败重试与成功/失败反馈
- 跳过原因校验
