## 1. 用户价值与目标

Owner 查询审计时，需要快速定位某一种动作或某一种处理结果。HCT-434 在现有安全游标分页和 `request_id` 筛选上增加 `action`、`outcome` 条件，并将所有筛选条件绑定到签名游标，避免翻页时混入其他范围的审计记录。

## 2. 范围与非目标

本切片实现：

1. Owner 可按 `action`、`outcome` 或两者组合分页查询审计；
2. 下一页游标绑定家庭、请求 ID、动作和结果四项查询范围；
3. 筛选条件改变、游标被篡改或跨家庭复用时拒绝继续翻页；
4. 补充动作/结果筛选、游标范围和非 Owner 边界契约测试。

不做：

- 不新增数据库字段或迁移；
- 不修改审计记录内容、权限结论或审计保留策略；
- 不返回健康正文、证据或敏感请求参数。

## 3. Given / When / Then 验收

- Given Owner 选择 `action=UPDATE_TIME_ZONE`、`outcome=ALLOWED`；When 请求分页接口；Then 只返回同时满足两个条件的记录。
- Given Owner 使用第一页返回的游标继续查询；When action、outcome、request_id 和家庭范围保持一致；Then 返回下一页且不重复。
- Given 任一筛选条件改变或游标签名被篡改；When 继续分页；Then 返回 `422 AUDIT_CURSOR_INVALID`。
- Given 非 Owner 查询任意审计筛选；When 请求接口；Then 返回 `404 RESOURCE_NOT_FOUND`。
