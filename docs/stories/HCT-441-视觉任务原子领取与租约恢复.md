# HCT-441 视觉任务原子领取、租约续期与过期恢复

- Issue：[#397](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/397)
- 负责角色：后端组
- 阶段：P1-W8
- 风险：R2（只影响异步视觉任务调度，不改变人工复核和健康事实写入边界）
- 状态：已合并；原子领取、租约恢复和尝试上限已有自动化证据，生产多 worker/多主机压测仍由父任务追踪

## 用户故事

作为视觉识别 worker 和系统维护者，我希望任务领取是原子的，并且在 worker 崩溃后能够自动恢复，从而避免多个 worker 重复处理同一份药盒证据，也避免任务永久卡在 `running` 状态。

## 背景与边界

原有 worker 通过 `GET /vision-tasks?task_status=queued` 查询队列，再直接提交证据。多个 worker 可能同时读到同一个任务；进程在下载、OCR 或模型推理期间退出时，任务也没有可观察的恢复边界。本切片为 `vision_task` 增加短期租约和尝试次数，保留现有 `queued → running → terminal` 状态机，并继续要求 OCR/融合结果经过人工复核后才能写入健康事实。

本切片不负责模型精度、候选融合、人工确认或移动端界面；不把原始图片、视频、OCR 文本写入日志。

## 验收标准

- [x] Given 两个 worker 同时领取同一批任务，When 请求 `POST /api/v1/vision-tasks/claim`，Then 条件更新只允许一个 worker 获得任务，返回任务带有 `lease_owner`、`lease_expires_at` 和 `attempt_count`。
- [x] Given worker 已领取任务，When 另一个 worker 提交证据或续租，Then 返回稳定的 `VISION_TASK_LEASE_LOST`/`VISION_TASK_LEASE_HELD` 冲突，不覆盖当前 worker 的结果。
- [x] Given 本地推理耗时较长且租约仍有效，When worker 调用 `POST /api/v1/vision-tasks/{id}/lease`，Then 只延长同一 owner 的租约。
- [x] Given worker 崩溃导致租约过期且未达到尝试上限，When 下一轮领取，Then 任务重新进入队列并可被再次原子领取。
- [x] Given 同一任务租约连续过期达到最大尝试次数，When 系统恢复过期任务，Then 任务进入 `timeout`，错误码为 `WORKER_MAX_ATTEMPTS`，等待人工重试。
- [x] Given 旧版本地适配器直接处理未领取的 queued 任务，When 提交证据，Then 保持兼容；已领取任务仍必须通过租约校验。
- [x] Given 数据库从任意旧版本升级，When 执行 Alembic，Then `0020_hct441_vision_task_leases` 增加租约字段和索引，既有任务默认 `attempt_count=0`。

## 实现设计

1. `VisionTask` 新增 `lease_owner`、`lease_expires_at`、`attempt_count`；`Settings` 提供租约时长、最大尝试次数和批量上限。
2. `claim_vision_tasks` 先恢复本 worker 创建的过期任务，再通过带状态/过期条件的 SQL 更新领取 queued 任务；条件更新失败只跳过竞争任务，不影响同批其他任务。
3. `renew_vision_task_lease` 仅接受同一 `lease_owner` 且尚未过期的请求；终态转换、取消和手工重试都会清除租约。
4. 证据写入在已有访问控制之后校验租约；未领取任务保留旧适配器兼容路径，已领取任务拒绝过期或跨 worker 写入。
5. `scripts/vision_worker.py` 改为调用 claim 接口，并在提交证据前续租；worker 异常时不伪造失败结果，等待服务端按租约恢复。

## 回滚

停止使用新的 worker 入口可暂时回退到旧适配器；数据库迁移保持向前兼容，代码回滚前应先停止 worker。租约字段为可空字段，旧任务记录不会因缺少 owner 而丢失；不得手工删除任务结果或修改健康事件。
