## 1. 用户价值与目标

HCT-429 已允许家庭 Owner 修改业务时区，但如果只保存最终值，维护者无法解释某次趋势口径变化由谁、何时发起。此切片复用现有 `AccessAudit` 最小证明，记录设置字段变更和请求关联 ID，不保存旧值/新值正文或任何健康数据。

## 2. 范围与非目标

本切片实现：

1. 家庭时区实际变化时追加一条 `AccessAudit`；
2. 审计记录包含家庭、操作者、操作 `UPDATE`、动作 `UPDATE_TIME_ZONE`、字段 `household.time_zone`、允许结果、请求 ID 和时间；
3. 同值更新不追加重复审计；
4. 复用已有 Owner 审计查询和游标分页接口；
5. 覆盖请求 ID 关联、同值更新、非 Owner 边界和历史审计兼容测试。

不做：

- 不记录旧值、新值、健康正文、证据、凭据或完整请求体；
- 不改变 Owner 权限、时区校验、授权判断或移动端趋势算法；
- 不新增数据库迁移、API 路径或外部网络出口。

## 3. Given / When / Then 验收

- Given Owner 将家庭时区从 `Asia/Shanghai` 改为 `Europe/London`，且请求带合法 `X-Request-ID`；When 更新成功；Then 审计包含 `UPDATE_TIME_ZONE`、`household.time_zone`、`ALLOWED` 和相同请求 ID。
- Given Owner 将时区更新为当前相同值；When 请求成功；Then 不追加新的设置变更审计。
- Given 非 Owner 修改家庭时区；When 请求接口；Then 返回 `404 RESOURCE_NOT_FOUND`，且不产生允许结果审计。
- Given 既有授权审计和设置审计；When Owner 使用普通列表或游标分页查询；Then 两类最小记录均可按既有 Schema 返回，不泄露设置值正文。
