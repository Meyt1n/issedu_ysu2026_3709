# HCT-512 正式账号密码字母数字策略

- Issue：待开（本任务 agent 无 issues 权限，需维护者创建并回填）
- 关联：HCT-107（本地账号）、HCT-417（Web 会话）、HCT-498（正式账号密码）、HCT-509（改密/找回）
- FR/NFR：FR-01、NFR-01、NFR-07
- 风险等级：R2（认证输入校验；不改变会话、授权或 PIN）
- 状态：实现完成，待 Issue/PR 与维护者人工验收

## 1. Story

作为家庭管理员，我希望账号密码至少 8 位，并且同时包含英文字母和数字，避免用纯数字或纯英文弱密码登录或开户。

## 2. 产品决定

| 操作 | 规则 |
|---|---|
| 登录、注册、修改密码、PIN 找回后的新密码 | 8–256 位，至少 1 个英文字母 `A–Z/a–z`，至少 1 个数字 `0–9` |
| 当前密码（改密时核对旧口令） | 仍只要求长度 8–256，以兼容尚未轮换的旧哈希 |
| 六位 PIN | 不变 |

教学默认密码由 `DemoOnly-ChangeMe!`（无数字）改为 `DemoOnly-ChangeMe1!`。若库里仍是旧哈希，用新默认密码登录时会一次性改写哈希，不提供通用“无验证改密”。

明确不做：不宣称这能挡住 Chrome 泄露库提醒；常见口令仍可能被浏览器标红。不改 APP 演示模式。不把 PIN 改成字母数字。登录卡片不展示策略小字，也不把 `PASSWORD_FORMAT_INVALID` 显示给登录用户。

## 3. 范围

允许修改：`src/api/app/password_policy.py`、`schemas.py`、`auth.py`、`formal_demo_plan.py`；Web 登录/改密/找回；演示密码文档；对应单测与契约测试。

## 4. 验收标准

1. Given 注册或登录请求，When 密码不足 8 位、或只有英文、或只有数字，Then 服务端仍返回 HTTP 422 `PASSWORD_FORMAT_INVALID`；登录主按钮保持可点亮态。登录卡片不展示「至少 8 位…」小字，也不把策略文案当作红色警告；空字段提示「请输入正式账号和密码」，提交后失败（含格式不符）统一提示「账号或密码不正确」。注册、改密、找回仍提示至少 8 位且需同时含英文和数字。
2. Given 符合策略的密码（如 `password-123`），When 注册或登录，Then 仍按原契约建立会话。
3. Given 库中 `demo-parent` 仍是旧教学密码哈希，When 用 `DemoOnly-ChangeMe1!` 登录，Then 登录成功且哈希升级为新默认，旧口令不再可用。
