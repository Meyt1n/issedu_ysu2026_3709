# HCT-101：工程骨架与健康检查

- 需求：NFR-04、NFR-06
- 状态：进行中
- 负责人：Meyt1n（仓库维护者，需项目组确认）
- 复核人：待项目组指定，不得由实现者独立验收
- 风险：中；依赖锁定、启动方式和密钥扫描失败会阻塞后续开发
- 允许修改：`pyproject.toml`、`uv.lock`、`package.json`、`package-lock.json`、`src/api/`、`src/web/`、`scripts/`、`docker/`、`docker-compose.yml`、`.env.example`、`.github/workflows/ci.yml`

## 用户价值

新成员可以从干净克隆启动 API、Web 和 MySQL，并用同一套锁定依赖执行检查；增强 AI 能力缺失时，基础健康检查仍然可用。

## 范围与非目标

范围包括 Vue/Vite、FastAPI、SQLAlchemy、Alembic、Docker Compose、启动脚本、健康检查和 CI。非目标包括真实视觉模型、RAG、Ollama、天气和医疗判断。

## Given / When / Then

- Given 全新克隆且已安装 Python 3.11、Node 22、uv 和 Docker；When 执行 `uv sync`、`npm ci` 和 `docker compose config`；Then 依赖和 Compose 配置通过校验。
- Given API 依赖已安装；When 执行 `uv run uvicorn app.main:app --app-dir src/api`；Then `/health` 返回 `status=ok`。
- Given CI 运行；When 后端、前端或密钥扫描失败；Then PR 不得被视为可合并。

## 测试与证据

- `uv run ruff check src/api tests migrations`
- `uv run pytest`
- `npm run check:web`
- `npm run build:web`
- `docker compose config`

## 部署与回滚

部署使用 `scripts/start.ps1`、`scripts/start.sh` 或 `docker compose up --build`。回滚以 Git 提交和上一份依赖锁文件为单位；不得把真实密钥提交到仓库。
