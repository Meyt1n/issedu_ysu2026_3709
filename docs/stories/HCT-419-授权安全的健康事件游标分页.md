## 1. 用户价值与目标

健康事件会随着家庭使用持续增长。原有事件列表一次性读取全部授权记录，移动端首屏和弱网场景不必要地传输大量数据，也不符合项目 API 设计规范中的游标分页要求。本切片新增兼容式分页接口，让调用方按页读取，同时保持每次请求都重新执行授权校验。

## 2. 范围与非目标

本切片实现：

1. 新增 `GET /api/v1/households/{household_id}/events/page`，返回 `items`、`next_cursor` 和 `has_more`；
2. 使用 HMAC 签名的不透明游标，游标只包含家庭、成员筛选、稳定排序键和事件 ID，不包含健康事件正文；
3. 以 `sequence_no + event_id` 作为稳定翻页顺序，兼容同一数据库时间精度下的并列时间戳；
4. 每次分页请求重新检查家庭、成员、数据域、动作、用途、有效期和撤权状态；
5. 游标绑定家庭和成员筛选条件，篡改、跨家庭、跨成员、失效事件锚点和格式错误均返回 `EVENT_CURSOR_INVALID`；
6. 单页数量限制为 1 至 100，不改变旧 `/events` 接口和事件写入链路。

不做：

- 不修改健康事件追加、补偿、投影、规则或 outbox 语义；
- 不引入外部缓存、网络服务或客户端 UI；
- 不在游标中保存药品、症状、成员姓名或其他健康正文。

## 3. Given / When / Then 验收

- Given 授权家庭中有多条事件；When 使用 `limit` 和 `next_cursor` 连续请求；Then 事件按稳定顺序返回、无重复，最后一页 `next_cursor=null`。
- Given 仅授权成员 A；When 查询家庭分页接口；Then 只能得到成员 A 的事件，不能通过游标看到成员 B。
- Given 游标被篡改、跨家庭或跨成员复用；When 请求下一页；Then 返回 422 `EVENT_CURSOR_INVALID`，不泄露数据。
- Given caregiver 已获得有效读取授权；When 撤权后继续使用旧游标；Then 请求重新执行授权检查并返回资源不存在。
- Given `limit` 小于 1 或大于 100；When 请求接口；Then 由 API Schema 返回 422。

风险为 R2：分页游标属于客户端持有的不透明状态，密钥变更会使旧游标失效；权限撤回不能依赖游标缓存。回滚时移除新分页路由和游标模块，保留旧 `/events` 接口；更换签名密钥可主动使全部旧游标失效。
