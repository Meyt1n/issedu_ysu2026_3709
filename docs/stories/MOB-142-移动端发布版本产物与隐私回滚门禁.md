## 用户价值

演示或受控发布时，每个安装包都能回答"这是哪个版本、哪个提交构建的、文件是否被改过"：页面显示真实构建信息而不是固定文案；发布清单给出每个产物的 SHA-256；隐私扫描确认包里没有密钥、数据库、日志或未声明文件；出问题时能按哈希定位上一份可用产物并执行恢复。

## 范围

- 构建期注入 `__APP_VERSION__`/`__BUILD_TIME__`/`__BUILD_COMMIT__`（vite define，CI 可用环境变量覆盖）；「我的 → 关于」展示动态版本行；
- `APP/scripts/release-manifest.mjs`：生成发布清单（版本、源码提交、产物注入提交一致性、每个 dist/APK 产物的 SHA-256 与体积），写入 `APP/release/`；
- `APP/scripts/privacy-scan.mjs`：dist 资源类型白名单、禁止类型（.env/.pem/.key/.keystore/.sqlite/.log 等）、单文件 3 MiB 体积上限、私钥内容特征扫描、Android 目录签名材料检查；
- npm scripts：`release:manifest`、`privacy:scan`；
- 回滚演练：按清单哈希定位上一份产物与源码提交的可执行步骤（见本 Story"回滚演练"）。

## 非目标

- 不做生产签名、商店上架或真实分发（需独立发布审批）；
- 不提交真实服务器地址、密钥、健康数据或 APK 二进制入库（清单与截图作为证据入库）；
- 不改变现有功能与安全状态（不通过删功能"变快"或"变小"）。

## Given / When / Then

- Given 一次发布候选；When 构建 APP（PWA dist / debug APK）；Then 清单记录版本号、构建时间、提交哈希与每个产物 SHA-256，且产物内注入的提交与源码提交一致；「关于」页显示同一组信息。
- Given 演示包/受控包；When 隐私扫描；Then dist 只含白名单类型、无密钥/数据库/日志、无超限文件、Android 目录无签名材料。
- Given 发布失败或回归；When 回滚；Then 按 manifest 哈希找到上一份产物与对应提交，`git revert` + 重构建 + 清单核验即可恢复。
- Given 崩溃/错误收集策略；When 检查；Then 本应用不启用任何崩溃收集/上报（既有事实在 README 记录），诊断信息只存本机内存。

## 回滚演练

1. 在 `APP/release/` 找到上一份可用清单（版本 + 时间戳命名）；
2. 按清单定位源码提交 `sourceCommit`，`git revert <引入回归的提交>` 或直接检出该提交；
3. `npm ci && npm run build`，运行 `node scripts/privacy-scan.mjs` 与 `node scripts/release-manifest.mjs --apk <apk>`，比对产物 SHA-256 与旧清单一致（内容寻址验证）；
4. 重新分发产物（APK 重装 / PWA 重新部署静态目录）。

## 安全、隐私与回滚

- 不提交签名密钥；debug APK 本身不入库，入库的是清单 JSON 与截图证据；
- 产物哈希只覆盖文件字节，不含健康数据；
- 回滚方式即上文演练步骤；源码回退用可定位提交 revert。
