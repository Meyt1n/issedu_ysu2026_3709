## 用户价值

FR-03 明确接收图片、拍照和短视频；此前 ScanView 只接受 `image/*`。本任务补齐
移动端短视频录入：本地先校验再上传、服务端抽帧质量门、按媒体类型创建任务、
状态回查与人工复核交接，且在能力未声明/不支持时 fail-closed 隐藏入口。

## 范围与实现

- `APP/src/utils/videoInput.ts`：上传前本地校验格式（.mp4/.mov + MIME）、
  大小（≤10 MiB，镜像服务端 `max_upload_bytes`）、时长（≤30 秒，镜像
  `vision_video_max_duration_seconds`）、方向（竖/横屏入摘要）；输出
  "将上传：短视频（MP4，x.x 秒，x.x MB，竖屏）"摘要；元数据不可读时
  fail-closed 拒绝上传。
- `stores/capabilities.ts`：新增 `vision-task-video` 能力 ID 与说明。
  ScanView 仅在联机且该能力已声明时显示"选择短视频"入口；演示模式与
  未声明场景隐藏入口并给出明确说明（图片路径不受影响）。
- `api/client.ts` + `api/types.ts`：`checkVisionQuality` 支持 media_type；
  `createVisionTask` 携带 `media_type`；`VisionQualityResponse.metrics`
  兼容视频帧数统计（纯数字）；`VisionTask.media_type` 可选。
- `data/httpProvider.ts`：`checkVideoQuality`（帧数统计映射为信息型指标 +
  中文标签 + `framesSummary` 抽帧摘要）；`recognizeMedicine` 增加
  `mediaKind` 参数——视频路径先视频质量门，再以 `media_type=video` 创建
  任务，幂等键带 `vision-video:` 前缀且与图片路径隔离（同一文件图片/视频
  重试互不串扰）；候选卡增加"媒体类型"字段，notice 说明抽帧语义。
- `data/demoProvider.ts`：`checkVideoQuality` 演示实现（演示模式 UI 隐藏
  视频入口，仅为满足 Provider 契约与测试）。
- `ScanView.vue`：短视频入口（accept 限定 mp4/mov）、视频预览（muted
  controls）、"将上传"摘要、检查/识别文案按媒体区分、质量卡"抽帧摘要"
  行（含"任一帧都不会被单独当作已确认药品"说明）、会话切换/取消时清理
  媒体状态。

## 明确非目标

- 不在 APP 内确认候选（人工复核仍在网页端）；不自行生成 OCR/条码/医学结论。
- 不改后端契约（由 #246/#332 交付）；不采集/上传任何真实药品视频。

## 安全与隐私边界

- 视频、抽帧与识别结果不写 localStorage/Service Worker/日志/通知（沿用
  既有视觉路径边界）；质量回执与任务走既有授权/幂等/脱敏契约。
- 任一帧候选不当作已确认药品；确认只在网页端人工复核后发生。
- DEMO_ONLY：HCT-201 固定集/数据集证据批准前，不声明生产识别性能。
