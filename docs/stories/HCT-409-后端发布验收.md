## 用户价值

在最终交付前，用同一组命令证明：基础档 API 延迟可测量、已有隐私/安全/红队回归仍通过、依赖与密钥扫描进入 CI，并且每一个未关闭的 P0/P1 风险都有决定、责任人和回滚说明。

## 范围与非目标

本 Story 覆盖：

1. 基础档 API 延迟探针：`GET /health`、`GET /api/v1/health/db`、家庭创建与列表的 P50/P95、错误率和进程 RSS。
2. 发布回归包：把授权/撤权、出口守卫、日志脱敏、无导流、文件上传、本地认证、红队、删除传播和助手降级测试收成机器可读清单。
3. CI：Python 运行时依赖审计（对照允许清单）、前端生产依赖 `npm audit`（官方 registry）、性能 JSON 制品。
4. P0/P1 风险登记：关闭、接受或延期，附责任人、影响和回滚。

明确不做：

- 不把 in-process TestClient 延迟写成视觉全流程或发布模型性能；
- 不替代人工读屏、项目负责人签署和独立 R3 复核；
- 不因赶工放宽授权、人工确认、拒识、无证据拒答或无导流门禁；
- 不关闭 [#72](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/72)。

## Given / When / Then

- Given 临时 SQLite 与合成 owner；When 运行 `scripts/hct409_api_perf.py`；Then 报告含环境、P50/P95、错误率、RSS，且不含密钥或健康正文。
- Given 发布回归包；When 检查清单中的测试路径；Then 每个文件都存在于仓库，并可被 `uv run pytest` 执行。
- Given 风险登记；When 读取每条 P0/P1；Then 都有 `closed` / `accepted` / `deferred`、责任人、影响和回滚，且视觉全流程 P95 与 R3 签署仍为延期。
- Given CI；When 运行依赖审计；Then 运行时 Python 依赖对照允许清单，新漏洞 ID 失败；前端生产依赖走官方 registry 的 `npm audit`。
