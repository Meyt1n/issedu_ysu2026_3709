## 用户价值

一个身份被授权访问多个家庭时，用户自己决定看哪个家庭，而不是被应用悄悄替他选。切换家庭会把上一个家庭的成员、任务、风险、时间线和上传草稿全部丢掉再重新加载；当前家庭被撤权或删除时回到"请重新选择"，不会自动跳到另一个家庭，也不会继续显示旧数据。

## 修掉的问题

`HttpDataProvider.resolveHouseholdId()` 原本固定取 `listHouseholds()[0]`。这有两个后果：用户完全无法选择家庭；而且**服务端列表顺序一变，同一个人打开应用就会看到另一个家庭的数据**，界面上却没有任何提示。

顺带修掉我在 MOB-133 里留下的同类捷径：`MeView` 为了给二次确认取 `household_id`，也是自己调 `listHouseholds()` 拿第一个。现在两处都走同一套"已选家庭"规则。

## 选择规则

| 情形 | 行为 |
|---|---|
| 已选家庭仍在服务端返回的列表里 | 使用它，与列表顺序无关 |
| 恰好一个可访问家庭 | 自动选定（保持低步骤体验），界面仍显示当前来源与"出现多个家庭时会要求选择" |
| 可访问多个但未选择 | **fail-closed**：`409 HOUSEHOLD_NOT_SELECTED`，不发出任何成员/事件请求 |
| 已选家庭不在列表里（撤权、删除、授权变化） | `404 HOUSEHOLD_UNAVAILABLE`，清除选择回到安全选择态，不自动换一个 |
| 一个家庭都没有 | 沿用既有 `404 NO_HOUSEHOLD` |

`HOUSEHOLD_UNAVAILABLE` 在 Provider 守卫里单独处理：只丢弃 Provider 缓存，**不**把整个授权边界判为"需重新验证"（那会连带清掉能力探测并要求重新测试连接，对"换个家庭"过重），也**刻意不立即清空那个失效的选择**——保留它，设置页才能读到并明确告诉用户"之前选的家庭已不可用"，否则用户只会看到泛泛的"请选择家庭"，无从知道原因（NFR-07）。保留期间不存在数据泄漏风险：每次取数都会继续 fail-closed，页面拿不到任何内容；选择在设置页加载时被清除。

## 切换时清理什么

`selectHousehold()` 经 `updateSession` 写入，`currentHouseholdId` 已加入 `SCOPE_FIELDS`，因此写入即触发 `resetSessionScopedState()` 的 `context` 级清理：

- 丢弃 `HttpDataProvider` 实例 —— 成员缓存、任务缓存、已解析家庭 ID、文件上传 Promise 与视觉任务草稿都挂在实例上，丢实例即清空；
- `currentMemberId` 一并清空，避免新家庭沿用旧成员 ID；
- `currentHouseholdId` 参与 `sessionContextKey`，各页面（如拍药盒的成员加载）据此判断本轮结果已过期并放弃写入；
- 能力快照在切换时清除后**立即重探**，而不是留一个空状态让相关入口全部禁用。

## Given / When / Then

- Given 当前正式会话可访问多个家庭；When 打开"我的 → 数据来源"；Then 展示服务端授权的家庭名称与当前选择，并要求显式选择，不默认取数组第一个。
- Given 用户切换家庭；When 确认切换；Then 旧家庭的成员、任务、风险、时间线、上传草稿、能力快照与页面缓存全部丢弃后再加载新家庭。
- Given 当前家庭被撤权、删除或列表顺序改变；When 刷新；Then 选择失效并回到安全选择态，不自动跳到另一个家庭，也不展示旧数据。
- Given 只可访问一个家庭；When 使用 APP；Then 自动选定保持低步骤，但仍显示当前来源与可切换条件。
- Given 未登录、无家庭、无权家庭或请求失败；When 打开选择器；Then 显示可恢复错误，文案不透露隐藏家庭是否存在。

## 安全、隐私与回滚

- 家庭选择不是授权：所有 API 仍由服务端做家庭/成员/字段/动作/目的/期限校验，本 Story 不改变任何服务端判定；
- 本机 `localStorage` 只多存一个家庭 ID，不存家庭名称、成员或任何健康数据，登出与清理时一并丢弃；
- 家庭 ID 不进 URL、通知或日志；
- 回滚：revert 本 PR 会回到"固定取列表第一个家庭"的旧行为——**这本身就是缺陷**，因此回滚后应立即改为单家庭部署或要求重新选择，不可长期停留在旧行为上。
