# HCT-404 困难样本 V2 固定集对照与真实发布证据

- Issue：[#69 HCT-404](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/69)
- FR/NFR：FR-10、NFR-05、NFR-06
- 风险：R3（模型发布、数据许可、回滚）
- 状态：进行中（候选已登记为 `EXPERIMENTAL_UNRELEASED`；正式发布材料仍阻塞）
- 前置依赖：HCT-203、HCT-208

## 问题与边界

HCT-404 已有版本绑定、发布和回滚 API，但原 `hct404_benchmark_compare.py` 只输出
`PLACEHOLDER` 指标，`comparison_report_hash` 不能证明真实权重、批准固定集、困难负样本、
性能、人工确认覆盖或回滚后的新任务版本。因此它不能作为正式模型发布证据。

本 Story 将流程改为 fail-closed：只有受控环境提供真实外部权重、HCT-208 活跃导出清单、
批准固定 test/unknown 集、V1/V2 对照、人工安全审查和回滚演练后，绑定 API 才能激活
`hct404-*` 正式模型。仓库不提交图片、标签、权重、原始预测、真实健康数据或密钥。

## 交付范围

- `scripts/hct404_benchmark_compare.py`：使用两个外部 YOLO 权重对同一 `test` split 实测，
  复核同一 hard-negative manifest，并记录 V1/V2 指标、per-class、p95 延迟和哈希；缺失输入
  或依赖直接失败，不生成占位指标；
- `scripts/hct404_release_gate.py`：校验 HCT-208 导出清单状态、许可、训练/test 隔离、固定集、
  V1/V2 权重和模型卡哈希、unknown 集、人工确认覆盖率及其阈值、误匹配/漏检影响、R3 批准和回滚证据，
  输出 `ALLOW_FORMAL_RELEASE` 或 `BLOCK_MODEL_RELEASE`；
- `model_version_binding` 增加发布证据哈希和回滚证据哈希；正式 HCT-404 绑定缺证据时
  fail-closed，回滚缺原因或证据哈希时拒绝；
- `0019_hct404_release_evidence.py`、API schema/client 类型和单元/集成测试同步更新。

## 验收条件

- [x] 原占位 benchmark 改为真实外部权重 + `test` split + hard-negative + 实测性能入口；
- [x] 真实证据缺失、指标占位、固定集未批准、授权/导出无效或回滚证据缺失时输出
  `BLOCK_MODEL_RELEASE`；
- [x] HCT-404 正式绑定激活必须携带 release gate、模型制品、固定集、对照、审批和回滚哈希；
- [x] HCT-404 回滚必须提交非空原因和回滚证据 SHA-256，并保留历史 binding 版本信息；
- [ ] 真实 V1/V2 权重、批准固定集、HCT-208 活跃导出清单、人工 R3 记录和生产环境回滚演练
  尚未提供；本次实现不把合成 fixture 当成正式证据。

## 受控环境命令

以下路径必须位于仓库外的受控训练机；命令不会把原始数据写入仓库：

```powershell
uv run python scripts/hct404_benchmark_compare.py `
  --v1-weights <外部\v1.pt> `
  --v2-weights <外部\v2.pt> `
  --dataset-yaml <外部\approved-fixed-test.yaml> `
  --hard-negative-manifest <外部\hard-negatives.jsonl> `
  --device cpu `
  --output <外部\hct404-comparison.json>

uv run python scripts/hct404_release_gate.py `
  --evidence <外部\hct404-evidence-pack.json> `
  --comparison <外部\hct404-comparison.json> `
  --report <外部\hct404-release-gate.json>
```

通过后，将 gate 输出的 `binding_safety_thresholds` 复制到绑定创建请求，并将
`input_sha256.evidence` 作为 `release_evidence_hash`。回滚请求必须同时提交
`reason` 和 `evidence_hash`；API 不会自动激活模型或复制权重。

## 当前阻塞与回滚

当前已在 HCT-203 registry 中登记 V1/V2 外置候选权重，状态均为 `EXPERIMENTAL_UNRELEASED`，
且现场权重哈希已通过 registry 审计；但没有批准固定集、外部 HCT-208 导出清单或人工 R3 记录，
因此 HCT-404 正式发布仍为 `BLOCK_MODEL_RELEASE`。实验模型仅供内部受控测试，不得绑定家庭运行时。
回滚路径是撤销正式 V2、恢复上一有效 binding；若无可验证上一版本，运行端继续使用配置回退或安全
拒识，并保留撤销和证据哈希。
