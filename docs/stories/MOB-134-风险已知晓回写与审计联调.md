## 用户价值

作为当前风险的授权主体，我需要在阅读风险依据后提交一次“我已知晓”，并获得服务端确认的时间与回执标识。这样，家庭成员和审计人员可以区分“用户已阅读并确认”与“客户端仅展示过该风险”，同时不会把风险提醒误写成医疗处置、诊断结论或用药指令。

作为照护者，我需要在授权撤回、会话过期、网络中断、规则版本变化或服务端暂未提供能力时看到真实且可理解的状态，而不是把失败、缓存或演示数据伪装为已完成回写。

## 当前事实与阻塞结论

当前移动端联机适配器会先检查服务端 `risk-acknowledgement` capability，再读取当前风险的规则版本和指纹，使用 HCT-413 endpoint 提交正式回执；能力缺失、风险定位字段缺失或回执不完整时仍 fail-closed，不改写本地风险状态。演示模式的虚构知晓流程只用于教学演示，不能作为联机审计证据。

HCT-413（#247）现已提供以下移动端所需契约，移动端实现已按此对齐：

1. 风险确认 endpoint 与版本化请求/响应契约。
2. `risk_acknowledgement` capability 标识，且移动端不得因 endpoint 存在就假定能力可用。
3. 绑定家庭、成员、规则 ID/版本、风险去重键或证据指纹、操作者、访问目的、服务端时间的幂等语义。
4. 最小脱敏审计事件与稳定错误码。
5. 授权到期、撤权、跨家庭、风险失效、版本冲突、重复回执和会话失效的受控行为。

真实后端授权、版本冲突、撤权、同键重试、PWA 与 Android 设备证据仍待联调环境和设备持有人执行；在这些证据完成前，Story 不标记为已验证。

## 非目标

- 不在移动端生成诊断、处方、停药、换药、剂量判断或医疗建议。

## 后端契约准入清单

移动端开始编码前，后端 PR 必须给出以下可定位证据。字段名称、URL、HTTP 方法和错误码以 HCT-413 最终 OpenAPI 为准；本 Story 仅定义语义，不替代服务端契约。

| 契约项 | 移动端依赖 | 未满足时行为 |
| --- | --- | --- |
| Capability | `risk_acknowledgement` 可按当前身份/访问目的查询 | 确认按钮禁用并显示能力不可用原因 |
| 授权语义 | 当前 actor 对当前家庭、成员和风险具备确认动作权限 | 不显示资源存在性；使用受控未授权提示 |
| 风险定位 | 规则 ID、规则版本、当前风险去重键或证据指纹的稳定定位方式 | 不发起请求，不构造本地替代标识 |
| 幂等语义 | `Idempotency-Key` 同键同载荷返回同一回执；异载荷受控冲突 | 失败状态保留，可使用同键重试 |
| 成功回执 | 唯一回执标识、服务端确认时间、规则/风险版本、操作者可见性规则 | 回执缺失时不显示成功 |
| 审计语义 | 最小审计仅含动作、范围、操作者、时间、结果、request ID、版本 | 不把健康正文或图片复制到客户端审计展示 |
| 失效/撤权 | 风险已失效、规则重算、撤权、跨家庭、会话失效的稳定错误码 | 清除可操作状态，重新读取当前服务端视图 |
| 读取一致性 | 详情与列表可读取同一确认状态或明确的读取时序 | 不用旧缓存覆盖新回执 |

## 客户端状态模型

风险确认状态是“服务端事实 + 当前请求状态”的组合，不是单一布尔值。建议在 ViewModel 中使用下列状态；持久化边界只允许保存无障碍偏好和连接配置，禁止保存风险内容或回执。

| 状态 | 含义 | 按钮行为 | 用户可见信息 |
| --- | --- | --- | --- |
| `capability_unknown` | 尚未完成能力探测 | 禁用 | 正在确认家庭服务器能力 |
| `capability_unavailable` | 服务端未声明能力或能力不适用于当前主体 | 禁用 | 当前家庭服务器无法回写，页面不会标记为已记录 |
| `not_authorized` | 服务端拒绝当前动作且不得泄露资源存在性 | 禁用并刷新授权视图 | 当前身份无法记录该提醒 |
| `ready` | 能力、授权和风险定位均满足 | 可提交 | 我已知晓 |
| `submitting` | 已发送请求，等待服务端回执 | 禁用 | 正在记录，请勿重复点击 |
| `acknowledged` | 收到完整服务端回执 | 禁用 | 已记录知晓，显示回执时间和可公开的标识 |
| `retryable_failure` | 网络中断、超时或可重试服务端失败 | 可重试 | 未记录成功，可重试；不宣称已写入 |
| `conflict_or_stale` | 同键异载荷、规则版本变化或风险失效 | 禁用并刷新详情 | 提醒已变化或失效，请刷新后确认 |
| `session_expired` | 会话失效或重新认证需要 | 禁用 | 身份已失效，请重新连接/登录后再试 |

状态转换规则：

1. 页面加载先完成风险详情读取和 capability 探测；任一项失败时不进入 `ready`。
2. 用户仅能从 `ready` 进入 `submitting`；组件必须禁用重复点击。
3. 只有收到包含完整服务端回执的成功响应，才从 `submitting` 进入 `acknowledged`。
4. 网络错误、超时和契约允许的可重试错误进入 `retryable_failure`，保留同一幂等键和最小请求上下文于内存。
5. 规则版本变化、风险失效、授权撤回、会话失效或能力消失必须离开可提交状态，并重新加载服务端视图。
6. 页面卸载、刷新应用、切换成员或切换数据源时清除内存中的待提交上下文；不得通过本地持久化继续提交旧风险。

## 幂等与重试策略

### 幂等键生命周期

- 用户首次点击“我已知晓”时生成一个随机幂等键。
- 在同一风险定位和同一用户动作的可重试失败期间，重试必须复用原键和原始请求载荷。
- 用户主动刷新后，必须重新读取风险定位、版本和 capability；旧请求上下文不得盲目复用。
- 同一风险已经收到服务端回执后，按钮永久保持禁用，刷新后以服务端读取结果为准。
- 不得将幂等键写入分析日志、错误上报正文、浏览器存储或截图中的敏感说明。

### 重试原则

- 仅在网络中断、连接超时或后端明确标记可重试的错误时提供重试。
- 409、风险失效、版本冲突、授权撤回、401/403 和 capability 不可用不自动重试；应刷新或要求重新认证。
- 重试操作必须显示“未确认成功”的真实状态，不能在请求未返回时先把卡片改为“已记录”。
- 对非 JSON、空响应、回执字段缺失或未知错误码，进入保守失败状态并提示稍后重试或联系维护者，不展示技术堆栈。

## Given / When / Then

- 正常：Given 后端正式声明 `risk_acknowledgement` 且当前授权主体可确认当前成员风险，When 用户点击“我已知晓”，Then APP 带幂等键提交正式契约请求，并仅在收到完整服务端回执后显示确认时间和回执标识。
- 正常：Given 同键同载荷的网络重试，When 服务端返回先前回执，Then APP 显示同一回执，不创建第二条审计或第二个确认状态。
- 边界：Given 风险详情页打开后规则版本被服务端重新计算，When 用户提交或刷新，Then APP 不使用旧版本本地确认，显示风险已变化并重新读取详情。
- 边界：Given 风险列表、今日概览和详情页并存，When 任一页面收到成功回执，Then 后续刷新使用服务端状态统一呈现，未刷新页面不得伪造即时成功。
- 失败：Given 网络中断或超时，When 请求未获得回执，Then 页面显示“未记录成功，可重试”，保留结构化内存失败状态和同键重试路径。
- 失败：Given 回执缺少唯一标识、服务端时间、规则版本或其他 HCT-413 规定字段，When 客户端解析响应，Then 视为失败，不显示“已记录知晓”。
- 失败：Given 同键异载荷、风险失效或版本冲突，When 服务端返回受控冲突，Then 禁用操作、刷新当前风险，不进行自动重试。
- 未授权：Given 授权撤回、跨家庭、访问目的不匹配或会话过期，When 用户访问或提交，Then APP 不显示被拒绝资源的额外细节，不写本地确认，并将操作转为受控不可用状态。
- 能力缺失：Given HCT-413 尚未发布或 capability 未声明，When 用户查看风险详情，Then 按钮保持禁用，页面说明“当前家庭服务器无法回写，页面不会标记为已记录”。

## 回滚

- 在后端发生契约、授权、审计或数据一致性风险时，优先关闭 `risk_acknowledgement` capability；客户端自动恢复明确的 fail-closed 禁用态。
- 移动端适配 PR 未合并前关闭 PR 并删除分支；合并后通过新的 GitHub PR 执行 `git revert`，不改写历史。
- 回滚仅停止新回写能力，不删除、篡改或伪造既有服务端风险、回执和最小审计记录。
- 回滚后重新执行 PWA、Android、授权和缓存回归，并将状态更新为 Blocked 或待验收。
