## 用户价值

MOB-153 已把首次提醒、再提醒与通知隐私策略实现完，但只有代码级验证，缺 Android 真机矩阵签收。国内厂商 ROM 的省电与自启限制会让本地通知静默丢失，这在用药提醒场景是安全问题，必须用真机把矩阵跑一遍并签收。

## 范围

- 真机矩阵：前台、后台、锁屏、息屏、应用被划掉、重启后，六种状态下的首次提醒与再提醒到达情况。
- 厂商省电场景：电池优化开启/关闭、后台自启受限、勿扰模式，逐项记录实际行为。
- 锁屏通知隐私：默认不展示药品名与成员姓名，只给最小提示与「打开查看」。
- 签收记录与截图归档，含系统版本、ROM 版本与设置项状态。

## 非目标

- 不改提醒时间窗、再提醒次数与隐私策略（属 MOB-152/MOB-153）。
- 不引入第三方推送服务；只用本地通知。
- 不承诺在所有 ROM 上 100% 到达，但必须记录实际结果与已知限制。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 计划提醒已排定，When 设备处于锁屏或息屏，Then 通知按时到达且内容不含药品名与成员姓名。
2. Given 应用被从任务列表划掉，When 到达提醒时间，Then 记录通知是否到达；未到达须写明 ROM 与设置项。
3. Given 设备重启后未再打开应用，When 到达提醒时间，Then 记录实际行为并给出用户侧补救指引。
4. Given 电池优化限制后台，When 提醒触发，Then 记录实际结果，并在应用内提供「如何允许提醒」的指引入口。
5. Given 矩阵执行完成，When 归档，Then 记录含设备型号、Android/ROM 版本、各设置项状态与逐项截图，由设备持有人签收。

## 安全、隐私与回滚

- 锁屏与通知栏一律不展示药品名、剂量与成员姓名。
- 不为提高到达率申请超出必要范围的权限。
- 真机矩阵不得由 Cloud Agent 代签，需设备持有人执行。
- 回滚：矩阵为证据类交付，回滚只需删除记录；如暴露缺陷按 MOB-153 的回滚方式处理。

## 实现与验证证据

- `ReminderStatusCard.vue` 增加可展开的 Android 通知、后台活动、电池优化、自启动、锁屏通知与勿扰模式指引；文案明确不同 ROM 菜单可能不同，且不会把“已安排”说成“已送达”。`reminderScheduler` 为本地提醒创建显式私有通知通道（`hct_reminder`，锁屏 `PRIVATE`），通知载荷固定为“家健镜提醒 / 请打开应用查看今日安排。”；通道 ID 纳入稳定通知 ID，升级时会取消旧默认通道的待发提醒后再按私有通道重排，避免沿用未知锁屏策略。
- [Android 计划提醒验收矩阵](../../docs/testing/MOB-172-Android计划提醒验收矩阵.md) 固化前台、后台、锁屏、息屏、划掉、重启、电池优化和勿扰模式等 12 项到达用例，以及 2 项锁屏隐私专项；模板要求设备型号、ROM、WebView、权限设置、APK 哈希和脱敏截图哈希。
- `APP/scripts/verify-android-reminder-evidence.mjs` 提供签收门禁：拒绝模板/浏览器/模拟器记录，检查元数据、逐项结果、隐私专项和附件后才允许报告通过；命令为 `npm run verify:android-reminder-evidence`。
- 自动检查：`npm run check`、`npm run test`、`npm run build`、`npm run verify:android-reminder-evidence`（待验收模板按预期拒绝）与 `git diff --check`。

## 未完成证据
