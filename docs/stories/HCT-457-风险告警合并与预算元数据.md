## 用户价值

家人能看懂"为什么提醒只有这几条"：每条告警说明它合并了多少个同类信号、是否因每日预算被暂缓；被暂缓的告警不再无声消失，而是带着原因和"下次可见时间"一并返回。

## 修复的缺口

HCT-303 的去重是"丢掉重复项"、预算是"截断列表"，两者都不产生任何逐条元数据。风险列表只上报聚合的 `non_severe_budget` 与 `suppressed_count`，因此：

- 客户端无法说明某条告警代表几个信号；
- 被预算压掉的告警在响应里完全消失，用户看到的短列表与"确实没有别的事"无法区分；
- 移动端（MOB-156）已经实现并渲染 `merged_count`、`budget_status`、`budget_reason`、`next_visible_at`、`evidence_summary`、`deduplication_key`，但后端从不填充——**演示模式看得见、联机模式永远看不见**。

## 变更

`rules.py`：

- `Alert` 增加审计字段（`deduplication_key`、`merged_count`、`budget_status`、`budget_reason`、`next_visible_at`），规则函数不需要改动，默认为空；
- 新增 `deduplication_key(alert)`：以「规则 + 排序后的证据事件集合」为稳定分组键，证据顺序不影响分组；
- `dedup_alerts()` 保留分组键与被合并条数，并**不修改**入参对象（用 `dataclasses.replace` 产出新实例），同时保持首次出现顺序；
- `apply_daily_budget()` 给返回的告警标注结果：`SEVERE_EXEMPT`（严重豁免）或 `VISIBLE`（在预算内），并附中文原因；
- 新增 `suppressed_by_budget()`：返回被预算压下的非严重告警，标注 `SUPPRESSED`、原因，以及 `next_visible_at`＝**下一个 UTC 零点**（预算按日重置）。

`schemas.py`：`RiskAlertRead` 增加上述 5 个可选字段 + `evidence_summary`；`RiskListResponse` 增加 `suppressed_alerts`。

`routes.py`：风险列表把 `suppressed_by_budget()` 的结果一并序列化；`suppressed_count` 改为等于实际返回的暂缓条数（此前是 `len(deduped) - len(budgeted)` 的算术差，语义相同但现在与返回内容强一致）。`evidence_summary` 只写证据**条数**（"N 条已确认证据事件"），绝不写事件正文。

## 非目标

- 不改变风险等级判定、规则版本或指纹语义；
- 不把健康正文写进任何摘要或日志；
- 不改移动端（呈现已由 MOB-156 实现，等字段即可）。

## Given / When / Then

- Given 同一规则、同一证据集合的多条告警；When 去重；Then 只保留一条并带上分组键与被合并条数，证据顺序不影响分组，入参不被修改。
- Given 非严重告警超出每日预算；When 读取风险列表；Then 被压下的告警出现在 `suppressed_alerts`，带 `SUPPRESSED`、原因与下一个 UTC 零点。
- Given 严重告警；When 预算为 0；Then 仍然返回且标为 `SEVERE_EXEMPT`，绝不出现在 `suppressed_alerts`。
- Given 可见告警；When 读取；Then `next_visible_at` 为 `null`（已经可见，无需等待）。
- Given 没有任何告警；When 读取；Then `alerts` 与 `suppressed_alerts` 均为空数组、`suppressed_count` 为 0，而不是缺字段。
- Given 任意告警；When 读取；Then `evidence_summary` 只含证据条数，不含事件正文。
