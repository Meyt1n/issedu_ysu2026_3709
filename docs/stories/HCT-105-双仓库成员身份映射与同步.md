## 用户价值

成员通过自己的 GitHub PR 交付后，内部仓库按对应成员的云端 Token 记录同步身份，同时保持 GitHub 与内部仓库的提交 SHA 完全一致，不再把所有同步都记到维护者账号。

## 范围与非目标

范围包括合并 PR 作者识别、PR 提交账号核对、成员 Token 显式映射、逐个合并提交快进同步、
第一父链规划、每次 push 的新增可达提交边界、直接维护提交的最小白名单、错误提示和离线单元测试。
一个 PR 必须归属一个成员；作者未映射、提交身份冲突、Secret 缺失、内部 SHA 不在 GitHub 第一父链，
或 push 会引入该 PR 之外的提交时停止同步，不回退到其他成员 Token。直接 master 提交只有在先查不到唯一已合并 master PR 时才允许进入例外；它必须来自已登记成员、
GitHub author 与 committer 完全一致、明确普通单父拓扑，文件状态只能是 `added/modified` 且无 `previous_filename`，仅 `doc/` 或 `docs/` 文档变更且不删除文件；源代码、
配置、工作流和未知身份的直接提交仍必须阻断。

非目标包括改写 PR24/PR28 等既有统计、改写 Git author、把一个混合作者 PR 拆成多个 Token push，以及在仓库或日志中保存 Token 明文。

- Given 一父提交先查不到唯一已合并 master PR，且直接维护提交来自已登记成员，GitHub `author.login` 与 `committer.login` 一致、`parents` 为单父、文件状态只有 `added/modified` 且所有文件均在 `doc/` 或 `docs/`；When 同步预检；Then 按该成员 Token 快进同步，不关联或伪造 PR。
- Given 单父提交能够关联唯一已合并 master PR；When 同步预检；Then 必须走 PR 作者、PR 全部提交账号和 boundary 校验，不得进入直接维护例外。
- Given 直接提交的 GitHub author 与 committer 不一致、身份未登记、parents 缺失/非单父、文件状态未知/删除、携带 `previous_filename`、包含源代码/配置/工作流，或路径不在文档目录；When 同步预检；Then 在任何 push 前失败并说明原因。
- Given PR 作者未映射、提交账号混合或对应 Secret 缺失；When 同步预检；Then 工作流在任何 push 前失败并说明需要增加映射、拆分 PR 或更正提交身份。
- Given 内部仓库落后多个 PR；When 任一同步任务运行；Then 按 GitHub `master` 第一父链顺序逐个使用对应 Token 快进，最终两端 SHA 一致。
- Given 两端从共同基线分别提交了内容相同但 SHA 不同的文件；When 已评审的 GitHub PR 把内部
  `master` 只纳入非第一父祖先链；Then 自动同步停止并要求人工核对，不能把整段祖先路径记到
  对齐 PR 作者 Token。
- Given 某个同步目标关联 PR A；When 计算上一内部 SHA 到该目标的全部新增可达提交；Then 除
  PR A 提交和该目标 merge commit 外不得存在其他提交，否则在任何 push 前失败。

## 部署与回滚

部署只修改 GitHub Actions 与身份映射，不修改应用运行时。同步归属异常时先禁用 workflow，
保留两端 Git 历史并以前向 PR 修复；禁止为修复统计而重写或强推共享 `master`。新增成员时必须
先增加独立 Repository Secret、身份别名和单元测试。

本修复把三个同步工作流固定到触发 SHA、关闭标签抓取，并以 64 提交的受控窗口覆盖当前同步差距；
超出窗口时现有祖先/边界校验会安全停止，不会跳过历史。Runner Git 传输固定为单请求 HTTP/1.1，
减少专用 Runner 的 TLS/并发连接不稳定。一次性历史工作流
继续按逐提交身份计划处理混合 PR：每个动作只读取映射后的 Secret 名称与用户名，使用精确 SHA 校验、
备份标签和 `--force-with-lease` 暂存，不输出 Token 值，不改写 GitHub 历史。

最终两端 SHA 相等和工作流重新停用的证据必须在本修复 PR 合并后补录。在此之前 HCT-105 保持进行中。

PR #510 首次将检出从全部 refs 收敛为目标 SHA，但 2048 深度仍在专用 Runner 形成大历史包，
