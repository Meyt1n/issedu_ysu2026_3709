## 用户价值

成员通过自己的 GitHub PR 交付后，内部仓库按对应成员的云端 Token 记录同步身份，同时保持 GitHub 与内部仓库的提交 SHA 完全一致，不再把所有同步都记到维护者账号。

## 范围与非目标

范围包括合并 PR 作者识别、PR 提交账号核对、成员 Token 显式映射、逐个合并提交快进同步、错误提示和离线单元测试。一个 PR 必须归属一个成员；作者未映射、提交身份冲突或 Secret 缺失时停止同步，不回退到其他成员 Token。

非目标包括改写 PR24/PR28 等既有统计、改写 Git author、把一个混合作者 PR 拆成多个 Token push，以及在仓库或日志中保存 Token 明文。

- Given PR 作者为 `ry12-20`、`389883656-lgtm` 或 `jin-123-zip` 且 PR 内提交身份符合登记信息；When 合并进入 GitHub `master`；Then 分别使用其独立 Token 将合并 SHA 快进推送到内部 `ry12-20`、`yanghuan` 或 `jin-123-zip` 账号。
- Given PR 作者为 `Meyt1n` 且提交身份一致；When 合并；Then 只使用 `Meyt1n` 对应的 `CLOUD_REPO_USERNAME`/`CLOUD_REPO_PASSWORD`。
- Given PR 作者未映射、提交账号混合或对应 Secret 缺失；When 同步预检；Then 工作流在任何 push 前失败并说明需要增加映射、拆分 PR 或更正提交身份。
- Given 内部仓库落后多个 PR；When 任一同步任务运行；Then 按 GitHub `master` 第一父链顺序逐个使用对应 Token 快进，最终两端 SHA 一致。

## 部署与回滚

部署只修改 GitHub Actions 与身份映射，不修改应用运行时。回滚对应 PR 即恢复旧同步方式；禁止为修复统计而重写或强推共享 `master`。新增成员时必须先增加独立 Repository Secret、身份别名和单元测试。
