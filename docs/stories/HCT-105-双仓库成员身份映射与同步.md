## 历史目的

本 Story 曾用于实现“GitHub 合并后按 PR 作者 Token 将同一提交同步到内部仓库，并保留成员统计归属”。对应的 workflow、身份映射脚本和同步测试曾经在 GitHub 中运行过，并留下了 `sync-test/` 历史记录。

## 现行结论

该方案不再属于 HomeCare Twin 的当前开发、Review、CI 或发布流程：

- GitHub `master` 与内部仓库不再自动同步，也不再要求 SHA 一致；
- GitHub 不再读取或维护内部仓库 Token、用户名和成员身份映射；
- 旧实现文件已从当前树删除，但仍可从 Git 历史审计；
- 内部仓库只按解耦说明执行一次性回退，之后作为独立仓库使用。

## 历史范围与非目标

历史范围包括 PR 作者识别、提交账号核对、Token 映射、快进同步、错误提示和离线单元测试。以下内容从未被本次解耦重新实现：改写 Git author、重写既有统计、混合作者 PR 拆分或在仓库中保存 Token 明文。

## 当前验收替代项

本 Story 不再创建新的实现 PR，也不再以两端 SHA 一致作为验收条件。当前治理验收改为确认：

1. 自动同步 workflow、身份映射脚本和对应活动测试不在默认分支；
2. 开发前必读文档、生命周期流程和 README 均指向独立 clone 规则；
3. 内部回退使用精确旧 SHA、恢复标签和 `--force-with-lease` 保护；
4. GitHub Actions 中的 `CLOUD_*` Secrets 在合并后按解耦说明删除。

## 恢复边界

如果未来要重新关联两个仓库，必须建立新的架构决策并重新评审安全、凭据、贡献统计、分叉处理、回滚和隐私风险；不得直接恢复历史 workflow 或脚本。
