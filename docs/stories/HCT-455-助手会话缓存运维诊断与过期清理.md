# HCT-455 助手会话缓存运维诊断与过期清理

- Issue：[#468](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/468)
- 关联需求：NFR-01、NFR-02、NFR-06
- 负责角色：后端组
- 风险：R2
- 状态：实现中（待 PR、CI 和维护者复核）

## 用户故事

作为本地助手后端维护者，我希望能够查看指定会话缓存的匿名运行状态，这样在排查缓存未命中、授权范围切换和内存回收问题时，不需要读取用户问题、家庭成员标识或健康内容。

## 验收标准

- [x] 新增 `GET /api/v1/assistant/session-cache/ops`，只返回当前操作者和 opaque 会话的统计信息。
- [x] 统计包含有效条目数、作用域数量、按代理聚合的条目数、最短/最长剩余 TTL 和过期清理数量。
- [x] 诊断响应不包含原始问题、家庭/成员 ID、缓存键或缓存 payload；同名会话的其他 actor 不可见。
- [x] 读取诊断时清理当前 actor/会话范围的过期条目，避免过期数据长期占用进程内存。
- [x] 原有缓存命中前授权复核和 `POST /assistant/session-cache/clear` 行为保持不变。

## 实现与证据

1. 在检索缓存模块增加 actor/session 级匿名快照，按 scope 和代理聚合，不返回任何缓存内容。
2. 增加会话缓存运维路由，并将当前配置 TTL 与统计一起返回，便于后端排查运行状态。
3. 增加接口测试，覆盖 actor 隔离、过期清理、代理统计、TTL 和隐私字段约束。

## 回滚

回滚应用代码即可移除诊断路由和快照函数；不涉及数据库迁移，不影响既有本地助手调用和授权校验。
