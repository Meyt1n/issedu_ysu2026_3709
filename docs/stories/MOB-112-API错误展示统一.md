## FR/NFR 与用户价值

- NFR-01：错误展示不暴露跨家庭、撤权或资源存在性细节；
- NFR-04：网络失败、服务不可用和冲突状态提供可恢复入口；
- NFR-07：错误状态同时提供文字、图标和明确操作，不只依赖颜色。

当家庭服务器不可达、身份失效、权限变化或请求数据过期时，移动端用户能理解发生了什么、下一步如何处理，而不是看到原始后端详情、空数据或伪造成功。

## 范围

- 兼容 FastAPI 当前 `detail` 和目标 `error.code/message` 两种错误信封；
- 统一映射 401、403、404、409、422、429 和网络失败；
- 提供统一错误组件，支持重试或跳转“我的”检查身份/访问设置；
- 演示模式的本地业务校验提示继续保留，不被 API 文案覆盖。

## 非目标

- 不实现正式鉴权、服务端错误契约或新的后端接口；
- 不缓存、上传或记录健康数据，不改变错误请求的重试/幂等语义；
- 不把移动端联机适配层宣称为生产认证已完成。

## Given / When / Then

- Given 服务不可达；When 联机页面加载或测试连接失败；Then 显示可恢复提示并提供重试。
- Given API 返回 401/403；When 页面请求失败；Then 显示身份失效或权限不足的引导，不展示后端原始详情。
- Given API 返回 404；When 请求资源、授权或尚未提供的能力；Then 使用不泄露资源存在性的文案并允许刷新。
- Given API 返回 409/422/429；When 写操作或读取操作失败；Then 分别提示数据过期、输入校验或频率限制，并提供可执行下一步。
- Given 演示模式本地校验失败；When 用户跳过任务但未填写原因；Then 保留明确的本地业务提示。
