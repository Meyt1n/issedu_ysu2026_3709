## 用户价值

网页端已补了「成员前台正确进入指引」（HCT-456），移动端「我的」页仍缺一份把「填服务器地址 → 选家庭 → 测连接」讲清楚的三步清单。现在用户连不上时只能看到零散错误，不知道下一步该做什么。

## 范围

- 「我的」页新增联机三步清单：服务器地址、家庭选择、连接自检，每步显示当前状态与下一步动作。
- 每步失败时给出具体原因与修复动作，而不是通用「网络错误」。
- 与 MOB-140 的地址安全校验、MOB-158 的家庭选择状态联动，不重复实现判定。
- 长辈模式与 TalkBack 下清单的朗读顺序与聚焦顺序。

## 非目标

- 不改地址校验规则（属 MOB-140）与家庭选择规则（属 MOB-158）。
- 不在移动端提供管理后台入口或管理员登录方式。
- 不做自动发现家庭服务器或扫码配网。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 全新安装未配置，When 打开「我的」，Then 三步清单全部为未完成态，并高亮第一步应做什么。
2. Given 地址填写不合法或被安全策略拒绝，When 保存，Then 第一步显示具体原因与允许的地址形式，不进入后续步骤。
3. Given 身份可访问多个家庭且未选择，When 查看清单，Then 第二步提示需显式选择，且不发起任何成员/事件请求。
4. Given 三步全部完成，When 查看清单，Then 显示当前数据来源与能力快照摘要，并提供重新自检入口。
5. Given TalkBack 与特大字号，When 浏览清单，Then 每步的标题、状态与下一步动作可被依次朗读且不截断。

## 安全、隐私与回滚

- 清单只呈现状态与指引，不改变任何授权判定。
- 错误文案不得透露其它家庭是否存在或服务端内部细节。
- 回滚：隐藏三步清单区块，「我的」页其余功能不变。

## 实现与验证证据

- 新增 `APP/src/utils/onboardingSteps.ts`（纯函数，无副作用）：`buildOnboardingChecklist()` 只读已有会话状态与探测结果，推导「填服务器地址 → 选家庭 → 测连接」三步的 `status` / `detail` / `nextAction`，**不发请求、不改任何授权判定**。
- 验收 1：全新未配置时三步均非 `done`，且**同一时刻只有一步是 `current`**（`buildOnboardingChecklist()` 里把非高亮步骤降回 `todo`），第一步给出「该做什么」与允许的地址形式。
- 验收 2：地址校验失败时第一步为 `blocked`，`detail` 直接带上 `validateServerBaseUrl()` 的具体原因 + `SERVER_ADDRESS_HINT` 的允许形式，第二、三步保持 `todo`，不进入后续步骤。
- 验收 3：可访问多个家庭且未选择时第二步为 `current`，文案写明「需要显式选择」且「在选择之前不会发起任何成员或事件请求」。该 fail-closed 行为本身由 MOB-158 的 `resolveHouseholdId()` 与 provider 层保证，本 Story 只把它讲清楚，没有改判定逻辑。
- 验收 4：三步齐全时 `complete` 为真并给出摘要「当前数据来源：家庭服务器（联机）/ 本机演示数据 · 能力快照：N 项可用」；清单区块底部提供「重新自检」按钮，复用既有 `testConnection()`，自检中禁用并带 `aria-busy`。
- 能力探测未完成（`capabilityAvailableCount === null`）时，第三步与摘要都写「能力探测未完成 / 未探测到的能力一律按不可用处理」，不谎称能力可用。
- 验收 5：清单用 `<ol>` 承载，每步的朗读顺序固定为 标题 → 状态（`stepStatusLabel()` 给出中文状态）→ 说明 → 下一步；序号圆点标 `aria-hidden`，文本用 `overflow-wrap: anywhere` 保证特大字号下不截断。
- 安全边界：清单文案只根据「当前身份可访问的家庭数量」措辞，不列举也不暗示未授权家庭是否存在；失败原因取 `presentApiError()` 已脱敏的 `message`，不透出服务端内部细节。
- `cd APP && npx vue-tsc --noEmit` 通过；`npx vitest run` 通过（36 个测试文件、332 项，其中 `src/utils/onboardingSteps.test.ts` 9 项新增）；`npx vite build` 通过；`node scripts/privacy-scan.mjs` 通过；`git diff --check` 通过。

## 范围说明

- 允许修改范围里没有列 `APP/src/utils/`。本 Story 把清单推导放进 `onboardingSteps.ts` 而不是写在 `MeView.vue` 里，是为了让六条验收里的状态机可被单测覆盖（`MeView.vue` 有 1100+ 行且仓库内没有组件测试）。该文件是纯函数、无副作用、不引入新依赖；若维护者要求，可整体内联回 `MeView.vue`，代价是失去这 9 项自动回归。
- `APP/src/api/errors.ts` 未改动：现有 `presentApiError()` 文案已满足验收 2/3 的需要。
