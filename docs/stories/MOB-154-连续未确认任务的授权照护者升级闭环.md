## 用户价值

作为已获授权的照护者，我希望在服务端确认连续任务未确认并生成升级审计事件后，在移动端看到不泄露身份和健康正文的升级状态、原因、时间和下一步，以便按授权范围处理；没有有效授权、授权到期或撤回时，应用应明确说明不可用且不尝试本地升级。

## 范围与安全边界

- APP 只消费成员授权时间线中的 `care_escalated`、`care_level_escalated` 和 `caregiver_notified` 事件。
- 连续未确认条件、授权有效性、通知目标和事件幂等由服务端判定并审计；APP 不根据本地时间、缓存或联系人推断升级。
- 仅展示授权照护者的脱敏目标、服务端原因/时间、通知状态、服务端回执 ID 和安全下一步，不展示 `recipient_actor_id`、`authorization_id` 或健康正文。
- 服务端没有返回有效通知目标时展示“未发送升级通知”，保留联系家人和 120 求助路径；不做诊断、急症判断或自动拨号。

## Given / When / Then

- Given 时间线返回服务端 `care_escalated` 且通知授权有效，When 存在 `caregiver_notified` 回执，Then 今日任务显示授权照护者目标、服务端原因/时间、`QUEUED`/`VIEWED`/`PROCESSED`/`FAILED` 状态和审计回执。
- Given 时间线没有升级事件，When 任务尚未确认或本地时间已过期，Then 移动端不生成升级对象、不发送通知、不猜测联系人。
- Given 服务端升级事件标记无有效照护授权，When 页面刷新，Then 显示未发送原因和求助路径，不尝试升级。
- Given 同一时间线重复刷新或服务端返回同一事件，When 任务和历史重新推导，Then 事件 ID 和服务端状态稳定，不产生本地重复升级。
- Given 升级事件之后出现新的计划动作，When 页面刷新，Then 旧升级不覆盖服务端最新计划状态，但历史仍保留升级审计事件。

## 实现与验收证据

- `APP/src/data/httpProvider.ts`：从服务端时间线推导升级对象和脱敏历史；仅按服务端事件关联 `plan_event_id` 与通知回执。
- `APP/src/data/types.ts` / `APP/src/data/labels.ts`：定义升级状态、目标和可理解的状态文案。
- `APP/src/components/TaskCard.vue` / `APP/src/views/TodayView.vue`：升级任务进入需关注列表，隐藏联系人标识，提供联系家人/120 入口，不提供确认/延期/跳过按钮。
- `APP/src/data/httpProvider.test.ts`：覆盖无授权、有效授权排队回执、通知敏感标识脱敏、旧升级被后续动作覆盖和历史回执。
- 自动检查：`npm run check`、`npx vitest run src/data/httpProvider.test.ts`。
- 人工验收：服务端有效授权/到期/撤回、刷新幂等、会话切换、后台恢复、Android 真机和 PWA；服务端需提供对应审计事件和实际部署证据。

## 风险与回滚

- 风险：通知状态扩展或服务端字段缺失时不能被客户端猜测；未知状态保留为“服务端返回未知状态”，并保留求助路径。
- 风险：撤权后时间线必须由服务端立即收敛；客户端不缓存联系人或授权 ID，不把旧缓存当作当前通知目标。
- 回滚：移除升级对象解析和卡片展示，保留原有计划事件/确认历史；不回退服务端授权和审计策略。
