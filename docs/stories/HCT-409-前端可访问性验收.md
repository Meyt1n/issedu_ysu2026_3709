## 用户价值

让键盘用户、读屏用户和小屏用户能够无障碍地完成正式 Vue 前端（`src/web`）的核心操作路径，并把可访问性检查固化为可重复的自动化门槛，防止后续改动回退。

## 范围与非目标

本 Story 覆盖：

1. 对正式 Vue 前端的可访问性审计与修复（焦点指示器对比度、语言标注、表单提示关联、状态可理解性、移动端布局溢出、页脚对比度）。
2. 新增 `tests/browser/hct409-accessibility.spec.ts`：axe-core WCAG 2.1 AA 自动扫描（初始页、加载后、错误态、移动视口）、键盘路径、焦点可见性、表单错误播报、375px 无横向溢出和读屏地标结构，全部使用合成数据。

本 Story 不覆盖：性能压测、API 安全、越权/撤权、秘密扫描、依赖审计、医疗边界红队（HCT-409 其余部分，由测试/后端条线完成）；不修改 React 演示页（`src/web/react`，教学演示定位）；不接入真实健康数据。

## Given / When / Then

- Given 键盘用户打开页面；When 依次 Tab 并回车；Then 能聚焦身份、用途码和加载按钮并触发加载，焦点指示器可见且对比度达标。
- Given 读屏用户浏览页面；When 读取地标与语言；Then 只有一个 main 地标、一个 h1，英文区域与中文区域分别带正确 lang 标注，表单提示作为描述而非名称朗读。
- Given 用户提交无效输入或 API 不可用；When 错误出现；Then 错误通过 `role="alert"` 播报，`aria-invalid` 反映字段有效性，不丢失已确认数据。
- Given 小屏用户（375px）；When 加载完整 owner 视图；Then 页面无横向滚动，axe WCAG 2.1 AA 扫描零违规。

## 测试与证据

- `npm run check:web`：TypeScript 类型检查通过。
- `npm run test:web`：19 个单元测试通过（含新增 `qualityStateLabel` 用例）。
- `npm run build:web`：Vite 生产构建通过。
- `npm run test:e2e:web`：14 个 Playwright 用例通过（3 个原有 HCT-405 用例 + 11 个新增 HCT-409 可访问性用例），axe 扫描四种页面状态零违规。
- 新增 devDependency：`@axe-core/playwright`；本地另需 `npx playwright install ffmpeg`（录像依赖，Windows 环境首次运行）。
