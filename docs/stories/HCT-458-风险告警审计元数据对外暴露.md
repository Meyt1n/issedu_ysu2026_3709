- 负责人：维护者指定
- 复核人：维护者 merge 即完成复核

## 用户价值

照护者和成员在网页/手机上看到风险提醒时，能明白「这条是不是和刚才那条重复」「今天还剩几次提醒额度」「为什么暂时不弹了」，而不需要看原始健康事件正文。

## 范围

- 扩展风险告警 Schema 与助手 `get_risk_alerts`，返回 `deduplication_key`、`merged_count`、`budget_status`、`budget_reason`、`next_visible_at`、`evidence_summary`。
- 去重阶段累计同规则/来源事件的合并数量，生成不含健康正文的稳定分组键。
- 预算阶段区分严重/预算内 `VISIBLE` 与超额 `DEFERRED`；`suppressed_count` 继续准确统计。
- 风险详情和确认路径共用相同服务器元数据；证据摘要只返回来源事件数量。

## 非目标

- 不改变预算规则本身；不在本 Story 追加新告警类型。
- 不向客户端返回可识别个人的健康正文。

## 验收（Given / When / Then）

1. Given 合并后的告警，When `GET` 风险列表，Then 含 `deduplication_key` 与 `merged_count` 且不含正文。
2. Given 预算超额，When 查询，Then `budget_status`/`next_visible_at` 可解释暂缓原因。
3. Given MOB-156 连接真实后端，When 展示告警，Then 缺失字段时安全降级。
