# HCT-497：视觉质量检查记录与来源绑定

- Issue：[ #591 ](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/591)
- 关联：HCT-202（父 Issue [#49](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/49)）
- 绑定：FR-03、NFR-03、NFR-04、NFR-06
- 角色：后端组员
- 状态：实现完成，待 PR/CI 与维护者人工验收
- 风险：R2；只记录质量门控的可追溯元数据，不改变门控阈值、识别结果或健康事件结论

## 目标

为每次图片或视频质量检查建立一条可追溯记录，使调试和验收能够回答“谁在什么版本、针对哪个输入摘要得到什么质量结论”，同时不把家庭媒体留在业务数据库中。质量凭证仍只在请求链路中使用，记录接口不会返回凭证明文。

## 实现范围

- `POST /api/v1/vision-quality/check` 在 PASS 和 RETAKE 两种结果下写入 `VisionQualityRecord`，并返回不透明的 `quality_record_id`。
- 记录保存 actor、上传字节 SHA-256、媒体类型、schema/config 版本、判定、下游放行标志、指标、阈值、原因、补拍建议和视频抽帧的非像素摘要；凭证只保存 SHA-256 摘要，不保存凭证明文。
- `GET /api/v1/vision-quality/records/{record_id}` 仅允许创建该记录的 actor 读取；不存在或越权统一返回 `VISION_QUALITY_RECORD_NOT_FOUND`。
- `0025_hct497_vision_quality_records.py` 为 SQLite/MySQL 创建可回滚迁移；网页端类型同步新增可选记录 ID，但不向家庭成员展示内部记录详情。

## 验收条件（Given / When / Then）

- Given 一次合法图片或视频上传，When 质量检查完成，Then PASS/RETAKE 均生成记录 ID，记录中的输入摘要与响应一致。
- Given 创建者携带记录 ID查询，When 请求记录详情，Then 返回版本、判定和结构化质量证据，但不返回原媒体、路径、OCR 文本或 `quality_receipt`。
- Given 其他 actor 携带同一记录 ID查询，When 服务端鉴权，Then 返回 404，不能据此探测记录是否存在。
- Given 数据库迁移已执行，When 回滚迁移，Then 质量记录表及索引可完整删除，不影响既有视觉任务表。

## 非目标与回滚

本切片不声称 HCT-202 的正式固定质量集、真实视频编解码性能或部署 P95 已完成，也不修改 OpenCV 阈值、抽帧算法、OCR/YOLO、候选融合和人工复核流程。回滚时先停止使用记录 ID，再执行 Alembic downgrade 删除新表；质量检查和既有质量凭证仍可独立工作。
