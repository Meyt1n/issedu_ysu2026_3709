# HCT-482：知识库爬虫失败原因友好提示

- Issue：[ #560 ](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/560)
- 绑定：FR-08、NFR-02、NFR-04
- 角色：后端组员
- 状态：实现完成，待 PR/CI 与维护者人工验收
- 风险：R1；远程抓取仍受白名单、HTTPS、人工审核和不自动入库门禁约束

## 目标

让知识库爬虫的 API、CLI 和知识页能够区分权限、配置、来源拒绝、超时和暂时不可用等
失败原因。调用方不再看到原始 urllib 异常、URL 或服务器路径，也不会因失败被误认为“暂无
staging 草稿”。

## 实现范围

- `knowledge_crawl.friendly_crawl_error` 将每个来源异常归一为稳定的 `error`/`code`、
  人话 `message`、`retryable` 和下一步 `action` 字段，并保留旧的 `error` 字段兼容现有摘要。
- 403、429、5xx、超时、网络不可达、页面过大、夹具缺失、域名不在白名单等情况分别映射，
  严禁把远程 URL、文件路径和底层异常文本返回给用户。
- 白名单文件缺失与格式损坏分别返回 503 `KNOWLEDGE_CRAWL_CONFIG_MISSING` /
  `KNOWLEDGE_CRAWL_CONFIG_INVALID`；steward 权限校验仍优先执行并返回 403
  `KNOWLEDGE_STEWARD_REQUIRED`。
- 补充爬虫 README、排障说明和单元/接口测试；不放开 `auto_ingest`，不扩大爬虫权限。

## 验收条件（Given / When / Then）

- Given 来源返回 403、429、5xx 或超时，When 执行抓取，Then 报告包含稳定错误码、人话说明、
  可重试标记和处理建议，不包含原始 URL 或内部异常详情。
- Given 页面过大、夹具缺失或域名未在白名单，When 执行抓取，Then 报告准确说明配置/来源问题，
  且不写入新的 staging 草稿。
- Given API 运行目录缺少白名单或白名单 JSON 格式错误，When 访问状态/运行端点，Then 返回
  503 和对应配置错误码，不返回裸 500。
- Given 非 steward 访问任意爬虫端点，When 请求到达 API，Then 仍优先返回 403
  `KNOWLEDGE_STEWARD_REQUIRED`，不泄露配置状态。

## 非目标与回滚

不引入新的网络出口、不自动抓取或自动入库，不保存真实健康数据。回滚时恢复原有异常收集
逻辑和配置错误处理即可，权限、人工审核和 staging 状态机不变。
