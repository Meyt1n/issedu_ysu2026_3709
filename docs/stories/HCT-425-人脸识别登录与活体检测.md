# HCT-425 人脸识别登录与活体检测

- Issue: [#281](https://github.com/Meyt1n/issedu_ysu2026_3709/issues/281)
- 范围：桌面 Web 和本地 API，不包含移动端。
- 前置 Story：HCT-424 家庭账号人脸注册与绑定。

## 用户故事

作为家庭成员，我希望在已绑定的家庭范围内使用浏览器摄像头完成短时活体验证，系统自动判断我是爷爷、奶奶还是其他家庭成员，并进入对应的小账号；摄像头被拒绝、画面质量不足、无法确定成员或验证失败时，我可以回退到六位 PIN/账号登录。

## 验收标准

1. 服务端签发一次性、短时 challenge，并在 challenge、家庭和账号不匹配、过期或重放时拒绝登录。
2. 登录接口接收 2～3 个 multipart 图片帧，在服务端完成单人脸检测、活体运动序列检查和加密模板匹配；前端不比较向量、不决定身份。
3. 成功响应复用密码/PIN 登录的 Bearer session 契约，并返回服务端确认的 actor 与 household 范围。
4. 凭证不存在、已撤销、跨家庭、低质量、多人脸、活体失败、匹配失败或服务不可用时不创建 session，且错误不暴露候选账号、家庭或相似度。
5. 人脸失败使用独立限流；连续失败返回 429。原始图片、视频、模板和相似度不得写入响应、日志、浏览器持久化或健康事实。
6. 桌面欢迎页提供摄像头权限提示、采集状态和 PIN 回退；组件结束或卸载时停止摄像头轨道。
7. 已登录的家庭管理员进入“人脸凭证”页面时，注册流程同样使用三帧动态摄像头采集；页面不再把静态图片上传作为新凭证入口。
8. 设备可以绑定一个家庭作为人脸识别范围；家庭人脸登录只在该家庭的有效凭证中进行 1:N 匹配，不跨家庭搜索，也不把候选账号返回给前端。
9. 服务端要求序列中每一帧都独立命中候选成员模板（按全帧最低相似度聚合），再选择唯一最佳匹配；最佳分数低于阈值，或最佳与第二名的分差小于安全间隔时，统一返回 `FACE_AUTH_FAILED`，由前端引导用户改用 PIN/账号登录。在动作序列中混入单张本人照片、其余帧属于他人时不得登录。

## API

- `POST /api/v1/auth/face-challenge`：JSON `{ household_id, actor_id }`，返回 opaque `challenge_id` 和过期时间。
- `POST /api/v1/auth/face-login`：multipart `household_id`、`actor_id`、`challenge_id` 和重复的 `frames` 字段。
- `POST /api/v1/auth/family-face-challenge`：JSON `{ household_id }`，为已绑定家庭的人脸 1:N 识别签发一次性 challenge。
- `POST /api/v1/auth/family-face-login`：multipart `household_id`、`challenge_id` 和重复的 `frames` 字段；服务端返回识别出的 `actor_id` 与家庭范围 session。

## 非目标

- 不实现移动端 UI、持续摄像头监控、健康风险规则或原始生物照片存储。
- 不支持跨家庭的全局人脸搜索；本机只保存当前家庭的 opaque household id，不保存人脸图片或人脸模板。
- 当前实现使用本地 OpenCV YuNet 检测 + SFace（`opencv-yunet-sface-v3`）128 维嵌入做家庭内 1:N 成员区分；活体仍是版本化的本地启发式校验（`motion-sequence-v2`），不宣称具备生产级反欺诈能力。旧 v1/v2 灰度模板凭证仍可兼容登录，重新绑定后升级为 v3 嵌入。SFace ONNX 权重不入库，默认缓存在 `models/face/`，首次使用可按配置从 OpenCV Zoo 拉取。

## 回滚与验证

删除 family-face challenge/login 路由、设备家庭绑定 UI 及对应契约测试即可回滚；原有 1:1 face challenge/login、HCT-424 的注册和撤销接口保持不变。验证覆盖 challenge 重放/过期、家庭内最佳匹配、模糊匹配拒绝、跨家庭、撤销凭证、活体失败、限流、Bearer session 和桌面 API 契约。

2026-08-25 安全加固：登录匹配聚合从“最佳帧”改为“全帧最低分”，阻止在动作序列中注入单张本人照片冒用登录；活体校验升级为 `motion-sequence-v2`（拒绝 `[静帧, 静帧, 动帧]` 类部分重放和拼接序列）；人脸失败限流迁移到共享持久化表 `auth_rate_limit_attempt`，与密码/PIN 一致且重启不清零；challenge 逐出改为按家庭隔离，洪泛一个家庭无法逐出其它家庭的有效 challenge；迁移 `0021_hct425_face_credential_mysql_index` 修复 MySQL 上局部唯一索引退化导致的第二次换绑/删除传播 IntegrityError。前端 `FaceVideoCapture.vue` 逐帧引导轻微转头（与活体要求一致），删除未被引用且分辨率不满足质量门槛的 `FaceLoginCapture.vue`。

2026-08-25 识别模型升级：注册/匹配默认算法升级为 `opencv-yunet-sface-v3`（YuNet 检测 + SFace 嵌入，余弦阈值 0.40，家庭 1:N 使用相对阈值的 ranking margin 比较，避免 v2/v3 混用时原始分不可比）；灰度 v1/v2 仅作兼容，重新绑定后使用 v3。公开样例上同人约 0.74、异人约 0.10，显著优于原灰度模板，可支撑家庭成员级区分；仍非生产级生物识别。

2026-08-25 可用性加固：阈值改为环境可配置并提供 `scripts/calibrate_face_thresholds.py`；注册增加人脸占比/姿态/模糊门禁；注册保存 2～3 个多角度嵌入（登录对库 max、对帧 min）；活体升级 `motion-sequence-v3`（转头 yaw 跨度）；`/meta/capabilities` 暴露 `face-recognition-local`；管理员页提示旧 v1/v2 重绑；`/auth-audit/face-summary` 提供脱敏失败原因桶聚合。**真实家庭摄像头阈值标定必须在维护者本机完成**（云端无法代采真人脸），步骤见[本地部署与 Demo 操作指南 §1.3](../本地部署与Demo操作指南.md)。

2026-08-26 双端口家庭绑定修复：前后台拆分后，管理端 5174/5184 与成员端 5173/5183 属于不同浏览器 origin，原先仅保存在 `localStorage` 的本机家庭范围绑定会被端口隔离。用户虽然已在数据库录入人脸、也在管理端绑定家庭，成员端仍读到空值并误报「没有绑定家庭」。`store.ts` 现将同一份非认证秘密绑定（opaque household id + 展示名）同时写入当前 origin 的 `localStorage` 和 `Path=/; SameSite=Lax` 的同主机 cookie；成员端在本端 localStorage 为空时读取 cookie。旧版本绑定在原管理端重新加载后会自动镜像到 cookie，无需重新录入人脸。解绑会同时清理两处。cookie 只用于选定家庭内 1:N 搜索范围，不作为授权凭证；服务端仍校验家庭、有效人脸凭证、活体、阈值和会话，且浏览器中仍不保存图片、视频或模板。能力探测改为三态，探测中不再先显示不可用，断连/模型未就绪时明确提示「绑定和凭证未丢失」并允许重新检查。回归：`store.test.ts` 跨端口读取/旧绑定迁移，`tests/browser/hct425-welcome-face-binding.spec.ts` cookie 回退真实渲染。
