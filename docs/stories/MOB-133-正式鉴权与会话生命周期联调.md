## 用户价值

家人用账号密码登录家庭服务器后，移动端使用真正的服务端会话读取数据；会话过期、被撤销或返回 401 时立即清空本地上下文、提示重新登录并阻断写入，不会把上一段会话的健康数据留在屏幕上。开发期 `X-Actor-Id` 从默认路径降级为必须显式开启的开发配置。

## 移动端要求的 HCT-107 契约

移动端按下列契约实现适配器。所有请求都是 `POST`，凭据只出现在 JSON body 里。

| 端点 | 请求体 | 成功响应 | 移动端行为 |
|---|---|---|---|
| `POST /api/v1/auth/login` | `{ actor_id, password }` | `{ session_token, expires_at, actor_id? }` | 建立内存会话；缺 token 或缺 `expires_at` 视为契约不足并拒绝 |
| `POST /api/v1/auth/session` | `{}` + `Authorization: Bearer …` | `{ expires_at, actor_id? }` | 冷启动/回前台续验；401 表示过期或撤销 |
| `POST /api/v1/auth/logout` | `{ session_token }` | 任意 2xx | 先本地清空再通知服务端；网络失败不恢复本地会话 |
| `POST /api/v1/auth/pin-challenge` | `{ action, method }` + Bearer | `{ challenge_id, action, expires_at }` | **响应中出现 PIN 即判定契约违规并拒绝** |
| `POST /api/v1/auth/pin-verify` | `{ challenge_id, action, method, code }` + Bearer | `{ status: "confirmed", confirmed_at? }` | 一次性；409/410 记为过期或重放 |
| 所有业务端点 | — | — | 必须接受 `Authorization: Bearer <session_token>` 并据此解析 actor |

`expires_at` 允许秒级时间戳、毫秒时间戳或 ISO 字符串，移动端统一归一化为 ISO；无法解析时按"契约不足"处理，绝不当成永不过期。

## 契约缺口（阻塞真实联调）

在 `src/api/app/` 复核当前实现后确认以下缺口。它们都在后端范围内，本 Issue 的允许修改范围不包含 `src/`，因此需要单独的后端 Issue：

1. **业务端点不接受会话凭据。** `src/api/app/security.py` 的 `get_actor_id` 只读 `X-Actor-Id`，且在 `app_env == "production"` 或 `allow_dev_actor_header` 关闭时直接返回 `501 REAL_AUTH_REQUIRED`。`/auth/login` 发的 `session_token` 没有任何端点会校验，正式登录后仍然读不到家庭、成员、时间线和风险。
2. **`/auth/login`、`/auth/logout`、`/auth/pin-verify` 的参数是 query 参数。** `src/api/app/routes.py` 里这些处理函数的 `actor_id`、`password`、`session_token` 是裸 `str` 形参，FastAPI 会解析为 query string，导致密码和会话 token 进入 URL、访问日志与浏览器历史。移动端拒绝以 query 形式发送凭据，因此当前会收到 `422` 并按 `AUTH_UNAVAILABLE` 报告。
3. **`/auth/pin-challenge` 无法绑定登录会话，且回显 PIN。** 该端点自行 `secrets.token_hex(16)` 生成一个与调用者会话无关的 `session_token`，并把 PIN 直接放在响应体里返回。这样的 challenge 既不能绑定真实会话，也让"一次性口令"失去意义；移动端检测到响应含 PIN 会拒绝。
4. **缺少会话续验/撤销查询端点。** 没有 `/auth/session` 之类的接口，移动端无法在冷启动或回前台时确认会话仍然有效，只能等下一次业务请求返回 401。

在 1–3 修好之前，任何"正式鉴权已完成"的结论都不成立。移动端已按契约实现并在缺口处如实报错，不使用固定 actor 或 mock 响应掩盖。

## 会话生命周期设计

状态机（`APP/src/stores/auth.ts`）：

- `anonymous`：未登录或已主动登出；联机页面被路由守卫送到登录页。
- `authenticated`：持有未过期会话；允许读写。
- `reauth-required`：会话过期、被撤销或收到 401；读写全部 fail-closed，等待重新登录。

关键约束：

- **凭据只有一份副本。** `authSessionSlot` 是 store 与 HTTP 适配器共用的槽位，适配器不再自己存 token，杜绝"store 已登出、适配器仍持 token"的分叉。
- **凭据不进响应式状态。** token / sessionId 保存在模块内的普通变量里，页面只能读到 `actorId` 与 `expiresAt`，因此 devtools 快照和任何 `JSON.stringify(auth)` 都不含凭据。
- **不落盘。** `SessionSettings` 写 localStorage 时只包含界面配置；token、密码、PIN 与健康数据都不属于它。
- **过期在发请求前拦截。** `getAuthSession()` 发现会话过期就直接进入 `reauth-required` 并返回 `null`；`ApiClient` 另有一层过期前置检查。
- **清理分两级。** `session` 级（登录、登出、失效）丢弃联机 Provider 实例与能力探测快照；`context` 级（切换服务器、身份来源、访问目的、当前成员）只丢弃 Provider 实例。Provider 实例持有成员/任务缓存、已解析家庭 ID 和上传草稿，丢实例即等于清理这一轮的查询、上传与缓存状态。
- **会话指纹推进。** 每次状态变化 `generation += 1`，并参与 `sessionContextKey`，页面级缓存（如拍药盒的成员加载）也随之失效。

## 幂等与重复提交

网络中断后的重试不会重复创建写操作，这一点由 `HttpDataProvider` 保证且本次未改动语义：

- 计划动作使用 `${action}:${planEventId}` 作为稳定幂等键，回执丢失后重试返回原事件；
- 同一 `File` 的上传在运行时共享同一个 Promise，失败才允许重新上传；
- 视觉任务按 `File + 成员` 保存 `idempotency_key`，创建失败后重试复用同一上传与任务键。

会话失效会丢弃 Provider 实例（连同上述草稿），这是有意的：重新登录后由服务端重新判定授权，不允许跨会话复用旧幂等键。

## 开发态 actor 门禁

`session.authMode` 取 `real`（默认）或 `dev-actor`。`dev-actor` 仅在 `VITE_ALLOW_DEV_ACTOR=true` 或本地 `vite dev` 时可选；正式构建下开发入口不渲染，且 `normalizeSession` 会把已保存的 `dev-actor` 强制回退成 `real` 并清空 `actorId`。`real` 模式下 `ApiClient` 一定拿到会话提供方，未登录时不回退 `X-Actor-Id`。

## Given / When / Then

- Given 用户在登录页输入账号密码；When 家庭服务器认证通过；Then 建立内存会话并按契约在后续请求发送 `Authorization: Bearer`，不再发送 `X-Actor-Id`。
- Given 正式构建未开启开发配置；When 用户打开联机设置；Then 看不到开发期身份入口，已保存的 `dev-actor` 配置被回退成正式登录。
- Given 会话已过期或被撤销；When 任意页面发起请求；Then 请求在发出前被拦下，本地会话与 Provider 缓存被清空，页面提示重新登录，写入入口禁用。
- Given 业务请求返回 401；When 错误经过 Provider 守卫；Then 会话进入 `reauth-required`，能力探测快照被清空，用户被带到登录页，且不显示旧会话数据。
- Given 用户主动退出登录或切换成员；When 操作完成；Then 关联的查询、上传草稿和缓存被丢弃，`localStorage` 中不出现 token、密码、PIN 或健康数据。
- Given 网络中断后重试写操作；When 会话仍然有效；Then 复用既有幂等键，不重复创建任务或事件。
- Given 服务端在 PIN challenge 响应里回显了 PIN；When 移动端解析响应；Then 拒绝该二次确认并按契约不足提示，不显示"确认成功"。
