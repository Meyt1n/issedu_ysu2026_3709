## 用户价值

用药计划版本化存储，医嘱事实不可覆盖，安全时间窗防过早/过晚用药。

## 范围

- 计划版本模型（追加写，变更走补偿事件）
- 医嘱事实存储
- 安全时间窗校验（最小间隔、每日上限、最早/最晚时间）
- 计划确认/变更审计

确认接口读取计划事件中的可选 `safety_window`（或兼容的顶层键）策略：
`min_interval_hours`、`max_daily_doses`、`earliest_time` 和 `latest_time`。
重复请求必须使用同一个 `Idempotency-Key`；同一计划的新确认会重新经过服务端安全窗校验。

本次增量补充家庭成员用药提醒工作台：计划可记录每次用量、每日服用时间、开始日期和疗程结束日期；工作台保留确认、延期、跳过和漏服的动作历史。漏服使用独立的 `plan_missed` 事件，不覆盖原计划或伪装成主动跳过，并可通过“记录漏服”操作留下原因。

## Given / When / Then

- Given 用药计划；When 距上次用药不足最小间隔；Then 拒绝确认，返回 TIME_WINDOW_VIOLATION。
- Given 当日确认次数已达到上限或当前时间不在允许时段；When 确认计划；Then 拒绝确认，返回 TIME_WINDOW_VIOLATION。
- Given 同一确认请求重试且携带同一 Idempotency-Key；When 调用确认接口；Then 返回原事件且不新增事件。
- Given 医嘱变更；When 写入新版本；Then 旧版本保留，新版本通过补偿事件关联。
