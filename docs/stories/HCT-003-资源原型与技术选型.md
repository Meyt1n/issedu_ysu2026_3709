## 用户价值

团队在继续工程骨架、视觉训练和本地助手之前，可以用同一组命令判断设备是否满足基础档或增强档条件，并看到依赖不可用时的明确降级结果，避免把一次偶然运行或本机配置写成项目承诺。

## 范围与非目标

必须完成：

- MySQL 8.4 容器完成连接、Alembic 升级、`utf8mb4`、UTC 时区和数据库健康检查；
- OpenCV 在固定纯合成样例上输出图像尺寸、亮度、对比度、清晰度、样例哈希、CPU 耗时、进程内存和可见 GPU 能力；
- Ollama 在回环地址完成 JSON Schema 结构化调用，并在服务或模型不可用时返回可定位的本地降级结果；
- 用 ADR 固化版本、最低资源档、替代方案、已知风险、复审触发条件和回滚；
- 保存实际设备、命令、成功/失败模式和指标，不提交图片正文、提示词上下文、密钥或模型权重。

明确不做：

- 不训练或发布 YOLO、OCR、Embedding、LoRA 或量化模型；
- 不把合成图像质量探针宣称为药品识别能力；
- 不使用真实药盒、报告、家庭成员或健康数据；
- 不把 Ollama 不可用时的请求转发到云端，也不让 LLM 产生医学判断；
- 不承诺正式视觉/LLM 性能，最终指标仍由后续固定集和模型 Story 验证。

## 输入、输出、状态和异常

- 输入：Compose 数据库配置、固定合成灰度矩阵样例、回环 Ollama 地址和显式模型名；
- 输出：不含凭据与敏感正文的 JSON 报告，以及对应 ADR 和评审记录；
- 状态：`ok` 表示本次探针满足其技术检查，`review` 表示视觉质量需人工处理，`degraded` 表示增强能力不可用但基础档可继续；
- 异常：数据库未迁移、字符集/时区错误或严格模式依赖不可达时退出失败；Ollama 依赖故障默认形成降级证据，使用严格参数时退出失败；非回环 Ollama 地址直接拒绝。

## Given / When / Then

- Given 干净 MySQL 8.4 容器；When 运行 Alembic 到 head 后执行 MySQL 探针；Then 返回连接版本、字符集、排序规则、UTC 时区、表数和当前迁移，且报告不包含用户名或密码。
- Given 仓库固定的纯合成视觉样例；When 执行视觉探针；Then 返回结构化质量指标、SHA-256、OpenCV 版本、CPU 耗时和 RSS 内存，不返回药品身份或健康事实。
- Given 本地 Ollama 服务和显式模型；When 执行结构化探针；Then 输出通过 Schema 校验的固定技术握手、模型名、耗时和 token 计数，不包含健康问题。
- Given Ollama 未启动、模型不存在或响应非法；When 执行非严格探针；Then 返回 `degraded`、明确原因和 `structured_core_only`，且没有云端回退。
- Given 调用方配置公网 Ollama 地址；When 执行探针；Then 在发出网络请求前拒绝该地址。

## 隐私、网络、许可和模型边界

- 固定样例由仓库内数字矩阵生成，不属于药品图片或健康数据；
- MySQL 报告只保留驱动、主机、端口、库名和技术指标，隐藏用户名、密码和查询正文；
- Ollama 仅允许 `localhost`、`127.0.0.1` 或 `::1`，请求是无健康语义的固定握手；
- OpenCV Python wheels 使用 Apache-2.0 OpenCV 与 MIT NumPy 组件，正式制品仍需在发布阶段生成许可证清单；
- 探针不加载 YOLO/OCR 权重，不产生诊断、处方、停药、换药或剂量输出。
