# HCT-439：家庭前台/管理员后台门户分流与药品复核交接

> 2026-08-29 后续决策：HCT-498 / ADR-0008 统一两个门户的主认证方式为正式账号密码；本 Story 的成员/管理员门户分流、owner 真相和服务端授权边界不变。

## Story

作为一个家庭成员，我希望登录后只看到拍照录药、服药提醒和自己的已确认记录；作为家庭管理员，我希望进入后台处理成员、权限、药品复核和风险，这样长辈不需要理解后台术语，药品也不会未经确认直接进入健康档案。

## 范围

- 一个家庭继续使用同一套本地 API 和 Vue 应用，根据登录账号所属范围分为成员前台和家庭管理员后台。
- 家庭管理员由 `Household.created_by` 明确识别；家庭成员由 `Member.actor_id` 绑定识别。角色名称不能替代成员级权限判断。
- 成员前台提供：我的家庭、拍照录药、服药提醒、我的记录。
- 管理员后台保留：家庭总览、成员档案、健康计划、视觉扫描、人工复核、用药安全、健康图谱、本地助手、家庭大屏、授权、知识、人脸凭证。HCT-513 起不再在侧栏提供模型实验室与演示造数。
- 成员照片创建视觉任务后进入待识别/待复核链路；成员不能直接追加健康事件；管理员确认后才生成健康事件，成员前台只展示确认后的记录，并从服务端恢复最近任务状态。
- 管理员确认后的风险会回到成员前台，以“需要留意的情况”摘要展示；成员只能读取自己的风险，不能借此读取家庭其他成员。

## 验收标准

1. 绑定成员账号登录后，自动进入 `member-home`，侧栏只出现四个成员前台入口，后台入口不可见。
2. 管理员登录后自动进入 `overview`，管理员原有后台导航和人工复核入口可用。
3. 成员只能读取自己绑定的成员范围；读取时间线时不返回未确认记录。
4. 成员提交视觉任务只允许绑定到自己的 `member_id`；`POST /households/{id}/events` 仍需要管理员或明确的 `WRITE_EVENTS` 授权。
5. 成员前台不展示教学演示、OCR、模型版本、任务编号等后台技术信息。
6. 后台计划工作台兼容缺少可选展示字段的旧本地 Demo 响应，不因 `times` 或处理历史缺失而停留在加载态。

## 扩展：门户分流补完（一个家庭、两个门户、一个后端权限中心）

在首批合并（PR #387/#391/#392）的基础上，本 Story 扩展补齐以下缺口：

- **成员前台状态文案集中映射**：`src/web/src/ui/memberStatus.ts` 收拢成员可见的任务状态文案，配套 `memberStatus.test.ts` 回归保证 queued/succeeded/CONFLICT/UNKNOWN 等内部状态码永不透出到成员前台。
- **管理员后台五组导航**：`src/web/src/ui/navigation.ts` 固定为「日常照护 / 证据录入 / 安全与洞察 / 权限与凭证 / 家庭与研发」，浏览器断言见 `tests/browser/hct405-visible-workflows.spec.ts`。
- **研发/演示入口（HCT-513 修订）**：管理后台不再展示「模型实验室」「演示造数」；`featureFlags.ts` / `VITE_SHOW_ADVANCED_LAB` 已删除。后端模型绑定与 `scripts/seed_formal_demo_health.py` 补种仍可用。HCT-498 起 Web 登录固定为正式账号密码，不再提供开发身份开关。
- **演示数据环境标识（轻量）**：`src/web/src/ui/demoData.ts` 只认显式标记（名称/创建者 `demo-`、`test-` 前缀或「本地演示」「教学演示」字样）；成员前台家庭选择器默认过滤演示家庭（只剩演示家庭时不清空），管理员选项追加「演示数据」标识。不做数据迁移。
- **安全演示清理脚本**：`scripts/cleanup_demo_data.py` 默认 dry-run，`--apply` 时复用 HCT-405 擦除服务逐家庭传播删除，仅命中显式标记数据，生产环境拒绝执行；集成测试 `tests/integration/test_hct439_cleanup_demo_data.py`。
- **成员帮助页**：`src/web/src/views/MemberHelpView.vue` 提供拍照步骤、隐私说明、紧急提示与退出入口，纳入成员前台导航（`member-help`）。
- **管理员待复核徽章**：`store.ts` 的 `pendingReviewCount` 汇总全家待复核任务数；`App.vue` 在「人工复核」导航项显示数量徽章，并在健康数据刷新时更新。
- **成员状态文案补全**：`memberStatus.ts` 增加 `CONFLICT`/`UNKNOWN`/`REVIEW_REQUIRED` 等映射，符合计划中的前台可读文案表。
- **跨角色边界扩展**：`tests/contract/test_hct439_portal_boundaries.py` 增加成员自有风险/视觉任务读取与他人范围拦截、成员不能直接 POST 已确认事件。
- **前端视图守卫单测**：`store.test.ts` 验证成员/管理员 `setView` 路由守卫。
- **拍照→确认闭环浏览器演示（mock API）**：`tests/browser/hct439-member-portal.spec.ts` 增加成员提交照片 → 待确认（正在识别/等待家人确认）→ 模拟管理员确认 → 前台出现已确认记录的 UI 全链路；该用例为 mock API 的界面证据，真实 OCR/复核后端验收仍由契约测试与 HCT-405 主线负责。

## 回滚

本 Story 不新增数据库迁移。回滚本 Story 的代码提交即可恢复原单一导航和原视觉入口；后端新增的自有成员读取判断不会改变管理员和已有授权照护者的路径。门户补完部分（导航分组、环境开关、演示标识、清理脚本、测试）同样无迁移，revert 对应提交即可完全回滚；`scripts/cleanup_demo_data.py` 是显式手动命令，不回滚也不会自动执行。
