## 用户价值

PR #499 修了安全区与窄屏，但横屏与折叠屏仍未系统走查。折叠屏展开/折叠会触发配置变更与尺寸突变，长辈模式下横屏字号更容易溢出。本 Story 把十页主要界面在横屏与折叠形态下的基础布局与状态保持定下来。

## 范围

- 主要页面在横屏、折叠内屏、折叠外屏三种形态下的布局走查与修复。
- 形态切换时的状态保持：滚动位置、已填表单、上传草稿、当前会话不得丢失。
- 安全区与刘海/挖孔在横屏下的内边距处理。
- 长辈模式与特大字号在横屏下的溢出与截断修复。

## 非目标

- 不做平板专属的双栏/主从布局重设计。
- 不改任何业务逻辑或数据流。
- 不为折叠屏引入厂商专有 SDK。
- 不做诊断/处方/停药/换药/剂量判断；不买药/问诊/广告导流。
- 健康数据默认不出网（联网搜索遵循 ADR-0007 显式 opt-in）。

## 验收（Given / When / Then）

1. Given 任一主要页面，When 旋转到横屏，Then 无内容被裁切、无横向滚动，安全区内边距正确。
2. Given 折叠屏从外屏展开到内屏，When 配置变更发生，Then 滚动位置、表单内容与上传草稿保持，不触发重复请求。
3. Given 正在进行的写操作（如任务确认），When 形态切换，Then 不重复提交，也不丢失已提交结果。
4. Given 长辈模式与特大字号在横屏，When 浏览，Then 文字不重叠不截断，触控区不小于既有标准。
5. Given 走查完成，When 归档，Then 每种形态与每个页面均有截图，由设备持有人在真机/折叠设备上签收。

## 安全、隐私与回滚

- 纯布局与状态保持改动，不触碰授权与数据流。
- 不得为适配横屏而缩小触控区或降低对比度。
- 折叠设备截图若无真实设备，须明确记为未验证而非通过。
- 回滚：revert 样式改动回到既有竖屏布局；状态保持修复可独立保留。

## 实现与验证证据

- `APP/src/style.css` 增加 MOB-174 响应式契约：`html/body/#app` 和 `.screen` 可收缩且不使用 `100vw`，横屏统一保留安全区和底部导航留白，低高度横屏在不降低触控尺寸的前提下压缩间距，并为支持 CSS Foldables API 的 WebView 增加双分段安全边距；横屏逻辑内边距明确按左侧→右侧映射物理安全区，避免刘海/挖孔仅在一侧时错位。
- 页面仍保持单列信息流，不改变路由、表单、上传草稿、助手会话或任务写入逻辑；`min-width: 0`、长文本换行和 `overflow-x: clip` 负责避免内容溢出。
- `APP/scripts/audit-responsive-layout.mjs` 与 `npm run audit:responsive` 提供本地只读静态预检，确认横屏、低高度横屏、折叠屏分段规则、页面收缩和安全区边界存在。
- 响应式预检额外锁定横屏、低高度横屏、折叠屏及底部导航的左右安全区顺序，防止后续样式改动把 `padding-inline` 的起始/结束边距反置。
- [MOB-174 Android 横屏与折叠屏布局走查记录](../../docs/testing/MOB-174-Android横屏折叠屏布局走查记录.md) 固化 10 个主要页面、标准/特大字号、高对比/减少动效、旋转/折叠状态保持和截图哈希记录方式。
