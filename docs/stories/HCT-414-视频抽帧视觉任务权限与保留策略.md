## 本增量范围

- 新增 `scripts/hct414_video_perf.py`：本地生成合成视频夹具，测量"容器解码 → 间隔抽帧 → 近重复剔除 → 逐帧质量门控"的 P50/P95/Max，并记录硬件、内存 RSS 增量、夹具磁盘占用与 SHA-256；
- 覆盖受控拒绝样例：无法解码的容器、零字节文件、超时长上限、失焦低质量；
- 输出机器可读报告 `artifacts/hct414-video-perf.json`（`hct414-video-perf-v1`），并在超预算或出现"本应拒绝却被接受"时以非零退出码阻断；
- 新增 `tests/unit/test_hct414_video_perf.py` 守住报告契约与安全声明；
- 新增 [性能与证据记录](../reviews/HCT-414-视频抽帧CPU性能与证据记录.md)。

## 非目标

- 不改动 D1/D2/HCT-439 已交付的实现与契约；
- 不测 OCR、条码、候选融合与人工复核交接（父任务的"全链路"结论因此仍不成立）；
- 不使用真实药品实拍或任何真实健康数据；夹具为合成图案且不入库；
- 不做准确率或阈值校准结论 —— 那取决于 HCT-201 的授权固定集。

## Given / When / Then（本增量覆盖的部分）

- Given 合成短视频在上限内；When 运行探针；Then 报告返回可复核的分阶段帧数、决定、P50/P95/Max 与夹具哈希。
- Given 视频非法、超限、无法解码或低质量；When 处理；Then 在进入识别前受控拒绝，报告逐条列出期望与实测错误码。
- Given 报告生成；When 检查预算；Then 超过 P95 预算或出现"本应拒绝却被接受"时以非零退出码阻断。
- Given HCT-201 未满足；When 生成报告；Then `release_status` 固定为 `DEMO_ONLY` 并列出阻断项。

## 实测结果（2026-08-25，提交 `9a23ad53a165`）

最差视频链路 P95 = **133.617 ms**，预算 8000 ms，在预算内；四条受控拒绝样例全部按预期拒绝。完整数字、环境、夹具哈希与限制见[性能与证据记录](../reviews/HCT-414-视频抽帧CPU性能与证据记录.md)。

成本主要在容器解码（30s 片段解码 450 帧约 119 ms）；合成画面高度自相似，近重复剔除把 30 个抽样帧收敛到 1 个，因此逐帧打分部分是**下界**，真机采集会更高。
