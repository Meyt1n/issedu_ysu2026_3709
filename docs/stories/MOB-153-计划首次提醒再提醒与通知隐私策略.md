## 用户价值

作为获得授权的照护成员，我希望在服务端确认的计划提醒窗口内收到不含健康正文的本地提醒，并在计划、授权或会话改变后及时撤销旧提醒，以便查看今日安排而不暴露成员或用药信息。

## 范围

- 仅调度含完整服务端计划版本、稳定去重键、首次/再提醒时间、授权标记和预算证据的提醒。
- Android 使用 Capacitor Local Notifications；PWA 不具备可靠后台本地调度时明确降级，不宣称已提醒。
- 通知正文固定为非敏感的“查看今日安排”，不包含药名、风险详情、家庭成员全名、电话或健康正文。
- 首次/再提醒使用稳定键去重；确认、延期、跳过、计划变更、撤权、登出、成员/家庭切换均取消旧调度。

## 非目标

- 不引入远程推送、云通知、外部网络出口或客户端医疗判断。
- 不根据 UI `dueAt`、缓存或本地推断创建提醒。
- 不把通知送达视为服务端动作回执或计划执行事实。

## Given / When / Then

- Given 服务端返回已授权且具备完整计划元数据的提醒，When 到达首次或再提醒时间，Then Android 调度无敏感正文的本地通知；PWA 仅在可靠能力存在时调度，否则说明降级。
- Given 用户确认、延期、跳过、撤权、登出或计划变更，When 新快照同步或会话上下文清理，Then 取消或替换旧计划版本的本地通知。
- Given 权限拒绝、系统限制、能力缺失或离线，When 调度失败，Then 返回可理解的不可用状态且不声称已经提醒。
- Given 同一计划多次刷新，When 同一稳定计划版本重新调度，Then 只保留一组首次/再提醒。

## 测试与回滚

- 自动化：契约验证、去重、取消、权限拒绝、PWA 降级、会话/上下文清理和通知隐私文案。
- 人工验收：Android 权限、后台/重启、时区变更、撤权及 PWA 差异。
- 回滚：禁用本地调度入口；保留今日页任务和服务端计划事实，不恢复客户端推断或远程通知。
