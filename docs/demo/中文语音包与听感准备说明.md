# 中文语音包与听感准备说明

> **给演示者、验收人与后续开发者的硬提醒：**  
> 家健镜的语音输出走浏览器/WebView 的 `speechSynthesis`，**不会随仓库附带 TTS 模型或音色文件**。  
> 代码只能在本机已安装的语音里做优选；若环境只有机械默认包（常见如 Windows「Microsoft Huihui」），听感改善会非常有限——**这不是产品回归，而是演示机未准备语音包。**

| 随身版长辈播报 | `APP/src/composables/useSpeech.ts` | [MOB-118](../stories/MOB-118-语音播报降级.md)、[无障碍说明](../../APP/docs/无障碍模式设计说明.md) |

## 1. 必须先接受的限制

1. **听感取决于本机/浏览器已安装的中文 TTS 语音包**，不是 Git 仓库里的配置项。
2. 仓库**不提供、不下载、不捆绑**第三方 Natural/Neural 语音引擎；演示前需在演示机自行安装。
3. 未装中文包、权限受限、或浏览器首次交互限制时：文字路径必须仍可用（降级提示，不阻塞核心操作）。
4. 语音**输入**（Speech Recognition）同样依赖浏览器实现，不能对外宣称“本地离线识别”；本仓库 API **不接收原始音频**。
5. 部分更自然的系统音色可能走厂商在线合成：朗读助手文字时，文本可能离开本机。教学演示若强调“健康数据默认不出网”，验收应优先选用**本地 Natural** 音色，或明确告知演示边界。

## 2. 应用如何选音色（便于对照）

两端优选逻辑一致（细节以代码为准）：

1. 只要 `zh` / `zh-CN` 中文语音；
2. 名称含 Natural / Neural / Premium / Enhanced、晓晓、云希、婷婷等高质量命名 → **大幅加分**；
3. 同档时本地音色略加分；
4. 明显机械引擎（eSpeak 等）以及常见机械默认名（如 Microsoft Huihui / Yaoyao）→ **降权**；
5. 列表为空时短暂等待 `voiceschanged`（约 800ms），超时则按现状降级播报；
6. 默认参数约：`rate=0.92`、`pitch=1.05`、`volume=1`（适老略慢、略抬高音高）。

**结论：** 代码可以把“有 Natural 包”的机器播得更自然；**不能把“只有 Huihui”的机器变成 Natural。**

## 3. 推荐安装的中文语音包（演示机 checklist）

> 下表为常见教学演示环境的**操作指引**，不是对任何厂商音色的产品捆绑承诺。名称以系统设置为准，系统更新后菜单文案可能变化。

### 3.1 Windows 10 / 11（Edge / Chrome 演示 Web 助手）

| 目标 | 建议操作 |
|---|---|
| 安装中文语音 | **设置 → 时间和语言 → 语言和区域 → 中文（简体）→ 语言选项 → 语音包**，安装「中文（简体）」语音 |
| 优先自然音色 | 在同一语言选项中查看是否有 **自然语言 / Natural** 或名称含 **Xiaoxiao / 晓晓、Yunxi / 云希** 等；有则安装 |
| 避免误判 | 仅有 **Microsoft Huihui** 时听感通常偏机械——演示前应补装 Natural 包，或换已装 Natural 的机器 |
| Edge 提示 | Edge 往往能枚举到更多系统/在线中文音色；Chrome 也读系统语音列表，但可用集合可能不同 |

快速自检（演示机浏览器控制台）：

```js
speechSynthesis.getVoices()
  .filter(v => /^zh/i.test(v.lang))
  .map(v => ({ name: v.name, lang: v.lang, local: v.localService }))
```

期望至少看到一条名称含 `Natural` / `Neural` / `晓晓` / `Yun` / `Ting` 等的 `zh-CN` 项；若只有 `Huihui`，听感验收不应按“自然音色”通过。

### 3.2 macOS（Safari / Chrome）

| 目标 | 建议操作 |
|---|---|
| 系统语音 | **系统设置 → 辅助功能 → 朗读内容 → 系统声音**（或「声音」相关入口），下载 **婷婷 Ting-Ting** 等中文声音 |
| 质量 | 优先下载标记为增强/高质量的中文女声；装好后重启浏览器再测 `getVoices()` |
| 注意 | Safari 与 Chrome 可见语音列表可能不一致，**以实际演示浏览器为准** |

### 3.3 Android 真机 / WebView（随身版 APP）

| 目标 | 建议操作 |
|---|---|
| 系统 TTS | **设置 → 无障碍 → 文字转语音（TTS）输出**，引擎选系统或 Google，语言选 **中文（中国）**，并下载中文数据包 |
| 数据完整 | 进入引擎的「安装语音数据」，确认简体中文已下载；未下载时应用会提示“未发现中文语音” |
| WebView | 首次播报常需用户先点按一次页面；无中文包时必须静默降级，不得阻塞求助/任务 |
| 验收记录 | 真机签收应填写引擎名与版本（见 [MOB-141 验收记录](../testing/MOB-141-Android真机无障碍验收记录.md)） |

### 3.4 iOS / iPadOS（若用浏览器演示）

| 目标 | 建议操作 |
|---|---|
| 系统声音 | **设置 → 辅助功能 → 朗读内容 → 声音**，下载中文声音 |
| 限制 | Safari 对自动播报更严，须由用户手势触发；WebView/壳应用行为以真机为准 |

## 4. 演示与验收前自检（约 2 分钟）

在演示「朗读回答」或长辈「语音播报」前，勾选：

- [ ] 演示浏览器支持 `window.speechSynthesis`
- [ ] `getVoices()` 中至少有一条 `zh` / `zh-CN`
- [ ] 其中至少一条名称像 Natural / Neural / 晓晓 / 云希 / 婷婷（或团队认可的高质量包）
- [ ] 用户已点过页面（规避首次交互静音）
- [ ] 麦克风权限仅在测唤醒输入时需要；纯朗读可不测输入
- [ ] 若只有机械默认包：在演示说明中诚实标注「本机未装 Natural 中文语音包，听感受限」

**禁止：** 把“未装语音包导致的机械听感”写成代码缺陷或已验证的自然音色能力。

## 5. 故障对照

| 现象 | 优先排查 |
|---|---|
| 完全无声 | 系统音量、浏览器标签是否静音、是否从未点击页面、TTS 引擎是否禁用 |
| 有声但很机械 | 几乎总是缺少 Natural 包或选中了 Huihui 类默认音色 → 按第 3 节安装 |
| 提示未发现中文语音 | 未装中文 TTS 数据；Android 需下载语音数据包 |
| 唤醒慢 / 不准 | 麦克风权限、浏览器 Speech Recognition 支持、环境噪声；见 HCT-412（与 TTS 语音包无关） |
| 文字仍可用、仅语音失败 | 符合降级设计；不要为了播报阻塞核心流程 |

## 6. 隐私与出网边界（演示话术）

- **本仓库 API**：不接收、不存储麦克风音频；朗读也不经 HCT 后端。
- **浏览器识别服务**：处理位置由浏览器厂商决定，不得宣称为本地离线 ASR。
- **系统/浏览器 TTS**：若选用在线 Natural 音色，朗读文本可能发往厂商服务。强调本地优先时，请选用 `localService === true` 的中文 Natural 音色，或在演示脚本中说明“听感演示使用系统在线音色，业务健康数据仍不经 HCT 出网”。

## 7. 维护约定

- 改动音色优选、播报参数或降级文案时：同步更新本文、HCT-412 / MOB-118 与 `APP/docs/无障碍模式设计说明.md` 中的交叉链接与表述。
- 新增自建/联网 TTS 服务属于**范围外**变更，须先过隐私与 ADR，不得在未评审前写入默认演示路径。
