# 人脸凭证录入与登录操作手册（HCT-424 / HCT-425）

> 适用版本：包含 2026-08-26「Windows 中文路径 ONNX 加载失败」修复之后的 `master`。
>
> 读者：家庭管理员（负责录入）与家庭成员（刷脸登录），以及负责部署的维护者。
>
> 边界提醒：人脸凭证只用于本地家庭登录（教学演示），只保存加密特征模板，不保存照片、视频或原始像素；活体检测是本地启发式校验，不宣称生产级反欺诈能力。

## 1. 前置条件（一项一项过）

在录入第一张人脸前，请逐项确认：

| # | 条件 | 怎么确认 | 不满足会怎样 |
|---|---|---|---|
| 1 | 本地 API 已启动 | 浏览器打开 `http://127.0.0.1:8000/health` 返回 `{"status":"ok",...}` | 页面提示「本地 API 服务不可用」 |
| 2 | 人脸模型已就绪 | `GET http://127.0.0.1:8000/api/v1/meta/capabilities` 的 `available` 里包含 `face-recognition-local`；或确认 `models/face/` 下存在两个 `.onnx` 文件 | 首次注册时现场下载约 37MB（慢网络可能等 1～2 分钟），或直接提示「人脸功能暂时不可用」 |
| 3 | 摄像头可用且授权 | 操作系统里摄像头未被占用；浏览器地址栏允许摄像头权限 | 采集区提示无法打开摄像头 |
| 4 | 使用**正式账号会话**登录（不是开发演示身份） | 登录方式是「账号密码」注册/登录，页面右上身份不是 `demo-` 前缀开发身份 | 注册按钮旁提示「必须使用正式账号会话」 |
| 5 | 当前账号是该家庭的**管理员（owner）** | 该家庭由这个账号创建 | 403，提示没有权限 |
| 6 | 家庭中目标成员已有**登录账号 ID** | 人脸凭证页「给成员分配登录账号」卡片中该成员不再出现 | 无法在「家庭账号」下拉里选到该成员 |
| 7 | 家庭 PIN 已设置（若用 PIN 做二次确认） | 人脸凭证页「设置家庭 PIN」卡片保存过六位数字 | 二次确认只能改用「账号密码」 |
| 8 | （刷脸登录前）本机已**绑定一个家庭** | 人脸凭证页「本机登录范围 → 绑定一个家庭」显示已绑定 | 欢迎页人脸标签提示「本机还没有绑定家庭」，无法发起刷脸 |

> 提示：条件 4「正式会话」是硬要求——注册接口要求 Bearer 会话，开发演示身份头（`X-Actor-ID`）不能录入人脸。

## 2. 预下载人脸模型（维护者，一次性）

人脸识别使用本地 OpenCV **YuNet（检测）+ SFace（识别）** 两个 ONNX 模型，**权重不进 Git**。推荐在演示/使用前预下载，避免首次注册时现场拉取：

```powershell
# 仓库根目录（Windows PowerShell / Linux / macOS 一致）
uv run python scripts/ensure_face_models.py
```

成功输出两行本地路径：

```text
yunet=...\models\face\face_detection_yunet_2023mar.onnx
sface=...\models\face\face_recognition_sface_2021dec.onnx
```

- 默认缓存目录由 `.env` 的 `FACE_MODEL_DIR` 决定（默认 `./models/face`）。
- 离线环境：在能联网的机器上跑一次脚本，把两个 `.onnx` 文件拷贝到目标机的 `FACE_MODEL_DIR`，并将 `FACE_MODEL_AUTO_DOWNLOAD=false`。
- 模型来源是 [OpenCV Zoo](https://github.com/opencv/opencv_zoo)（YuNet 约 345KB、SFace 约 37MB）。

## 3. Windows 特别注意：仓库路径含中文怎么办

### 3.1 历史故障与根因（已修复）

2026-08-26 之前，如果仓库或模型目录的**完整路径含有非 ASCII 字符**（例如 `C:\Users\你\多模态医疗\issedu_ysu2026_3709`），Windows 上注册/刷脸会弹出：

```text
本地 API 处理该请求时出错（HTTP 500: OpenCV ... (-5:Bad argument)
Can't read ONNX file: C:\...\多模态医疗\...\face_recognition_sface_2021dec.onnx ...）
```

根因：OpenCV 的 C++ 文件加载器在 Windows 上使用 ANSI 窄字符文件 API，把路径字符串直接传给 `cv2.FaceRecognizerSF_create` / `cv2.FaceDetectorYN_create` 时无法打开含中文的路径，抛出的原生 C++ 异常又绕过了业务错误处理，以 HTTP 500 把完整本机路径泄漏进了页面提示。

### 3.2 本修复如何处理

现在服务端**不再把模型路径交给任何 OpenCV 文件 API**：由 Python 自己读取 `.onnx` 字节（Python 在所有平台原生支持 Unicode 路径），再通过 OpenCV 的内存缓冲接口加载模型。因此：

- 仓库放在含中文/空格/特殊字符的路径下，人脸注册与登录**可以正常工作**；
- 即使模型文件损坏或加载失败，接口也只返回稳定错误码 `FACE_DETECTOR_UNAVAILABLE`（HTTP 503），页面显示中文指引，**不会再出现 C++ 堆栈或本机路径**。

### 3.3 仍建议 & 仍失败时怎么排查

尽管已修复，仍**建议把仓库放在纯英文路径**（如 `C:\work\issedu_ysu2026_3709`）：中文路径在其它工具链（Docker 卷挂载、部分终端、旧版 Python/依赖）上仍可能踩坑。

若更新代码后仍提示「人脸功能暂时不可用」，按顺序排查：

1. **确认代码已包含本修复**：`src/api/app/face_credentials.py` 中应能看到 `_read_onnx_model_bytes`（按字节缓冲加载）；老代码是 `cv2.FaceRecognizerSF_create(str(sface), "")`。
2. **确认模型文件完整**：`models/face/` 下两个 `.onnx` 存在且大小正常（SFace 约 37MB；只有几 KB 说明下载中断，删掉后重跑 `ensure_face_models.py`）。
3. **确认重启过 API**：修复/换模型后必须重启（`scripts/start.ps1 api` 或 Compose `docker compose restart api`）。
4. **看 API 日志**：启动窗口若打印 `FACE_DETECTOR_UNAVAILABLE` 相关栈，通常是模型文件缺失/损坏，而不是路径问题。
5. **OpenCV 版本**：依赖锁定 `opencv-python-headless>=4.10`。若你手工装过旧版 OpenCV（<4.8 无缓冲加载接口），请 `uv sync` 恢复锁定版本。
6. 以上都正常仍失败 → 按 §8 联系维护者，附 API 日志。

## 4. 管理员：录入（注册）一个家庭账号的人脸

> 入口：**管理后台**（本地进程 `http://127.0.0.1:5174`，Compose `http://localhost:8081`）→ 用**账号密码**登录 → 左侧导航「人脸凭证」页。

### 第 1 步：给成员分配登录账号（若还没有）

1. 在「先绑定家庭账号 → 给成员分配登录账号」卡片选择成员（如「奶奶」）。
2. 填「登录账号 ID」，例如 `grandma-1`（只用于本地登录，不是姓名，不要填密码）。
3. 点「绑定登录账号」。同一家庭内账号 ID 不能重复；换绑会立即使旧账号的人脸凭证和会话失效。

*【截图占位：给成员分配登录账号卡片】*

### 第 2 步：设置家庭 PIN（若用 PIN 做二次确认）

1. 在「家庭账号安全 → 设置家庭 PIN」输入六位数字，两次一致后点「保存家庭 PIN」。
2. 不想用 PIN 时，注册时二次确认可改选「账号密码」（输管理员自己的登录密码）。

### 第 3 步：绑定本机家庭（供刷脸登录用，本机一次）

在「本机登录范围 → 绑定一个家庭」点「绑定当前家庭」。刷脸登录只会在这个家庭的有效凭证里 1:N 认人，不会跨家庭搜索。

### 第 4 步：采集三帧动态画面并注册

1. 在「注册或重新绑定」卡片的「家庭账号」下拉里选择目标账号（如 `奶奶 · grandma-1`）。
2. 请**本人**坐到摄像头前：光线充足、不逆光，整张脸放进圆圈内，约占画面六分之一以上。
3. 点「开始录入（有语音提示）」，按横幅文字/语音提示：**正对 → 轻轻左转 → 轻轻右转**，系统自动倒计时拍三张。
4. 选择二次确认方式（家庭 PIN 或账号密码）并输入。
5. 勾选「我已获得本人明确同意，允许为所选家庭账号注册人脸凭证。」
6. 若该账号已有凭证且要替换，勾选「已有凭证时重新绑定」（旧凭证与该账号的家庭会话会立即失效）。
7. 点「完成注册」。等待「正在保存…」结束（通常 1~3 秒；首次使用且未预下载模型时可能 1～2 分钟）。

*【截图占位：三帧采集 + 注册表单】*

### 第 5 步：确认成功

- 页面顶部出现绿色成功提示，「凭证清单」自动滚动并高亮新记录：状态 `ACTIVE`、算法 `opencv-yunet-sface-v3`、版本号 +1。
- 换下一位成员时，重复第 1、4 步即可（PIN 与本机绑定不用重做）。

## 5. 家庭成员：欢迎页刷脸登录

> 入口：**成员前台**（本地进程 `http://127.0.0.1:5173`，Compose `http://localhost:8080`）。

1. 打开欢迎页，登录方式选「**人脸识别**」标签。
2. 确认卡片显示已绑定的家庭名（如果提示「本机还没有绑定家庭」，先请管理员完成 §4 第 3 步，或改用 PIN/账号密码）。
3. 点「开始本次动态采集并登录（有语音提示）」，把脸放进圆圈，按提示轻轻转头，等待三张自动拍完。注意：管理员之前录入的人脸是“注册凭证”；每次登录仍要现场采集这三张动态画面，不能只依靠已录入状态直接跳过。
4. 系统在本家庭内自动识别是哪位成员并直接进入该成员账号；页面会显示成员姓名与角色。
5. 识别不了怎么办：换个光线充足的位置再试一次；连续失败会被临时限流（提示等待分钟数）；任何时候都可以点「改用 PIN 登录」或「改用账号密码」。

## 6. 常见错误速查表

| 页面提示 / 错误码 | 含义 | 怎么办 |
|---|---|---|
| `FACE_FRAME_LOW_QUALITY`（画面太小或过暗过亮） | 摄像头分辨率低于 480×360，或画面近全黑/全白 | 换分辨率更高的摄像头位；避免逆光、遮挡镜头；开灯 |
| `FACE_NOT_FOUND`（没有检测到清晰人脸） | 脸不在画面里或太暗太糊 | 正对镜头、脸放进圆圈、改善光线 |
| `FACE_MULTIPLE_SUBJECTS`（多张人脸） | 画面里出现了第二个人（含海报/照片） | 保证画面里只有本人 |
| `FACE_TOO_SMALL` / `FACE_TOO_LARGE` | 离摄像头太远/太近 | 调整距离，整脸完整入画约占 1/6 以上 |
| `FACE_POSE_EXTREME` | 转头幅度过大接近侧脸 | 按提示**轻轻**转头即可 |
| `FACE_BLURRY` | 人脸区域运动模糊/失焦 | 稳住设备，转头放慢 |
| `FACE_LIVENESS_FAILED`（没有形成有效转头变化） | 三帧几乎一样（静止/照片翻拍）或帧间不是同一人 | 重新采集，按提示做出可见的左右转头；不要用照片对着摄像头 |
| `FACE_AUTH_FAILED`（登录失败） | 未命中任何成员、分数不够或两位成员太接近无法安全区分 | 重试一次；仍失败改用 PIN/密码，并考虑重新绑定该成员（多角度、光线好） |
| 连续失败被锁定（`LOCKED:秒数`/429） | 人脸失败限流触发 | 按提示等待后再试，或改用账号密码 |
| 「人脸功能暂时不可用…模型缺失或加载失败」（503 `FACE_DETECTOR_UNAVAILABLE`） | 本地模型没下载/文件损坏/加载失败 | 运行 `uv run python scripts/ensure_face_models.py`，重启 API；仍失败看 §3.3 |
| 「人脸识别暂时不可用，本次未进入家庭」（503 `FACE_AUTH_UNAVAILABLE`） | 登录时人脸服务不可用（含模板解密失败） | 先改用 PIN/密码进入；再按 §3.3 排查，必要时重新绑定凭证 |
| 「本地服务响应超时：请求可能仍在后台处理」 | 服务端还在算（常见于首次现场下载 37MB 模型 + 慢网络） | **不要立刻重试**：稍候点「刷新」看凭证清单，注册很可能已成功（重复提交会得到 409 已存在） |
| 「本地 API 服务不可用，本次没有改变任何数据」 | 请求根本没到 API（API 没启动 / 代理不通） | 确认 `http://127.0.0.1:8000/health` 可访问，再重试 |
| 409「当前身份已经有有效的人脸凭证」 | 目标账号已有 ACTIVE 凭证 | 想替换就勾选「已有凭证时重新绑定」 |
| 「二次确认失败」（`CONFIRMATION_FAILED`） | PIN 或密码输错 | 核对六位 PIN / 管理员账号密码；PIN 未设置时先到本页设置 |
| 「此操作需要正式账号会话」 | 当前是开发演示身份 | 切换到「正式账号登录」（账号密码）后再操作 |

> 区分三类「不可用」：**超时**（可能已成功，先刷新确认）≠ **API 连不上**（服务没起来，数据必然未变）≠ **人脸服务 503**（API 是好的，只是人脸模型/服务有问题，改用 PIN/密码不受影响）。

## 7. 如何验证整条链路成功

1. **能力声明**：`GET /api/v1/meta/capabilities` 的 `available` 包含 `face-recognition-local`。
2. **凭证清单**：管理后台「人脸凭证」页能看到目标账号的 `ACTIVE` 记录（算法 `opencv-yunet-sface-v3`）。
3. **刷脸进门**：成员前台欢迎页「人脸识别」→ 刷脸 → 直接进入对应成员账号，右上显示成员名。
4. **失败可观测**：管理员可通过 `GET /api/v1/households/{household_id}/auth-audit/face-summary` 查看最近 7 天脱敏失败原因桶（无分数、无模板、无图片）。
5. **自动测试**（开发者）：

```bash
uv run pytest tests/unit/test_hct424_face_model_unicode_path.py \
              tests/contract/test_hct424_face_onnx_error_contract.py \
              tests/contract/test_hct424_face_pipeline_offload.py \
              tests/contract/test_hct425_face_login.py -q
```

## 8. 回滚与何时找维护者

- **单个账号**：管理员在凭证清单里「删除」该账号凭证即可立即失效（模板被清空，只留脱敏元数据）；成员改用 PIN/密码登录不受影响。
- **本机**：在「本机登录范围」点「解除绑定」，本机不再提供刷脸入口。
- **整体功能**：把 `.env` 的 `FACE_MODEL_AUTO_DOWNLOAD=false` 且移走 `FACE_MODEL_DIR` 下的模型文件并重启 API——人脸接口统一返回 503，欢迎页自动引导 PIN/密码，其它业务不受影响。
- **代码级回滚**：本修复是纯代码变更（无迁移、无数据变化），revert 对应 PR 即可；已注册凭证与旧版本完全兼容。

以下情况请停止操作并联系维护者（附页面截图 + API 日志）：

- 按 §3.3 排查后仍持续 503 `FACE_DETECTOR_UNAVAILABLE`；
- 页面出现**任何**含本机路径或英文异常堆栈的提示（按当前设计不应出现，属于新缺陷）；
- 同一家庭两位成员频繁互相认错（需要维护者在本机做阈值校准，见[本地部署与 Demo 操作指南 §1.3](../本地部署与Demo操作指南.md)的标定步骤——云端无法代采真人脸）。
