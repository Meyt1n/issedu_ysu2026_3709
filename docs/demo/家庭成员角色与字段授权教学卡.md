# HomeCare Twin 家庭成员角色与字段授权教学卡

## 1. 用途和边界

本卡是合成教学演示知识（internal-demo），用于说明家庭、成员与字段级授权（field-level authorization）的教学口径。本卡不构成法律意见或机构合规认证，也不提供诊断或处方建议。演示产品强调「子女只能看到被精细授权的信息」。

## 2. 角色与责任

- 家庭（household）内可有多位成员（member）与不同角色：本人、照护者、只读观察者等（具体以产品配置为准）。
- 录入、确认、授权变更等高风险操作应记录操作者身份与时间。
- 教学演示可用开发身份头；正式环境必须换成真实认证，不得把演示身份当作生产授权。

## 3. 字段级授权原则

- 授权粒度应落到字段或字段组（如过敏、药品清单、指标、计划），而不是「整户全开」。
- 最小必要披露（need-to-know）：分享给子女或照护者时，只开放完成照护所需的字段。
- 撤权后，后续检索、助手上下文与界面展示不得继续返回已撤字段。
- 跨成员提问时，后端必须先按调用者权限过滤，禁止检索后再遮挡。

## 4. 常见误区

- 「家人就能看全部」不符合本产品边界。
- 「模型已经知道所以可以回答」不能绕过授权；模型只能使用本轮授权工具结果。
- 授权变更本身是高风险事件，应可审计、可回滚到明确版本。

## 5. 系统演示口径

- API 与 RAG 均在权限前置过滤后再检索。
- 未授权返回结构化拒绝或空可见范围，不泄露字段名以外的敏感值（按现有隐私规范执行）。
## FAQ（教学问答）

**Q: 家里人是不是默认全能看？**  
A: 不是。授权应落到字段或字段组，禁止「整户全开」作为默认。

**Q: 撤权后助手会不会还记得？**  
A: 不应。后续检索与回答不得继续使用已撤字段；不能靠模型记忆绕过。

**Q: 演示用的 Actor 头能当生产登录吗？**  
A: 不能。演示身份仅用于教学；正式环境必须真实认证。
