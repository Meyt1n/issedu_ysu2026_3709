# HomeCare Twin 健康事件追加与不可覆盖教学卡

## 1. 用途和边界

本卡是合成教学演示知识（internal-demo），用于说明健康事件（health event）追加写入与状态投影的教学口径。本卡不构成病历法律效力说明，也不对任何真实健康记录做诊断解读。

## 2. 为什么要追加而不是覆盖

- 药品、过敏、指标和计划的变化应写成不可覆盖的事件流，保留「当时发生了什么」。
- 原地修改会抹掉纠错前的证据，不利于人工复核与审计。
- 纠错时保留原预测或原记录、修正值、原因、操作者与时间；不能静默覆盖。

## 3. 状态投影

- 当前可见「状态」由事件投影得到，投影结果应能追溯到事件版本。
- 投影失败或事件缺失时，界面应显示信息不完整，而不是用模型补全。
- 删除或遗忘请求按隐私规范传播；投影与检索不得继续暴露已删除内容。

## 4. 系统演示口径

- 路由层不直接写随意覆盖 SQL；事件写入走领域服务与校验。
- 助手解释「当前状态」时必须引用已授权事实与事件证据，不能把推测写成事实。
- 教学演示可使用合成事件；禁止提交真实家庭健康数据到仓库或公共日志。
## FAQ（教学问答）

**Q: 为什么不能直接改掉错误记录？**  
A: 原地覆盖会抹掉纠错前证据。应追加事件并保留原值、修正原因、操作者与时间。

**Q: 当前状态从哪里来？**  
A: 由事件投影得到，应能追溯到事件版本；缺失时显示不完整，不由模型补全。
