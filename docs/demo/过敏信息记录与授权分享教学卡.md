# HomeCare Twin 过敏信息记录与授权分享教学卡

## 1. 用途和边界

本卡是合成教学演示知识（internal-demo），用于演示过敏信息的记录字段、授权边界和分享注意事项，不构成诊断、处方或个体化用药建议。系统不判断某次反应是否属于过敏反应；这类判断必须由医务人员完成。

## 2. 过敏信息应记录哪些内容

家庭记录过敏信息（allergy record）时，建议包含：

- 过敏原名称（allergen）：药物、食物或其它接触物的通用名，尽量抄录包装或病历上的规范名称；
- 反应表现：皮疹、瘙痒、肿胀、呼吸不适等用户自己观察到的描述，不写推断的诊断名；
- 发生时间和场景：首次发现时间、当时正在使用的药品或食物；
- 信息来源：本人回忆、家属转述、病历或医务人员告知，来源不同可靠性不同；
- 确认状态：是否已经由医务人员确认过。

记录"疑似过敏"时应明确标注"疑似、待医务人员确认"，不能直接写成确定事实。

## 3. 过敏信息的授权边界（教学演示）

- 过敏信息属于敏感健康信息，默认只有本人和被明确授权的照护者可以查看。
- 授权应精确到成员、字段、动作和期限；"家人"不等于自动拥有查看权限。
- 撤销授权后，被撤权者不能再查看过敏信息；历史审计记录保留但不暴露正文。
- 助手回答过敏相关问题时，只能使用当前调用者授权范围内的记录，不能跨成员拼接信息。

## 4. 对外分享的注意事项

- 就医、配药时向医务人员出示过敏记录是最重要的分享场景；建议同时说明信息来源和确认状态。
- 向学校、照护机构等第三方提供时，遵循最小必要原则（data minimisation），只提供与场景相关的条目。
- 不在公开社交平台发布包含真实姓名和过敏细节的组合信息。
- 分享的清单可以注明生成时间，提醒接收方信息可能过时，需要以本人最新陈述为准。

## 5. 系统内的对应演示口径

- 登记过敏规则命中时，系统只标记"高关注、需人工确认"，不判断是否会发生过敏反应。
- 演示环境使用合成数据；禁止把真实家庭健康数据录入演示库。
