# 家庭内人脸到用药助手连续展示主线

这是一条面向课堂展示的本地、可重复演示路径。它使用合成药盒和本地教学知识，不使用真实家庭健康数据，也不把人脸原图、视频、模板、模型权重或数据库文件提交到仓库。

## 0. 一次性准备

在仓库根目录打开 PowerShell：

~~~powershell
# 启动 MySQL、API、Ollama、Web；有 PaddleOCR 环境时同时启动视觉 worker
.\scripts\start-demo.ps1 -Model hct402-qlora-v5 -IncludeVisionWorker -VisionWorkerPython "<你的 PaddleOCR 环境>\python.exe" -ActorId "demo-parent,grandpa-demo,grandma-demo"

# 生成本地合成药盒主数据，并入库本地批准知识
uv run python scripts/setup_vision_demo.py
uv run python scripts/ingest_local_knowledge.py --manifest docs/demo/本地RAG知识清单.json --source-root docs/demo --actor-id demo-parent --index-version demo-cn-en-v1

# 创建或复用本地演示家庭、爷爷和奶奶账号；输出家庭 ID 和成员 ID
.\scripts\prepare-family-demo.ps1
~~~

如果 API/Web/Ollama 已经运行，只执行后两组命令即可。脚本是幂等的：同名且由 demo-parent 创建的家庭会复用；如果已有同名成员绑定了其他账号，脚本会停止，不会偷偷覆盖家庭身份。

## 1. 密码首次进入与家庭账号

1. 打开 http://127.0.0.1:5173，选择“正式账号登录”。
2. 使用 demo-parent 和演示密码登录。首次没有家庭时，也可以在页面创建；推荐使用上面的准备脚本，展示时不临时填写家庭 ID。
3. 进入后右上角应显示家庭名称；成员页中应有“爷爷”和“奶奶”，并分别显示 grandpa-demo、grandma-demo。

## 2. 绑定动态人脸

1. 打开“人脸凭证”，选择“爷爷”，点击绑定账号（如果准备脚本已完成绑定则跳过）。
2. 点击开始采集，让爷爷面对摄像头，按页面提示完成 2～3 个不同动作/角度的短时画面；同意说明并完成 PIN/密码二次确认。
3. 对“奶奶”重复一次。页面只显示凭证版本和状态，服务端保存加密模板，不保存视频原片。
4. 在页面执行“绑定本机到家庭”。这只保存家庭的 opaque ID，设备端不保存成员人脸数据。

## 3. 家庭内 1:N 自动登录

1. 退出当前会话，选择“正式账号登录 → 人脸识别”。首次绑定后页面会自动显示家庭名称，不再要求手填家庭 ID。
2. 让爷爷面对摄像头完成动态采集。服务端只在该家庭的有效凭证中比较，成功后右上角和首页问候应显示“爷爷”，而不是固定显示第一个成员。
3. 退出后让奶奶重复一次，应进入“奶奶”账号。打开成员、时间线或助手页面，确认当前成员上下文也随识别结果切换。
4. 画面低质量、多人脸、动作重复或两个成员分数过近时，系统应拒绝登录并给出 PIN/密码回退；不能显示候选账号或相似度。

## 4. 扫描药品与人工确认

1. 以刚识别出的成员身份打开“视觉扫描”。上传仓库内的合成样品：
   - docs/demo/vision-samples/demo-box-cn.jpg：阿莫西林胶囊；
   - docs/demo/vision-samples/demo-box-en.jpg：Ibuprofen/布洛芬。
2. 等待视觉 worker 完成 OCR/条码证据。任务一直排队时，先看 tmp/demo-artifacts/demo-logs/vision-worker.out.log，确认 worker 的 --actors 包含当前登录账号。
3. 打开“人工复核”，检查药品名称、规格、厂家、证据和候选信息。识别结果即使置信度高，也不会自动写入健康档案。
4. 点击“确认保存”，写入一条 CONFIRMED 健康事件。然后回到成员时间线，看到该药品已经成为已确认事实。

## 5. 重复/相互作用提醒与助手依据

1. 先确认阿莫西林，再确认布洛芬；两条事件都必须由人工确认后才参与规则计算。
2. 打开“风险提醒”，演示主数据会显示本地规则的组合提醒。文案应是“需要核对当前医嘱和说明书”，不是让模型直接下结论。
3. 打开“本地助手”，询问“阿莫西林和刚才扫描的布洛芬需要核对什么？”。
4. 展开回答下方的“依据/引用”和“多智能体协作”：应看到本地数据库查询、知识库检索、受控联网（默认关闭）和 Ollama 综合等节点；引用只能来自本轮服务端返回的本地知识片段和已确认事件。
5. 如果 Ollama 不可用，页面应保留结构化事实、规则和引用状态，并明确提示不能判断；不要在展示时把降级结果说成模型回答。

## 6. 展示验收清单

| 画面 | 应看到的结果 |
|---|---|
| 登录后右上角 | 家庭名、当前成员姓名、actor ID/角色；爷爷和奶奶不同 |
| 人脸凭证 | 两个成员各有动态注册凭证；不出现原图或模板 |
| 视觉扫描 | OCR/条码证据、任务状态、模型/规则版本 |
| 人工复核 | 候选卡、规格/厂家/注意事项、明确的“确认保存” |
| 风险提醒 | 仅针对已确认事实的重复/相互作用规则和依据 |
| 本地助手 | 五个本地/受控节点的执行轨迹、可展开详情、引用来源 |

## 7. 清理与回滚

展示结束后执行：

~~~powershell
.\scripts\stop-demo.ps1 -KeepDatabase
~~~

这会停止本次脚本启动的 API、Web、worker，保留 MySQL、Ollama 和本地模型。下次展示可以复用同一演示家庭；如果要重新采集某个成员的人脸，应在“人脸凭证”页面撤销旧凭证后重新注册。正式发布前仍需完成摄像头真实环境阈值校准、隐私 R3、持久化会话和模型/主数据正式评估。
