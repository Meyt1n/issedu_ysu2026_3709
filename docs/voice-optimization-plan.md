# 语音识别优化方案

## 问题分析

### 延迟问题
1. 浏览器 Web Speech API 依赖远程服务器（Google/Edge）
2. 网络往返延迟（RTT）100-300ms
3. 识别会话断开重启延迟 30ms
4. 静音检测时间过长（15秒）

### 识别错误问题
1. 中文同音字混淆（小燕→晓燕、小严等）
2. 唤醒词误触发
3. 环境噪音干扰
4. 热词纠正库不完善

## 优化方案

### 第一阶段（立即实施，1-2周）

#### 1. 减少识别备选项
- 当前：`maxAlternatives: 3`
- 优化：`maxAlternatives: 1`
- 收益：减少 20-30% 处理延迟

#### 2. 调整静音检测时长
- 当前：15秒/18秒
- 优化：2.5秒/3.5秒
- 收益：用户体验大幅提升

#### 3. 缩短重启延迟
- 当前：30ms
- 优化：10ms
- 收益：识别连续性更好

#### 4. 扩展热词纠正库
- 补充医疗健康高频词
- 添加数字、家庭成员等常用词
- 收益：准确率提升 15-20%

#### 5. 默认开启双重唤醒
- 当前：单次唤醒（误触发多）
- 优化：双重唤醒确认
- 收益：误唤醒率降低 60%

### 第二阶段（2-4周）

#### 1. 噪音检测和提示
- 启动前检测环境噪音
- 高噪音时提示用户
- 自动调整识别参数

#### 2. 置信度阈值过滤
- 新增 `wakeConfidenceThreshold: 0.7`
- 低置信度结果不触发唤醒
- 减少误触发

#### 3. VAD（语音活动检测）
- 精确检测说话开始/结束
- 优化断句时机
- 减少漏字和错字

#### 4. 个性化学习
- 记录用户纠正习惯
- 自动应用历史纠正
- 越用越准确

### 第三阶段（1-2月）

#### 1. 本地识别引擎
- 集成 Vosk 或 Whisper.cpp
- 离线可用
- 延迟降至 50ms 以下

#### 2. 混合识别模式
- 本地+在线双路识别
- 快速显示本地结果
- 在线结果更新纠正

#### 3. 性能监控
- 延迟统计
- 准确率追踪
- 持续优化依据

## 预期收益

## 注意事项

1. **兼容性**：确保 Chrome/Edge/Safari 都能正常工作
2. **降级策略**：本地识别失败时回退到在线模式
3. **用户反馈**：添加"识别有误"反馈入口
4. **隐私保护**：本地识别不上传语音数据
5. **性能平衡**：监控 CPU/内存使用，避免卡顿

## 技术选型

### 在线识别
- ✅ Web Speech API（已使用）
- 优点：免费、集成简单
- 缺点：依赖网络、延迟高

### 本地识别
- 🎯 Vosk（推荐）：轻量、中文支持好
- ⭐ Whisper.cpp：准确度高、但体积大
- ❌ PocketSphinx：准确度较低

### 混合方案
本地识别（快速响应）+ 在线识别（准确纠正）
