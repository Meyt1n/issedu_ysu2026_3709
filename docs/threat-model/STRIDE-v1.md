## 2. STRIDE 威胁清单

### 2.1 Spoofing（身份伪造）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| S-01 | 伪造 `X-Actor-ID` 头冒充其他用户 | 越权访问家庭成员健康数据 | ⚠️ 当前 `allow_dev_actor_header=true`，生产环境 `REAL_AUTH_REQUIRED` 返回 501 | P0：实现真实身份认证前，dev 模式下校验 actor_id 格式和来源 IP；生产环境强制 OAuth2/OIDC |
| S-02 | 伪造家庭成员身份创建虚假健康事件 | 污染健康事件链，误导照护决策 | ⚠️ 当前仅校验 `household.created_by == actor_id` 或授权记录 | P1：成员创建时记录创建者身份链；健康事件追加需双重校验 |
| S-03 | 伪造天气服务响应注入虚假环境数据 | 触发错误的天气行动卡建议 | ❌ 天气适配器未实现 | P1：天气适配器启用时校验 TLS 证书 + 响应 Schema + 来源 IP |

### 2.2 Tampering（数据篡改）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| T-01 | 直接修改数据库绕过 API 授权 | 健康事件、授权记录被篡改，审计链断裂 | ⚠️ 数据库仅受网络隔离保护，无应用层签名 | P0：健康事件表增加 HMAC 签名列，写入时签名、读取时校验 |
| T-02 | 篡改健康事件 `payload` 或 `evidence` 字段 | 事实链不可信，风险规则误判 | ❌ 无完整性保护 | P0：事件追加后对其 hash 上链/记录，重放时校验 |
| T-03 | 篡改 `outbox_message` 投递状态 | 下游消费者错过关键事件 | ⚠️ outbox 表仅有 `dispatched` 布尔标记 | P1：outbox 增加 `version` 和 `dispatched_at` 时间戳，消费者做幂等校验 |
| T-04 | 中间人篡改前端静态资源 | 注入恶意脚本窃取健康数据 | ⚠️ 前端通过 Vite dev server 或静态文件服务 | P1：生产构建启用 SRI（子资源完整性）；CI 对构建产物做 hash 校验 |

### 2.3 Repudiation（抵赖/不可否认）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| R-01 | 操作者否认执行了撤销授权操作 | 授权纠纷无法仲裁 | ⚠️ `revoked_at` 记录了时间但未记录操作者 IP 和 User-Agent | P1：所有写操作记录 `actor_id` + `timestamp` + `request_id` + `client_ip` |
| R-02 | 管理员否认修改了风险规则版本 | 风险决策无法追溯 | ❌ 规则版本管理尚未实现 | P2：规则变更走 Git 提交 + PR 审批，版本号绑定 commit hash |
| R-03 | 删除操作缺少不可否认证据 | 隐私合规审查时无法证明已删除 | ❌ 删除仅做物理删除，无审计留存 | P1：删除操作保留脱敏审计记录（操作者、时间、请求 ID、删除范围），不含敏感正文 |

### 2.4 Information Disclosure（信息泄露）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| I-01 | 日志输出健康事件 `payload` 正文 | 密钥、药品、疾病信息泄露到日志文件 | ❌ 当前无日志脱敏 | **P0：日志中间件统一脱敏，匹配密钥模式 + 健康字段模式，替换为 `<REDACTED>`** |
| I-02 | 错误响应返回数据库堆栈或 SQL 语句 | 数据库结构泄露，辅助 SQL 注入 | ⚠️ FastAPI 默认不会暴露，但 `ValueError` handler 直接返回 `str(exc)` | P0：生产环境 `app_env=production` 时错误响应不返回内部细节 |
| I-03 | 天气适配器外发健康数据 | 城市编码之外的敏感字段泄露到外部服务 | ❌ 天气适配器未实现 | **P0：出口守卫校验请求体，仅允许 `{city_code, district_code}`，拒绝含 `member_id/name/drug/disease/allergy/report/image/vector/conversation` 的请求** |
| I-04 | CI 日志泄露测试数据中的密钥或健康字段 | CI 公开可读，敏感信息扩散 | ⚠️ CI 已有 gitleaks，但未覆盖健康字段模式 | P0：gitleaks 配置增加健康字段正则规则 |
| I-05 | 备份文件包含未加密的健康数据 | 备份介质被窃取或误放 | ❌ 备份机制未实现 | P1：备份前加密，密钥与备份分存，备份文件 restrict 权限 |
| I-06 | 向量索引中编码了未授权的健康事实 | RAG 检索时未做权限前置过滤 | ❌ RAG 尚未实现 | P2：RAG 实现时做权限前置过滤 + 检索结果脱敏 + 引用校验 |

### 2.5 Denial of Service（拒绝服务）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| D-01 | 大量无效请求耗尽 API 连接池 | 合法照护操作被阻塞 | ❌ 无限流、无连接池限制 | P1：Uvicorn 配置 `limit_concurrency` 和 `limit_max_requests` |
| D-02 | 天气服务不可用时阻塞核心链路 | 家庭照护功能因外部依赖不可用而整体降级 | ⚠️ 架构要求"不可用不能阻塞核心链路"，但未实现 | **P0：天气适配器调用设超时（≤3s）+ 异常捕获 + 降级返回空行动卡，不抛异常** |
| D-03 | 大文件上传耗尽磁盘或内存 | API 进程 OOM 或磁盘满 | ⚠️ `max_upload_bytes=10MB` 已有，但未限制并发上传数 | P1：增加并发上传限制，文件写入前校验磁盘余量 |
| D-04 | Ollama 推理超时阻塞请求 | LLM 助手不可用时影响用户体验 | ❌ Ollama 未集成 | P2：LLM 调用设超时 + 降级策略，不可用时返回"助手暂不可用" |

### 2.6 Elevation of Privilege（权限提升）

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| E-01 | 非家庭 owner 通过篡改 `actor_id` 创建成员 | 越权向他人家庭添加成员 | ⚠️ `require_household_owner` 已校验 `created_by == actor_id` | 当前缓解基本充分，需补：owner 变更时需原 owner + 新 owner 双重确认 |
| E-02 | 授权过期后仍可访问 | `valid_until` 校验依赖应用层，时钟偏移可绕过 | ⚠️ `has_authorized_action` 已校验 `valid_until > now` | P1：服务器时钟同步 NTP；授权过期加 5 分钟缓冲防时钟抖动 |
| E-03 | 通过批量请求枚举 member_id | 遍历发现未授权成员的存在性 | ⚠️ 404 和 403 返回不同 detail，可区分"不存在"和"无权限" | P1：未授权访问统一返回 404，不泄露资源存在性 |
| E-04 | 模型/知识管理员通过管理权限访问家庭数据 | 管理员角色越权读取健康事件 | ❌ 管理员角色尚未实现 | P2：管理员权限与数据访问权限正交设计，管理员不能自动读取家庭数据 |
| E-05 | 依赖劫持——恶意包通过 npm/pip 供应链注入 | 前端或后端在 CI 或运行时执行恶意代码 | ⚠️ CI 有 `npm ci` 和 `uv sync --frozen`，但无依赖审查 | P0：CI 增加 `npm audit` / `pip audit`；锁定依赖 hash；关键依赖变更需人工审查 |

### 2.7 密钥与备份专项

| ID | 威胁 | 影响 | 当前状态 | 缓解措施 |
|---|---|---|---|---|
| K-01 | `.env` 或 `.env.example` 中残留真实密钥提交到仓库 | 数据库密码、API Key 泄露 | ⚠️ CI 已有 gitleaks | P0：补充 `.gitleaks.toml` 规则覆盖中文常见密钥模式；`.env.example` 仅含 `change-me` 占位符 |
| K-02 | 代码注释或 docstring 中硬编码密钥 | 密钥泄露到公开文档 | ❌ 无扫描 | P0：gitleaks 配置加入注释扫描；CI secret-scan job 覆盖 `src/` 和 `docs/` |
| K-03 | Docker 镜像层中缓存密钥 | 镜像分发后密钥不可撤销 | ❌ 无 Dockerfile 规则 | P1：`.dockerignore` 排除 `.env`；多阶段构建；镜像扫描 |
| K-04 | 备份恢复时未校验完整性 | 恢复被篡改的备份导致数据污染 | ❌ 备份未实现 | P2：备份时附带 HMAC 签名，恢复前校验 |

## 6. 回滚

如威胁模型被证明有重大遗漏或过度约束：
1. 恢复上一版威胁模型文档（Git 回滚）
2. 对应的缓解代码通过 `WEATHER_ADAPTER=disabled` 和环境变量开关逐项关闭
3. 本地核心功能（家庭/成员/事件/授权）不依赖威胁缓解措施
