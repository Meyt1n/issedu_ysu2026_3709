# HomeCare Twin 任务拆分与交付清单

## 1. 唯一执行入口

完整的八周阶段、36 个 Story/Issue、依赖关系、角色交接、Ready/Done 门禁和最终交付条件统一维护在[项目全生命周期开发流程](19-项目全生命周期开发流程.md)。本文件只保留任务拆分原则和交付物索引，避免与阶段路线图形成两套编号。

`HCT-105` 已用于“双仓库成员身份映射与同步”；原计划中的“字段级子女视图”统一使用 `HCT-106`。任何新 Story 编号必须先在全生命周期流程中登记并检查 `docs/stories/`，不得重复占号。

## 2. 拆分原则

- 每个 Story/Issue 在 1 至 3 天内形成可演示、可回滚的纵向增量；
- 一个 Issue 只绑定一个 Story 和一组明确 FR/NFR；
- 优先按“页面 + API + 数据 + 测试 + 证据”贯通，不按技术层堆积半成品；
- 负责人、复核人、风险 R0-R3、依赖、允许修改文件和回滚必须在进入 Ready 前填写；
- 视觉、规则、RAG、LLM 和模型任务必须同时交付固定集、失败样例、版本登记和回滚；
- Mock、固定文本、截图、Notebook 或训练曲线只能作为开发材料，不能作为功能完成证据。

## 4. Story 最小字段

需求编号、用户价值、范围/非目标、风险等级、输入/输出/状态/异常、Given/When/Then、负责人/复核人、依赖、允许修改文件、测试/评估、数据/模型/规则版本、部署影响和回滚。

Story 文件命名为 `docs/stories/HCT-xxx-简短标题.md`。Issue 可以先进入 Backlog，但没有 Story 文件不得进入 Ready，也不得创建功能 PR。

## 5. 交付物清单

- 前后端源码、OpenAPI、MySQL 迁移、锁文件和三档部署说明；
- 数据集/标注规范、数据卡、YOLO V1/V2 模型登记和评测报告；
- 指令数据、LoRA/量化模型登记、基础/微调对照和安全红队；
- 规则集、来源、版本、单元测试、风险证据和告警预算报告；
- RAG 来源/许可/切片/Embedding/索引版本与引用完整性报告；
- 需求追踪、ADR、测试报告、隐私报告、备份恢复、演示录屏和答辩材料；
- GitHub 与内部仓库相同的 `master` SHA 及成员同步记录。

## 6. 状态更新

Issue 关闭只代表该 Story 的 PR 和验收已完成。FR/NFR 只有在需求追踪矩阵中链接自动测试、人工演示、环境/版本和回滚证据后，才能标记为“已验证”。
