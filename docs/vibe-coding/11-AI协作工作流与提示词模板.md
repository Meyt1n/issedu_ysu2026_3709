# AI 协作工作流与提示词模板

## 1. 任务卡模板

```markdown
# 任务标题

## 背景与用户价值
[为什么做]

## 范围
- 必须完成：
- 明确不做：
- 禁止修改：

## 输入与输出
[接口、数据结构、页面或命令]

## 验收条件
- Given ... When ... Then ...
- 异常/权限/安全条件：

## 相关材料
[文件、接口、ADR、设计链接]

## 验证
[格式化、静态检查、测试命令]
```

## 2. 实现提示词

```text
你正在实现“[任务]”。先阅读 AGENTS.md、[相关文档] 和现有代码。

请先输出：
1. 对需求和验收条件的复述；
2. 将修改的文件与原因；
3. 发现的歧义、假设和医疗/隐私/权限风险；
4. 最小实现步骤。

确认范围后小步实现。不得修改[禁止范围]，不得引入真实患者数据、密钥或未说明依赖。
完成后运行[测试命令]，报告真实结果、未验证项、风险和回滚方式。
```

## 3. 代码评审提示词

```text
请只审查当前差异，不直接修改。以正确性、越权、隐私泄露、医疗误导、
提示词注入、并发/事务、错误处理和测试缺口为重点。

每个问题必须包含：严重度、文件与行号、可触发场景、实际影响和最小修复建议。
如果没有问题，说明检查过哪些风险和仍无法验证的部分。不要只总结代码。
```

## 4. 测试生成提示词

```text
根据[需求/接口]补充最小但充分的测试。先列测试矩阵，覆盖：
正常、边界、错误、未登录、越权、重复请求、依赖故障、敏感信息泄露，
以及医疗 S0-S3 安全场景。只使用合成数据。

测试必须验证可观察行为，不依赖实现细节，不通过关闭安全校验来通过。
运行相关测试并报告命令与结果。
```

## 5. RAG 评估提示词

```text
基于已授权的[知识库版本]设计评估集，包含有答案、无答案、相似但不支持、
冲突来源、越权文档、提示词注入和紧急医疗场景。

给出每题期望引用和期望安全行为。不要生成真实患者资料。
计算 Recall@K、引用准确率、无答案识别率和紧急场景召回率，并保留失败样例。
```

## 6. AI 输出记录

PR 中填写：

```markdown
## AI 使用声明
- 使用工具/模型：
- AI 参与：需求拆解 / 代码 / 测试 / 文档 / 评审
- 关键提示词或任务卡：
- 人工修改与复核：
- 未采纳建议：
- 测试证据：
- 剩余风险：
```

不要粘贴包含密钥、真实医疗信息或其他用户数据的完整对话。

## 7. 常见失败模式

| 失败 | 纠正方式 |
|---|---|
| “帮我把项目写完” | 切成单一用例和可执行验收条件 |
| AI 虚构已有接口 | 提供事实文件并要求先搜索引用 |
| 为通过测试删除校验 | 把安全规则写成不可绕过回归测试 |
| 一次生成大量不可审查代码 | 限制文件和差异规模，逐步提交 |
| 医疗回答过度确定 | 增加证据阈值、拒答与人工升级 |
| 用真实数据调试 | 使用合成 fixture 并执行敏感信息扫描 |
