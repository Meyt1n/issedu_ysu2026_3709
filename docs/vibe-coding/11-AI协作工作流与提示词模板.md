# AI 协作工作流与提示词模板

## 1. 使用方法

提示词模板不能替代任务卡、仓库事实和人工判断。使用时：

1. 先填写任务卡和风险等级；
2. 只附相关事实文件，不把整个仓库或敏感数据交给模型；
3. 先让 AI 复述与计划，再授权修改；
4. 代码、测试、评审尽量分成不同会话或不同阶段；
5. 保留关键提示词版本、人工修改和验证证据。

## 2. 通用上下文包

```text
项目阶段：[启动准备/开发/验收]
任务编号与需求编号：
风险等级：[R0/R1/R2/R3]
目标和用户价值：
必须完成：
明确不做：
允许修改：
禁止修改：
事实文件：
输入/输出/异常/权限：
验收条件：
医疗、隐私、数据和 AI 风险：
验证命令：
输出格式：
```

## 3. 需求澄清提示词

```text
你现在只做需求澄清，不写代码。

阅读[任务卡和需求文件]后输出：
1. 用自己的话复述用户、场景、价值和非目标；
2. 把验收条件改写成 Given/When/Then；
3. 列出正常、边界、错误、未登录、越权、依赖故障和回滚场景；
4. 识别医疗误导、隐私、数据授权、提示词注入和模型不确定性风险；
5. 列出必须由人决定的歧义，不替用户做产品决策；
6. 判断任务是否足够小，若过大则给出可独立验收的拆分。

每条结论引用事实文件。没有证据时标注“待确认”。
```

## 4. 仓库调研提示词

```text
你现在只读仓库，不修改文件。

围绕[目标]搜索：
- 现有实现和复用点；
- 相关契约、数据模型、配置、测试和 ADR；
- 可能冲突的命名、依赖和模块边界；
- 当前真实状态与文档是否一致。

输出具体文件/符号、证据和缺口。不要仅凭目录名推断已经实现。
```

## 5. 实施计划提示词

```text
根据已确认的任务卡和调研结果，给出最小实施计划，不修改文件。

计划必须包含：
1. 文件清单及每个文件的修改原因；
2. 实现顺序和每一步可观察结果；
3. 先失败的测试/评估样例；
4. 接口、迁移、依赖、配置、模型和数据影响；
5. 医疗/隐私/权限风险控制；
6. 从窄到宽的验证命令；
7. 回滚方式和超出范围时的停止条件。

如果需要新增依赖或跨模块修改，给出替代方案和取舍。
```

## 6. 小步实现提示词

```text
你正在实现[单一任务]。已批准计划为[计划链接/摘要]。

规则：
- 只修改[允许文件]，不得修改[禁止范围]；
- 先建立或确认失败测试，再做最小实现；
- 不引入真实患者数据、密钥、未说明依赖或伪造模型结果；
- 发现计划外依赖、数据迁移或安全影响时立即停止说明；
- 每完成一个可验证步骤就运行对应测试；
- 不顺手重构无关代码。

结束时按“结果、变更、验证、限制、风险、回滚”报告。
```

## 7. 调试提示词

```text
请诊断[失败现象]，先不要修改代码。

已知信息：
- 复现步骤：
- 期望/实际：
- 错误日志和请求 ID：
- 最近变化：
- 环境和版本：

请：
1. 区分事实与假设；
2. 给出按可能性排序的根因；
3. 为每个根因设计最小证伪实验；
4. 先运行只读/低风险检查；
5. 找到根因后提出最小修复和回归测试；
6. 不通过关闭校验、吞异常或放宽测试来“修复”。
```

## 8. 代码评审提示词

```text
请只审查当前差异，不直接修改。

优先检查：
- 正确性、边界、事务、并发和幂等；
- 未登录、越权、字段级授权和资源枚举；
- 医疗误导、S3 升级、低置信度和无证据行为；
- 敏感信息、提示词注入、不安全输出和过度工具权限；
- 数据删除传播、缓存/向量/对象残留；
- 依赖、许可证、回滚和兼容性；
- 测试是否只验证实现细节或漏掉失败场景。

每个发现包含严重度、文件/行号、触发方式、影响、证据和最小修复建议。
没有发现时说明检查范围和仍无法验证的风险。
```

## 9. 测试设计提示词

```text
根据[需求/接口]先输出测试矩阵，再编写最小充分测试。

至少覆盖：
- 正常、边界、格式错误、重复和超时；
- 未登录、越权、撤权和资源枚举；
- 依赖故障、重试、幂等和降级；
- 敏感信息泄露、恶意文件和资源耗尽；
- 医疗 S0-S3、低置信度、无引用和冲突证据；
- 提示词注入、越权文档和不安全输出。

只使用合成/公开授权数据。测试验证可观察行为，不依赖私有实现细节。
运行相关测试并报告真实命令、退出状态和失败样例。
```

## 10. 威胁建模提示词

```text
针对[功能/数据流]建立轻量威胁模型。

列出：
1. 资产、信任边界、数据流和外部依赖；
2. 攻击者能力与滥用场景；
3. 认证/授权、隐私、提示词注入、数据投毒、不安全输出、
   模型拒绝服务、供应链和过度代理风险；
4. 现有控制、缺口、严重度和负责人；
5. 可自动化的安全测试与上线阻断条件。

不要把“使用大模型安全过滤”作为唯一控制。
```

## 11. 数据集与模型实验提示词

```text
为[模型目标]设计可复现实验，不直接声称某模型更好。

输出：
- 数据来源、许可、用途限制、去重与隐私处理；
- 按主体/药品实例隔离的训练/验证/测试划分；
- 基线模型、候选模型、固定配置和随机种子；
- 主指标、分组指标、阈值选择和接受标准；
- 光照、遮挡、角度、未知类和偏差测试；
- 硬件、运行时间、制品哈希和成本；
- 失败样例、已知限制和下一实验。

禁止根据测试集反复调参；禁止用单一准确率掩盖类别失败。
```

## 12. RAG 与提示词评估提示词

```text
基于已授权的[知识库版本]设计固定评估集，包含：
有答案、无答案、相似但不支持、冲突来源、过期资料、越权文档、
文档内提示词注入、敏感信息请求和紧急医疗场景。

每题给出期望引用、期望拒答/升级行为和允许的回答边界。
评估 Recall@K、MRR、引用准确率、引用覆盖率、无答案识别率、
越权阻断率和 S3 召回率。保留失败样例，不用 LLM 自评作为唯一裁判。
```

## 13. 文档更新提示词

```text
根据当前已合并代码、契约、测试和评审证据更新[文档]。

要求：
- 区分“计划、进行中、待验收、已完成”；
- 每个完成声明附提交/PR/测试或评估证据；
- 删除与实现冲突的示例，不虚构命令和接口；
- 更新需求追踪、已知限制、迁移和回滚；
- 检查相对链接、术语和版本一致性。

只修改文档，不根据未合并分支提前更新完成状态。
```

## 14. 交接提示词

```text
为下一位成员生成可验证交接，不继续实现。

包含：
- 目标和当前真实状态；
- 已合并/未合并提交；
- 已通过和失败的验证；
- 关键设计决定与原因；
- 未解决风险、阻塞和负责人；
- 下一步最小任务；
- 环境、数据、模型、提示词和知识版本；
- 不得丢失的失败样例和回滚入口。
```

## 15. PR 中的 AI 使用声明

```markdown
## AI 使用声明

- 工具/模型及版本：
- 任务卡/提示词版本：
- AI 参与：调研 / 设计 / 代码 / 测试 / 文档 / 评审
- 允许修改和禁止修改范围：
- AI 生成后由人修改的关键内容：
- 未采纳建议及原因：
- 人工复核人：
- 验证命令与结果：
- 数据/模型/提示词/知识版本：
- 剩余风险和回滚：
```

不要粘贴包含密钥、真实医疗信息、完整内部日志或其他用户数据的对话。

## 16. 常见失败模式

| 失败                       | 纠正方式                            |
| -------------------------- | ----------------------------------- |
| “帮我把项目写完”           | 拆成一个用户场景和可执行验收        |
| AI 虚构已有接口            | 要求先搜索并引用事实文件            |
| 不看计划直接改几十个文件   | 限定文件、先确认计划、小步提交      |
| 为通过测试删除校验         | 把安全规则写成不可绕过回归          |
| 用训练集或单个样例证明模型 | 冻结独立测试集并报告分组指标        |
| RAG 回答有链接但证据不支持 | 检查引用蕴含关系和无答案识别        |
| AI 自评 AI 输出            | 固定规则、人工抽样和独立评估结合    |
| 对话过长导致约束丢失       | 重新提供精简上下文包和当前事实      |
| 用真实数据“快速调试”       | 使用合成 fixture 并执行敏感信息扫描 |
| AI 摘要代替人工 review     | 评审人逐行阅读差异和测试证据        |
