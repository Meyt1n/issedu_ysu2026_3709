# HomeCare Twin AI 协作工作流与提示词模板

> 使用本文件前，必须先阅读[开发前必读与 Vibe Coding 工作流](开发前必读与Vibe%20Coding工作流.md)和根目录 [`AGENTS.md`](../../AGENTS.md)。任何 agent 都不能跳过共同工作流直接执行本模板。

## 1. 使用方法

选择下方模板，补齐方括号内容，并附相关需求、架构、API、领域模型和测试文档。不要把真实健康数据、密钥、原始报告或未脱敏图片发送给外部 AI。AI 产出必须由责任人验证。

## 2. 通用上下文包

```text
项目：HomeCare Twin，本地优先家庭主动照护教学系统。
医疗边界：不得诊断、处方、停药、换药、改变频次或剂量。
核心架构：MySQL 事实；关系为投影；规则计算风险；LLM 只解释和调用工具。
视觉边界：允许 MATCHED/CONFLICT/UNKNOWN/REVIEW；正式入库必须人工确认。
证据契约：事实 + 规则 + 文档 + 确认状态 + 版本。
任务：[需求编号和目标]
允许修改：[文件]
禁止修改：[文件/模块]
验收条件：[Given/When/Then]
验证命令：[命令]
```

## 3. 仓库调研

```text
只读检查与 [需求编号] 有关的代码、文档、测试、迁移和 ADR。
输出：当前事实、数据流、权限点、事件/状态机、外部依赖、已有测试、冲突和未知项。
不要修改文件，不要把文档计划当成已实现。
```

## 4. 实施计划

```text
为 [Story] 制定最小纵向计划。每步写明文件、接口/表/事件、失败测试、隐私与医疗风险、验证和回滚。
特别检查：未确认药品、跨成员授权、事件追加写、规则/模型版本和依赖降级。
```

## 5. 视觉任务

```text
设计/实现 [视觉任务]。保留原始证据、模型与阈值版本，允许四种识别状态。
评估按实体/日期/设备/视频会话分组，报告每类指标、未知转人工率、自动通过精确率、延迟和失败样例。
不得把 SKU 分类置信度当作药品身份或医学结论。
```

## 6. 规则任务

```text
实现/审查规则 [rule_id]。规则输入只能是已确认事实；输出包含等级、版本、参与事实、证据、覆盖范围、去重键和有效期。
请列出边界、反例、告警预算行为和 100% 必过单元测试。不要由 LLM 生成医疗结论。
```

## 7. RAG/LLM 任务

```text
实现/评估 [工具/回答链]。先授权，再工具/检索，再生成；返回结构化证据和真实引用。
覆盖检索为空、引用不支持主张、恶意文档、跨成员参数、诊断/处方/停药/剂量诱导和 Ollama 离线。
比较基础模型与微调模型的工具选择、参数、Schema、引用忠实和安全拒绝。
```

## 8. 代码评审

```text
按严重度审查差异，重点找可复现缺陷：越权、撤权延迟、历史覆盖、未确认事实进入规则、引用伪造、状态竞态、敏感日志、训练泄漏和不可回滚。
每条问题给出文件/行、触发条件、影响和最小修复；不要只做摘要或样式评价。
```

## 9. 测试设计

```text
基于 [需求] 设计单元、集成、契约、E2E、模型和安全测试。
至少覆盖成功、边界、UNKNOWN、CONFLICT、重复请求、依赖超时、未登录、跨家庭、撤权、删除传播、无证据和危险医疗请求。
固定评估集不可因结果不佳而替换。
```

## 11. AI 使用声明

PR 中记录工具/模型、使用环节、读取的仓库事实、生成内容、人工修改、未采纳建议、验证结果和复核人；只记必要摘要，不保存敏感提示词正文。
