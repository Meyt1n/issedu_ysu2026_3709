# HomeCare Twin 测试与验收方案

## 1. 测试分层

- 单元：事件状态机、候选融合、告警预算、计划安全时间窗、权限谓词。
- 迁移/集成：MySQL、文件、投影重建、向量权限、CV/OCR/Ollama/天气适配器。
- 契约：OpenAPI、错误码、幂等、Schema、模型/规则版本字段。
- E2E：扫描复核、事件、图谱、风险、解释、计划、照护升级和删除。
- 模型评估：固定视觉集、LLM 盲测集、V1/V2 对照和失败案例。
- 安全/隐私：越权、字段越权、撤权、网络出口、恶意文件、提示词注入、泄露、拒答和数据权利。

## 2. 视觉目标

视觉录入采用 OCR-first 作为主验收口径。YOLO 指标只能证明包装/条码区域辅助定位质量，不能替代药名、规格、厂家、批号和有效期的文字识别指标，也不能单独证明药品身份。

| 指标 | P0 目标 |
|---|---:|
| 药品包装 Recall | ≥ 95% |
| 受控测试集 mAP@0.5 | ≥ 90% |
| OCR 文本区域召回率 | ≥ 95% |
| 药名字段原始值保真率 | ≥ 95% |
| 规格/厂家/批号字段来源区域完整率 | 100% |
| 日期区域 Recall | ≥ 92% |
| 药名字段完全匹配率 | ≥ 90% |
| 有效期字段完全匹配率 | ≥ 88% |
| 良好图像条码解码率 | ≥ 95% |
| 未知 SKU 转人工复核率 | ≥ 95% |
| 自动通过结果精确率 | ≥ 99% |
| CPU 单图全流程 P95 | ≤ 8 秒 |
| V2 旧类别最大下降 | ≤ 2 个百分点 |
| 识别修正前后值与原因完整率 | 100% |

必须报告每类结果、置信区间/样本量、失败样例和硬件。消融至少比较：全图 OCR；OCR+YOLO 辅助裁剪；OCR+条码；OCR+条码+主数据；完整多证据融合，以及质量门控/拒识/困难样本 V2 的影响。不得以“YOLO 单独识别药品”作为发布路径。

字段级回归还必须验证：原始 OCR 文本不可被 LLM 覆盖、字段必须引用来源区域、无证据时输出 `UNKNOWN`/`REVIEW`、OCR 与条码冲突输出 `CONFLICT`、YOLO 不可用时仍能明确降级，以及人工修正保留 before/after 和模型版本。

## 5. 核心 E2E

1. 图片/视频成功识别并经人工确认写入事件。
2. 未知药品进入 `UNKNOWN`，不能加入风险计算。
3. OCR/条码冲突进入 `CONFLICT`，纠正后保留原预测和证据。
4. 新事件更新投影并触发有限规则，风险卡证据完整。
5. 一般告警合并，严重告警不被预算压制。
6. 计划只在安全时间窗内优化，连续未确认升级给有效授权照护者。
7. 无证据/越权/停药剂量问题被拒；Ollama 离线仍展示结构化规则结果。
8. 撤权立即生效；删除传播到文件、索引和缓存。
9. 子女只能读取授权字段；导出范围与二次确认可审计。
10. 家庭版健康上下文不产生网络出口；天气只发送城市/区县代码。
11. 页面不存在购药、问诊、广告和佣金导流入口。
12. V2 使用同一固定集比较，旧类退化超阈值则禁止发布。

## 6. 发布阻断

跨家庭或字段越权、未确认药品参与规则、严重案例漏报、危险医疗建议、引用伪造、删除/撤权失败、默认网络出口放行、真实敏感数据入库或日志、出现购药/问诊/广告导流、模型/规则/知识不可回滚、固定集泄漏或指标无法复现，任何一项存在均不得发布。

## 7. 验收证据

提交/PR、环境和版本、测试日志、固定集清单与哈希、数据卡/模型卡、失败案例、性能报告、安全红队、迁移/回滚、备份恢复、演示录屏及合并人复核记录。只有证据齐全才能在追踪矩阵标为“已验证”。
