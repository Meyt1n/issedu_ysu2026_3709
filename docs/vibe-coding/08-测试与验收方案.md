# 测试与验收方案

> 状态：启动前测试计划。当前没有已通过的功能、性能或模型验收结果。

## 1. 测试分层

| 层级     | 内容                                 | 门禁                   |
| -------- | ------------------------------------ | ---------------------- |
| 静态检查 | 格式、类型、安全扫描、依赖与密钥扫描 | PR 必须通过            |
| 单元测试 | 领域规则、阈值、权限、安全分级       | 核心逻辑覆盖率目标 80% |
| 集成测试 | 数据库、对象存储、向量库、模型适配器 | 关键接口通过           |
| 契约测试 | OpenAPI、错误码、权限和兼容性        | API 变化必须通过       |
| 端到端   | MVP 六条主链路                       | 发布必须通过           |
| 模型评估 | 视觉、检索、问答与安全回归集         | 达到登记基线           |
| 非功能   | 性能、并发、故障、安全与恢复         | 无阻断问题             |

## 2. 核心验收用例

### 用户与权限

- 用户只能看到本人及明确授权的家庭成员。
- 普通用户访问管理接口返回 `403`。
- 撤销授权后，API、搜索、缓存和导出均不可再访问。

### 药物识别

- 合规图片返回边界框、候选类别、置信度和模型版本。
- 模糊、遮挡、未知药物返回低置信度或拒识别。
- 恶意文件、超大图片、伪装扩展名被拒绝且无服务崩溃。

### 问答与 RAG

- 有证据的问题返回可定位引用。
- 知识库没有答案时明确“不确定”，不编造出处。
- 用户不能通过提示词访问其他用户文档。
- 高风险症状触发 S3 升级，普通问答不能覆盖该提示。
- 文档中的恶意“忽略系统规则”不会改变系统行为。

### 数据权利

- 用户可导出本人数据，导出包不含他人数据。
- 删除后业务库、对象存储、向量索引和缓存均不可检索。
- 审计保留最小删除事件但不保留被删除正文。

## 3. 性能目标

使用固定硬件和数据集记录结果：

- 普通 API：50 并发下 P95 < 800 ms。
- 单图识别：P95 < 3 s。
- RAG 问答首段：P95 < 8 s。
- 文档入库：50 页 PDF 在 5 分钟内完成或给出可观察的异步进度。
- 视频演示：达到约定抽帧率且业务 API 不被推理阻塞。

若硬件不满足，报告真实数据和瓶颈，不修改指标或伪造通过。

## 4. 发布阻断条件

- 存在越权、密钥或真实敏感数据泄露；
- S3 紧急场景不能稳定触发；
- 模型无版本、无评估或无法回滚；
- RAG 引用虚构或跨用户泄露；
- 删除功能只改界面状态、未删除派生数据；
- 关键流程失败且无明确降级；
- 测试依赖手工修改数据库或关闭安全校验。

## 5. 证据清单

每次里程碑保存测试命令和结果摘要、环境与模型版本、失败用例、性能报告、演示截图/录屏、已知限制和签字确认。缺陷使用“严重度 + 复现步骤 + 期望/实际 + 请求 ID”记录。

## 7. 测试前移

每个 Story 在编码前由开发和测试共同完成：

1. Given/When/Then 验收条件；
2. 正常、边界、错误、权限和依赖故障矩阵；
3. 所需合成/公开授权 fixture；
4. 可自动化范围与人工验收范围；
5. 失败时的用户可见行为；
6. 证据存放位置和验收人。

AI 可以生成测试草案，但测试工程师必须检查是否复制实现逻辑、遗漏失败场景、使用不合规数据或通过降低断言掩盖问题。

## 8. 模型与 RAG 评估集治理

- 评估集在调参前冻结版本，测试集不参与提示词/阈值反复优化；
- 数据按主体/药品实例隔离，报告重复和泄漏检查；
- 同时报告总体、每类、关键人群/场景和失败样例；
- RAG 题目包含有答案、无答案、冲突、过期、越权和注入；
- S3 场景以高召回为核心，同时评估普通问题误升级；
- LLM 自评可作辅助信号，不能作为唯一真值；
- 指标、环境、代码、模型、数据和提示词版本必须绑定。

## 9. 缺陷闭环

```text
发现 -> 分级 -> 复现 -> 根因 -> 修复 -> 回归
-> 受影响范围检查 -> 证据 -> 关闭
```

S0/S1 缺陷关闭前不得发布。医疗危险建议、越权、敏感数据泄露、伪造引用和删除不完整均按 S0 处理。

## 10. 过程与结业考核证据

培训材料的考核包含综合过程、项目代码质量和答辩。项目组至少保留：

- 考勤/短会、知识分享和角色履责记录；
- Story、提交、PR、代码检视和返工记录；
- 测试用例、执行结果、BUG 列表和测试报告；
- 数据卡、模型卡、实验和失败样例；
- 部署复现、演示录屏、PPT 和个人成果说明；
- AI 使用记录、人工复核和典型错误复盘。

代码质量不能用提交数量或 AI 生成行数替代；答辩必须能解释个人负责部分、设计取舍、测试证据和已知限制。
