# 八周迭代计划

## 1. 计划原则

培训周期为 8 周、40 个工作日、320 学时。课程学习和项目研发采用双轨制：

- **学习轨**：完成 PDF 规定的知识与练习；
- **项目轨**：把已掌握能力转化为经过评审的项目增量。

完成课堂练习不等于完成项目 Story。项目交付必须经过需求、设计、代码、测试、PR 和验收门禁。

## 2. 40 天课程与项目交付

| 周次    | PDF 学习轨（5 天）                                   | 项目轨目标                                            | 周末证据                                  |
| ------- | ---------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------- |
| 第 1 周 | 环境、NumPy、Matplotlib、Pandas                      | 项目启动、需求评审、数据分级、仓库和 Vibe Coding 基线 | 需求评审记录、角色表、风险清单、环境验收  |
| 第 2 周 | 数据分析、KNN、线性/多项式/逻辑回归                  | 合成数据管线、指标口径、实验追踪和最小 API 契约       | 数据卡草案、实验模板、OpenAPI 草案        |
| 第 3 周 | OpenCV、年龄/性别演示、神经网络、PyTorch/Keras       | 视觉数据来源与许可、非诊断标签边界、单图处理原型      | 数据样例审查、隐私评估、视觉适配器契约    |
| 第 4 周 | 情绪演示、AlexNet、ResNet、GoogLeNet、YOLO 基础      | 目标检测基线、数据划分、unknown 类和失败样例          | 训练基线、模型卡草案、每类指标            |
| 第 5 周 | YOLO 进阶、药物识别、Flask 与路由                    | 药物单图 MVP 和业务 API 骨架                          | 受控识别演示、拒识别测试、接口契约        |
| 第 6 周 | Flask 模板/表单、多模态 API、云平台                  | Web 最小链路、上传安全、异步任务和多模态适配器        | 登录到识别链路、恶意文件测试、演示录屏    |
| 第 7 周 | Ollama、Open-WebUI、VLLM/Xinference、WebUI、微调基础 | RAG/LLM 网关、引用、S0-S3 安全、微调可行性评估        | 带引用问答、拒答回归、微调决策 ADR        |
| 第 8 周 | LLaMA Factory、LoRA、评估/量化、国产模型、集成答辩   | 系统集成、加固、部署、答辩和项目总结                  | 测试报告、模型/数据卡、部署包、PPT 和录屏 |

具体模型版本以复现实验为准。若 GPU、数据或许可证不满足，允许以公开小模型、模拟适配器或受控 API 完成工程链路，但必须明确标注，不得伪装成真实训练成果。

## 3. 每周节奏

| 时间 | 活动                               | 必须产出                         |
| ---- | ---------------------------------- | -------------------------------- |
| 周一 | 计划、需求澄清、风险识别、任务拆分 | 周目标、Story、负责人、验收条件  |
| 周二 | 原型/实现、结对检查                | 小提交、实验记录、测试草案       |
| 周三 | 实现、集成、缺陷处理               | PR、自动测试、接口/模型证据      |
| 周四 | 回归、文档、演示准备               | 测试结果、缺陷状态、操作说明     |
| 周五 | 集成验收、复盘、状态更新           | 周验收记录、演示、度量、下周风险 |

每日短会只回答：昨天完成的可验证结果、今天的单一目标、阻塞和风险。不得用“正在研究”替代交付物。

## 4. 角色与制衡

| 角色                | 主要责任                       | 不得独立批准            |
| ------------------- | ------------------------------ | ----------------------- |
| 项目经理/客户代表   | 范围、优先级、验收、风险       | 自己实现的高风险变更    |
| 模块设计师/开发     | 设计、实现、单元测试、技术文档 | 自己的权限/医疗安全代码 |
| 测试经理/测试工程师 | 测试计划、用例、回归、缺陷报告 | 降低验收标准以适配实现  |
| 文档经理/文档工程师 | 文档基线、评审记录、证据归档   | 无证据修改完成状态      |
| 数据/算法负责人     | 数据卡、模型卡、实验和评估     | 自己模型的发布门禁      |

角色可兼任，但认证授权、医疗安全规则、数据发布和最终演示至少需要第二人复核。

## 5. 里程碑

### M0：第 1 周末，启动就绪

- 需求范围和非目标已评审；
- 数据来源、许可、隐私和删除方案已登记；
- Vibe Coding 规则、分支、PR 和证据模板可用；
- 候选架构和高风险技术有验证计划；
- 所有需求状态仍可为“未开始”，但负责人和验收条件明确。

### M1：第 2 周末，工程基线可实施

- 合成数据和实验追踪可复现；
- API/错误/版本字段形成契约草案；
- 最小 CI 和质量门禁方案评审通过。

### M2：第 5 周末，视觉链路可演示

- 限定药品类别可识别；
- unknown/低置信度可拒绝；
- 数据、模型、阈值和代码版本可追溯。

### M3：第 7 周末，带引用问答可演示

- 公共授权资料可以入库和检索；
- 回答引用可定位；
- 无答案、越权、注入和 S3 场景回归通过。

### M4：第 8 周末，可交付

- MVP 主链路和降级链路通过；
- 安全、性能、部署和恢复有真实报告；
- 答辩能说明 AI 参与、人工复核、失败案例和已知限制。

## 6. 课程进度变化规则

- 课程日程可调整，但里程碑退出条件不能静默降低；
- 未掌握的技术不得由 AI 直接生成后标记完成；
- 项目受阻时优先缩小功能或类别，不删除安全、测试和证据门禁；
- 每次计划变化记录原因、影响、负责人和新的验收日期；
- 第 8 周不得首次集成核心链路，最迟第 7 周形成可降级的端到端演示。
