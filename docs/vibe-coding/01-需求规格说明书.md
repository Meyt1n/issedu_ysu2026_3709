# HomeCare Twin 需求规格说明书

- 文档状态：P0 需求基线；HCT-001 合并后完成范围冻结，业务实现仍按追踪矩阵验收
- 产品阶段：8 周 P0 教学演示
- 状态事实：工程骨架、家庭/成员/授权、健康事件和状态投影已有起步实现；完整 P0 业务仍在开发，状态以需求追踪矩阵为准

## 1. 产品定位

HomeCare Twin 是本地优先、事件驱动、证据可验证的家庭主动照护系统。它围绕成员疾病史、过敏史、当前用药、库存、计划、指标、健康文档、环境变化和照护授权维护家庭健康运营型数字孪生，在事实变化时生成可解释、可确认、可追溯的任务。

系统不是在线诊疗平台、药品销售平台、自动分药硬件、持续监控设备或通用医学问答机器人。

### 1.1 产品硬承诺

- 家庭版健康数据默认不出网；成员档案、用药、报告、图片、视频、向量、对话和模型输入留在家庭可信域。
- 药盒录入采用 OCR-first：用户主动拍照后先做 OCR，YOLO 只辅助定位包装/条码区域，条码/二维码由专用解码器读取；包装特征、本地主数据和人工复核共同决定候选是否成立，冲突/未知/低质量不得自动进入健康状态。
- 子女/照护者权限细到成员、数据域/字段、动作、目的、期限和升级条件，不因家庭关系默认开放全部健康信息。
- 提醒按 INFO、GENERAL、HIGH、URGENT 分级；普通提醒合并并受每日预算控制，严重提醒不被预算压制。
- 风险等级由确定性规则决定；LLM 只能基于有权限的事实、规则和文档解释，不做诊断、处方、停药、换药或剂量判断。
- 产品只做居家照护，不提供买药、问诊、广告、佣金或健康消费导流。

## 2. 用户与场景

| 角色 | 目标 | 权限边界 |
|---|---|---|
| 家庭成员 | 录入事实、确认识别/计划、查看自己的任务与证据 | 默认只能访问自己或明确授权成员 |
| 授权照护者 | 处理被委托成员的未确认任务和风险 | 授权可撤回、限定成员/动作/期限 |
| 家庭管理员 | 邀请成员、配置照护关系、管理家庭级设置 | 不能绕过成员同意读取全部敏感正文 |
| 数据/知识管理员 | 审核主数据、规则、文档和困难样本 | 使用脱敏数据；发布需复核和版本化 |
| 模型/系统管理员 | 训练、评测、部署、回滚和查看技术指标 | 不自动获得家庭健康正文访问权 |

核心故事：老人或慢病成员新增药品，系统从图片/视频提取候选；冲突时由本人复核；确认事件改变关系投影并触发规则；风险卡由事实、规则、文档和确认状态共同支撑；照护者在授权范围内处理未确认任务。

## 3. 功能需求

### FR-01 身份、家庭与授权

- 账号密码加 PIN 或二维码二次确认；P0 不以人脸为身份入口。
- 支持家庭、成员、照护关系、成员/字段级权限、授权期限、目的约束、动作约束和撤回。
- 每次敏感读取/修改记录操作者、对象、目的、时间和结果。
- 默认拒绝子女查看高敏字段；授权界面显示可见范围、用途和到期时间。

验收：跨家庭和未授权成员访问被拒；撤权立即生效；子女只能读取被授权字段；审计不保存不必要的健康正文。

### FR-02 家庭健康事件中心

- 管理疾病、过敏、指标、药品、库存批次、计划、文档和照护关系。
- 每次新增、修改、确认、撤销形成不可覆盖事件，包含前后状态、来源、操作者、时间、证据及模型/规则版本。
- 当前状态由事件投影得到，事件时间线能解释变化原因。

验收：可重放事件恢复成员状态；更正使用补偿事件，不原地篡改历史。

### FR-03 多证据视觉录入

- 接收图片、浏览器拍照和短视频；执行模糊、曝光、反光、方向、透视、抽帧与去重检查。
- OCR 对整张受控图片提取文字框和原始值；YOLO 主要检测包装对象与条码区域，字段区域只作为可选裁剪辅助；条码/二维码由专用解码器读取，OCR、条码、包装特征和主数据共同排序候选。
- 字段抽取只能从已有 OCR token 和条码结果中选择药名、规格、厂家、批号和有效期；本地 LLM 只做 Schema 结构化和规范化，不生成不存在的文字或直接识别 SKU。
- 输出 `MATCHED`、`CONFLICT`、`UNKNOWN` 或 `REVIEW`，展示证据框、字段、置信信息和模型版本。
- 允许用户在复核页修正药品、规格、批号和有效期；原始预测不可覆盖，修正必须记录原因和操作者。

验收：未知 SKU 和证据冲突不得自动通过；只有人工确认/修正结果才能写入正式健康状态；原预测与修正差异可追溯。

### FR-04 家庭健康关系图谱

- 展示成员、疾病、过敏、药品、成分、批次、计划、文档和照护者关系。
- P0 从 MySQL 投影生成，可从事实库重建，不引入第二事实源。

验收：事件确认后关系更新；撤销/更正后投影一致；每条边可追溯到事实和事件。

### FR-05 风险规则与告警预算

- 支持过期、临期、低库存、重复成分、登记过敏及 30–50 组人工审核的有限相互作用/药物—疾病提示规则。
- 风险分为严重、较高、一般、信息四级；同类重复合并，一般/信息提示受每日预算限制，严重风险不受预算压制。
- 只有已匹配且人工确认药品参与计算；规则显示覆盖范围、来源和版本。
- 产品默认不提供购药、问诊或广告推荐；风险卡只指向查看依据、确认任务或联系现有专业人员。

验收：已知严重测试案例零漏报；普通告警预算 100% 执行；风险不输出“可一起吃”或“必须停药”。

### FR-06 计划、确认与照护升级

- 在既有医嘱/用户设定的安全时间窗内生成首次提醒和再提醒优化建议。
- 支持确认、延期、跳过、原因记录和连续未确认后的授权照护者升级。
- 新医嘱只比较版本差异，未经人工批准不切换计划；系统不得改变频次或剂量。

验收：越过安全时间窗的建议被阻止；升级对象必须有有效授权；每次批准可审计。

### FR-07 环境行动卡

- 天气适配器只使用城市/区县编码，读取温度、温差、降雨、空气质量、紫外线及可用花粉等级。
- 根据成员主动授权标签生成低风险生活安排提示；同一事件有效期内仅生成一次。

验收：不上传健康详情，不推断疾病，不触发药物/剂量修改。

### FR-08 本地证据型助手

- 识别意图并调用成员授权、MySQL、图谱、规则和 RAG 工具。
- 证据型回答必须包含数据库事实、规则命中、文档片段、人工确认状态及相关版本；证据不足时澄清或拒答。
- 拒绝诊断、处方、停药、换药和个体剂量请求；紧急表述直接提示求助。
- 家庭版不把健康上下文发送到云端；模型不可用时退化为结构化事实/规则卡。

验收：前端不能直连 Ollama；结构化输出通过 Schema 和引用完整性检查；越权拒绝率与安全目标见测试方案。

### FR-09 大屏与模型实验室

- 家庭大屏展示今日任务、待确认风险、事件趋势、照护响应和环境卡。
- 模型大屏展示 CV/LLM 版本、固定集指标、延迟、困难样本、训练任务和部署/回滚状态。
- 指标不得混入真实身份或健康正文。

### FR-10 困难样本与追加训练

- 保存原预测、人工修正、错误类型、授权状态和模型版本到困难样本池。
- 批量审核后在研发环境追加训练，以同一固定测试集比较 V1/V2，检查旧类别退化并支持回滚。

验收：未授权样本不训练；失败实验保留；家庭端不自动训练或发布模型。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 安全 | RBAC + 成员级 ABAC、最小权限、二次确认、限流、恶意文件检查 |
| NFR-02 隐私 | 本地默认不出网、网络出口默认拒绝、目的限定、最短留存、加密、可导出/删除/撤权 |
| NFR-03 可追溯 | 事实、事件、规则、文档、模型、提示词和工具调用均有版本/请求 ID |
| NFR-04 可用性 | 基础档在 LLM/向量库离线时仍可管理档案、规则和任务 |
| NFR-05 性能 | CPU 单图全流程 P95 ≤ 8 秒；其余预算由原型冻结 |
| NFR-06 可复现 | 环境、随机种子、数据划分、参数、制品哈希和回滚可复现 |
| NFR-07 可访问 | 状态不只依赖颜色；风险、证据和确认操作有明确文本 |

## 5. P0 页面

家庭总览、成员健康档案、视觉扫描中心、人工复核中心、家庭健康图谱、用药安全中心、健康计划中心、本地健康助手、家庭健康大屏、模型实验室，共十个核心页面。授权设置是成员档案、家庭总览和大屏共用的跨页面支撑视图，不新增核心页面编号。每个核心页面必须定义正常、加载、空、错误、离线、未授权和低置信状态；页面信息架构、状态和文案以[产品信息架构与页面设计](18-产品信息架构与页面设计.md)为准。

| 编号 | 核心页面 | P0 主要职责 |
|---|---|---|
| P0-01 | 家庭总览 | 汇总近期变化、待确认风险、今日任务和本地/授权状态 |
| P0-02 | 成员健康档案 | 展示获权的健康事实、来源、确认状态和时间线 |
| P0-03 | 视觉扫描中心 | 完成质量门控、多渠道证据提取和四态候选展示 |
| P0-04 | 人工复核中心 | 完成确认、修正、拒绝和独立训练同意 |
| P0-05 | 家庭健康图谱 | 展示可由已确认事件重建的家庭关系投影 |
| P0-06 | 用药安全中心 | 展示确定性规则结果、证据、等级和处理状态 |
| P0-07 | 健康计划中心 | 区分医嘱事实与安全时间窗内的提醒策略 |
| P0-08 | 本地健康助手 | 基于获权事实、规则和文档进行证据解释或拒答 |
| P0-09 | 家庭健康大屏 | 展示非敏感聚合、照护任务和本地运行状态 |
| P0-10 | 模型实验室 | 展示数据/模型版本、固定集指标、发布和回滚状态 |

## 6. 非目标

- 在线问诊、挂号、购药、保险或国家药品追溯平台真实接入；
- 买药链接、问诊转化、广告推荐和任何与居家照护无关的商业导流；
- 自动确认“已吞服”、自动开药/停药/换药/调剂量；
- 任意药品识别、完整相互作用数据库、疾病诊断或生理孪生；
- 人脸识别、连续家庭摄像头监控、医院 HIS 和全量可穿戴接入；
- 用课程 Demo 推断改善疾病结局。

## 7. P0 完成定义

完整演示必须贯通：短视频/图片 → 质量门控 → 多证据识别 → 冲突/未知复核 → 健康事件 → 状态/图谱 → 规则/告警预算 → 证据型解释 → 计划确认/照护升级 → 困难样本 V2。至少同时展示一个成功、一个拒识、一个证据冲突、一个越权、一个无证据拒答和一个依赖降级场景。
