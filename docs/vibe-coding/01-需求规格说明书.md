# 需求规格说明书

## 0. 文档状态

当前为启动前需求草案，尚未完成客户代表、开发、测试和资料组联合评审。所有需求状态均以
[需求追踪矩阵](12-需求追踪矩阵.md)为准。

## 1. 产品定位

“多模态智能医疗家庭助手”面向家庭健康管理和实训演示，融合图像/视频、文本、知识库和结构化健康记录，提供药物识别、健康信息问答、资料检索和家庭成员数据管理。

系统仅提供辅助信息和风险提示，不替代医生诊断、处方或急救服务。

## 2. 用户与场景

| 角色       | 核心需求                                                          |
| ---------- | ----------------------------------------------------------------- |
| 家庭用户   | 注册登录、管理本人资料、识别药盒/药瓶、咨询健康常识、查看历史记录 |
| 家庭管理员 | 经授权管理家庭成员、查看提醒和风险事件                            |
| 内容管理员 | 导入公开医学资料、审核切片与来源、维护药品基础数据                |
| 系统管理员 | 用户与权限管理、审计、模型配置、服务健康检查                      |

## 3. 功能需求

### FR-01 用户与权限

- 支持注册、登录、退出、令牌刷新和密码修改。
- 采用 RBAC，至少包含普通用户、家庭管理员、内容管理员、系统管理员。
- 家庭成员数据默认隔离；访问他人数据必须有可撤销授权。

### FR-02 药物图像识别

- 支持上传 JPG/PNG 图片，识别候选药盒或药瓶并返回边界框、类别、置信度和模型版本。
- 低于阈值时返回“无法可靠识别”，不得猜测药名。
- 结果必须提示核对包装、说明书或咨询药师；不得仅凭识别结果给出用药决定。

### FR-03 视频监控演示

- 支持摄像头或演示视频流接入、抽帧推理和结果叠加。
- 可演示年龄段/表情等非诊断性标签；结果不得解释为心理疾病判断。
- 默认不持久化原始视频，保存须另行征得同意并设置期限。

### FR-04 医疗辅助问答

- 支持多轮文本对话和“文字+图片”输入。
- 回答包含免责声明、信息来源和生成时间。
- 不确定或证据不足时明确拒答；命中高风险症状时优先给出立即就医/联系急救人员的升级提示。
- 历史对话按用户隔离，并允许查看与删除。

### FR-05 RAG 私有知识库

- 支持导入 PDF/DOCX 等已授权资料，完成解析、切片、向量化、检索和版本管理。
- 回答必须列出可定位到文档、章节/页码或切片的引用。
- 用户私人资料与公共资料使用独立命名空间和访问控制。

### FR-06 健康数据管理

- 支持家庭成员基础信息、过敏史、体检指标和事件记录的增删改查。
- 敏感字段加密保存，所有查看、导出、修改和删除写入审计日志。
- 支持用户导出和删除本人数据。

### FR-07 管理与可观测

- 提供用户、角色、知识文档、模型版本、风险事件和任务状态管理。
- 提供健康检查、结构化日志、关键指标和失败任务重试。

## 4. 非功能需求

| 编号   | 要求          | 基线                                           |
| ------ | ------------- | ---------------------------------------------- |
| NFR-01 | 普通 API 性能 | P95 小于 800 ms（不含模型推理）                |
| NFR-02 | 问答首段响应  | 演示环境 P95 小于 8 s                          |
| NFR-03 | 图片识别      | 单图演示环境 P95 小于 3 s                      |
| NFR-04 | 可用性        | 关键服务具备健康检查与明确降级提示             |
| NFR-05 | 安全          | TLS、RBAC、最小权限、速率限制、审计            |
| NFR-06 | 可追溯        | 每次 AI 输出记录请求 ID、模型/知识库版本和引用 |
| NFR-07 | 兼容性        | 最新两个主版本的 Chrome/Edge                   |
| NFR-08 | 可维护性      | 核心逻辑单测覆盖率目标不低于 80%               |

## 5. 明确不在首版范围

- 临床诊断、处方生成、自动改变用药计划。
- 与医院 HIS/EMR 的生产接入。
- 未经授权的人脸身份识别和持续行为监控。
- 用情绪识别结果推断精神疾病。
- 真实患者数据训练、公开部署或跨境传输。
- 对模型“百分之百准确”的承诺。

## 6. MVP 验收主链路

1. 用户登录并创建脱敏的家庭成员。
2. 上传合规药物图片，看到候选结果、置信度、免责声明和模型版本。
3. 导入一份公开医学资料，完成索引并提出问题，回答带可打开的引用。
4. 提出高风险症状问题，系统触发就医升级提示。
5. 管理员查看脱敏审计记录和服务状态。
6. 用户删除自己的对话或健康记录，删除结果可验证。

| 医疗垂类对话、文字+图片、多轮历史 | FR-04            | 必须加入证据、拒答和风险升级          |
| PDF/DOCX 私有知识库、语义检索     | FR-05            | 入库前授权，检索前鉴权，回答带引用    |
| 注册登录、JWT、家庭/健康数据 CRUD | FR-01/06         | 采用最小采集、可撤权和可删除设计      |
| Swagger/ReDoc、异步任务和管理后台 | FR-07            | 作为工程能力，不作为医疗可信证明      |
| LoRA/LLaMA Factory 微调           | FR-04 的候选实现 | 先证明 RAG/提示词不足，再决定是否微调 |
