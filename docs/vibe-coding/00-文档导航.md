## 需求来源与解释原则

- 来源：`【软通教育-燕山大学 8周】-基于Vibe Coding 的.pdf`，重点参考第 9-17 页。
- 原报告要求：视觉监控与药物识别、医疗垂类对话、RAG 私有知识库、综合后台与 Web 系统。
- 本方案增加：医疗免责声明、紧急风险升级、授权与审计、数据最小化、模型可追溯和人工复核。
- “实时”“精准”“专业”等描述必须通过指标和测试证明，不能仅作为宣传语。
- 报告中的 YOLOv12、DeepSeek/Llama、Flask/FastAPI、MySQL/ChromaDB 等是候选技术；最终版本必须经过实验记录或 ADR 决策。

## 文档维护规则

- 需求变更先改需求文档，再改设计、代码和测试。
- 每个功能 PR 必须引用需求追踪矩阵中的编号，并更新对应状态或证据。
- 架构或技术选型变化需在 PR 中写明原因、影响和回滚方式。
- 每个文档在重大迭代后由模块负责人复核。
- 本文档集是研发基线，不替代医生意见、伦理审查或正式合规评估。
