## 4. 配置分组

| 分组 | 示例 |
|---|---|
| 应用 | `APP_ENV`、公开地址、日志级别、请求体限制 |
| 数据库 | URL、池大小、连接超时、时区 |
| 安全 | JWT/文件加密密钥路径、令牌期限、允许源 |
| 文件 | 根目录、单文件/像素/视频限制、原图保留天数 |
| 视觉 | 模型/阈值/OCR/匹配器版本、设备、超时 |
| RAG | 索引路径/服务地址、Embedding/切片/知识版本 |
| LLM | Ollama 地址、模型、Schema、超时、并发 |
| 规则 | 规则集版本、告警预算、去重窗口 |
| 天气 | 城市编码、适配器、超时和缓存期 |

配置启动时用 Pydantic 校验；缺少增强档配置时不得影响基础档。密钥不允许默认值。

## 5. 端口规划

| 服务 | 容器内建议 | 暴露原则 |
|---|---:|---|
| Nginx/Web | 80/443 | 唯一对用户入口 |
| FastAPI | 8000 | 仅内部或开发机 |
| MySQL | 3306 | 仅容器/本机网络 |
| Qdrant（可选） | 6333 | 仅内部 |
| Ollama | 11434 | 仅内部 |

一期实际入口：API `8000`、Vite Web `5173`、Compose Web `8080`、MySQL 容器 `3306`。宿主端 `3306` 冲突时可临时映射 `3307`；Ollama `11434` 只允许本地增强档使用，完整业务能力仍未实现。

HCT-003 的可复现入口是 `uv run python scripts/hct003_probe.py {mysql|vision|ollama|all}`。探针输出结构化技术指标；`--strict` 只在选定能力不满足时返回非零。Ollama 服务或模型不可用时，默认结果是 `degraded`，严禁替换为云端健康上下文回退。

## 6. 依赖准入与复现

新增依赖须记录用途、替代方案、维护状态、许可证、体积、CVE、CPU/GPU 支持和卸载方案。所有语言依赖锁版本，容器镜像固定摘要，模型/数据/规则/知识保存版本与哈希。README 只写实际验证过的命令。

基础档生命周期统一使用 `scripts/start.ps1` 或 `scripts/start.sh` 的 `setup/up/health/down`；`check` 运行 Ruff、pytest、前端类型检查/构建和 Compose 静态校验。`down` 默认保留数据库卷，不能在团队脚本中隐式删除业务数据。HCT-101 的环境、版本、耗时和失败记录见[工程骨架干净环境复现记录](../reviews/HCT-101-工程骨架干净环境复现记录.md)。
