# 环境、配置与依赖规范

## 1. 当前状态

项目尚未建立可执行代码、依赖文件、Compose 或 CI。以下是启动候选基线，必须在第 1 周环境原型后确认。

## 2. 培训环境最低要求

- Windows 10/11 64 位；
- 至少 8 GB 内存，建议 16 GB；
- 至少 60 GB 可用磁盘；
- Git、Python、浏览器和 IDE；
- 模型训练按需要使用 AutoDL/PAI/其他经批准 GPU 环境；
- 本地大模型根据实际内存/显存选择，不把无法运行的大模型写成必选项。

## 3. 候选版本

| 项目     | 候选基线                          | 确认方式                     |
| -------- | --------------------------------- | ---------------------------- |
| Python   | 3.11.x                            | 课程库兼容和干净安装         |
| Node.js  | 建立前端时固定 LTS                | Vue/Vite 构建验证            |
| API      | FastAPI；Flask 为课程/管理端候选  | 原型和 ADR                   |
| ORM/迁移 | SQLAlchemy 2 + Alembic            | PostgreSQL/MySQL 原型        |
| 数据库   | PostgreSQL 16 或课程要求的 MySQL  | 功能、运维和团队能力评估     |
| 视觉     | PyTorch、OpenCV、可复现 YOLO 版本 | 小数据集基准                 |
| 向量库   | ChromaDB MVP 候选                 | 权限过滤、Recall@K、备份实验 |
| 本地 LLM | Ollama 候选                       | 资源、延迟和模型许可评估     |
| 测试     | pytest/httpx/Playwright 候选      | 首个纵向增量                 |

版本确认后写入依赖文件/锁文件，本文档只引用事实文件，不重复维护精确补丁版本。

## 4. 第 1 周环境验收

```powershell
git --version
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip --version
```

在依赖文件尚未建立前，不执行不存在的安装、迁移或启动命令。首个工程 PR 应补充：

- 依赖文件和版本策略；
- `.env.example`，只包含占位值；
- 最小健康检查；
- 本地检查命令；
- CI 使用的相同命令；
- 从全新克隆开始的复现记录。

## 5. 环境变量规划

| 前缀/变量          | 用途                     | 敏感       |
| ------------------ | ------------------------ | ---------- |
| `APP_*`、`API_*`   | 环境、名称、监听地址     | 部分       |
| `DATABASE_URL`     | 业务数据库               | 是         |
| `REDIS_URL`        | 缓存与任务队列           | 是         |
| `OBJECT_STORAGE_*` | 对象存储                 | 密钥为是   |
| `VECTOR_STORE_*`   | 向量库                   | 视认证配置 |
| `LLM_*`            | 模型网关、模型和 API Key | Key 为是   |

敏感值只通过本地未跟踪文件或秘密管理服务注入。缺失必需密钥时应拒绝启动，不能回退硬编码示例值。

## 6. 端口规划

## 7. 依赖准入

新增/升级依赖时记录：

- 解决的问题和不使用标准库/现有能力的原因；
- 精确版本、来源、许可证、维护活跃度和安全公告；
- 对镜像、CPU/GPU、内存、启动时间和攻击面的影响；
- Windows/CI/部署环境兼容性；
- 替代方案、锁定方式和回滚；
- 干净安装及相关测试。

模型权重、数据集、嵌入模型和外部 API 同样属于供应链依赖，必须记录来源、许可证、哈希和用途。

## 8. 可复现性

- 不依赖全局包、本机绝对路径或 IDE 隐式设置；
- 代码、依赖、数据库、模型、数据、提示词和知识库分别版本化；
- 模型权重和数据集不直接进入 Git，通过受控制品地址和哈希获取；
- 实验记录随机种子、硬件、运行时、参数、代码提交和成本；
- CI 从全新环境安装，禁止使用开发者缓存掩盖缺失依赖。

## 9. 环境完成定义

- [ ] 新成员可按文档建立环境
- [ ] 本地与 CI 使用相同主版本和检查命令
- [ ] 示例配置无真实密钥
- [ ] 最小服务和健康检查可运行
- [ ] 依赖许可证与漏洞检查有记录
- [ ] 模型/数据下载可校验哈希
- [ ] 清理和资源释放步骤明确
- [ ] 环境验收由另一名成员复现
