# HomeCare Twin Vibe Coding 开发约束

## 1. 目标

Vibe Coding 在本项目中是“人负责决策与验证、AI 加速可审查工作”的工程方法。AI 可以检索仓库、提出计划、生成小步代码与测试、分析失败和起草文档；不能决定医疗边界、数据授权、规则发布、模型发布或验收结论。

## 2. 事实优先级

已接受 ADR/迁移/OpenAPI/测试与模型登记 > 需求和架构基线 > 追踪矩阵/Issue > 会议与个人笔记 > AI 对话和外部示例。发现冲突必须报告并由责任人裁决，不能让 AI 猜测。

## 3. 风险分级

| 级别 | 示例 | 门禁 |
|---|---|---|
| R0 | 文案、无行为格式调整 | 一人检查 |
| R1 | 普通页面、非敏感查询 | 单测 + PR 评审 |
| R2 | API、迁移、模型适配器、文件上传 | 集成测试 + 合并人复核 |
| R3 | 成员授权、健康事件、风险规则、删除、模型/知识发布 | 威胁分析、安全回归、合并人复核、可回滚 |

## 4. 九步闭环

1. **澄清**：写出需求编号、用户价值、范围、非目标、风险和验收。
2. **检索**：读取相关需求、架构、接口、数据、ADR 和现有实现。
3. **复述与计划**：列出假设、允许修改的文件、验证和回滚。
4. **先建失败证据**：单测、契约用例、固定评估样本或可复现缺陷。
5. **小步实现**：每次只完成一个可验证纵向增量。
6. **自动验证**：正常、边界、故障、未登录、越权和撤权场景。
7. **AI 自审**：检查证据链、版本、敏感数据、幻觉和范围漂移。
8. **人工评审**：逐行检查关键差异；R2/R3 由合并人完成最终复核，不设置额外第二人 approval。
9. **验收沉淀**：更新追踪矩阵、模型卡/数据卡、ADR、演示和回滚记录。

## 5. HomeCare Twin 强制约束

- 未确认药品不得进入关系图谱正式状态或风险计算。
- `UNKNOWN` 和 `CONFLICT` 是合法结果，不得强制映射到已知药品。
- 风险由版本化规则生成，LLM 不改变风险等级、不补充剂量或治疗决定。
- 证据型输出必须携带事实、规则、文档、确认状态和版本；检索为空则澄清或拒答。
- 健康事件追加写；更正使用补偿事件，不覆盖审计历史。
- 训练、验证、测试按实体药盒、采集日期、设备和视频会话分组，防止相邻帧泄漏。
- 人工纠错进入困难样本池前必须检查授权；家庭端不得自动训练或发布。
- 天气接口只能获取粗粒度位置对应环境数据，不能上传家庭健康详情。

## 6. 禁止行为

- 用 mock、固定文本或 UI 截图宣称模型/业务已实现；
- 为通过测试关闭鉴权、安全检查、引用校验或降低目标阈值；
- 向外部模型、日志、Issue 或提示词粘贴真实健康数据和密钥；
- 让 AI 生成或批准相互作用规则、停药、换药、处方或剂量；
- 只保留最好实验、替换固定测试集或隐瞒旧类别退化；
- 在未读完整上下文时大范围重构，或混入与 Story 无关的修改。

## 7. AI 任务交付格式

每次 AI 产出至少说明：读取的事实源、所作假设、修改范围、验证命令/结果、未验证项、风险与回滚。合并人对最终提交负责，不能以“AI 生成”为免责理由；merge 记录即为人工复核证据。

## 8. 完成定义

- 验收条件逐条有证据；
- API、数据、模型、规则、知识和提示词版本一致；
- 正常、拒识、冲突、无证据、越权和依赖降级已覆盖；
- 无真实健康数据、密钥、模型权重或缓存误入仓库；
- 追踪矩阵和受影响文档同步；
- 回滚可执行且未夸大系统能力。
