# Vibe Coding 开发约束

## 1. 定义

Vibe Coding 在本项目中指：开发者用自然语言与 AI 协作完成需求澄清、设计、编码、测试和文档，但责任仍由人承担。AI 是受控的实现助手，不是需求负责人、医生、安全审批人或代码所有者。

## 2. 标准闭环

```text
需求卡片 -> AI 复述与拆解 -> 人工确认 -> 小步实现
-> 自动测试 -> 人工阅读差异 -> 安全检查 -> PR 评审 -> 合并
```

每个任务必须给 AI 提供：

- 背景与用户价值；
- 明确范围和禁止修改范围；
- 输入、输出与异常；
- 可执行的验收条件；
- 相关文件、接口和约束；
- 测试命令与交付格式。

事实来源的优先级为：

1. 已批准的需求与安全规范；
2. OpenAPI、数据库迁移和 ADR；
3. 当前分支代码与自动测试；
4. Issue/PR 中经确认的补充说明；
5. AI 的推断。

低优先级内容与高优先级内容冲突时，AI 必须停止相关实现并指出冲突。

## 3. 强制规则

### 3.1 需求与设计

- AI 不得擅自扩大需求；发现歧义时先列出假设和影响。
- 跨模块、数据库、权限、模型和公开 API 的变化先更新文档。
- 单次任务只解决一个可验证目标，避免“大而全”的提示词。
- 使用现有代码和仓库文档作为事实来源，禁止凭空虚构接口、字段和依赖。

### 3.2 编码

- 先搜索复用点，再新增实现；禁止复制出第二套认证、权限或错误处理。
- 保持模块边界；业务逻辑不得写在路由、模板或模型推理脚本中。
- 不吞异常、不返回伪造成功、不用硬编码测试数据冒充真实结果。
- 禁止提交密钥、真实患者数据、模型权重、构建产物和本地缓存。
- AI 不得绕过测试、关闭校验或删除安全规则来“让测试通过”。
- 外部依赖、模型、数据集必须记录版本、来源、许可证和用途。

### 3.3 医疗 AI

- 所有输出均为辅助信息；禁止确诊、开方、改变药量或替代急救建议。
- 必须实现高风险词与场景的确定性安全规则，不能只依赖 LLM 自觉。
- 无可靠引用或置信度不足时拒答/拒识别，不补全看似合理的结论。
- 情绪、年龄、性别等模型输出只用于技术演示，不得做歧视性决策。
- 训练集、验证集、测试集按主体隔离，防止同一对象泄漏到不同集合。

### 3.4 数据安全

- 默认使用合成或脱敏数据，采集真实数据必须有目的、授权、期限和删除方案。
- 任何上传内容都视为不可信输入；限制大小、格式、数量和处理时间。
- 提示词注入不能改变系统规则、访问其他用户知识库或调用未授权工具。
- 日志使用脱敏 ID；调试完成后清除临时文件和包含敏感内容的追踪。

### 3.5 变更规模

- 单个任务只包含一个用户价值或一个明确的工程改进。
- AI 先给出最小文件清单；新增文件或依赖超出清单时必须解释原因。
- 避免一次 PR 同时做功能、重构、依赖升级和格式化。
- 生成文件、锁文件和迁移可较大，但手写逻辑必须保持可逐段评审。
- 发现顺手可修的问题时记录为新 Issue，除非它会阻断当前任务。

### 3.6 禁止行为

| 行为 | 规则 |
|---|---|
| 虚构测试结果 | 禁止；必须报告真实命令、退出状态和失败原因 |
| 用 mock 冒充已接入服务 | 禁止；响应和文档必须明确标注 mock/未实现 |
| 自动合并或发布 | 禁止；必须由有权限的人确认 |
| 绕过认证或安全策略 | 禁止，即使只为演示或让测试通过 |
| 批量删除/迁移数据 | AI 只能生成方案和脚本，实际执行需人工确认 |
| 隐式更换模型或阈值 | 禁止；必须版本化、评估并记录 ADR/实验报告 |

## 4. AI 自检清单

AI 每次交付前必须回答：

- 改了哪些文件，为什么？
- 是否存在未经确认的假设？
- 是否引入依赖、迁移、配置或接口变化？
- 哪些测试已运行，结果如何？
- 对隐私、权限、医疗安全和回滚有何影响？
- 是否有无法验证的内容需要人工复核？

AI 最终交付按以下顺序汇报：结果、变更文件、验证证据、假设与限制、风险与回滚。不得用“应该可用”“理论上通过”替代未执行的验证。

## 5. 人工评审门禁

以下变化至少需要两人评审，其中一人是对应模块负责人：

- 认证、授权、加密、审计和数据删除；
- 医疗风险规则、系统提示词和拒答策略；
- 模型或知识库版本切换；
- 数据库迁移和公开 API 破坏性变化；
- 生产/演示环境发布。

评审人必须阅读代码差异和测试证据，不得只接受 AI 的摘要。

## 6. 完成定义

- 需求与验收条件可追溯；
- 实现无占位符和未解释的 TODO；
- 格式化、静态检查和相关测试通过；
- API、数据、部署或用户行为变化已同步文档；
- 不包含敏感数据或密钥；
- AI 参与范围和人工复核结果写入 PR；
- 有明确回滚方式。

## 7. 文档同步矩阵

| 发生变化 | 必须更新 |
|---|---|
| 用户行为或验收条件 | 需求规格、需求追踪矩阵、测试 |
| API 路径/字段/错误码 | OpenAPI、API 规范、契约测试 |
| 数据表/字段/保留期 | 数据模型、迁移、隐私规范、删除测试 |
| 模型/数据集/阈值 | 模型卡、数据卡、评估报告、版本配置 |
| RAG 切片/检索/提示词 | RAG 规范、评估集、提示词版本 |
| 架构或核心依赖 | 技术方案、ADR、部署文档 |
| 环境变量或端口 | `.env.example`、环境规范、部署文档 |
