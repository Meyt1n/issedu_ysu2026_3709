# 一期开发实施方案

## 1. 目标

一期建立可运行、可测试、可迁移、可持续扩展的业务后端基线，让后续视觉、RAG、LLM、
健康数据和 Web 小组能通过稳定接口协作。系统仍定位为健康信息与家庭照护辅助工具，
不进行诊断、处方或自动用药决策。

## 2. 报告原文复核

本方案于 2026-07-29 重新复核实训 PDF 第 9-17 页。原文要求构建可交互、可部署、可扩展的
多模态医疗家庭助手，并包含：

| 报告要求 | 一期处理 | 后续里程碑 |
|---|---|---|
| FastAPI 异步 API、Swagger/ReDoc | 已实现统一 API、自动 OpenAPI | 持续扩展 |
| JWT、SQLAlchemy、注册登录、七天免登 | 已实现短时 JWT 和七天刷新令牌轮换 | 二次认证/限流加固 |
| 家庭成员和健康数据 CRUD | 已实现家庭、角色与授权基线 | M3 健康档案/过敏/体检 |
| Flask 模块化管理后台 | 通过 ADR 保留为独立客户端 | M3 只调用业务 API |
| OpenCV/YOLO 药物与视频识别 | 只保留明确“未接模型”的 Demo | M2/M3 |
| DeepSeek/Llama、LoRA、本地推理 | 不伪造接入 | M3，先评估再选型 |
| LangChain、ChromaDB 私有知识库 | 先完成权限边界 | M2 |
| 图片+文字、多轮历史 | 不采集真实病例或患处图片 | M3 |

报告中的具体模型和 MySQL/Flask 是候选技术输入。仓库通过技术方案和 ADR 选用
FastAPI + PostgreSQL 作为统一业务数据基线，确保权限判断只有一个事实来源。

## 3. 已实现范围

### 工程底座

- `core/config.py`：环境变量强类型校验，生产环境拒绝示例密钥；
- `core/logging.py`：JSON 结构化日志，不记录请求正文或查询串；
- `core/errors.py`：稳定错误码和统一错误结构；
- `X-Request-ID`：校验调用方 ID，否则生成不可预测 ID；
- 严格 mypy、Ruff、80% 覆盖率和迁移一致性 CI。

### 身份与会话

- 邮箱注册与规范化唯一；
- Argon2id 密码哈希，不保存明文；
- 15 分钟访问 JWT；
- 七天随机刷新令牌，数据库只存哈希；
- 刷新时轮换，退出或旧令牌重放后不可继续刷新。

### 家庭、RBAC 与授权

- 创建家庭并自动建立 `owner` 关系；
- `owner/caregiver/member/viewer` 角色；
- 只有 owner/caregiver 可添加普通成员，只有 owner 可添加 caregiver；
- 授权仅允许 owner 创建，支持到期和立即撤销；
- 资源查询先做后端所有权/授权过滤，越权返回不可枚举的 404。

### 审计和数据库

- 认证、家庭和授权关键动作写入脱敏审计；
- Alembic 从空库建立六张一期表；
- PostgreSQL 16 Compose 用于协作开发，SQLite 用于快速测试；
- `/health` 检查进程，`/ready` 检查数据库。

## 4. 分层约束

```text
HTTP -> routes/schemas -> application -> db/core
                             |
                             +-> integrations（后续外部服务）
```

- `routes` 不写 SQL、不决定医疗安全规则；
- `application` 负责用例、权限和事务边界；
- `db` 只负责持久化模型与会话；
- `core` 不依赖具体业务；
- 后续模型只能通过 `integrations` 适配器接入，未接入时返回明确不可用状态。

## 5. 一期不做

- 不接真实视觉、LLM、RAG 或医疗数据；
- 不实现年龄、性别、情绪等摄像头推断；
- 不提供诊断、处方、药物身份确认或用药建议；
- 不实现完整健康档案 CRUD、数据导出删除和管理后台；
- 不把 Demo 固定回复描述为模型推理。

## 6. 验收方式

```powershell
Copy-Item .env.example .env
docker compose up -d postgres
.\scripts\check-local.ps1
.\scripts\start-demo.ps1
```

人工验收：

1. `/docs` 可看到一期接口和统一模型；
2. 注册、登录、刷新、退出链路可运行；
3. 越权用户无法读取家庭；
4. 授权后可读，撤销后立即不可读；
5. 审计输出不含密码、令牌或医疗正文；
6. `alembic upgrade head` 可从空库成功执行；
7. Demo 仍明确声明视觉模型和通用 LLM 未接入。

3. 建立健康档案、过敏和体检指标，先补字段授权与删除传播测试；
4. 为前端建立注册、登录、家庭和授权页面；
5. 定义视觉/RAG `integrations` 协议和不可用适配器；
6. 增加 PostgreSQL 服务级集成测试与备份恢复演练。
