# HomeCare Twin 一期开发实施方案

## 1. 一期目标

一期不直接追求完整十页和全部 AI 能力，而是建立可持续扩展的第一个安全纵向增量：**授权家庭成员手工/模拟录入一条药品事实，经人工确认形成不可覆盖事件，并在时间线中可追溯**。视觉、规则和 LLM 先以明确不可用的适配器占位，不伪装结果。

## 2. 启动就绪门禁

- [ ] 新项目需求、非目标和医疗边界完成团队评审
- [ ] MySQL/FastAPI/Vue 原型、版本和许可证通过 ADR
- [ ] 家庭、成员、授权、事件最小 Schema 评审完成
- [ ] 合成测试数据、数据分级和删除策略确认
- [ ] Story 负责人、合并确认人、验收和回滚明确
- [ ] CI、分支保护和密钥扫描可用

## 3. 第一个纵向增量

```text
登录
-> 创建/选择家庭成员
-> 建立本人或照护授权
-> 手工录入药品候选事实
-> 人工二次确认
-> 事务内追加 health_event + outbox
-> 更新当前状态投影
-> 时间线展示来源、操作者和确认状态
-> 撤权后禁止照护者访问
```

此阶段不得声称完成视觉识别或风险判断。

## 4. 分层与任务顺序

```text
HTTP routes/schemas
        -> application（授权、用例、事务）
        -> domain（事件、状态机）
        -> persistence（MySQL、outbox、投影）
        -> integrations（明确 unavailable 的 AI 适配器）
```

实施顺序：环境/健康检查 → 请求 ID/错误/脱敏日志 → 家庭/成员/授权迁移 → 认证与所有权 → 事件/outbox/投影 → 最小 Web 流程 → 撤权/重放/故障测试 → 部署复现和文档。

## 5. 一期明确不做

YOLO/OCR/条码、真实药品主数据、相互作用规则、计划优化、天气、RAG、LLM 微调、Ollama、模型大屏和真实健康资料。占位接口必须返回 `MODEL_UNAVAILABLE` 或能力清单，不能返回假药名、假置信度或固定医疗回答。

## 6. 一期完成定义

- 干净环境可以启动 Web/API/MySQL 并运行迁移；
- 未登录、跨家庭、未授权、撤权和重复请求测试通过；
- 事件不可覆盖，补偿和投影重建可验证；
- 日志/提交无密钥和健康正文；
- API、迁移、需求追踪和部署指南一致；
- AI 能力缺失时失败清晰、可观察、可测试。

## 7. 退出评审

开发演示纵向链，测试复核权限和事件，资料负责人核对证据，项目负责人确认边界。任一严重越权、历史覆盖、敏感日志或不可复现问题未关闭时，一期不得退出。
