# 一期开发实施方案

## 1. 文档状态

项目尚未开始开发。本方案定义从零启动的一期目标、前置门禁和首个可验证增量，不记录任何“已实现”内容。

## 2. 一期目标

一期只建立可运行、可测试、可迁移、可持续扩展的业务工程基线，让视觉、RAG、LLM、Web 和测试小组后续能够通过稳定契约协作。

一期不追求一次接入全部模型和基础设施，不采集真实患者数据，不对外提供诊断、处方或自动用药功能。

## 3. 启动就绪门禁（Definition of Ready）

以下项目全部通过后才能进入一期编码：

- [ ] 产品范围、用户、非目标和 MVP 主链路完成评审
- [ ] 医疗安全边界、S0-S3 风险分级和免责声明责任人明确
- [ ] 数据来源、许可证、脱敏、保留和删除方案登记
- [ ] 候选技术有原型验证计划和资源预算
- [ ] API、错误、版本和身份授权形成契约草案
- [ ] 测试组建立功能、安全和模型评估骨架
- [ ] 分支、提交、PR、AI 使用声明和证据模板可用
- [ ] 所有成员完成环境、Git、敏感数据和 Vibe Coding 规则确认

未达到门禁时只允许做文档评审、无敏感数据原型和环境验证。

## 4. 第一个纵向增量

首个增量只验证工程协作链路：

1. 提供 `GET /api/v1/health` 候选接口；
2. 建立统一配置、错误结构、请求 ID 和结构化日志；
3. 建立最小用户/家庭领域模型草案和迁移；
4. 实现一个受权限保护的家庭成员读取用例；
5. 补正常、未登录和越权测试；
6. 在 PR 中提供 AI 使用、测试结果、风险和回滚证据。

模型服务仅定义适配器契约和明确的“未配置/不可用”响应，不返回伪造识别或固定医疗答案。

## 5. 候选分层

```text
HTTP -> routes/schemas -> application -> domain -> persistence
                              |
                              +-> integrations（视觉/RAG/LLM）
```

- 路由只处理协议和校验，不写 SQL 或医疗安全规则；
- 应用层负责用例、权限和事务边界；
- 领域层保存与框架无关的规则；
- 持久化层通过接口访问数据库；
- 外部模型通过版本化适配器接入；
- 未接入服务必须失败清晰、可观察、可测试。

该分层需要在首个原型后通过 ADR 确认，不得把文档图直接视为最终实现。

## 6. 一期任务顺序

| 顺序 | 任务                    | 验收证据                   |
| ---- | ----------------------- | -------------------------- |
| 1    | 环境、配置、健康检查    | 干净环境复现记录           |
| 2    | 请求 ID、错误和脱敏日志 | 单元测试与日志样例         |
| 3    | 用户/家庭领域模型和迁移 | 迁移前进/回滚测试          |
| 4    | 最小认证与授权          | 未登录、越权、撤权测试     |
| 5    | 审计事件骨架            | 不含敏感正文的样例         |
| 6    | 模型适配器契约          | 超时、不可用和版本字段测试 |
| 7    | CI 与文档一致性         | PR 门禁运行结果            |

## 7. 一期明确不做

- 真实视觉模型、LLM、RAG 或微调训练；
- 真实健康档案、病例、患处图片和持续视频采集；
- 年龄、性别、情绪结果用于医疗判断；
- 完整管理后台、视频流、高并发和生产部署；
- 用 mock、固定回复或 UI 截图宣称功能已经完成；
- 为追赶进度跳过授权、测试、评审或证据。

## 8. 完成定义

- [ ] 从干净环境可以按文档复现
- [ ] API 契约、迁移、错误和版本字段一致
- [ ] 正常、边界、未登录、越权和依赖故障测试通过
- [ ] 日志、测试数据和提交中无密钥或真实医疗信息
- [ ] AI 参与和人工复核记录完整
- [ ] 需求追踪矩阵有提交、测试和验收链接
- [ ] 回滚步骤实际演练或在隔离环境验证
- [ ] 未实现的 AI 能力明确返回不可用，不伪装成功

## 9. 一期退出评审

退出评审由开发演示、测试复核、资料组检查证据，项目经理确认范围。任何一项发布阻断问题未关闭时，一期状态保持“待验收”或“阻塞”，不得标记“已完成”。
