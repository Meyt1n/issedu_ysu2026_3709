# 部署与运维方案

## 1. 环境

| 环境 | 数据 | 用途 |
|---|---|---|
| local | 合成数据 | 个人开发 |
| test | 固定脱敏测试集 | 自动测试与联调 |
| demo | 专用演示数据 | 答辩演示 |
| production | 本实训默认不启用 | 需额外合规与安全评估 |

各环境使用独立数据库、对象存储、向量集合、密钥和模型配置，禁止复用生产凭据。

## 2. 容器服务

MVP 建议由 Docker Compose 管理：`web`、`api`、`worker`、`postgres`、`redis`、`chromadb`、`minio`、可选 `ollama` 与 `vision-service`。模型权重通过受控卷挂载，不进入镜像和 Git。

## 3. 配置

- 仓库只提供 `.env.example`，值必须是无效示例。
- 密钥由环境或密钥服务注入；启动时校验缺失项。
- 配置包含环境名、数据库地址、对象存储、模型版本、阈值、数据期限和允许来源。
- 安全阈值和医疗提示模板版本化，变更需双人评审。

## 4. 发布流程

1. 合并受评审 PR，生成不可变版本号和变更说明。
2. 在干净环境构建镜像并进行依赖、安全和密钥扫描。
3. 运行迁移预检、单元/集成/端到端与安全回归。
4. 备份元数据并验证恢复；部署 test。
5. 冒烟通过后部署 demo，使用演示数据复验主链路。
6. 记录代码、镜像、数据库、模型、知识库和提示词版本。

## 5. 可观测性

- 日志：JSON 结构，包含时间、服务、级别、请求 ID、脱敏用户 ID、事件和结果。
- 指标：请求量、P95、错误率、队列深度、模型时延、拒答率、低置信度率、检索无结果率。
- 健康检查：区分存活与就绪；依赖故障时就绪检查失败。
- 审计：登录、授权、上传、查看、导出、删除、模型与知识库发布。
- 不把提示词全文、病历正文、原始图片和令牌发送到普通监控平台。

## 6. 备份与恢复

- 备份数据库和对象元数据；向量索引应能从版本化源文档重建。
- 备份加密并设置独立访问权限和保留期。
- 每个里程碑至少演练一次恢复，记录 RPO/RTO 实测。
- 删除请求必须能传播到备份生命周期，避免无限期保留。

## 7. 回滚

- 代码：保留上一镜像，健康检查失败自动/人工回退。
- 数据库：迁移提供前向修复或经验证的回退方案，禁止直接丢列。
- 模型：模型注册表切回上一稳定版本。
- 知识库：切换版本化集合，不覆盖当前稳定索引。
- 提示词/安全策略：作为独立版本回滚，但 S3 安全规则不得关闭。

## 8. 演示前清单

- [ ] 所有服务从干净环境启动
- [ ] 仅加载合成/脱敏演示数据
- [ ] 模型、知识库和提示词版本固定
- [ ] 断网或模型故障降级已演练
- [ ] 测试账号权限正确，默认密码已修改
- [ ] 日志、屏幕和浏览器不会展示密钥或个人信息
- [ ] 备份与回滚点可用
