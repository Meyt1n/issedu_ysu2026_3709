# HomeCare Twin 部署与运维方案

## 1. 三档环境

| 档位 | 组件 | 目标 |
|---|---|---|
| 基础档 | Nginx、Vue、FastAPI、outbox worker、care-plan worker、MySQL、规则、轻量 OCR、加密文件 | 低配置/断网仍可管理事实、任务和规则 |
| 增强档 | 基础档 + FAISS/Qdrant + Ollama 量化模型 | 本地证据检索和语言解释 |
| 研发档 | 增强档 + 标注、训练、评测、模型登记 | GPU 工作站或短时云 GPU |

家庭端不执行自动训练。所有内部服务默认只监听本机或容器网络；仅 Nginx 对受信局域网开放，正式演示使用 HTTPS。

## 2. 配置与密钥

配置按环境分层，仓库只提交 `.env.example`。数据库密码、JWT/加密密钥、外部天气令牌不得写入镜像、日志或文档。必须锁定代码、迁移、视觉/OCR、主数据、规则、知识、Embedding、LLM/LoRA/量化和提示词版本。

## 3. 发布流程

```text
构建并生成制品哈希
-> 迁移/兼容与固定集回归
-> 安全和隐私门禁
-> 备份事实库与登记当前模型组合
-> 隔离环境演练升级
-> 基础档健康检查
-> 增强档按需启动
-> 烟雾测试与人工验收
-> 发布或回滚
```

数据库迁移先备份并验证回滚；模型、规则和知识支持独立回滚，但组合版本必须经过回归。不得边演示边训练或热改规则。

一期基础档统一入口为 `scripts/start.ps1`/`scripts/start.sh`：`setup` 安装锁定依赖，`up` 构建并等待 MySQL/API/outbox worker/Web 健康，`health` 重复检查容器状态和 HTTP 端点，`down` 停止服务且默认保留数据库卷。API 镜像启动时前滚到当前 Alembic head；worker 等 API 健康后再启动并自动恢复过期锁；迁移历史不得重写。

## 4. 可观测性

- 技术：请求量/延迟/错误、outbox 状态/尝试/过期锁、CPU/GPU/内存/磁盘、数据库连接、模型加载和推理延迟。
- 业务：识别状态分布、人工复核时间、风险等级、告警合并、任务确认与照护升级。
- 模型：模型/阈值版本、字段准确率、未知转人工率、工具/引用失败和漂移信号。
- 隐私：日志不包含图片、OCR 正文、健康详情、完整提示词或密钥；指标只用不可逆聚合。

outbox worker 日志只输出批次计数和稳定错误码，不输出事件 payload、evidence、成员状态或异常正文。
care-plan worker 默认每 30 秒扫描一次，仅处理 `automation.authorization=AUTHORIZED` 的计划；日志只输出检查成员数、
新增事件数和通知数。`CARE_PLAN_POLL_SECONDS` 可设为 5～3600 秒，重复轮询和进程重启依赖事件幂等键去重。

## 5. 备份、恢复和删除

加密备份覆盖 MySQL、必要文件、规则/知识清单和模型登记；向量索引与关系投影应可重建。定期演练恢复并记录 RPO/RTO。成员删除需传播到主库、文件、索引与缓存；备份按保留策略到期清理。

## 6. 故障降级

Ollama/向量库离线时禁用自然语言证据回答但保留事实、规则和任务；视觉服务离线允许手工录入；天气失败不产生新卡；投影损坏从事实事件重建。所有降级明确展示，不返回伪造结果。
