# 需求追踪矩阵

## 1. 当前基线

项目尚未开始功能开发，所有功能和非功能需求统一为 `未开始`。不得根据来源仓库、示例目录、计划接口或 AI 生成内容推断已经实现。

## 2. 状态定义

| 状态   | 进入条件                                   |
| ------ | ------------------------------------------ |
| 未开始 | 只有需求或设计，没有负责人分支和可验证实现 |
| 进行中 | 已有负责人、任务卡、分支和首个可审查增量   |
| 待验收 | 实现、测试、文档和证据已合并，等待人工验收 |
| 已完成 | 验收人确认全部条件，证据链接和版本完整     |
| 阻塞   | 写明阻塞原因、负责人、解除条件和复查时间   |

## 6. 更新门禁

把条目标记为“进行中”前必须提供：

1. Issue/Story、需求编号和负责人；
2. Given/When/Then 验收条件；
3. 安全、隐私和数据影响；
4. 计划修改范围和验证命令。

标记为“待验收”前必须提供：

1. 已合并提交和 PR；
2. 实现文件、接口/迁移/模型版本；
3. 自动测试命令、退出状态和报告；
4. 医疗安全、隐私、越权和失败场景证据；
5. 演示步骤、截图/录屏或评估报告；
6. 已知限制和回滚方法。

状态更新由开发填写、测试核验、资料组检查链接，项目经理最终确认。
