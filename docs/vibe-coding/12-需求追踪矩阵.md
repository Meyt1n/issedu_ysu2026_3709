# 需求追踪矩阵

## 1. 使用规则

每个 Issue、分支、提交和 PR 至少关联一个需求编号。状态只允许：

- `未开始`：没有可验证实现；
- `进行中`：已有负责人和分支，但未满足验收；
- `待验收`：实现和自动测试完成，等待人工验收；
- `已完成`：代码、测试、文档和验收证据全部合并；
- `阻塞`：写明阻塞原因、负责人和解除条件。

不能因为页面存在或模型能返回内容就标记完成，必须满足本表验收证据。

## 5. 状态更新门禁

把条目标记为“待验收”前，PR 描述中必须提供：

1. 关联 Issue 和需求编号；
2. 实现文件与 API/迁移版本；
3. 自动测试命令和结果；
4. 医疗安全与隐私影响；
5. 演示步骤或评估报告；
6. 已知限制与回滚方法。
