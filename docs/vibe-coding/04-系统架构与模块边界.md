# HomeCare Twin 系统架构与模块边界

## 1. 建议目录

```text
src/
├─ web/                 家庭端与十个业务页面
├─ admin/               规则、知识、模型与任务管理
├─ api/                 FastAPI 统一入口
│  ├─ routes/           HTTP 与 Schema 适配
│  ├─ application/      用例、授权、事务与编排
│  ├─ domain/           事件、计划、任务、告警预算规则
│  ├─ persistence/      MySQL 仓储与投影
│  └─ integrations/     CV、OCR、RAG、Ollama、天气
└─ ai/
   ├─ vision/           数据、训练、推理、融合与评估
   ├─ rag/              文档、切片、检索、引用验证
   └─ safety/           路由、输出 Schema、拒答与红队
```

## 2. 四层职责

| 层 | 负责 | 不负责 |
|---|---|---|
| 家庭事实 | 成员、事件、药品、计划、授权、审计 | 不保存模型猜测为事实 |
| 关系投影 | 从已确认事实构造成员—药品—成分等关系 | 不成为第二事实源 |
| 确定规则 | 过期、库存、重复成分、过敏、有限相互作用、告警预算 | 不让 LLM 改规则结果 |
| 语言解释 | 工具选择、澄清、引用、摘要和通俗表达 | 不诊断、处方、停药、换药、调剂量 |

## 3. 模块边界

- Web 只调用 `/api/v1`，不直连 MySQL、向量库或 Ollama。
- 路由只做协议、鉴权依赖和 Schema；不得写 SQL、模型推理和医疗规则。
- 应用层决定授权、事务、事件追加和工具编排。
- 领域层不依赖 FastAPI/ORM，保存可单测的状态机和规则。
- 视觉模块返回候选与证据，不直接创建正式药品状态。
- RAG 返回有权限且可定位的文档片段，不生成最终医疗结论。
- 天气适配器只接收城市/区县编码，失败不能阻塞本地核心链路。

## 4. 数据所有权

MySQL 是唯一事实主库；加密文件存储保存原图/裁剪/文档并由数据库引用；向量索引是可重建派生物；图谱是可重建投影；模型登记只描述制品、指标和状态。任何派生存储不得反向覆盖事实主库。

## 5. 依赖方向

```text
routes -> application -> domain
                    -> persistence interfaces
                    -> integration interfaces
adapters implement interfaces; domain never imports adapters
```

跨模块通信优先使用显式应用服务和版本化 Schema。异步识别/训练任务必须幂等、有状态机、超时、取消和审计。

## 6. 必须建立 ADR 的变化

数据库/向量库更换、引入 Neo4j、身份方案、生物识别、事件模型、规则引擎、视觉主模型、LLM 基础模型、外部云服务、原图留存、加密与密钥方案、训练数据授权或部署拓扑变化。
