# AI 与 RAG 设计规范

## 1. 目标

让视觉、LLM 和 RAG 的输出可评估、可追溯、可拒绝、可替换。模型不能绕过业务权限或确定性医疗安全规则。

## 2. 模型注册

每个模型记录：

- 模型名称、版本、哈希和来源；
- 许可证、用途和禁止用途；
- 训练/微调数据版本与数据卡；
- 运行环境、量化方式和资源需求；
- 评估集、指标、阈值、已知偏差和负责人；
- 上线、回滚和停用时间。

未经注册和评估的模型不得成为默认模型。

## 3. 视觉识别

- MVP 先限定 5-10 类、外加 `unknown`，再按数据质量扩展。
- 划分数据时按药品实例/拍摄主体隔离，避免背景或连拍泄漏。
- 报告每类 precision、recall、F1、mAP，以及不同光照、遮挡、角度下的指标。
- 置信度阈值由验证集校准；低置信度必须拒识别。
- 药品基础库匹配使用稳定 ID，名称相似不能自动视为同一药品。
- 对年龄段、性别、表情等属性的演示要展示局限，禁止用于医疗结论。

## 4. RAG 入库

```text
授权校验 -> 解析/OCR -> 清洗 -> 结构化切片 -> 元数据
-> 敏感信息检查 -> 嵌入 -> 索引 -> 抽样质检 -> 发布
```

每个切片至少包含 `document_id`、版本、标题、页码/章节、来源、权限域、内容哈希和更新时间。切片建议按标题语义分段并保留少量重叠，参数通过检索评估确定。

## 5. 检索与生成

1. 校验用户和知识域权限。
2. 识别紧急风险、越权意图和提示词注入。
3. 混合检索（向量 + 关键词），再按权限和元数据过滤。
4. 对候选结果重排；低于相关性阈值时不生成确定性答案。
5. 只把最小必要上下文传给模型。
6. 生成后验证引用是否存在且支持结论。
7. 运行安全后处理，返回风险等级、免责声明和版本信息。

## 6. 提示词安全

- 系统规则与用户内容、检索文档使用明确边界和不同角色。
- 检索文档中的指令一律视为数据，不得覆盖系统规则。
- 工具调用使用白名单和结构化参数；默认无写权限。
- 不向模型暴露密钥、完整权限表或其他用户数据。
- 高风险规则在模型调用前后各执行一次。

## 7. 医疗安全响应

| 等级 | 场景 | 行为 |
|---|---|---|
| S0 | 一般健康科普 | 带来源回答 |
| S1 | 个体化健康问题 | 限定回答，建议咨询专业人员 |
| S2 | 用药、症状持续或证据不足 | 拒绝诊断/改药，明确线下咨询 |
| S3 | 胸痛、呼吸困难、意识障碍、自伤等 | 停止常规问答，立即就医/求助提示 |

具体紧急联系方式不得硬编码猜测；按部署地区配置，并由负责人审核。

## 8. 评估与发布

- RAG：Recall@K、MRR、引用准确率、引用覆盖率、无答案识别率。
- 回答：事实一致性、完整性、拒答准确率、紧急场景召回率。
- 安全：越权检索、提示词注入、敏感信息泄露和有害建议测试。
- 新版本使用固定回归集与影子对比；关键指标未达到基线不得发布。
- 保存评估报告和版本，生产样本回流前必须脱敏并重新授权。
