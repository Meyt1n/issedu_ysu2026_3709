# 双仓库解耦与独立克隆说明

状态：待本文件所在 PR 合并后生效

决策日期：2026-08-11
适用范围：GitHub `Meyt1n/issedu_ysu2026_3709` 与原内部仓库

## 1. 决策结论

从本文件所在 PR 合并起，两个仓库不再互相同步，也不再共享开发分支：

- GitHub `master` 是 HomeCare Twin 的唯一开发、Issue、PR、Review、CI 和发布基线。
- 内部仓库保留为独立仓库，不再接收 GitHub Actions 推送，不再要求与 GitHub 保持 SHA 一致。
- GitHub 不再维护内部仓库的用户名、Token 或成员身份映射；任何 `CLOUD_*` Secret 都不再属于现行开发流程。
- `sync-test/`、旧同步说明和 HCT-105 只保留为历史审计材料，不能作为当前操作指南。

这次解耦不是把 Git author 改成其他人，也不是重新生成一份提交。内部仓库只做一次明确的历史回退，之后与 GitHub 分开维护。

## 3. 一次性内部仓库回退（维护者执行）

本操作必须在本文件所在 PR 合并、GitHub 自动同步 workflow 已从默认分支删除后执行。不要把内部仓库凭据写入命令历史、文档、Issue 或日志；下方地址可替换为管理员实际地址。

```powershell
$internalUrl = 'http://119.3.217.118:30181/29092881243490627/issedu_ysu2026_3709.git'
$expectedBefore = '21cbe549f5faf0f4094c486fc7a7d4d05ee11c3b'
$firstVersion = '068a4db921dfbe3a3b77519524f524b892603a91'
$backupTag = 'archive/internal-master-before-disconnect-20260811'
$meetingCommits = @(
    '45f4b8308051e8b5d02f26a5bf5d7e6857db5cf2', # 7.28-7.30
    '14655cf7c2e801d841a1f0a777552d9b5ea9d202', # 7.31
    '485ea4620a4d9ad2728aa0dc564386bc9ff722a9', # 8.1
    '83d7f52cb550fd7896af3dc9f1aa4bcbe2c79b33', # 8.3
    'fc7b4e36c391c4df4ac26ddc865d5c9c661c6937', # 8.4 最终文件
    '492bc14f8f93b4fa67354a018d58de3c784d44b1', # 8.5
    '7d2e1299425a931a89c8e78685af8b53d915910e', # 8.7
    'e01b9259230d710178da482f13de9ee03c257b3a'  # 8.8
)

git clone $internalUrl internal-recovery
Set-Location internal-recovery
git fetch origin master --tags

# 先确认目标没有变化，避免覆盖别人的新提交。
if ((git rev-parse origin/master) -ne $expectedBefore) {
    throw "内部 master 已变化，停止回退；请重新核对当前 SHA。"
}

# 保存当前版本，便于需要时恢复。
git tag $backupTag $expectedBefore
git push origin "refs/tags/$backupTag"

# 只在确认备份标签已存在后，用带旧 SHA 保护的方式回退 master。
git push --force-with-lease="refs/heads/master:$expectedBefore" origin "${firstVersion}:refs/heads/master"

# 按原提交顺序重新提交早会记录；每个 cherry-pick 后单独 push，保留可审计粒度。
foreach ($meetingCommit in $meetingCommits) {
    git cherry-pick $meetingCommit
    if ($LASTEXITCODE -ne 0) {
        throw "会议记录提交 $meetingCommit cherry-pick 失败，请保留现场并人工处理。"
    }
    git push origin master
    if ($LASTEXITCODE -ne 0) {
        throw "会议记录提交 $meetingCommit push 失败，请保留现场并人工处理。"
    }
}

# 恢复当前内部仓库其余 doc 文件，但不覆盖上面刚重放的 doc/07 记录。
# 由于内容与 expectedBefore 之后的内部版本一致，这一步只会形成文档保留提交。
git restore --source=$expectedBefore --worktree --staged -- doc
if ((git diff --cached --name-only -- 'doc/07.会议记录')) {
    throw 'doc/07.会议记录出现意外 staged 变更，停止提交。'
}
git commit -m 'docs: 保留内部仓库会议与项目文档'
git push origin master
```

回退后必须执行：

```powershell
git ls-remote $internalUrl refs/heads/master refs/tags/archive/internal-master-before-disconnect-20260811
```

预期结果是：内部 `master` 的代码与 `068a4db...` 相同，`src/` 只有 `.gitkeep`；`doc/07.会议记录` 包含 7.28、7.29、7.30、7.31、8.1、8.3、8.4、8.5、8.7 和 8.8 记录；备份标签仍指向 `21cbe549...`。最终 `master` 会因为会议记录和文档保留提交而拥有新的 SHA，不应再要求它等于 `068a4db...`。若内部仓库分支保护拒绝回退，不得改用裸 `--force`；由内部仓库管理员在受控窗口完成一次性操作，或记录为阻塞。

## 4. 以后如何分别 clone

推荐为两个仓库使用两个独立目录，两个目录都只保留自己的 `origin`：

```powershell
git clone https://github.com/Meyt1n/issedu_ysu2026_3709.git homecare-twin-github
git clone http://119.3.217.118:30181/29092881243490627/issedu_ysu2026_3709.git homecare-twin-internal
```

分别核验远端：

```powershell
git -C homecare-twin-github remote -v
git -C homecare-twin-internal remote -v
```

日常 HomeCare Twin 开发只进入 `homecare-twin-github`，从 GitHub `master` 建分支、创建 PR 并合并。不要给 GitHub clone 添加 `cloud` 远端，不要给内部 clone 添加 `github` 远端，不要使用双推脚本，也不要将两个目录的分支互相 push。

如果已有旧 clone，先删除旧的跨仓库远端配置，再按上面的独立 clone 方式重新建立目录：

```powershell
git remote -v
git remote remove cloud       # 仅当旧 clone 存在 cloud 远端时执行
git remote remove github      # 仅当内部 clone 存在 github 远端时执行
git remote -v
```

- `CLOUD_REPO_USERNAME`
- `CLOUD_REPO_PASSWORD`

- `CLOUD_TOKEN_RY12_20`

删除前只需确认新默认分支中已经没有引用这些名称；不要在 Issue、PR、Actions 日志或本地文件中复制 Secret 值。删除 Secret 不会改写 GitHub 提交历史，也不会删除内部仓库的备份标签。
