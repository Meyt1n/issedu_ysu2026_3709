## 1. 目的与禁止用途

允许用途：验证指令数据格式、证据字段绑定、工具/路由枚举、安全拒答、盲测隔离和 LLaMA Factory 数据转换。

禁止用途：诊断、处方、停药、换药、剂量判断、真实家庭事实记忆、患者身份识别、直接确认药品身份或替代规则引擎。

本版本是合成起步 fixture，不是生产训练集，不支持模型发布结论。仓库中的盲测评估器只允许评估外部提供的结构化预测文件；合成回放报告仅用于演示评估链。

## 2. 来源、许可与训练同意

- 来源：项目内确定性生成的虚构教学样本；
- 许可：`internal-teaching-fixture`；
- 训练同意：`NOT_APPLICABLE_SYNTHETIC`；
- 真实健康数据：否；
- 公开再分发：否，fixture 只服务本仓库教学验证；
- 后续真实或公开来源：必须新建数据版本、数据卡、许可清单和删除传播记录，不能沿用本版本状态。

## 3. 数据内容

每条源记录包含：

- `sample_id`：稳定样本 ID；
- `scenario_group`：防止同一场景跨集合；
- `split`：`train`、`validation` 或 `blind`；
- `task_category`：证据抽取、冲突处理、未知处理、授权或安全拒答；
- `source`：来源、许可、训练同意、去标识化和质量审查；
- `messages`：system/user/assistant 对话；assistant 内容必须是 `hct-llm-output/v1` JSON；
- assistant 目标中的字段来源、证据、状态、路由和安全响应。

允许的路由：`DIRECT`、`EVIDENCE_REQUIRED`、`RISK_ONLY`、`REFUSE`、`URGENT_ESCALATE`。

允许的识别状态：`MATCHED`、`CONFLICT`、`UNKNOWN`、`REVIEW`。

## 4. 划分与隔离

准备脚本按源记录中明确登记的 `scenario_group` 和 `split` 输出数据，不使用运行时随机数。训练与验证输出包含 assistant 目标；盲测输出拆成：

- `blind/inputs.jsonl`：只有输入消息；
- `blind/labels.jsonl`：评测标签，不能传给训练命令；

脚本会拒绝同一场景组跨 split，并在 manifest 中记录每个 split 的样本和场景组数量。正式盲测集必须在训练期间由权限控制隔离，本 fixture 只验证目录和格式约束。`hct402_evaluate_blind.py` 会拒绝预测缺失、重复或多余样本，并校验引用是否来自输入证据。

## 5. 质量与安全审查

必须通过：JSONL 解析、重复 ID、场景分组、来源许可、去标识化标记、输出 Schema、绝对路径、密钥模式和盲测 assistant 泄漏检查。

必须人工抽检：证据是否支持结论、冲突是否进入 `CONFLICT`、未知是否拒绝猜测、授权字段是否隐藏、危险医疗请求是否拒答。

## 6. 存储、删除与回滚

- 仓库只保存小体积合成 fixture、规范和准备脚本；
- 真实样本、训练缓存、模型权重和生成输出放在受控外部目录，不提交 Git；
- 删除或撤销数据时隔离源数据、派生 JSONL、缓存、索引和可控备份，并保留不含正文的最小审计；
- 本版本未进入任何生产模型；撤销时删除 fixture 和 manifest 即可，不涉及运行时回滚。

## 7. 发布阻断

以下任一条件存在时保持 `PREPARED_SYNTHETIC_NOT_RELEASED`：样本不是合成或许可不明、盲测泄漏、没有完整人工抽检、没有基础模型/QLoRA 对照、没有安全评估、没有模型卡或没有回滚版本。
