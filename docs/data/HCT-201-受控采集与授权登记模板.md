# HCT-201 受控采集与授权登记模板

> 用途：当公开数据源无法完成许可、数量或标注核验时，为经明确授权的自采包装数据或合成包装数据提供接入模板。本文不授权任何人采集真实患者健康资料，也不替代负责人和 R3 复核人的批准。

## 1. 采集边界

只采集或生成“包装本身”的视觉证据，不采集家庭成员、患者、处方或用药行为。

允许：

- 经包装所有者明确同意的未使用/空包装或教学样品；
- 仅包含产品包装信息的正面、背面、侧面和条码区域；
- 明确标记为合成的虚构包装和虚构字段。

禁止：

- 患者姓名、电话、地址、病历号、处方、购药记录、服药记录和手写用药说明；
- 药房标签、快递面单、聊天通知、屏幕通知或可识别家庭背景；
- 未取得训练同意的他人包装、网络截图、搜索引擎图片或第三方数据转存；
- 把真实个人追溯码、处方码或家庭成员关系写入文件名、路径、日志或标注说明。

条码/追溯码只有在包装本身属于已授权样本、且不携带个人信息时才能保留；它只作为 OCR/解码证据，不作为诊断、处方或用药判断依据。

## 2. 每个样本必须登记

| 字段 | 要求 |
|---|---|
| `sample_id` | 不可逆随机 ID，不使用姓名、药名、时间戳或原文件名 |
| `source_id` | `consented-self-capture-<batch>` 或 `synthetic-<batch>` |
| `license` | `consented-self-capture` 或 `synthetic`，不得写 `unknown` |
| `consent_status` | 只有取得独立训练同意并保存证明后才可为 `granted` |
| `consent_ref` | 受控域中的授权证明 ID；仓库只保存引用，不保存签名、身份证或联系方式 |
| `deidentified` | 脱敏检查通过后才为 `true` |
| `entity_key` / `session_key` | 用于防止同一包装、同一采集会话或相邻帧跨集合泄漏 |
| `group_key` | 固定的分组键；train/validation/test/unknown 之间不得重复 |
| `capture_date` / `device_key` | 只记录审计所需的日期和设备类别，不记录 GPS 或个人设备账号 |
| `delete_ref` / `retention_until` | 指向删除责任和保留期限的受控登记 |
| `status` / `split` | 初始为 `QUARANTINED`/`quarantine`，审核后才能进入批准集合 |
| `sha256` | 对受控域原始制品和每个派生版本分别计算 |

## 3. 推荐采集批次

每个授权包装至少登记一组独立拍摄，不以连拍相邻帧冒充不同样本：

1. 正面：可读药名/规格，记录清晰度、反光和遮挡；
2. 背面：可读厂家、批号、有效期等字段；
3. 侧面或底面：包装类型和条码区域；
4. 困难样本：受控地加入旋转、暗光、轻微反光或部分遮挡，并标记困难属性；
5. 非目标/未知：空背景、非药品包装或无法确认边界的样本，进入 `unknown`，不得删除以改善指标。

同一包装的所有角度、重拍和相邻视频帧必须共享 `entity_key` 与 `group_key`，只能整体进入一个 split。不得先随机拆帧再划分。

## 4. 合成数据要求

合成样本必须：

- 使用虚构名称、虚构厂家和虚构批号/日期，避免映射到真实药品；
- 在 manifest 中写明 `license=synthetic`、`consent_status=granted`、`source_id=synthetic-*`；
- 单独记录字体、背景、颜色、反光和遮挡生成参数；
- 不与真实授权样本混合计算最终固定集指标；
- 不能证明真实包装 OCR、条码和跨设备泛化，只能用于管线联调和回归。

## 5. 接入与验收顺序

```text
授权/合成证明
  -> 受控域保存原始制品
  -> 去 EXIF 与 PII 检查
  -> 生成 sample_id / group_key / sha256
  -> 标注包装、条码和 OCR 区域
  -> 按实体/会话分组
  -> 近重复、泄漏、许可和保留期审计
  -> QUARANTINED -> R3 复核 -> APPROVED
```

批准前必须能运行：

```powershell
uv run python scripts/hct201_dataset_audit.py --manifest <受控域脱敏 manifest> --strict
uv run pytest tests/data/test_hct201_dataset_audit.py tests/data/test_hct201_mendeley_inventory.py
```

PR 只提交 manifest 的脱敏摘要、哈希、统计和报告链接，不提交图片、视频、授权原件、真实条码正文、EXIF、模型权重或受控域路径。

## 6. 撤销与回滚

授权撤回或发现隐私问题时：

1. 将样本和数据集版本标记为 `REVOKED`；
2. 禁止训练入口继续读取该版本；
3. 按 `delete_ref` 隔离/删除原始图、裁剪、增强、缓存、困难样本和可控备份；
4. 重新计算受影响 manifest 和模型版本的可用性；
5. 审计只保留样本 ID、版本、动作、时间和结果，不保留健康正文或个人信息。

## 7. 当前 HCT-201 下一步

本模板只能解除“没有统一采集登记方式”的工程阻断，不能自动解除 Mendeley 的数量冲突或任何数据许可问题。负责人需要在受控域完成一批明确授权的包装样本登记，或取得来源方对公开数据的书面核实；完成前 HCT-201 维持 `Blocked`，HCT-202/HCT-203 不得启动。
