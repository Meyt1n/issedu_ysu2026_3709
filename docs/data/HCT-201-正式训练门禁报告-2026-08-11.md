# HCT-201 正式训练门禁报告（2026-08-11）

## 结论

当前不能把 `HCT-201-dataset-v1` 改为 `APPROVED`，也不能启动 HCT-202/HCT-203 的正式训练。门禁结果为：

```text
BLOCK_FORMAL_TRAINING
```

这不是代码或文档状态问题，而是授权来源、真实实体分组、固定评估集和 unknown 集缺少可追溯证据。现有实验模型继续保持 `EXPERIMENTAL_UNRELEASED`，不得进入家庭运行或生产路径。

## 已落地的防误用门禁

新增 `scripts/hct201_formal_gate.py`。它只读取脱敏 JSONL 元数据，只有同时满足以下条件才返回零退出码：

- 所有样本为 `APPROVED`，并有许可证、训练授权依据、脱敏、删除/保留证据；
- 每条记录具有非代理的实体/会话/分组键和分组证据引用；
- `train`、`validation`、`test`、`unknown` 四个 split 均存在，且同一分组不跨 split；
- `test`/`unknown` 的 `fixed_eval=true`，训练/验证为 `false`；
- `unknown` 与 `unknown_set=true` 一致并有 `unknown_reason`；
- sample ID 和 SHA-256 不重复。

验证命令：

```powershell
uv run ruff check scripts/hct201_formal_gate.py tests/data/test_hct201_formal_gate.py
uv run pytest tests/data/test_hct201_formal_gate.py
uv run python scripts/hct201_formal_gate.py --manifest <批准版脱敏-manifest.jsonl> --report <仓库外报告.json>
```

当前候选 manifest 预期必须返回非零并报告 `BLOCK_FORMAL_TRAINING`，不能通过改名、补哈希或把代理 pHash 改写成实体键来绕过。

## 解除顺序

1. 对当前 Roboflow 来源完成逐图授权/PII/EXIF/背景检查，并登记删除/撤销传播路径；Mendeley 不再纳入当前路线。
2. 对最终来源完成逐图授权、脱敏和删除传播检查。
3. 获取真实实体、采集日期、设备、会话信息；没有这些字段的图片只能留在隔离候选区。
4. 重新生成 `canonical/v1.3`：按实体/会话分组，先冻结 test 和 unknown，再从剩余组划分 train/validation；保存 manifest 和文件哈希。
5. 由负责人提交、`Shen-huang-123` 完成 R3 复核；门禁脚本通过后，才解除 HCT-201 对下游训练的阻断。
6. HCT-202 在批准固定质量集上校准误拒绝、漏拒绝和真实视频性能；HCT-203 再使用批准 train 训练，并在固定 test/unknown 上评估。

## 不允许的替代

- 不把公开页面的 CC BY 标记等同于逐图隐私/训练授权完整；CC BY 本身也提示隐私、公开权或其他权利可能需要额外许可。Mendeley 的历史数量冲突不再是当前路线的工作项，但历史审计仍保留。
- 不把 pHash、文件名、Roboflow 原始 train/valid/test 或随机索引称为真实实体分组。
- 不把现有 147 张候选测试图、Open Images 已取消候选或当前实验模型登记当作 fixed evaluation/unknown。
- 不把 `EXPERIMENTAL_UNRELEASED` 模型用于家庭运行，不让 YOLO 替代 OCR、条码和人工确认。
