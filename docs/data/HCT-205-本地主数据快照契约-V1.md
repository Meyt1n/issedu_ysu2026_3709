# HCT-205 本地主数据快照契约 V1

## 用途

该快照只为 OCR-first 证据管线提供离线候选核对，不是监管数据库，也不是药品身份确认结果。家庭端默认没有快照时，API 必须返回 `MASTER_DATA_UNAVAILABLE` 并保持 `UNKNOWN`。

## 文件位置与版本

- 根目录由 `MASTER_DATA_ROOT` 配置，默认 `./data/master-data`。
- 文件名必须是 `<version>.json`，版本只允许字母、数字、点、下划线和连字符。
- API 的 `master_data_version` 必须精确匹配文件名和文件内 `version`。
- 服务端只允许 `MASTER_DATA_APPROVED_VERSIONS` allowlist 中的版本，并要求 `approval_status=APPROVED`、非空 `approval_ref` 和 `revocation_status=ACTIVE`；文件自报批准状态不能替代 allowlist。
- 读取只允许本地文件，不访问网络；路径不能逃逸 `MASTER_DATA_ROOT`。

## JSON 结构

```json
{
  "schema_version": "hct-master-data/v1",
  "version": "demo-master-v1",
  "approval_status": "APPROVED",
  "approval_ref": "controlled-approval-record",
  "revocation_status": "ACTIVE",
  "records": [
    {
      "record_id": "controlled-record-id",
      "product_barcode": "4006381333931",
      "name_aliases": ["受控名称"],
      "specification": "受控规格",
      "manufacturer": "受控厂家",
      "packaging_type": "carton"
    }
  ],
  "sha256": "对去掉 sha256 字段后的规范 JSON 做 SHA-256"
}
```

规范 JSON 使用 UTF-8、`ensure_ascii=false`、按 key 排序且无多余空白。`sha256`、schema、版本、批准状态、撤销状态、allowlist 或记录结构任一校验失败，加载器都返回不可用快照，不能降级为无校验候选。

## 证据边界

- 条码精确匹配和 OCR 名称精确匹配只产生 `master_candidates`，不产生 `MATCHED`。
- 药名、规格、厂家、批号、有效期和商品条码不能只由 YOLO 区域标签支持。
- 字段必须引用已提交的 OCR/条码证据；不在来源证据中的值会被拒绝。
- 快照记录必须经过项目的数据许可、删除传播和 R3 复核后才能用于正式任务；本 PR 不提交真实药品主数据。
- 适配器证据必须由受控本地适配器生成 HMAC receipt，并绑定任务、输入 SHA、适配器版本、运行批次和完整 payload；前端不能直接伪造可消费证据。
