## 1. 批准范围与禁止用途

本版本批准用于 HCT-402 的内部路由/安全指令实验：训练模型识别“外部医学问答只是未核验参考”、要求受控证据或人工确认，并保持 `EVIDENCE_REQUIRED/REVIEW` 的结构化输出。原始公开问答中的参考答案已从 train、validation 和 blind 输入中移除，因此本版本不是医学事实记忆集。

禁止用途：诊断、处方、停药、换药、剂量判断、个体化医疗建议、患者身份识别、生产发布或替代规则引擎。`approval-record.json` 中的 `model_release` 固定为 `NOT_APPROVED`。

SORRY-Bench 不进入本版本 SFT；它保持 evaluation-only，用于另行的安全评估。

## 2. 许可与训练同意

- 来源数据卡元数据显示 `Apache-2.0`；来源原始文件 SHA-256、候选数量和批准引用写入外部 `manifest.json` 与 `approval-record.json`。
- 训练同意状态为 `PUBLIC_LICENSE_TRAINING_ALLOWED_INTERNAL_SCOPE`，依据为公开许可证元数据加项目负责人对本内部范围的明确批准。
- 这不是患者/临床同意证明；该目录不接收项目真实家庭对话、患者资料、图像或 HCT-201/HCT-205 数据。

## 3. 脱敏与人工审查

- 仅保留公开来源 ID 和经裁剪的提问；参考答案不写入任何 prepared 消息。
- 生成器执行 JSON Schema、重复 ID、跨 split 场景组、密钥/绝对路径和 blind assistant 泄漏检查。
- 人工记录为 `OWNER_SCOPE_REVIEW_RECORDED`：项目负责人批准全部 256 条转换后的路由边界样本及其用途；这不等同于逐条医学事实核查，`clinical_fact_check` 明确为 `NOT_PERFORMED_AND_NOT_CLAIMED`。

## 4. 划分与哈希

目录生成固定为 192 条 train、32 条 validation、32 条 blind；每条记录使用独立 `scenario_group`，三组无交集。`manifest.json` 的 `output_sha256` 记录四个文件哈希，`split_sha256` 记录 train、validation 和由 blind inputs/labels 组合得到的盲测哈希。QLoRA 入口在外部训练前会重新计算并拒绝哈希不一致。

blind 目录分为：

- `blind/inputs.jsonl`：仅输入，不含 assistant 标签；
- `blind/labels.jsonl`：仅评估阶段加载的标签。

## 5. 删除策略与回滚

许可证撤销、来源更正、项目负责人撤回或隐私发现触发删除。按外部 `deletion-policy.json` 传播到原始源文件、候选、train/validation/blind、索引、缓存、adapter、checkpoint 和评估输出；受控备份执行同一删除请求，只保留不含正文的最小审计记录。数据撤销后，任何依赖该 manifest 的训练或模型产物均不得继续使用。

## 6. 尚未完成的验收

本数据准入不代表 QLoRA 已训练、基础模型对照已完成、盲测已通过或模型可发布。仍需在受控外部环境执行真实训练、相同 blind set 的 base/QLoRA 预测、安全评估、模型卡、回滚演练和 R3 发布复核。
