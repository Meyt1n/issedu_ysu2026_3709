# 后端术语表

> 本文档收集家健镜系统后端开发中使用的专业术语和缩写，帮助新成员快速理解项目概念。

## A

### ADR (Architecture Decision Record)
架构决策记录。记录重要架构决策的文档，包括决策背景、选项、选择和后果。

### API (Application Programming Interface)
应用程序编程接口。后端提供给前端或其他系统调用的接口规范。

### Alembic
SQLAlchemy 的数据库迁移工具，用于管理数据库 schema 版本。

### AsyncSession
SQLAlchemy 的异步数据库会话，用于异步数据库操作。

## B

### Backend
后端。服务端应用，负责业务逻辑、数据存储和 API 提供。

### BaseModel
Pydantic 的基础模型类，用于数据验证和序列化。

## C

### CQRS (Command Query Responsibility Segregation)
命令查询职责分离。将写操作（Command）和读操作（Query）分离的架构模式。

### CRUD (Create, Read, Update, Delete)
增删改查。基本的数据操作。

### CORS (Cross-Origin Resource Sharing)
跨域资源共享。允许浏览器向不同源的服务器发起请求的机制。

### Cache
缓存。将频繁访问的数据存储在高速存储中，减少数据库查询。

## D

### DDD (Domain-Driven Design)
领域驱动设计。以业务领域为核心的软件设计方法。

### Dependency Injection
依赖注入。通过外部传入依赖对象，而非内部创建，提高可测试性和解耦。

### Docker
容器化平台，用于打包和部署应用。

### Docker Compose
用于定义和运行多容器 Docker 应用的工具。

## E

### Event Sourcing
事件溯源。将所有状态变更记录为事件序列，通过重放事件重建状态。

### Event Store
事件存储。存储所有事件的数据库或存储系统。

### Exception Handler
异常处理器。统一处理应用异常并返回标准化错误响应的机制。

## F

### FastAPI
现代、高性能的 Python Web 框架，基于类型提示和异步。

## G

### GraphQL
一种 API 查询语言，允许客户端精确请求所需数据。

## H

### Health Check
健康检查。用于检测服务是否正常运行的端点。

### Household
家庭。系统中的核心组织单位，包含多个成员和共享健康数据。

## I

### i18n (Internationalization)
国际化。使产品支持多种语言和地区的设计和实现。

### JWT (JSON Web Token)
JSON Web 令牌。用于身份认证的紧凑、自包含的令牌格式。

## K

### K8s (Kubernetes)
容器编排平台，用于自动化部署、扩展和管理容器化应用。

## L

### LLM (Large Language Model)
大语言模型。如 GPT、Claude 等，用于自然语言理解和生成。

### Load Balancer
负载均衡器。将请求分发到多个后端实例的组件。

### Logging
日志记录。记录应用运行时事件的机制。

## M

### Member
成员。家庭中的个人，拥有自己的健康数据和用药记录。

### Middleware
中间件。在请求处理前后执行的组件，用于认证、日志、CORS 等。

### Migration
迁移。数据库 schema 变更的版本化管理。

### Mock
模拟。在测试中替代真实依赖的对象。

## N

### N+1 Query
N+1 查询问题。查询主记录后，对每条记录单独查询关联数据，导致性能问题。

## O

### ORM (Object-Relational Mapping)
对象关系映射。将数据库表映射为 Python 对象的技术，如 SQLAlchemy。

### OAuth
开放授权标准，用于第三方应用授权访问。

## P

### Pagination
分页。将大量数据分成多页返回的机制。

### Pydantic
Python 数据验证库，基于类型提示。

### Postgres / PostgreSQL
开源关系型数据库，系统的主数据库。

### Prometheus
开源监控和告警系统，用于指标采集和存储。

## Q

### Query
查询。只读的数据获取操作。

## R

### RAG (Retrieval-Augmented Generation)
检索增强生成。结合信息检索和大语言模型生成回答的技术。

### Redis
开源内存数据存储，用作缓存、消息队列和分布式锁。

### REST (Representational State Transfer)
表述性状态转移。一种 API 设计风格。

### Role
角色。用户在系统中的权限角色，如 admin、member、viewer。

## S

### Schema
Schema。数据结构定义，用于验证和序列化。

### SQLAlchemy
Python 的 ORM 和 SQL 工具包。

### SSE (Server-Sent Events)
服务器发送事件。服务器向客户端推送实时更新的技术。

### Swagger / OpenAPI
API 文档规范，FastAPI 自动生成交互式 API 文档。

## T

### Trace ID
追踪 ID。标识一个请求全链路的唯一标识符，用于日志和链路追踪。

### Transaction
事务。数据库操作的原子性单元，要么全部成功，要么全部回滚。

## U

### Uvicorn
ASGI 服务器，用于运行 FastAPI 应用。

### User
用户。系统的注册账户，可以属于一个或多个家庭。

## V

### Validation
验证。检查输入数据是否符合规则的过程。

### Versioning
版本管理。API、数据库、文档等的版本控制。

## W

### WebSocket
全双工通信协议，用于实时双向通信。

### Worker
工作进程。处理后台任务的独立进程，如视觉识别、邮件发送。

## 项目特定术语

### 健康事件 (Health Event)
系统中所有健康相关操作的不可变记录，如添加药品、记录体征、确认风险等。

### 风险事件 (Risk Event)
风险规则引擎触发的健康风险提醒，如过敏冲突、药品过期、重复成分等。

### 风险等级 (Risk Level)
风险的严重程度分级：SEVERE（严重）、HIGH（高）、INFO（信息）、LOW（低）。

### 视觉任务 (Vision Task)
药品图片识别任务，包含 OCR、条码识别和结果融合。

### 行动卡 (Action Card)
基于环境或健康数据生成的可操作建议卡片，如高温用药提醒、天气变化建议。

### 投影 (Projection)
事件溯源中的读模型，通过订阅事件更新，用于高效查询。

### 预算控制 (Budget Control)
风险提醒的数量限制机制，避免信息过载，严重风险不受限制。

### 去重键 (Deduplication Key)
用于识别相同风险的唯一键，避免重复触发相同风险。

### 指纹 (Fingerprint)
风险事件的内容哈希，用于确认时验证风险未发生变化。

### 家庭空间 (Household Space)
家庭的数据隔离边界，不同家庭的数据完全隔离。

### 成员档案 (Member Profile)
家庭成员的健康档案，包含基本信息、过敏史、用药记录等。

### 药品模板 (Medicine Template)
预定义的药品信息模板，包含名称、规格、成分、用法等。

### 用药计划 (Medication Plan)
成员的用药计划，包含药品、剂量、频率、时间等。

### 体征记录 (Vital Record)
生命体征记录，如血压、血糖、体温、体重等。

### 知识库 (Knowledge Base)
健康知识文档库，用于 RAG 检索和健康问答。

### 知识分块 (Knowledge Chunk)
知识库文档分割后的小块，用于向量化和相似度检索。

### Embedding
向量化。将文本转换为高维向量表示，用于相似度计算。

### 向量存储 (Vector Store)
存储向量并支持相似度搜索的数据库，如 pgvector、FAISS。

### 降级 (Degradation)
系统在依赖不可用时的优雅降级策略，返回部分功能或提示信息。

### 熔断 (Circuit Breaker)
在依赖服务故障时快速失败，避免级联故障的保护机制。

### 限流 (Rate Limiting)
限制请求频率的机制，防止滥用和过载。

### 幂等 (Idempotent)
多次执行同一操作产生相同结果的特性，重要操作应保证幂等。

### 乐观锁 (Optimistic Locking)
通过版本号实现的并发控制，冲突时重试或报错。

### 悲观锁 (Pessimistic Locking)
通过数据库行锁实现的并发控制，操作期间锁定数据。

### 软删除 (Soft Delete)
标记记录为已删除而非物理删除，保留数据用于审计和恢复。

### 审计日志 (Audit Log)
记录用户操作的日志，用于安全审计和追溯。

### 灰度发布 (Canary Release)
逐步将新版本发布给部分用户，降低发布风险的策略。

### 回滚 (Rollback)
将系统恢复到之前版本的操作，用于发布失败时的应急处理。
