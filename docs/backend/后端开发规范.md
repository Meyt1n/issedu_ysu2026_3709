# 后端开发规范

> 本文档是家健镜后端的开发规范，覆盖代码风格、项目结构、命名规范、API设计、错误处理、日志、测试、Git工作流。面向后端开发者，作为日常开发的权威依据。

## 1. 技术栈规范

### 1.1 核心技术

| 类别 | 技术 | 版本 | 说明 |
| --- | --- | --- | --- |
| 语言 | Python | 3.11+ | 类型提示强制 |
| Web框架 | FastAPI | 0.110+ | 异步、自动OpenAPI |
| ORM | SQLAlchemy | 2.0+ | 异步风格 |
| 数据库驱动 | aiosqlite / asyncpg | - | 异步驱动 |
| 迁移 | Alembic | 1.13+ | 数据库迁移 |
| 校验 | Pydantic | 2.5+ | 请求/响应模型 |
| 测试 | pytest | 8+ | 单元/集成测试 |
| 代码风格 | Ruff | - | lint + format |
| 类型检查 | mypy | - | 静态类型检查 |

### 1.2 禁止使用

- 不使用 Django / Flask（统一 FastAPI）
- 不使用同步数据库驱动（统一异步）
- 不使用 requests（统一 httpx 异步）
- 不使用 print 调试（统一 logging）
- 不使用裸 except（必须指定异常类型）
- 不使用可变默认参数
- 不使用通配符导入（from x import *）

## 2. 代码风格

### 2.1 命名规范

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 模块/文件 | snake_case | `health_events.py` |
| 类 | PascalCase | `HealthEventService` |
| 函数/方法 | snake_case | `create_health_event` |
| 变量 | snake_case | `member_id` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 私有方法 | _snake_case | `_validate_payload` |
| 类型别名 | PascalCase | `EventPayload` |

### 2.2 类型提示

所有函数必须有类型提示：

```python
# 好
def create_event(
    household_id: str,
    member_id: str,
    payload: EventPayload,
    db: AsyncSession,
) -> HealthEvent:
    ...

# 不好
def create_event(household_id, member_id, payload, db):
    ...
```

### 2.3 函数长度

- 单函数不超过 50 行
- 超过则拆分为多个小函数
- 嵌套不超过 3 层
- 参数不超过 5 个（超过用 dataclass 封装）

### 2.4 导入顺序

```python
# 1. 标准库
import asyncio
from datetime import datetime

# 2. 第三方库
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

# 3. 本地模块
from ..domain.models import HealthEvent
from ..infrastructure.db import get_db
from ..application.dto import EventResponse
```

### 3.2 分层依赖规则

```
api → application → domain ← infrastructure
```

- `api` 依赖 `application`，不直接依赖 `domain` 或 `infrastructure`
- `application` 依赖 `domain`，定义 `infrastructure` 的接口
- `domain` 不依赖任何外部层
- `infrastructure` 实现 `domain` 定义的接口

## 4. API 设计规范

### 4.1 路由命名

```python
router = APIRouter(prefix="/api/v1/households", tags=["households"])

@router.post("/{household_id}/members/{member_id}/events")
async def create_event(...):
    ...
```

- 资源用复数名词
- 层级关系体现在路径中
- 版本前缀 `/api/v1/`
- 动作用 HTTP 方法，不用动词在路径中

### 4.2 请求/响应模型

```python
# 请求模型
class CreateEventRequest(BaseModel):
    event_type: str = Field(..., description="事件类型")
    occurred_at: datetime | None = None
    payload: dict[str, Any]

    @field_validator("event_type")
    @classmethod
    def validate_event_type(cls, v):
        if v not in VALID_EVENT_TYPES:
            raise ValueError(f"无效事件类型: {v}")
        return v

# 响应模型
class EventResponse(BaseModel):
    event_id: str
    event_type: str
    occurred_at: datetime
    sequence_no: int

    model_config = ConfigDict(from_attributes=True)
```

### 4.3 错误处理

```python
# 自定义异常
class BusinessError(Exception):
    def __init__(self, code: str, message: str, status_code: int = 400):
        self.code = code
        self.message = message
        self.status_code = status_code

# 全局异常处理器
@app.exception_handler(BusinessError)
async def business_error_handler(request, exc):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "error": {"code": exc.code, "message": exc.message},
            "request_id": request.state.request_id,
        },
    )
```

### 4.4 依赖注入

```python
async def get_db() -> AsyncSession:
    async with async_session() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise

async def get_current_user(
    token: str = Depends(oauth2_scheme),
    db: AsyncSession = Depends(get_db),
) -> User:
    user = await verify_token(token, db)
    if not user:
        raise HTTPException(status_code=401, detail="未认证")
    return user
```

## 5. 数据库操作规范

### 5.1 异步查询

```python
# 好：异步查询
async def get_member(member_id: str, db: AsyncSession) -> Member | None:
    result = await db.execute(
        select(Member).where(Member.member_id == member_id)
    )
    return result.scalar_one_or_none()

# 不好：同步查询
def get_member(member_id: str, db: Session) -> Member | None:
    return db.query(Member).filter(Member.member_id == member_id).first()
```

### 5.2 事务管理

```python
# 使用依赖注入自动管理事务
@router.post("/events")
async def create_event(
    cmd: CreateEventCommand,
    db: AsyncSession = Depends(get_db),  # 自动 commit/rollback
):
    event = await handler.handle(cmd, db)
    return event

# 手动事务（复杂场景）
async with db.begin():
    await db.execute(insert_event(event))
    await db.execute(insert_outbox(event))
```

### 5.3 避免 N+1

```python
# 不好：循环查询
for member in members:
    meds = await get_medications(member.member_id, db)

# 好：批量查询
result = await db.execute(
    select(Medication).where(
        Medication.member_id.in_([m.member_id for m in members])
    )
)
med_map = {}
for med in result.scalars():
    med_map.setdefault(med.member_id, []).append(med)
```

### 5.4 索引使用

- 所有外键列必须有索引
- 常用查询条件建联合索引
- 不在低基数字段建索引
- 定期检查慢查询

## 6. 错误处理规范

### 6.1 异常分类

| 异常类型 | 基类 | HTTP 状态码 | 说明 |
| --- | --- | --- | --- |
| 业务异常 | BusinessError | 400/409 | 业务规则违反 |
| 认证异常 | AuthError | 401 | 未认证/Token过期 |
| 授权异常 | PermissionError | 403 | 无权限 |
| 未找到异常 | NotFoundError | 404 | 资源不存在 |
| 校验异常 | ValidationError | 422 | 参数校验失败 |
| 限流异常 | RateLimitError | 429 | 请求过于频繁 |
| 系统异常 | Exception | 500 | 未预期错误 |

### 6.2 异常抛出

```python
# 好：抛出有意义的异常
if not member:
    raise NotFoundError("MEMBER_NOT_FOUND", f"成员 {member_id} 不存在")

# 不好：抛出通用异常
if not member:
    raise Exception("不存在")
```

### 6.3 异常捕获

```python
# 好：捕获具体异常
try:
    await db.commit()
except IntegrityError as e:
    if "idempotency_key" in str(e):
        raise BusinessError("IDEMPOTENCY_CONFLICT", "操作已提交")
    raise

# 不好：裸 except
try:
    await db.commit()
except:
    pass
```

## 7. 日志规范

### 7.1 日志级别

| 级别 | 用途 | 示例 |
| --- | --- | --- |
| DEBUG | 开发调试 | 函数入参、中间结果 |
| INFO | 正常操作 | 请求完成、事件创建 |
| WARNING | 异常但可恢复 | 重试、降级、缓存未命中 |
| ERROR | 错误 | API 失败、异常捕获 |
| CRITICAL | 严重错误 | 数据库连接失败、数据丢失 |

### 7.2 日志格式

```python
logger = structlog.get_logger()

logger.info(
    "event_created",
    event_id=event.event_id,
    member_id=event.member_id,
    event_type=event.event_type,
    request_id=request.state.request_id,
)
```

### 7.3 日志规范

- 不记录密码、Token、健康数据内容
- 所有日志包含 request_id
- 错误日志包含异常堆栈
- 生产环境关闭 DEBUG 级别
- 日志结构化（JSON 格式）

## 10. Git 工作流

### 10.1 分支策略

| 分支 | 用途 | 命名 |
| --- | --- | --- |
| master | 主分支 | master |
| feature | 功能开发 | `feat/xxx-描述` |
| fix | Bug 修复 | `fix/xxx-描述` |
| docs | 文档更新 | `docs/xxx-描述` |
| refactor | 重构 | `refactor/xxx-描述` |

### 10.2 提交规范

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type：**
- feat: 新功能
- fix: Bug 修复
- docs: 文档
- refactor: 重构
- test: 测试
- chore: 构建/工具

### 10.3 PR 规范

- 每个 PR 关联一个 Issue
- PR 描述包含：变更内容、验收方式、风险、回滚方式
- 单个 PR 不超过 500 行（文档除外）
- 测试通过后才能合并
- 维护者合并即代表人工复核完成
