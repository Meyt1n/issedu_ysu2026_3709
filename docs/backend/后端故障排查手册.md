# 后端故障排查手册

> 本文档是家健镜系统后端故障排查的操作手册，覆盖常见故障现象、排查步骤、解决方案、应急处理。面向运维人员和后端开发者，作为线上问题排查的权威依据。

## 1. 排查总览

### 1.1 排查流程

```
发现故障
    ↓
确认影响范围（用户数、功能模块、严重程度）
    ↓
检查服务状态（健康检查、日志、指标）
    ↓
定位故障层级（网络/应用/数据库/依赖）
    ↓
执行应急处理（重启/回滚/降级）
    ↓
根因分析
    ↓
修复并验证
    ↓
记录复盘
```

### 1.2 紧急联系人

| 角色 | 职责 |
| --- | --- |
| 运维负责人 | 基础设施、部署、监控 |
| 后端负责人 | 应用代码、API、数据库 |
| 算法负责人 | 视觉识别、LLM、知识库 |
| 移动端负责人 | APP 端问题 |

## 2. 服务不可用

### 2.1 现象

- 所有 API 返回 502/503/504
- 健康检查失败
- 客户端无法连接

### 2.2 排查步骤

```bash
# 1. 检查容器/进程状态
docker ps -a | grep homecare
systemctl status homecare-backend

# 2. 检查健康检查
curl http://localhost:8000/health
curl http://localhost:8000/health/db
curl http://localhost:8000/health/redis

# 3. 查看最近日志
docker logs --tail 200 homecare-backend
journalctl -u homecare-backend -n 200 --no-pager

# 4. 检查端口监听
netstat -tlnp | grep 8000
ss -tlnp | grep 8000
```

### 2.3 常见原因

| 原因 | 排查方法 | 解决方案 |
| --- | --- | --- |
| 进程崩溃 | 查看日志中的 Traceback | 修复代码后重启 |
| OOM 被 kill | `dmesg | grep -i oom` | 增加内存或优化内存使用 |
| 端口被占用 | `netstat -tlnp` | 杀掉占用进程或换端口 |
| 配置错误 | 检查环境变量 | 修正配置后重启 |
| 依赖服务不可用 | 检查数据库/Redis | 修复依赖服务 |

### 2.4 应急处理

```bash
# 重启服务
docker restart homecare-backend
# 或
systemctl restart homecare-backend

# 如果重启失败，回滚到上一个版本
docker rollback homecare-backend
```

## 3. 响应缓慢

### 3.1 现象

- API 响应时间 > 3 秒
- 页面加载慢
- 客户端超时

### 3.2 排查步骤

```bash
# 1. 检查系统资源
top
htop
free -h
df -h

# 2. 检查慢查询日志
# PostgreSQL
tail -f /var/log/postgresql/postgresql-*.log | grep "duration"

# 3. 检查 Redis 延迟
redis-cli --latency-history

# 4. 检查应用日志中的慢请求
grep "slow_request" /var/log/homecare/backend.log
```

### 3.3 常见原因

| 原因 | 排查方法 | 解决方案 |
| --- | --- | --- |
| 数据库慢查询 | 开启慢查询日志，EXPLAIN 分析 | 添加索引、优化查询 |
| 连接池耗尽 | 查看连接数 `SELECT count(*) FROM pg_stat_activity;` | 增加连接池、优化连接使用 |
| N+1 查询 | 检查日志中的重复查询 | 使用 selectinload/joinedload |
| 外部 API 慢 | 检查外部调用耗时 | 增加超时、缓存结果 |
| CPU 密集型任务 | `top` 查看 CPU 占用 | 异步处理、移到 Worker |
| 内存不足导致 swap | `free -h` 查看 swap | 增加内存、优化内存 |

### 3.4 数据库慢查询排查

```sql
-- 查看当前运行的查询
SELECT pid, now() - query_start AS duration, query
FROM pg_stat_activity
WHERE state = 'active'
ORDER BY duration DESC
LIMIT 10;

-- 终止慢查询
SELECT pg_terminate_backend(pid);

-- 分析查询计划
EXPLAIN ANALYZE SELECT * FROM health_events WHERE member_id = 'xxx' ORDER BY occurred_at DESC;
```

## 4. 数据库问题

### 4.1 连接耗尽

**现象**：`sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached`

**排查**：
```sql
-- 查看连接数
SELECT count(*), state FROM pg_stat_activity GROUP BY state;

-- 查看空闲连接
SELECT pid, usename, application_name, client_addr, state, query
FROM pg_stat_activity
WHERE state = 'idle'
ORDER BY query_start;
```

**解决**：
- 增加连接池大小：`pool_size=20, max_overflow=30`
- 检查连接泄漏（确保每次请求后释放连接）
- 设置 `pool_recycle=1800` 防止连接超时
- 终止长时间空闲连接

### 4.2 锁等待

**现象**：部分更新操作卡住

**排查**：
```sql
-- 查看锁等待
SELECT blocked_locks.pid AS blocked_pid,
       blocked_activity.query AS blocked_query,
       blocking_locks.pid AS blocking_pid,
       blocking_activity.query AS blocking_query
FROM pg_catalog.pg_locks blocked_locks
JOIN pg_stat_activity blocked_activity ON blocked_activity.pid = blocked_locks.pid
JOIN pg_catalog.pg_locks blocking_locks
  ON blocking_locks.locktype = blocked_locks.locktype
 AND blocking_locks.database IS NOT DISTINCT FROM blocked_locks.database
 AND blocking_locks.relation IS NOT DISTINCT FROM blocked_locks.relation
 AND blocking_locks.page IS NOT DISTINCT FROM blocked_locks.page
 AND blocking_locks.tuple IS NOT DISTINCT FROM blocked_locks.tuple
 AND blocking_locks.virtualxid IS NOT DISTINCT FROM blocked_locks.virtualxid
 AND blocking_locks.transactionid IS NOT DISTINCT FROM blocked_locks.transactionid
 AND blocking_locks.classid IS NOT DISTINCT FROM blocked_locks.classid
 AND blocking_locks.objid IS NOT DISTINCT FROM blocked_locks.objid
 AND blocking_locks.objsubid IS NOT DISTINCT FROM blocked_locks.objsubid
 AND blocking_locks.pid != blocked_locks.pid
JOIN pg_stat_activity blocking_activity ON blocking_activity.pid = blocking_locks.pid
WHERE NOT blocked_locks.granted;
```

**解决**：
- 终止阻塞进程：`SELECT pg_terminate_backend(pid);`
- 优化事务，缩短事务持有时间
- 避免在事务中做外部 API 调用

### 4.3 磁盘满

**现象**：`could not write to file: No space left on device`

**排查**：
```bash
df -h
du -sh /var/lib/postgresql/data/*
du -sh /var/log/*
```

**解决**：
- 清理旧日志：`pg_archivecleanup`
- 清理 WAL 日志
- VACUUM 回收空间
- 增加磁盘容量

### 4.4 迁移失败

**现象**：Alembic 迁移报错

**排查**：
```bash
# 查看当前版本
alembic current

# 查看迁移历史
alembic history

# 检查待执行迁移
alembic heads
```

**解决**：
- 回滚到上一个版本：`alembic downgrade -1`
- 修复迁移脚本后重新执行
- 手动修复数据库状态

## 5. Redis 问题

### 5.1 连接失败

**现象**：`redis.exceptions.ConnectionError`

**排查**：
```bash
redis-cli ping
redis-cli info server
```

**解决**：
- 检查 Redis 是否运行：`systemctl status redis`
- 检查配置：密码、地址、端口
- 检查网络连通性

### 5.2 内存满

**现象**：`OOM command not allowed when used memory > 'maxmemory'`

**排查**：
```bash
redis-cli info memory
redis-cli memory usage <key>
```

**解决**：
- 配置淘汰策略：`maxmemory-policy allkeys-lru`
- 清理大 key
- 增加内存

## 6. 认证问题

### 6.1 Token 验证失败

**现象**：API 返回 401

**排查**：
- 检查 JWT_SECRET 是否一致
- 检查 Token 是否过期
- 检查 Token 签名算法

**解决**：
- 统一各服务的 JWT_SECRET
- 检查系统时间是否准确
- 重新签发 Token

### 6.2 权限不足

**现象**：API 返回 403

**排查**：
- 检查用户角色
- 检查家庭成员关系
- 检查资源归属

**解决**：
- 确认用户角色配置
- 检查家庭邀请是否接受
- 检查资源是否属于该家庭

## 7. 文件上传问题

### 7.1 上传失败

**现象**：文件上传返回 413 或 500

**排查**：
- 检查 Nginx client_max_body_size
- 检查应用 MAX_UPLOAD_SIZE
- 检查磁盘空间
- 检查文件存储路径权限

**解决**：
```nginx
# Nginx 配置
client_max_body_size 50M;
```

```python
# 应用配置
MAX_UPLOAD_SIZE = 50 * 1024 * 1024  # 50MB
```

### 7.2 图片无法访问

**现象**：图片 URL 返回 404

**排查**：
- 检查文件是否存在
- 检查静态文件服务配置
- 检查文件权限

**解决**：
- 确认文件存储路径正确
- 配置 Nginx 静态文件服务
- 检查文件权限

## 8. 视觉识别问题

### 8.1 任务卡住

**现象**：视觉任务一直处于 QUEUED 状态

**排查**：
- 检查 Worker 进程是否运行
- 检查 Worker 日志
- 检查任务队列

**解决**：
- 重启 Worker
- 检查模型是否加载成功
- 检查依赖库是否安装

### 8.2 识别准确率低

**现象**：识别结果经常错误

**排查**：
- 检查图片质量（模糊、光线）
- 检查 OCR 引擎版本
- 检查药品数据库完整性

**解决**：
- 引导用户拍摄清晰图片
- 升级 OCR 模型
- 补充药品数据库
- 增加人工复核

## 9. LLM/知识库问题

### 9.1 LLM 调用失败

**现象**：对话功能不可用

**排查**：
- 检查 API Key 是否有效
- 检查 API 地址是否可达
- 检查是否超过配额

**解决**：
- 更新 API Key
- 检查网络连通性
- 切换备用模型
- 降级到纯检索模式

### 9.2 知识库检索无结果

**现象**：回答"根据现有资料无法回答"

**排查**：
- 检查是否有已批准文档
- 检查索引是否构建
- 检查 Embedding 服务

**解决**：
- 上传并审核知识文档
- 重建索引
- 检查 Embedding 服务状态

## 10. WebSocket 问题

### 10.1 连接失败

**现象**：客户端无法建立 WebSocket 连接

**排查**：
- 检查 Nginx WebSocket 配置
- 检查 Token 是否有效
- 检查服务是否支持 WebSocket

**解决**：
```nginx
# Nginx WebSocket 配置
location /ws/ {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 300s;
}
```

### 10.2 频繁断开

**现象**：连接经常断开

**排查**：
- 检查心跳间隔
- 检查 Nginx proxy_read_timeout
- 检查网络稳定性

**解决**：
- 确保客户端每 30 秒发送心跳
- 增加 Nginx 超时时间
- 实现客户端自动重连
