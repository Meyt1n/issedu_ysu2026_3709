# 数据库设计与迁移指南

> 本文档是家健镜系统的数据库设计完整说明，覆盖表结构设计、索引策略、迁移流程、SQLite/PostgreSQL 兼容、数据备份恢复。面向后端开发者和 DBA，作为数据库开发和运维的权威依据。

## 1. 数据库选型

### 1.1 支持的数据库

| 数据库 | 版本 | 适用场景 | 特点 |
| --- | --- | --- | --- |
| SQLite | 3.40+ | 家庭单机、开发测试 | 零配置、单文件、备份简单 |
| PostgreSQL | 15+ | 多用户、生产部署 | 并发、JSONB、全文检索、扩展 |

### 1.2 选择策略

- 家庭用户：默认 SQLite，无需安装数据库
- 生产环境：PostgreSQL，支持并发和高级功能
- 开发测试：SQLite，快速隔离
- 通过 SQLAlchemy ORM 抽象，同一套代码支持两种数据库

### 1.3 连接配置

```python

# PostgreSQL
DATABASE_URL = "postgresql+asyncpg://user:pass@localhost:5432/homecare"
```

### 2.4 健康事件表（核心）

```sql
CREATE TABLE health_events (
    event_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    household_id UUID NOT NULL REFERENCES households(household_id),
    member_id UUID NOT NULL REFERENCES household_members(member_id),
    sequence_no INTEGER NOT NULL,
    event_type VARCHAR(50) NOT NULL,
    occurred_at TIMESTAMPTZ NOT NULL,
    recorded_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    actor_user_id UUID NOT NULL REFERENCES users(user_id),
    source_type VARCHAR(20) NOT NULL DEFAULT 'manual',
    source_id UUID,
    payload JSONB NOT NULL,
    before_snapshot JSONB,
    after_snapshot JSONB,
    evidence_ids UUID[],
    recognition_model_version VARCHAR(50),
    rule_version VARCHAR(50),
    idempotency_key VARCHAR(100) UNIQUE,
    correlation_id UUID,
    causation_id UUID,
    supersedes_event_id UUID REFERENCES health_events(event_id),
    schema_version INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE(member_id, sequence_no)
);

CREATE INDEX idx_events_household ON health_events(household_id);
CREATE INDEX idx_events_member ON health_events(member_id);
CREATE INDEX idx_events_type ON health_events(member_id, event_type);
CREATE INDEX idx_events_time ON health_events(member_id, occurred_at DESC);
CREATE INDEX idx_events_correlation ON health_events(correlation_id);
CREATE INDEX idx_events_idempotency ON health_events(idempotency_key);
```

**设计要点：**
- `sequence_no` 成员内单调递增，用于事件回放顺序
- `idempotency_key` 唯一约束，防止重复提交
- `payload` JSONB 存储事件详情，灵活支持不同事件类型
- `supersedes_event_id` 支持事件补偿
- `correlation_id` / `causation_id` 支持事件链路追踪

## 3. 索引策略

### 3.1 索引设计原则

1. **主键索引**：所有表 UUID 主键
2. **外键索引**：所有外键列建索引
3. **查询过滤索引**：常用 WHERE 条件列建联合索引
4. **排序索引**：常用 ORDER BY 列建索引
5. **部分索引**：对有过滤条件的列建部分索引
6. **JSONB 索引**：频繁查询的 JSONB 字段建 GIN 索引

### 3.2 常用查询与索引对应

| 查询 | 索引 |
| --- | --- |
| 成员事件列表 | `(member_id, occurred_at DESC)` |
| 今日任务 | `(member_id, task_date)` |
| 活跃风险 | `(household_id, acknowledged, created_at DESC)` |
| 待处理 Outbox | `(status, created_at)` |
| 药品过期 | `(expiry_date) WHERE expiry_date IS NOT NULL` |
| 授权查询 | `(grantee_user_id, status)` |

### 3.3 SQLite 注意事项

- SQLite 不支持 `GENERATED` 列和部分索引的某些语法
- SQLite 的 JSONB 实际是 TEXT，查询用 `json_extract()`
- SQLite 不支持 `vector` 类型，向量检索用 SQLite-vss 扩展或应用层处理
- 并发写入性能差，家庭单用户场景足够

## 4. 迁移管理

### 4.1 迁移工具

使用 Alembic 管理数据库迁移：

```bash
# 创建迁移
alembic revision --autogenerate -m "add vision_tasks table"

# 执行迁移
alembic upgrade head

# 回滚
alembic downgrade -1

# 查看当前版本
alembic current

# 查看历史
alembic history
```

### 4.2 迁移文件命名

```
migrations/versions/
├── 001_initial_schema.py
├── 002_add_health_events.py
├── 003_add_vision_tasks.py
├── 004_add_risk_budget.py
└── ...
```

### 4.3 迁移规范

1. **每个迁移只做一件事**：不混合多个不相关变更
2. **必须可回滚**：`downgrade()` 函数必须实现
3. **数据迁移分离**：结构迁移和数据迁移分开
4. **幂等安全**：迁移可重复执行不报错
5. **大表变更谨慎**：ALTER TABLE 在大表上可能锁表

### 4.4 迁移示例

```python
'''add risk_events table

Revision ID: 003
Revises: 002
Create Date: 2026-09-01 10:00:00.000000
'''
from alembic import op
import sqlalchemy as sa

revision = '003'
down_revision = '002'

def upgrade():
    op.create_table(
        'risk_events',
        sa.Column('risk_id', sa.String(36), primary_key=True),
        sa.Column('household_id', sa.String(36), nullable=False),
        sa.Column('member_id', sa.String(36), nullable=False),
        sa.Column('risk_level', sa.String(10), nullable=False),
        sa.Column('rule_id', sa.String(100), nullable=False),
        sa.Column('title', sa.String(200), nullable=False),
        sa.Column('description', sa.Text(), nullable=False),
        sa.Column('acknowledged', sa.Boolean(), default=False),
        sa.Column('created_at', sa.DateTime(), server_default=sa.func.now()),
    )
    op.create_index('idx_risks_household', 'risk_events', ['household_id'])
    op.create_index('idx_risks_active', 'risk_events', ['household_id', 'acknowledged'])

def downgrade():
    op.drop_index('idx_risks_active', table_name='risk_events')
    op.drop_index('idx_risks_household', table_name='risk_events')
    op.drop_table('risk_events')
```

### 4.5 迁移执行流程

1. 开发环境执行迁移，验证通过
2. 提交迁移文件到代码仓库
3. CI 执行迁移测试（临时数据库）
4. 生产环境备份后执行迁移
5. 验证应用正常运行

## 6. 性能优化

### 6.1 查询优化

```python
# 好：使用索引列过滤
events = await db.execute(
    select(HealthEvent)
    .where(HealthEvent.member_id == member_id)
    .order_by(HealthEvent.occurred_at.desc())
    .limit(20)
)

# 好：只查询需要的列
result = await db.execute(
    select(Member.member_id, Member.display_name)
    .where(Member.household_id == household_id)
)

# 不好：SELECT *
result = await db.execute(select(Member))
```

### 6.2 连接池

```python
engine = create_async_engine(
```

### 6.3 异步查询

```python
# 所有数据库操作异步
async def get_member(member_id: str):
    result = await db.execute(
        select(Member).where(Member.member_id == member_id)
    )
    return result.scalar_one_or_none()
```

### 6.4 N+1 查询避免

```python
# 不好：循环查询
for member in members:
    meds = await get_medications(member.member_id)  # N+1

# 好：批量查询
medications = await db.execute(
    select(Medication).where(Medication.member_id.in_([m.member_id for m in members]))
)
med_map = {}
for med in medications.scalars():
    med_map.setdefault(med.member_id, []).append(med)
```

## 7. 数据安全

### 7.1 敏感字段

- 密码：bcrypt 哈希，不明文存储
- JWT 密钥：环境变量，不入代码库
- 健康数据：不记录到日志，不输出到错误响应
- 文件存储：路径不暴露，通过接口访问

### 7.2 数据加密

- 传输：HTTPS（公网）
- 存储：SQLite 文件系统级加密（可选）
- 备份：加密存储

### 7.3 数据删除

- 软删除：药品、疾病等用 status 标记
- 硬删除：家庭删除时级联删除所有数据
- 成员删除：生成事件记录，保留审计日志
