# 后端数据库性能优化指南

> 本文档是家健镜系统数据库性能优化的完整指南，覆盖索引优化、查询优化、配置调优、监控诊断。

## 1. 概述

### 1.1 优化目标

1. 查询响应时间 < 100ms
2. 慢查询比例 < 1%
3. 连接池利用率 < 80%
4. 数据库 CPU < 70%
5. 支持水平扩展

### 1.2 性能瓶颈

| 瓶颈 | 表现 | 解决方案 |
| --- | --- | --- |
| 慢查询 | 响应时间长 | 索引优化、查询改写 |
| 锁等待 | 并发性能差 | 事务优化、隔离级别 |
| 连接耗尽 | 无法建立连接 | 连接池调优 |
| 内存不足 | 频繁磁盘 IO | 缓存优化、内存配置 |
| 磁盘 IO | 吞吐量低 | SSD、分区表 |

## 2. 索引优化

### 2.1 索引设计原则

```sql
-- 主键索引（自动创建）
CREATE TABLE medicines (
    id UUID PRIMARY KEY,
    name VARCHAR(255),
    member_id UUID,
    created_at TIMESTAMP
);

-- 常用查询字段建索引
CREATE INDEX idx_medicines_member_id ON medicines(member_id);
CREATE INDEX idx_medicines_name ON medicines(name);

-- 复合索引（最左前缀原则）
CREATE INDEX idx_medicines_member_created
  ON medicines(member_id, created_at DESC);

-- 唯一索引
CREATE UNIQUE INDEX idx_users_email ON users(email);

-- 部分索引（只索引部分数据）
CREATE INDEX idx_medicines_active
  ON medicines(member_id) WHERE deleted_at IS NULL;

-- 表达式索引
CREATE INDEX idx_medicines_lower_name
  ON medicines(LOWER(name));
```

### 2.2 索引使用检查

```sql
-- 查看索引使用情况
SELECT
    schemaname,
    tablename,
    indexname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes
ORDER BY idx_scan ASC;

-- 查看未使用的索引
SELECT
    schemaname,
    tablename,
    indexname
FROM pg_stat_user_indexes
WHERE idx_scan = 0
  AND indexname NOT LIKE '%_pkey';
```

### 2.3 索引维护

```sql
-- 重建索引
REINDEX INDEX idx_medicines_name;

-- 分析表（更新统计信息）
ANALYZE medicines;

-- 查看索引膨胀
SELECT
    indexname,
    pg_size_pretty(pg_relation_size(indexrelid)) as index_size
FROM pg_stat_user_indexes
WHERE tablename = 'medicines';
```

## 3. 查询优化

### 3.1 EXPLAIN 分析

```sql
-- 查看执行计划
EXPLAIN ANALYZE
SELECT * FROM medicines
WHERE member_id = 'abc' AND name LIKE '%阿莫%';

-- 关注：
-- Seq Scan -> 全表扫描，需要加索引
-- Index Scan -> 索引扫描，正常
-- Bitmap Heap Scan -> 位图扫描
-- Nested Loop -> 嵌套循环连接
-- Hash Join -> 哈希连接
-- Sort -> 排序，注意是否使用内存
```

### 3.2 查询改写

```sql
-- 避免 SELECT *
-- 不好
SELECT * FROM medicines WHERE member_id = ?;

-- 好
SELECT id, name, dosage FROM medicines WHERE member_id = ?;

-- 避免 LIKE 前缀通配
-- 不好（无法使用索引）
SELECT * FROM medicines WHERE name LIKE '%阿莫%';

-- 好（可以使用索引）
SELECT * FROM medicines WHERE name LIKE '阿莫%';

-- 避免在索引列上使用函数
-- 不好
SELECT * FROM medicines WHERE LOWER(name) = 'amoxicillin';

-- 好（使用表达式索引）
SELECT * FROM medicines WHERE name ILIKE 'amoxicillin';

-- 分页优化
-- 不好（深分页性能差）
SELECT * FROM medicines ORDER BY id LIMIT 20 OFFSET 10000;

-- 好（游标分页）
SELECT * FROM medicines
WHERE id < ?
ORDER BY id DESC
LIMIT 20;
```

### 3.3 连接优化

```sql
-- 优先使用 INNER JOIN
SELECT m.name, COUNT(r.id)
FROM medicines m
INNER JOIN medication_records r ON r.medicine_id = m.id
WHERE m.member_id = ?
GROUP BY m.id;

-- 避免子查询，改用 JOIN
-- 不好
SELECT * FROM medicines
WHERE member_id IN (
    SELECT id FROM members WHERE household_id = ?
);

-- 好
SELECT m.* FROM medicines m
INNER JOIN members mem ON mem.id = m.member_id
WHERE mem.household_id = ?;
```

## 4. 事务优化

### 4.1 事务隔离级别

```sql
-- 读取已提交（默认）
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 可重复读
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- 可串行化（最高隔离，性能差）
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

### 4.2 事务最佳实践

```python
# 保持事务简短
async with db.begin():
    # 只做必要的数据库操作
    await db.execute(insert_medicine)
    await db.execute(update_stock)

# 避免在事务中做耗时操作
# 不好
async with db.begin():
    await db.execute(insert)
    await call_external_api()  # 耗时操作
    await db.execute(update)

# 好
result = await call_external_api()
async with db.begin():
    await db.execute(insert)
    await db.execute(update)
```

## 5. 连接池配置

### 5.1 连接池参数

```python
# SQLAlchemy 连接池配置
engine = create_async_engine(
    DATABASE_URL,
    pool_size=10,           # 连接池大小
    max_overflow=20,        # 最大溢出连接
    pool_timeout=30,        # 获取连接超时
    pool_recycle=1800,      # 连接回收时间（秒）
    pool_pre_ping=True,     # 连接前 ping
)
```

### 5.2 连接池监控

```sql
-- 查看当前连接数
SELECT count(*) FROM pg_stat_activity;

-- 查看连接状态
SELECT state, count(*) FROM pg_stat_activity GROUP BY state;

-- 查看空闲连接
SELECT * FROM pg_stat_activity WHERE state = 'idle';

-- 终止空闲连接
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE state = 'idle' AND state_change < NOW() - INTERVAL '5 minutes';
```

## 7. 监控诊断

### 7.1 慢查询日志

```sql
-- 开启慢查询日志
ALTER DATABASE homecare SET log_min_duration_statement = 1000;

-- 查看当前运行的查询
SELECT
    pid,
    now() - query_start as duration,
    state,
    query
FROM pg_stat_activity
WHERE state != 'idle'
ORDER BY duration DESC;

-- 终止慢查询
SELECT pg_terminate_backend(pid);
```

### 7.2 性能视图

```sql
-- 表大小
SELECT
    relname,
    pg_size_pretty(pg_total_relation_size(relid)) as total_size
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC
LIMIT 10;

-- 表统计信息
SELECT
    relname,
    n_live_tup,
    n_dead_tup,
    last_vacuum,
    last_analyze
FROM pg_stat_user_tables
ORDER BY n_dead_tup DESC;
```
