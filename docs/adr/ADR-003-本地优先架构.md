# ADR-003: 本地优先架构

## 状态

已采纳

## 背景

家健镜系统处理敏感的家庭健康数据，用户对隐私有较高要求。同时，家庭网络环境可能不稳定，需要支持离线使用。

## 决策

采用本地优先（Local-First）架构：

1. **数据本地存储**：核心数据在家庭服务器本地存储
2. **离线可用**：APP 离线时可查看和操作
3. **增量同步**：联网后自动同步变更
4. **冲突解决**：多端修改时智能合并
5. **隐私保护**：敏感数据不上传公网

## 理由

### 为什么选择本地优先

1. **隐私保护**：健康数据不出家庭网络
2. **离线可用**：网络不稳定时仍可使用
3. **快速响应**：本地数据访问毫秒级
4. **数据主权**：用户完全掌控自己的数据
5. **降低成本**：减少云端存储和带宽费用

### 技术实现

- APP 端：Hive 本地数据库 + 增量同步
- 服务端：家庭服务器部署，数据本地存储
- 同步：基于事件的增量同步 + 冲突解决
- 备份：支持本地备份和导出

## 后果

### 正面

- 数据隐私有保障
- 离线体验好
- 响应速度快
- 用户数据主权

### 负面

- 同步复杂度高
- 冲突解决困难
- 多设备一致性挑战
- 数据丢失风险（需备份）

## 替代方案

1. **云端优先**：数据存云端，实时同步，但隐私风险大
2. **混合模式**：敏感数据本地，非敏感云端，复杂度更高
3. **纯本地**：不支持多端同步，体验差

## 实施要点

- 本地数据加密存储
- 同步有版本号和时间戳
- 冲突有自动合并和人工解决
- 定期本地备份
- 支持数据导出和迁移

---

*ADR-003 记录了本地优先架构决策，为隐私保护和离线体验提供基础。*
