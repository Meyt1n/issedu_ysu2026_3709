# ADR-001: 技术栈选型

## 状态

已采纳

## 背景

家健镜系统需要选择合适的技术栈，满足家庭健康管理的需求：后端 API、移动端 APP、本地部署、隐私保护。

## 决策

### 后端

| 技术 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11 | 生态丰富、AI 库支持好、开发效率高 |
| Web 框架 | FastAPI | 异步高性能、自动文档、类型提示 |
| ORM | SQLAlchemy 2.0 | 成熟稳定、异步支持 |
| 数据库迁移 | Alembic | SQLAlchemy 官方迁移工具 |
| 数据库 | PostgreSQL 15 | 关系型、JSONB 支持、可靠 |
| 缓存 | Redis 7 | 高性能、多种数据结构 |
| 任务队列 | Celery / ARQ | 异步任务处理 |

### 移动端

| 技术 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Flutter | 跨平台、高性能、UI 一致 |
| 状态管理 | Provider | 官方推荐、轻量 |
| 路由 | go_router | 声明式、深链接支持 |
| 网络 | Dio | 功能丰富、拦截器 |
| 本地存储 | Hive + SharedPreferences | 轻量、快速 |

### 基础设施

| 技术 | 选择 | 理由 |
| --- | --- | --- |
| 容器化 | Docker | 环境一致、易于部署 |
| 编排 | Docker Compose / K8s | 按需选择 |
| 反向代理 | Nginx | 高性能、成熟 |
| 监控 | Prometheus + Grafana | 开源、强大 |
| 日志 | ELK / Loki | 集中式日志 |

## 后果

### 正面

- Python 生态丰富，AI/ML 库多
- FastAPI 性能好，开发效率高
- Flutter 一套代码双端运行
- 技术栈成熟，社区活跃

### 负面

- Python 性能不如 Go/Java
- Flutter 包体积较大
- 需要维护多套技术栈

## 替代方案

- 后端：Node.js (NestJS)、Go (Gin)、Java (Spring Boot)
- 移动端：React Native、原生开发
- 考虑因素：团队技能、性能需求、生态成熟度
