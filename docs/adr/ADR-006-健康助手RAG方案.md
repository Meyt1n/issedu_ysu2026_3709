# ADR-006: 健康助手采用RAG方案

## 状态

已采纳

## 背景

家健镜系统的健康助手需要回答健康相关问题。可以选择纯 LLM 或检索增强生成（RAG）。

## 决策

健康助手采用 RAG（检索增强生成）方案：

1. **知识库**：维护已批准的健康知识文档
2. **检索**：用户提问时检索相关知识
3. **生成**：基于检索结果生成回答
4. **引用**：回答附带引用来源
5. **降级**：无相关知识时如实告知

## 理由

### 为什么选择 RAG

1. **准确性**：回答基于可信知识库，减少幻觉
2. **可追溯**：每个回答有引用来源
3. **可更新**：知识更新只需更新文档，无需微调模型
4. **可控**：只使用已批准的知识，避免错误信息
5. **隐私**：检索在本地完成，数据不出网

### 为什么不选择纯 LLM

1. **幻觉问题**：LLM 可能编造信息
2. **知识过时**：模型训练数据有截止日期
3. **不可控**：无法保证回答基于可信来源
4. **不可追溯**：回答没有引用来源

## 后果

### 正面

- 回答准确
- 有引用来源
- 知识易更新
- 可控可审计

### 负面

- 系统复杂度高
- 检索质量影响回答
- 需要维护知识库
- 回答可能不完整

## 替代方案

1. **纯 LLM**：简单但幻觉问题
2. **微调模型**：准确但成本高、更新慢
3. **规则问答**：准确但覆盖有限

## 实施要点

- 知识库文档需要审核批准
- 检索有相关性阈值
- 回答必须有引用
- 无答案时如实告知
- 不提供医疗诊断
- 知识库有版本管理
