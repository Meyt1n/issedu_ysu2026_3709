## 本目录是什么、不是什么

- **是**：下一期迭代的规划事实源草案（主题、Backlog、波次依赖、Story 卡片、可粘贴 Issue 正文），以及支撑规划的两篇现状基线（功能完成度、Issue/PR 盘点）。
- **不是**：需求追踪矩阵的替代品。唯一进度入口仍是 [`docs/vibe-coding/12-需求追踪矩阵.md`](../vibe-coding/12-需求追踪矩阵.md)。本目录发现的矩阵滞后项**只列建议、不直接改矩阵**，见[建议的矩阵与Issue回填清单](建议的矩阵与Issue回填清单.md)，由维护者手工执行。
- 本目录不修改任何已有文档；按仓库规则，规划中的任何条目在建立 Issue + Story 并合并 PR 之前，状态都是「未开始」。

## 使用方式

1. 维护者先读规划正文，裁决主题与波次；
2. 按[建议的矩阵与Issue回填清单](建议的矩阵与Issue回填清单.md)手工回填矩阵与补建 Issue（agent 无 issues 写权限，见盘点摘要中的 403 说明）；
3. 采纳的条目按 [Story卡片集](Story卡片集-HCT-5xx与NEXT.md) 中的可粘贴正文建 Issue，再在 `docs/stories/` 建正式 Story 文件后进入 Ready；
4. 事实冲突时按 [`开发前必读与Vibe Coding工作流`](../vibe-coding/开发前必读与Vibe%20Coding工作流.md) 的事实优先级处理——本目录属于第 3 级（计划/Story），低于 ADR、迁移与自动测试。
