## 1. 迭代主题

**「验收闭环与教学演示成熟度」——从功能堆叠转向证据收口。**

依据：截至 2026-08-27，六大 P0 功能域的代码与自动测试大面积就位（近两周合并约 45 个 PR，覆盖助手安全/联网、人脸登录成熟度、双端口门户、语音、告警预算、UTC 时间戳、移动端发布链），但需求追踪矩阵中「已验证」的 Story 仍只有个位数；主要债务不是缺功能，而是：正式验收（R3）未做、部署/备份演练未实跑、模型盲测未跑、矩阵与 Issue 治理滞后。下期不再新开大功能面，集中把「进行中/待验收」推进到可审计的「已验证」，并把教学演示主线打磨到可连续展示。

## 2. 原则（本期所有任务共同遵守）

1. **证据优先**：先收验收债，再开新功能；每个条目的完成定义包含「矩阵状态同步 + 可定位证据链接」。
2. **产品边界不动摇**：教学演示；不做诊断/处方/停药/换药/剂量判断；不做买药/问诊/广告导流；健康数据默认不出网；人脸非生产级生物识别。
3. **fail-closed 不当缺陷修**：`hct201-formal-drug-set` 恒不可用、爬虫永不 auto_ingest、生产关闭开发身份头等是诚实声明，不允许为「点亮能力」而放松门禁。
4. **单 PR 单 Issue 单 Story**：每个条目先由维护者建 Issue（agent 无权限），再建 `docs/stories/HCT-5xx-*.md`，才能进入 Ready。
5. **真机/真实环境验收不由 Cloud Agent 代签**：Android 真机矩阵、真实摄像头阈值标定、研发机 GPU 训练等只能由持有设备/环境的成员执行并回填证据。
