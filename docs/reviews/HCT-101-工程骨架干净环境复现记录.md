## 复现步骤与结果

### 依赖与空库迁移

```powershell
scripts/start.ps1 setup
$env:DATABASE_URL='sqlite+pysqlite:///C:/Users/<user>/AppData/Local/Temp/hct101-<id>.sqlite3'
scripts/start.ps1 migrate
uv run alembic current
```

结果：首次 `setup` 用时 17.07 秒；最终脚本的 `uv sync --frozen` 和 `npm ci` 均按 `uv.lock`、`package-lock.json` 重复验证通过。临时 SQLite 空库在 5.23 秒内依次执行 `0001_initial_schema`、`0002_allow_pending_health_events`，`alembic current` 返回唯一 head `0002_allow_pending_health_events`。临时库不包含真实健康数据。

`.env` 由 `.env.example` 创建；示例只含 `change-me` 占位密码、回环地址和未启用能力版本，不含仓库、中转服务或生产密钥。真实环境必须在仓库外替换占位值。

```powershell

$env:API_PORT='18000'
$env:WEB_PORT='18080'

```

## 已知限制与故障记录

- 第一次构建在 Docker Hub 匿名令牌端点超时，属于外部镜像拉取故障；宿主访问恢复后单独拉取固定标签并重试成功。首次离线部署仍需提前缓存基础镜像。
- Node 本机版本为 24，团队和 CI 基线为 Node 22；本次 `npm ci`、类型检查和构建均只使用锁文件，正式最低兼容性由 CI Node 22 结果确认。
- `down` 默认保留 MySQL 数据卷，防止误删；清空卷不是标准流程，执行 `docker compose down --volumes` 前必须确认数据可丢弃或已备份。
- HCT-101 只证明工程骨架、迁移和健康检查可复现，不证明视觉、OCR、规则、RAG、LLM、天气或完整页面已交付。

## 风险、回滚与结论

- **P2/外部依赖**：首次构建需要访问镜像仓库和语言包源；缓解为按锁文件预热镜像/依赖缓存并保留失败日志。
- **P2/端口**：默认端口可能与本机服务冲突；通过 `.env` 覆盖宿主端口，容器端口和服务契约不变。
- **P2/数据**：标准停机保留 MySQL 卷；删除卷必须从标准脚本之外显式执行并记录影响。

回滚方式：回退本任务对脚本、Compose、环境示例、测试和文档的提交，恢复上一版本锁文件与启动方式；不重写已共享的 `0001/0002` 迁移历史，不删除现有业务卷。
