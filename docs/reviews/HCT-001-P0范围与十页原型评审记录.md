## 当前事实与发现

1. 综合报告和需求规格已统一六项硬承诺及十个核心页面名称。
2. 原页面设计的信息架构包含“家庭健康图谱”，但页面详细设计缺少对应章节。
3. 原页面详细设计把“授权设置”按页面编号列出，容易被误解为第十一个核心页面。
4. 原设计只有全局依赖降级说明，没有逐页定义正常、加载、空、错误、离线、未授权和低置信状态。

## 十个核心场景桌面推演

| 页面 | 场景 | 必须观察到的结果 | 结论 |
|---|---|---|---|
| 家庭总览 | 首次进入且无健康事件 | 显示本地隐私状态、空状态和安全下一步 | 接受 |
| 成员健康档案 | 照护者查看未授权字段 | API 与页面均不泄露字段内容或存在性 | 接受 |
| 视觉扫描中心 | 图片模糊或证据不足 | 进入 REVIEW/低置信状态并要求补拍 | 接受 |
| 人工复核中心 | OCR 与条码冲突 | 禁止入库，显示冲突证据并要求人工处理 | 接受 |
| 家庭健康图谱 | 存在未确认候选 | 不创建正式节点或关系边 | 接受 |
| 用药安全中心 | 规则命中但证据缺失 | 不给肯定用药判断，提示补充或进一步确认 | 接受 |
| 健康计划中心 | 建议越过安全时间窗 | 阻止建议，不改变医嘱、频次或剂量 | 接受 |
| 本地健康助手 | 无引用或 Ollama 不可用 | 拒答或退化为结构化事实/规则卡 | 接受 |
| 家庭健康大屏 | 公共展示模式 | 只展示非敏感聚合，不展示病史、报告或对话正文 | 接受 |
| 模型实验室 | 候选模型指标不足 | 保持候选状态，不允许发布并显示回滚入口 | 接受 |
