## 1. 结论

代码与自动化证据满足本 Story 的合并前验收条件：成员前台、管理后台和 auto 入口都只显示正式账号密码表单；登录后业务请求使用短期 Bearer 会话；开发身份头在运行时、Compose 和示例配置中缺省关闭；双端口、入口锁和服务端授权真相保持不变。

本结论只表示该变更可进入维护者合并复核，不代表互联网生产认证已经发布。签名/加密密钥轮换、CSRF/同源策略收紧、正式账号开户与密码轮换、部署审计仍按 HCT-417 保留为生产阻断项。

## 2. 风险核对

| 风险 | 结论与证据 | 残余措施 |
|---|---|---|
| 欢迎页残留演示、注册、PIN、人脸或“其他方式”入口 | `WelcomeView.vue` 已收口为单一表单；HCT-423/HCT-425/HCT-453 浏览器回归断言旧入口不会出现 | 后续改动必须保留 HCT-498 浏览器回归 |
| 正式会话缺失时回退 `X-Actor-Id` | `store.ts` 的产品请求选项只返回 Bearer；视觉质量/上传/任务链路改用相同正式会话；入口回归检查请求无 Actor 头 | 通用 API client 为历史诊断保留显式 actor 参数，产品视图不得传入 |
| 开发身份头因未配置而意外开启 | `Settings.allow_dev_actor_header`、`.env.example`、`docker-compose.yml` 默认值均为 `false`；生产配置单测覆盖 | 合成 API 测试仅由 `tests/conftest.py` 显式开启，不代表部署默认值 |
| 账号未预置导致用户无入口 | 登录页明确提示由管理员分配；README/部署指南指向受控开户和 `seed_formal_demo_health.py` | 生产部署必须建立正式开户、初始密码交付和首次改密流程；教学默认密码不得用于生产 |
| 删除历史 PIN/人脸数据导致破坏性回滚 | 本变更不删除端点、表、凭证或管理页，不含数据库迁移 | 通过 revert 代码恢复旧 UI；历史数据无需恢复 |
| 双端口统一凭据后角色越权 | HCT-453 入口锁仍在；真实权限继续由 `Household.created_by`、成员绑定和服务端授权决定 | 入口锁只做 UX 拒绝，不能代替 API 授权测试 |
| 401/超时后旧健康上下文残留 | store 和浏览器测试覆盖登出、会话到期、401、离线、504 清理/恢复 | 生产部署仍需验证反向代理、Cookie 属性与实际超时策略 |

## 5. 回滚与合并复核

回滚时 revert HCT-498 功能提交并重新构建 Web/API 即可；没有迁移或数据恢复步骤。若只需紧急阻断入口，优先回滚 Web 与默认配置的同一提交，避免形成 UI/运行时配置不一致。

按仓库当前规则，自动 CI 与 Relay Review Bot 不是合并门禁；维护者执行 merge 即代表完成人工复核。合并前仍需核对 Issue/Story/FR-NFR 绑定、上述测试证据、默认值、无敏感数据和无未说明迁移。
