## 验收结果

### MySQL 基础档

命令：

```powershell
$env:MYSQL_PORT='3307'
docker compose up -d --wait --wait-timeout 60 db
$env:DATABASE_URL='mysql+pymysql://homecare:change-me@localhost:3307/homecare?charset=utf8mb4'
uv run alembic upgrade head
uv run python scripts/hct003_probe.py mysql --database-url $env:DATABASE_URL --strict
```

结果：容器 `healthy`；Server `8.4.11`；`utf8mb4`/`utf8mb4_unicode_ci`；会话时区 `+00:00`；当前迁移和 head 均为 `0002_allow_pending_health_events`；表数 `7`；探针耗时约 `238 ms`。Docker stats 观察到容器约 `445.9 MiB / 7.567 GiB`。同一连接串启动 FastAPI 临时端口 `8001` 后，`/health` 和 `/api/v1/health/db` 均返回 `status=ok`，验证完成后临时进程已停止。

### OpenCV 视觉资源探针

命令：`uv run python scripts/hct003_probe.py vision --strict`

结果：`ok`；固定合成样例 SHA-256 为 `a5a11659418eb3bc93fe0c38fc5ae8e08355708156d512c7c7bad20e5ef4cde4`；8x8 灰度；CPU elapsed 约 `15.6 ms`，墙钟约 `51.1 ms`，RSS 约 `69.8 MiB`；OpenCV CUDA device `0`，执行 backend 为 CPU。输出明确声明仅为质量门控，不包含药品身份。

### Ollama 增强档与降级

成功命令：`uv run python scripts/hct003_probe.py ollama --model qwen2.5:7b --strict --timeout 120`

结果：回环地址、Ollama `0.20.2`、Schema `OllamaHandshake/v1` 校验通过；warm 墙钟约 `7.1 s`，服务推理约 `0.93 s`，模型/VRAM 约 `4,696 MiB`，返回固定技术握手，不含健康语义。

降级命令：`uv run python scripts/hct003_probe.py ollama --model hct003-missing:latest`

结果：退出成功但状态为 `degraded`，原因 `ollama_model_unavailable`，动作是安装或选择本地模型，`fallback=structured_core_only`，`cloud_fallback=false`。单元测试还覆盖了连接拒绝、非法响应和非回环地址拒绝。

## 选型结论

- 接受 MySQL 8.4 为事实库资源基线，继续沿用 ADR-0001；
- 接受 OpenCV CPU 质量探针作为视觉 W1 资源基线，不提前接受 YOLO/OCR 模型；
- 接受回环 Ollama 结构化协议作为增强档探针，不接受云端 fallback；
- 7B 模型属于增强/演示资源，不是基础档硬依赖；基础档在 Ollama/视觉模型缺失时仅展示结构化事实、规则和任务。

## 风险、缓解与回滚

- **P2/资源**：当前只验证一台设备，不能推出团队最低性能；缓解：后续成员按同一探针提交设备和指标，低于暂定下限时降级或阻塞。
- **P2/视觉**：当前没有 YOLO/OCR/条码业务能力；缓解：HCT-201 至 HCT-205 交付授权数据、模型卡、固定集、失败样例和回滚后再验收。
- **P2/本地模型**：7B 模型冷启动约 23 秒且占用约 4.7 GiB VRAM；缓解：增强档按需加载，超时保留事实/规则卡，禁止云端回退。
- **P2/环境**：3306 端口占用和 Ollama 模型目录权限会造成启动失败；缓解：提供端口覆盖，修正本机目录权限或显式设置可写 `OLLAMA_MODELS`，不修改仓库默认秘密。

回滚为回退探针、依赖锁、Compose UTC 参数、ADR 和本记录；不删除业务迁移、模型文件或运行数据。
