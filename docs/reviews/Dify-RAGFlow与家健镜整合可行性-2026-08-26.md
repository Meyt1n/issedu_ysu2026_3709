# Dify / RAGFlow 与家健镜整合可行性研判

- 日期：2026-08-26
- 状态：研判结论（推荐方案 A；方案 B 仅作远期可选实验档）
- 关联：HCT-401（本地知识/RAG）、HCT-430（本地多智能体）、FR-08、NFR-01/02/03
- 相关 ADR 草稿：[ADR-0006](../decisions/0006-不默认引入Dify或RAGFlow.md)

## 1. 一句话结论

**技术上可以对接，但按家健镜的本地优先与医疗安全边界，默认不应把 Dify / RAGFlow 接成主多智能体或主知识库；应继续强化本仓库已有的本地编排与批准制 RAG。** 若课堂需要「低代码工作流 / 文档解析演示」，仅允许**自托管、可选增强档、严禁健康上下文外送**的外围实验（方案 B），不得替换 FastAPI 校验与权限前置检索。

> 说明：用户原请求通过云端 Task 子代理执行；当时云端/本机 Task 均 `resource_exhausted`，由父会话按同等范围完成本研判文档。

## 2. 家健镜已有能力（事实）

| 能力 | 仓库现状 | 关键约束 |
|---|---|---|
| 多智能体 | HCT-430：`local_agents` 路由数据库 / 规则 / 知识 / 受控联网 / 本地 Ollama 合成 | 双重开关联网；脱敏；`agent_trace`；失败不阻断本地链路 |
| 知识库 / RAG | HCT-401：批准清单入库、权限前置过滤、引用校验、章节分块、同义词/轻量向量 | 正式索引与 demo 分离；禁止未审核网页 `auto_ingest` |
| 知识运营 | 白名单爬虫 → staging → 人工批准 → 晋升 → dry-run 入库；详情可查看 | API 强制离线夹具；Compose 需含 `docs/knowledge` |
| 运行时边界 | FastAPI 统一 API；Web 不直连 DB/向量库/Ollama | 家庭版健康数据不出可信域；云端推理非默认回退 |

事实源：`docs/vibe-coding/07-AI与RAG设计规范.md`、`04-系统架构与模块边界.md`、`05-数据与隐私安全规范.md`。

## 3. Dify 评估

| 维度 | 判断 |
|---|---|
| 是什么 | 应用编排 / Agent / Workflow / 知识库的低代码平台，常接多家模型与工具 |
| 技术可对接 | **能**：HTTP/Webhook/OpenAPI 工具可调用家健镜 `/api/v1`；自托管可挂本地模型 |
| 与现有重叠 | 高度重叠 HCT-430 多智能体与部分知识问答；易形成「第二编排脑」 |
| 产品风险 | 默认云或混云易把对话/工具上下文送出家庭域；工作流若绕过 FastAPI 校验器，医疗拒答与引用墙失效 |
| 运维成本 | 额外服务、版本、账号、密钥与备份；八周 P0 交付负担大 |
| 适用场景 | 仅适合「无健康 PHI 的教学工作流沙盘」或运营同学编排非核心演示，且必须自托管 |

**结论：** 不宜作为家健镜主 Agent 运行时。

## 4. RAGFlow 评估

| 维度 | 判断 |
|---|---|
| 是什么 | 偏文档解析、切片、索引与召回的 RAG 引擎 |
| 技术可对接 | **能**：可自托管；解析 PDF/复杂版式能力通常强于当前教学 Markdown 路径 |
| 与现有重叠 | 与 HCT-401 入库/检索重叠；但**缺少**家健镜硬需求：成员级权限前置、引用存在性校验、批准清单与删除传播契约 |
| 产品风险 | 若直接用 RAGFlow 回答并带健康问题，易绕过权限过滤与「主张—证据」校验；未审核文档易流入索引 |
| 运维成本 | 向量库/解析 worker/GPU 或 CPU 资源；与 Compose 基础档目标冲突 |
| 适用场景 | 可选「说明书/公开科普预处理车间」：只产出脱敏 UTF-8 摘要，再**人工**进入 `docs/knowledge/approved/` |

**结论：** 不宜替换本仓库 RAG 主链路；最多作为离线预处理辅助（仍须批准入库）。

## 5. 对照总表

| 需求 | 本仓库现状 | +Dify | +RAGFlow | 推荐 |
|---|---|---|---|---|
| 多智能体协作与可解释 trace | 已有 | 可增强编排 UI，但易双脑 | 弱相关 | 强化自研 |
| 家庭事实 + 规则 + 知识联合回答 | 已有工具链 | 需大量自定义工具且易泄上下文 | 不覆盖规则/事件 | 强化自研 |
| 复杂 PDF 解析 | 弱（偏 md/txt 批准清单） | 一般 | 较强 | 可选离线预处理 |
| 成员级权限前置检索 | 已有 | 默认不提供，需自建 | 默认不提供，需自建 | 必须留在 FastAPI |
| 本地优先 / 默认拒绝出口 | 已有 | 云版冲突；自托管可缓解 | 自托管可缓解 | 坚持自研主路径 |
| 课程八周可维护性 | 单栈 | 多栈 | 多栈 | 不引入为默认 |

## 6. 方案选择

### A. 不引入，强化现有本地多智能体 + 知识库（**推荐**）

- **做法：** 继续打磨 HCT-430/HCT-401（路由诚实、知识详情、爬虫运营、金标、引用墙、演示造数）。
- **优点：** 符合已接受隐私/架构事实；无第二运行时；验收路径清晰。
- **缺点：** 复杂版式解析、可视化工作流编辑器不如专用产品。
- **退出：** 无新外部依赖可退。

### B. 仅自托管可选增强档，严格隔离健康上下文（**远期可选，非默认**）

- **做法：** Compose profile 例如 `experimental-rag-tools`；仅处理**公开教学文档**；输出只能进 staging/approved 人工闸门；**禁止**传入 household/member/health_event/对话全文。
- **优点：** 可演示「行业 RAG 流水线」而不替换产品脑。
- **缺点：** 资源与安全评审成本高；易被误接成主路径。
- **最小接入草图（若未来立项）：**
  1. 独立容器网络，无路由到 MySQL 业务库；
  2. 只读挂载「已脱敏公开 PDF/HTML 投递目录」；
  3. 导出仅 Markdown + 来源/许可元数据 → `docs/knowledge/staging/`；
  4. 家健镜侧仍走批准 → ingest → 权限过滤检索；
  5. 开关默认关闭；回滚 = 停 profile + 删除投递卷。
- **回滚：** 关掉 profile 即恢复基础档；不删除家庭事件。

### C. 用 Dify 或 RAGFlow 替换现有 Agent / RAG（**不推荐**）

会破坏「统一业务 API + 校验器」分权，医疗与授权门禁难以保证，违背 04/05/07 规范。

### D. 混合（Dify 编排 + RAGFlow 检索 + 家健镜事实）（**不推荐为 P0**）

复杂度最高，三套权限模型；仅在有独立安全编制与长期运维时再议。

## 7. 非目标

- 本期不实现 Dify/RAGFlow 接入代码、密钥或云租户。
- 不把外部平台回答当作本地审核证据或正式健康结论。
- 不弱化引用校验、医疗拒答或默认拒绝出口。

## 8. 建议的后续工作（仍属自研主路径）

1. 知识运营：批准文档质量、金标、爬虫白名单与详情体验（已在主线演进）。
2. 多智能体：路由/opt-in 诚实性、证据预览、降级文案（HCT-430 持续）。
3. 若课程需要「外部 RAG 产品对比演示」：单独开 Story 评估方案 B，先做威胁模型与数据流图，再考虑 profile 草图——**不阻塞 P0**。

## 9. 验证本研判的方式

- 对照 05「健康数据不出家庭可信域」与 07「LLM 不得直连向量库 / 云端非默认回退」。
- 对照 HCT-401/430 已合并能力：外部平台不能在无等价门禁下宣称「可直接替代」。
