# 项目贡献指南与代码规范

> 本文档是家健镜系统项目贡献指南与代码规范，覆盖分支管理、提交规范、代码审查、测试要求、发布流程。

## 1. 分支管理

### 1.1 分支模型

```
master (生产环境)
  └── develop (开发环境)
       ├── feature/user-module
       ├── feature/medicine-reminder
       ├── bugfix/login-error
       └── hotfix/prod-crash
```

### 1.2 分支命名

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 功能 | feature/ | feature/medicine-reminder |
| 修复 | bugfix/ | bugfix/login-error |
| 紧急修复 | hotfix/ | hotfix/prod-crash |
| 文档 | docs/ | docs/api-guide |
| 重构 | refactor/ | refactor/user-service |
| 性能 | perf/ | perf/query-optimization |

### 1.3 分支规则

1. master 分支受保护，必须通过 PR 合并
2. develop 分支为集成分支
3. 功能分支从 develop 创建
4. hotfix 从 master 创建，合并回 master 和 develop
5. 分支生命周期不超过 2 周

## 2. 提交规范

### 2.1 Commit Message 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 2.2 Type 类型

| 类型 | 说明 |
| --- | --- |
| feat | 新功能 |
| fix | 修复 Bug |
| docs | 文档更新 |
| style | 代码格式（不影响功能） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试相关 |
| chore | 构建/工具相关 |
| ci | CI/CD 相关 |

### 2.3 示例

```
feat(medicine): add medication reminder feature

- Add reminder CRUD API
- Implement push notification integration
- Add unit tests for reminder service

Closes #123
```

```
fix(auth): resolve token expiration bug

- Fix JWT token refresh logic
- Add token expiration validation
- Update test cases

Fixes #456
```

## 3. 代码审查

### 3.1 PR 流程

1. 创建功能分支
2. 提交代码
3. 创建 Pull Request
4. 自动检查（CI）
5. 代码审查
6. 合并到 develop
7. 定期合并到 master

### 3.2 审查清单

- [ ] 代码符合规范
- [ ] 有单元测试
- [ ] 无安全漏洞
- [ ] 无性能问题
- [ ] 文档已更新
- [ ] 无硬编码密钥
- [ ] 错误处理完善
- [ ] 日志记录合理

### 3.3 审查标准

| 级别 | 说明 | 处理 |
| --- | --- | --- |
| P0 | 阻断性问题 | 必须修复 |
| P1 | 重要问题 | 建议修复 |
| P2 | 一般建议 | 可讨论 |
| P3 | 风格建议 | 可选 |

## 6. 安全规范

### 6.1 禁止事项

- 禁止硬编码密钥、密码
- 禁止提交真实健康数据
- 禁止在日志中记录敏感信息
- 禁止使用不安全的加密算法
- 禁止 SQL 拼接（使用参数化查询）

### 6.2 敏感信息处理

```python
# 正确：使用环境变量
api_key = os.getenv('API_KEY')

# 错误：硬编码
api_key = 'sk-1234567890'

# 日志脱敏
logger.info(f"User {mask_phone(user.phone)} logged in")
```

## 7. 发布流程

### 7.1 版本号

```
主版本.次版本.修订号
例如：1.2.3

主版本：不兼容的 API 变更
次版本：向下兼容的功能新增
修订号：向下兼容的问题修复
```

### 7.2 发布步骤

1. 更新版本号
2. 更新 CHANGELOG
3. 创建 Release PR
4. 合并到 master
5. 打 Tag
6. 触发自动部署
7. 验证生产环境
