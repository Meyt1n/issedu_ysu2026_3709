# HomeCare Twin 家庭健康联动学习记录

## 开头说明

这是一份与 HomeCare Twin 项目有关的学习记录。

记录的内容主要围绕家庭成员、健康事件、照护任务和移动端联动展开。

这份文档不是医学建议，也不是对真实家庭健康情况的判断。

文档中的家庭、成员、药品和事件都可以理解为教学演示中的虚构内容。

之所以写下这些看起来有些琐碎的文字，是因为软件项目的理解往往来自很多小地方。

有时候，一个接口名称就能影响前端和后端是否能够顺利沟通。

有时候，一条事件类型的拼写也会影响时间线是否能够正常显示。

所以，慢慢记录，反复确认，仍然是很有必要的事情。

## 项目印象

HomeCare Twin 可以看作一个面向家庭照护场景的数字化辅助系统。

它把家庭成员资料、健康事件、用药信息、照护计划和风险提示放在同一个可追踪的流程中。

移动端更接近家人日常使用的入口。

网页端更适合进行家庭管理、事件复核和较大屏幕下的信息查看。

两个端并不是各自保存一份互不相干的数据。

理想情况下，它们应该通过同一个可信的服务端接口来读取和写入数据。

这样做的好处是，手机上记录的内容可以在网页上看到。

网页上完成的确认，也可以在手机重新刷新后体现出来。

这种联动听起来很自然，但真正实现时需要考虑身份、授权、事件顺序和失败重试。

因此，联动验证并不是简单地打开两个页面看一眼。

## 移动端的使用想象

移动端页面应该尽量让家庭成员快速找到今天需要关注的内容。

例如，今日视图可以展示待处理的照护计划。

成员详情可以展示最近发生的健康事件。

用药相关内容可以展示药品名称、计划时间和必要的提示。

当用户点击确认、延期或跳过时，客户端需要把动作提交给服务端。

服务端接收动作后，会记录一条新的事件。

这条新事件不是简单覆盖旧数据，而是成为可追溯记录的一部分。

如果网络暂时不可用，界面应该给出明确的失败提示。

用户不应该看到一个模糊的空白页面，然后猜测自己的操作是否成功。

如果用户重新尝试，客户端还需要尽量避免重复创建相同的动作。

这也是幂等键和事件模型在实际项目中很重要的原因。

## 网页端的使用想象

网页端通常有更大的显示空间，因此适合放置家庭选择、成员选择和事件时间线。

照护者可以在授权范围内查看指定成员的信息。

家庭所有者可以管理成员，也可以调整授权的有效期和可用动作。

当网页端进行复核时，复核结果应该产生清晰的事件记录。

移动端下一次读取时间线时，就能看到这条记录。

如果操作者没有写入权限，服务端应该拒绝请求。

网页上不能因为按钮显示出来，就默认操作者一定有权限。

真正的权限判断仍然应该发生在服务端。

这种前后端共同遵守的边界，可以减少误操作，也能避免数据被越权读取。

## 联动验证的简单流程

第一步，准备一套固定的虚构演示数据。

演示数据可以包括一个家庭、两三个成员、几条过敏记录和几条计划事件。

数据的名称应该稳定，事件的幂等键也应该稳定。

这样重复运行造数脚本时，不会无休止地生成相同内容。

第二步，在移动端或移动端对应的接口写入一条演示事件。

事件写入完成后，记录返回的事件编号。

第三步，在网页端读取同一个成员的时间线。

检查事件类型、成员编号和事件载荷是否一致。

第四步，使用不同的身份尝试读取和写入。

有读取权限的照护者应该能够看到被授权的数据。

只有读取权限的照护者不应该能够提交需要写入权限的复核动作。

第五步，由具有写入权限的身份完成一次网页复核。

第六步，使用移动端身份重新读取时间线。

如果移动端能够看到新的确认事件，就说明这条联动链路基本闭合。

## 关于接口名称的一点废话

接口路径看上去只是字符串，但字符串其实承载了双方的约定。

例如，成员时间线接口需要明确家庭编号和成员编号。

如果少了家庭编号，服务端就很难判断请求属于哪个家庭。

如果少了成员编号，服务端就无法判断应该返回谁的事件。

事件类型也不能随意写成多个近似的名字。

`plan_created` 和 `plan_confirmed` 表示两个不同的阶段。

一个代表计划被创建。

另一个代表计划经过确认。

前端根据这些事件推导任务状态时，必须使用与服务端一致的语义。

这件事看起来有些啰嗦，但程序最怕的就是“差不多”。

差一个字母，可能就会从正常状态变成空状态。

## 失败情况也要记录

联动验证不能只验证成功场景。

没有授权时的请求应该失败。

服务端暂时不可用时，客户端应该失败得可理解。

请求超时后重新尝试时，不应该重复写入相同的事实。

成员切换时，旧成员的内容不应该继续冒充新成员的内容。

网页端和移动端看到的数据如果不一致，也需要有排查路径。

排查路径可以从请求身份、访问目的、事件编号和记录时间开始。

能够留下这些线索，后续定位问题会轻松很多。

## 结尾

HomeCare Twin 的价值不只在于页面能否显示一张卡片。

更重要的是，家庭照护过程中的信息能否被清楚地记录、授权地共享和可靠地回读。

移动端负责贴近日常使用。

网页端负责提供更完整的管理视角。

服务端负责保存事件并执行授权边界。

测试和文档负责把这些约定固定下来。

如果以后项目继续扩展，还可以增加更多演示数据、更多端到端场景和更细的审计记录。

不过，任何扩展都应该保持虚构数据和真实健康数据之间的边界。

最后再重复一次，这份记录的主要用途是学习项目结构、理解联动流程和帮助演示。

文字比较多，并不代表每一句都很深奥。

有些句子只是为了把步骤说完整。

把普通的事情认真写清楚，也算是软件工程中一种朴素但有用的习惯。
