> 本报告规划一款面向老人、慢病家庭成员与授权照护者的移动端 APP。技术栈与功能范围以参考蓝本「家健镜随身版」为依据拟定；该 APP 目前尚未开发，本报告用于明确后续**要做成什么样、用什么技术栈、有哪些功能、分几步落地**。
>
> **使用边界：** 教学演示与家庭照护辅助工具，不用于诊断或治疗；紧急情况请联系医生或当地急救服务。

## 一、项目背景与定位

主仓库（`issedu_ysu2026_3709`）已提供网页端（Vue 应用）与 FastAPI 后端。后续计划开发的移动端 APP 是它的「随身照护端」：老人和照护者用手机完成每天真正高频、低步骤的照护动作——确认服药任务、拍药盒录入、查看分级提醒和一键求助；而授权管理、人工复核、健康图谱、大屏和模型实验室等重度操作仍由网页端承担。

两端共用同一套术语与 API 契约；移动端计划采用**独立的视觉体系**（暖奶油底 + 森林绿 + 蜜桃琥珀，渐变英雄卡、任务进度环、悬浮胶囊导航），按移动场景与适老审美设计，不复刻网页端样式。

> **产品硬承诺（与主仓库一致）：** 家庭健康数据默认不出网；药盒识别永远需要人工确认，冲突/未知不自动入库；照护者只能看到被精细授权的字段；风险等级由确定性规则决定，应用不做诊断、处方、停药、换药或剂量判断；无购药、问诊、广告导流。

### 与网页端的分工呼应

| | 网页端（主仓库） | 移动端 APP（本方案） |
|---|---|---|
| 定位 | 家庭工作台 | 随身照护端 |
| 典型场景 | 授权管理、人工复核、健康图谱、大屏、模型实验室 | 今日任务确认、拍药盒、看提醒、家人视图、紧急求助 |
| 使用者 | 家庭管理员、数据/模型管理员 | 老人、慢病成员、授权照护者 |
| 数据 | MySQL 事实主库（唯一事实源） | 同一 FastAPI API，仅授权范围内读写 |
| 术语 | 健康事件 / 风险四级 / 识别四态 / 授权范围 | 完全一致 |

## 二、技术栈选型

移动端不引入第二套跨端框架，而是复用主仓库网页端的同一套 Web 技术栈，再用原生壳打包为 Android 应用，做到「一套代码、两端交付」。

| 层次 | 拟采用技术 | 使用方式与原因 |
|---|---|---|
| UI 框架 | Vue 3.5 + TypeScript 5.7 | 与主仓库网页端同栈同版本；组合式 API + 强类型领域模型 + 按路由懒加载。 |
| 工程构建 | Vite 6 + `@vitejs/plugin-vue` | 开发服务器开放局域网访问，便于手机真机联调；`/api`、`/health` 走代理。 |
| 页面导航 | vue-router 4（Hash 路由） | 任意静态托管可用；保留页面标题与路由切换时停止语音播报的行为。 |
| Android 打包 | Capacitor 8 + Android/Gradle | 同一套 Web 代码打包为原生 Android 应用；应用标识 `com.homecaretwin.companion`。 |
| 后端通信 | 自封装 `ApiClient` + `HttpDataProvider` | 对接主仓库 FastAPI；请求携带身份、访问用途与幂等键，避免页面直接拼 HTTP 请求。 |
| 双数据模式 | 演示 Provider + 联机 Provider | 默认演示数据本地运行、不连服务器；联机模式接家庭可信域内的服务端，便于分阶段验收。 |
| 离线能力 | PWA Manifest + Service Worker | 缓存应用外壳与静态资产；明确禁止缓存 `/api` 与 `/health`，健康数据不落缓存。 |
| 无障碍与语音 | Web Speech API、CSS 自定义属性、`localStorage` | 支持语音播报、字体缩放、深浅主题、高对比度和减少动效；偏好仅本地保存、不上传。 |
| 质量保障 | Vitest + happy-dom + vue-tsc | 数据适配、会话、无障碍、语音与工具函数单测，并纳入 CI 执行类型检查、测试和构建。 |

**选型原则：** 暂不引入全局状态库或 UI 组件库。轻量响应式 store 与手写设计系统（由 CSS 自定义属性驱动）即可覆盖项目范围；新增依赖只以真实的原生能力缺口或测试需求为依据。

## 三、APP 功能设计

移动端围绕「每日高频、低步骤、可信输入、快速求助」四条主线设计功能，共规划 9 个页面路由。

### 1. 今日照护与任务闭环（默认入口）

「今日」页作为默认入口，展示当日照护任务、任务完成进度、近 7 日完成趋势、待关注风险与最近变化时间线。用户可对任务执行**确认 / 延期 / 跳过**：

- 确认、延期、跳过分别写回 `plan_confirmed`、`plan_deferred`、`plan_skipped` 事件；
- 跳过必须填写原因，延期带明确时长；
- 每次写入生成幂等键，降低移动网络重试造成重复事件的风险；
- 提交后以 Toast、触感反馈与进度状态给出可理解的结果；全部完成有彩带庆祝。

### 2. 拍药盒与可信录入

「拍药盒」页承担「拍摄 → 质量门控 → 多证据候选 → 人工确认」的录入闭环：

- 先做图片质量检查，质量不通过只提示重拍原因、不进入识别；
- 通过后创建视觉任务，候选状态使用 `MATCHED / CONFLICT / UNKNOWN / REVIEW` 四态；
- OCR、条码、包装特征、主数据只作为证据来源，**任何候选都必须人工确认**；
- APP 中只显示任务状态与证据摘要，正式候选确认回网页端人工复核中心完成。

### 3. 家庭成员与授权视图

「家人」页与「成员档案」页用于查看成员、已确认时间线、用药清单和可见范围。访问控制由服务端决定，APP 负责如实呈现：

- 家庭所有者可见完整视图与授权信息；
- 照护者只显示服务端已授权的成员和字段；
- 未授权字段显示「未获授权」，不以空值伪装成没有数据；
- 用药、风险、事件请求携带 `X-Access-Purpose` 等上下文，由后端过滤。

### 4. 风险提醒与依据说明

「提醒」页按严重 / 较高 / 一般 / 提示四级展示风险卡；详情页展示「为什么出现这条提醒 + 证据事件 + 非医疗处置建议」。风险由家庭服务端的确定性规则产生，不由 APP 或模型作诊断推断。

### 5. 紧急求助

「求助」页提供拨打 `120`、联系预设家庭联系人与语音播报当前重要风险的入口；长辈模式下进入底部主导航。紧急按钮始终保持大尺寸、强对比度与可读标签。

### 6. 我的与设置

「我的」页承载长辈模式开关、无障碍设置、紧急联系人、数据源切换与隐私/边界声明。

## 四、页面路由规划

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 今日 | 默认入口，任务闭环 + 趋势 + 风险 + 时间线 |
| `/scan` | 拍药盒 | 拍摄 / 质量门控 / 候选 / 引导复核 |
| `/family` | 家人 | 仅显示被授权成员与字段 |
| `/family/:memberId` | 成员档案 | 时间线、用药清单、可见范围 |
| `/alerts` | 提醒 | 风险四级筛选 |
| `/alerts/:memberId/:ruleId` | 风险依据 | 规则版本 + 证据事件 + 处置建议 |
| `/help` | 紧急求助 | 急救 / 家人 / 语音播报 |
| `/me` | 我的 | 设置入口 |
| `/me/accessibility` | 无障碍设置 | 长辈模式与无障碍偏好 |

## 五、无障碍与长辈模式（核心特性）

无障碍不作为附加选项，而是核心交付标准：

- **长辈模式一键开启：** 特大字号 + 语音播报 + 简化底部导航（今日/拍药盒/求助/我的）+ 更大触控目标（≥60px）；
- **外观三档：** 浅色 / 深色（森林夜配色）/ 跟随系统，系统切换深浅色时实时生效；
- **字号三档：** 标准 / 大 / 特大，全局 rem 缩放；
- **高对比度：** 纯白实底 + 黑描边，自动去除玻璃、渐变、阴影与背景装饰，优先级高于深色模式；
- **语音播报：** Web Speech API（zh-CN）朗读今日安排、风险提醒与操作结果，支持手动「播报」按钮；
- **减少动效：** 应用内开关 + 自动尊重系统 `prefers-reduced-motion`，停用背景漂移、扫描线、彩带、数字滚动等全部动画；
- **不只靠颜色：** 所有等级/状态均为「文字 + 图标 + 颜色」三重表达；
- 全部设置保存在本机 `localStorage`，不上传。

## 六、数据来源与隐私边界

| 模式 | 说明 |
|---|---|
| 演示模式（默认） | 内置**虚构**家庭数据（人物、药品、风险均为编造，明确标注「演示」），不连接任何服务器，用于教学演示与交互验收 |
| 家庭服务器（联机） | 调用主仓库 FastAPI 既有接口；仅连接家庭可信域内地址，仅读写授权范围内数据 |

数据与接口原则：

1. 主仓库 MySQL / 事件中心仍是唯一事实来源，移动端不建立平行健康数据副本。
2. 所有写操作使用后端事件语义和幂等键；任务状态由计划事实与最后一个动作事件推导。
3. 本地仅持久化会话配置、无障碍偏好和紧急联系人等最小必要设置，不缓存 API 健康数据。
4. 演示模式中的人员、药品和风险必须显式标注为虚构数据，不与家庭服务端数据混用。
5. 识别、风险和提醒只提供证据与操作指引，不生成诊断、处方、停药、换药或剂量建议。

## 七、分阶段实施计划

| 阶段 | 主要交付 | 验收重点 |
|---|---|---|
| 第一阶段：工程骨架 | Vue + TS 工程、路由、设计系统与演示数据 Provider | `npm run check`、`npm run test`、`npm run build` 通过；页面可交互 |
| 第二阶段：核心功能 | 今日任务闭环、拍药盒、家人、提醒、求助、我的 | 各页面在演示模式完整可用 |
| 第三阶段：Android 打包 | Capacitor 壳、PWA 外壳、APK 可重复构建 | debug APK 构建通过，真机可安装运行 |
| 第四阶段：家庭服务器联调 | 成员、时间线、任务、风险、视觉质量接口联通 | 与主仓库同一局域网 API；确认/延期/跳过可见且可审计 |
| 第五阶段：身份与授权闭环 | 正式认证、会话刷新、访问用途校验、撤权与过期处理 | 不同身份只能读服务端许可范围；越权/撤权有明确界面状态 |
| 第六阶段：无障碍与发布 | 长辈模式、真机弱网与相机体验、签名与隐私说明 | 真机无障碍验收通过；发布包不记录密钥与健康数据 |

## 八、质量与安全门槛

- 每次合并前执行 TypeScript 检查、Vitest 单元测试和生产构建；新增数据适配或状态逻辑必须补测试。
- 对确认、延期、跳过、上传、风险详情、未授权、接口失败和离线状态编写浏览器/真机验收用例。
- 关键页面进行读屏与大字号人工验收，不能只依赖视觉截图。
- API 地址只允许可信家庭局域网或受控部署地址；开发代理与 Android 明文 HTTP 例外仅用于家庭局域网联调。
- 不将真实健康数据、真实人物信息、模型权重、密钥或访问令牌提交到仓库、日志或演示素材中。

## 九、结论

本方案以「家健镜随身版」为技术蓝本，规划一款与主仓库同栈（Vue 3 + TypeScript + Vite + Capacitor 8）的移动端 APP：以「今日任务闭环、拍药盒可信录入、家人授权视图、分级提醒、紧急求助」为核心功能，以「长辈模式 + 无障碍」为核心交付标准，通过演示 / 联机双数据提供者分阶段验收。

最终交付保持清晰边界：APP 让用户方便地完成每日照护、查看被授权信息、提交可信输入和快速求助；涉及授权管理、候选确认、复杂复核与模型治理的操作继续由网页端承担。
