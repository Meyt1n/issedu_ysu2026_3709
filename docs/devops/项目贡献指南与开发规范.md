# 项目贡献指南与开发规范

> 本文档是家健镜项目的贡献指南与开发规范，覆盖代码规范、提交规范、分支策略、代码审查、发布流程。

## 1. 贡献流程

### 1.1 贡献步骤

1. Fork 仓库或创建分支
2. 绑定 Issue 和 Story
3. 编写代码和测试
4. 提交 PR
5. 代码审查
6. 合并到 master

### 1.2 分支命名

```
{类型}/{简短描述}

类型：
- feature: 新功能
- fix: Bug 修复
- docs: 文档
- refactor: 重构
- test: 测试
- chore: 构建/工具

示例：
feature/medicine-reminder
fix/login-error
docs/api-documentation
```

### 1.3 提交信息规范

```
{类型}({范围}): {简短描述}

{详细描述}

{关联 Issue}

类型：
- feat: 新功能
- fix: Bug 修复
- docs: 文档
- style: 格式
- refactor: 重构
- test: 测试
- chore: 构建/工具

示例：
feat(medicine): add medication reminder feature

- 支持每日多次提醒
- 支持本地通知
- 支持漏服记录

Closes #123
```

def calculate_bmi(weight: float, height: float) -> float:
    '''计算 BMI 指数

    Args:
        weight: 体重（kg）
        height: 身高（m）

    Returns:
        BMI 指数

    Raises:
        ValueError: 身高或体重无效
    '''
    if height <= 0:
        raise ValueError("身高必须大于 0")
    return weight / (height ** 2)

### 2.3 代码风格

- 缩进：4 空格（Python），2 空格（Dart/JS）
- 行长度：不超过 120 字符
- 函数长度：不超过 50 行
- 文件长度：不超过 500 行
- 嵌套层级：不超过 4 层

## 3. 代码审查

### 3.1 审查清单

- [ ] 功能是否正确实现
- [ ] 是否有单元测试
- [ ] 代码是否符合规范
- [ ] 是否有安全问题
- [ ] 是否有性能问题
- [ ] 是否有硬编码
- [ ] 错误处理是否完善
- [ ] 日志是否合理
- [ ] 注释是否清晰
- [ ] 是否影响其他功能

### 3.2 审查意见级别

| 级别 | 说明 | 处理 |
| --- | --- | --- |
| blocker | 必须修改才能合并 | 必须修改 |
| major | 重要问题，建议修改 | 建议修改 |
| minor | 小问题，可选修改 | 可选修改 |
| nitpick | 风格建议 | 可选修改 |
| question | 疑问，需要讨论 | 需要回复 |

## 5. 发布流程

### 5.1 版本号规范

```
v{主版本}.{次版本}.{修订版本}

主版本：不兼容的 API 变更
次版本：向后兼容的功能新增
修订版本：向后兼容的 Bug 修复

示例：
v1.0.0
v1.1.0
v1.1.1
```

### 5.2 发布步骤

1. 更新版本号
2. 更新 CHANGELOG
3. 创建发布分支
4. 运行完整测试
5. 构建发布包
6. 部署到测试环境
7. 验证测试
8. 部署到生产环境
9. 打 Tag
10. 发布 Release Notes
