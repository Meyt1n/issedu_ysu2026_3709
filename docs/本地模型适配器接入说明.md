# 本地实验模型适配器接入说明

> 状态：`EXPERIMENTAL_UNRELEASED`。本说明描述如何在家庭可信域内，把两个仓库外的实验模型接入 HomeCare Twin 的 OCR-first 证据链路。默认全部关闭；未配置环境变量时系统行为与之前完全一致（`vision_model_version=unavailable`）。接入不等于发布：HCT-201 数据治理与 R3 模型发布复核完成前，这两个模型只能用于受控教学演示。

## 1. 接入的两个模型

| 模型 | 登记 ID | 制品位置（仓库外） | 用途边界 |
|---|---|---|---|
| YOLO11n 药盒辅助定位 | `hct-yolo11n-box-assist-experimental-v1.2`（SHA-256 `cedb5b52…`） | `data/hct201/runs/hct201_v1.2_annotation_reviewed_yolo11n/weights/best.pt` | 只提出包装/裁剪候选区域；不判断药品身份，不覆盖 OCR/条码证据 |
| HCT-402 Demo LoRA v4（Qwen3-4B + LoRA，4-bit NF4） | `hct402-demo-lora-v4` | `local-models/hct402-demo-lora-v4/`（`base-model` + `adapter`） | 只把已有 OCR/条码候选归类为字段提议（`source="llm"`）；不得编造值，不做诊断/剂量/停换药判断 |

模型权重不进 Git。适配器运行时自动计算权重 SHA-256 并写入 `model_version`（如 `hct-yolo11n-box-assist-experimental-v1.2+cedb5b52`）；若 YOLO 权重与登记哈希不一致，版本串会追加 `-UNREGISTERED` 以便审计。

## 2. 架构位置

按[AI 与 RAG 设计规范](vibe-coding/07-AI与RAG设计规范.md)与[HCT-201 OCR 字段提取契约](data/HCT-201-OCR字段提取契约-V1.md)，推理不在 API 进程内发生。适配器是家庭可信域内的独立进程，通过既有受控端点提交证据：

```text
适配器进程（本机独立推理环境，路径自行填写）
  质量门控 /vision-quality/check
  → 文件上传 /files/upload
  → 创建任务 /vision-tasks
  → 本地推理：YOLO 区域提议 + （可选外部 OCR）+ LLM 字段归类
  → HMAC 签名（issue_adapter_receipt）
  → 提交证据 /vision-tasks/{id}/evidence   ← allowlist + receipt 双重校验
  → 候选融合 /vision-tasks/{id}/fusion（四状态，仍需人工确认）
```

服务器端 `evidence_pipeline` 会再次执行反幻觉校验（`FIELD_VALUE_NOT_IN_EVIDENCE`、`FIELD_SOURCE_CHANNEL_UNSAFE` 等），LLM 提议无法绕过证据约束。

## 3. 代码入口

- `src/ai/vision/local_models.py`：`YoloBoxAssist`（区域提议）与 `QwenLoraFieldExtractor`（4-bit 字段归类，本地先做"值必须逐字来自证据"过滤）。
- `scripts/run_local_adapter.py`：端到端 CLI（质量门控 → 上传 → 任务 → 推理 → 签名 → 提交 → 可选融合）。
- `tests/unit/test_local_model_adapter.py`：降级路径、字段名映射、反幻觉过滤与管线兼容性的单元测试（不加载真模型）。

## 4. 启用方式（默认关闭）

适配器进程读取以下环境变量；不设置即为 `unavailable` 降级：

```powershell
# YOLO（CPU 即可；GPU 把 HCT_VISION_DEVICE 设为 "0"）
$env:HCT_VISION_WEIGHTS = "<仓库外的 YOLO 权重>\best.pt"
$env:HCT_VISION_DEVICE  = "cpu"
$env:HCT_VISION_CONF    = "0.25"

# LLM 字段归类（可选；需要约 3 GB 显存）
$env:HCT_LLM_BASE_MODEL = "<仓库外>\base-model"
$env:HCT_LLM_ADAPTER    = "<仓库外>\adapter"

# API 与签名（必须与 API 端 VISION_ADAPTER_SIGNING_KEY 一致）
$env:HCT_ADAPTER_SIGNING_KEY = "dev-only-change-me"
```

在 **含 ultralytics / transformers 的独立 Python** 中运行（不要使用项目 `.venv` 硬编码盘符）：

```powershell
# 只做本地推理并打印将要提交的 payload（不调 API）
& "<你的推理环境>\python.exe" -X utf8 scripts\run_local_adapter.py --image 药盒照片.jpg --dry-run

# 完整提交（API 需已启动）
& "<你的推理环境>\python.exe" -X utf8 scripts\run_local_adapter.py `
    --image 药盒照片.jpg --ocr-json docs\examples\local-adapter-ocr-example.json --fuse
```

## 5. 边界与已知限制

- 全图 OCR 由常驻 worker 在独立解释器中调用 PaddleOCR（`HCT_VISION_WORKER_PYTHON` 指向该环境）。未配置时 `ocr_version=unavailable`，适配器仍可只提交 YOLO 区域或外部 `--ocr-json`。
- LLM 字段提议在适配器与服务器两侧都执行"值必须逐字来自证据"校验；`raw_value=null` 的缺失字段不会生成提议。
- 两个模型均为 `EXPERIMENTAL_UNRELEASED`：困难负样本在低阈值仍会误检（见模型卡 V1.2/V1.3），LLM 尚无通过盲测+安全评估的发布记录。所有输出必须经人工确认后才能写入 `health_event`。
- 模型版本绑定账本（HCT-404 `model_binding`）仍以 `unavailable` 回退为准；本适配器不激活任何 binding，不改变发布状态。
