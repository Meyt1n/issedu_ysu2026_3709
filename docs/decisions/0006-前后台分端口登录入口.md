# ADR-0006：前后台分端口登录入口（一个认证 API、两个入口面）

> 凭据 UI 后续由 [ADR-0008](0008-Web单一正式账号密码登录.md) 替代：两个入口都只保留正式账号密码。本文关于双端口、入口品牌、同一认证 API、服务端角色事实和入口锁的决策继续有效。

- 状态：已接受（HCT-453）
- 日期：2026-08-25
- 关联：HCT-439（门户分流与 owner 真相）、HCT-417/423/425（密码/PIN/人脸登录）、ADR-0003（家庭 Owner 管理员权限边界）

## 背景

HCT-439 已把同一 Vue 应用按登录账号分为成员前台与管理员后台，但两者共用同一个登录页与同一个端口：长辈打开页面会看到管理员向导的文案，管理员也可能在“前台语境”里误操作。团队讨论了三种成熟系统的做法：

1. 同一认证 API + 登录后按角色跳转（单入口 SaaS 模式，即 HCT-439 现状）；
2. 同一认证 API + **分离的入口面**（如 admin.example.com 与 app.example.com；本地/教学环境用两个端口近似）；
3. 完全拆分的两套前端 + 两套端口（前端形态差异极大时）。

## 决策

采用模式 2：**保持一个 FastAPI 认证/授权后端不变，把 Web 拆成两个端口的入口面**。

- 成员前台：开发 `5173`、Compose `8080`（`WEB_PORT`）；品牌为「家庭成员前台」。凭据方式现由 ADR-0008 统一为正式账号密码。
- 管理后台：开发 `5174`（`HCT_ADMIN_WEB_PORT`）、Compose `8081`（`ADMIN_WEB_PORT`）；品牌为「家庭管理后台」。凭据方式现由 ADR-0008 统一为正式账号密码。
- 同一 Vue 代码与同一构建产物；入口模式在启动时解析（`?portal=` 查询 → `VITE_PORTAL_MODE` define → Nginx `sub_filter` 注入 → 已知后台端口回退 → `auto`）。
- Compose 采用**一个 Nginx 容器两个监听端口**（80/81）注入入口模式，而不是两个容器或两次构建——这是改动面最小、且不产生镜像分叉的方案。
- 登录后执行**入口锁**：账号真实门户（服务端 `Household.created_by` 判定，HCT-439/ADR-0003 不变）与入口不匹配时登出并指引跨端，不在错误端口渲染另一门户界面。

## 边界（安全声明）

入口模式是纯前端 UX 锁：它只做减法（拒绝渲染不匹配的门户界面），不参与也不放大任何权限。所有授权判断仍由服务端按 owner 事实与成员级授权执行；直接调用 API 不经过入口锁，也不因此获得任何额外能力。

## 后果

- 长辈与管理员各自拥有稳定、可书签化的入口，文案与凭据默认值不再互相污染；
- CORS 默认允许清单增加后台端口（5174/8081）；
- 裸 `npm run dev:web`（未设置模式）保留 `auto` 单入口行为，供调试与既有 e2e 使用；
- 未来若前端形态显著分叉，可在此基础上平滑演进到模式 3（拆应用），API 无需变化。

## 回滚

revert HCT-453 提交即可回到模式 1（HCT-439 单入口）；无迁移、无服务端契约变化。
