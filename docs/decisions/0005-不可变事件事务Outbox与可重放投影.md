# ADR-0005：不可变事件、事务 Outbox 与可重放投影

- 状态：提议，随 HCT-103 PR 合并接受
- 日期：2026-08-08
- 决策人/复核人：Meyt1n；维护者 merge 记录为最终人工复核证据
- 关联需求、Issue、PR：FR-02、NFR-03；Issue #44；HCT-103 PR
- 替代/被替代：细化 ADR-0001 的事件/outbox 接受条件，不改变 MySQL 唯一事实主库

## 背景与当前事实

旧骨架能在一个请求内追加事件、outbox 和简单状态，但没有幂等冲突控制、补偿关联、派发状态、checkpoint 或确定重放。重复请求可能产生多个事实；worker 中断和乱序无法定位；直接数据库修改也会破坏事件历史。健康事实属于 D2 敏感数据，恢复机制不能依赖把 payload 发到外部服务或写入日志。

## 决策驱动因素

- 健康事实必须只追加且能解释每次更正；
- API 重试、进程中断和重复投递不能重复生效；
- MySQL 是唯一事实主库，投影必须可从事件确定重建；
- 未确认视觉候选不能进入正式状态；
- 故障证据不得复制健康正文，且必须能安全前滚恢复。

## 候选方案

### 方案 A：直接更新当前状态并依赖请求重试

实现简单，但无法证明历史未被覆盖，事件、消息与状态可能分裂，也不能从空状态恢复，拒绝。

### 方案 B：外部消息系统作为事实源

可扩展性较高，但八周 P0 会引入第二事实源、额外部署和同步一致性成本，也扩大健康数据流转范围，拒绝。

### 方案 C：MySQL 不可变事件 + 事务 outbox + 可重建投影（采用）

事件、最小 outbox 和在线投影同事务写入；本地 worker 负责可重试派发；投影用成员序号、版本和状态哈希防重并支持从空状态或 checkpoint 重建。

## 决策

1. 每个成员的事件使用单调 `sequence_no`；写入前锁定成员行，数据库唯一约束防止静默重复序号。
2. `Idempotency-Key` 在家庭内唯一，请求指纹包含操作、操作者和规范化 payload；相同指纹返回原结果，不同指纹返回 409。
3. 更正追加已确认补偿事件，使用 `supersedes_event_id`/`causation_id` 关联原事件；同一事件只能被一个直接补偿替代，后续更正应补偿上一事件。
4. `UNCONFIRMED` 事件可以保存，但不进入正式投影；outbox 只包含事件/家庭/成员 ID、序号、确认和 Schema 版本，不包含健康 payload。
5. worker 状态机为 `PENDING -> PROCESSING -> DISPATCHED`，失败进入 `FAILED`；过期 `PROCESSING` 视为中断并回收。投影以 `last_sequence` 防止重复投递生效，缺少已确认前序时返回 `OUT_OF_ORDER`。
6. checkpoint 记录状态、最后序号/事件和 SHA-256；重放前校验哈希，按事件序号确定重建并比较在线状态哈希。
7. SQLite/MySQL 迁移建立拒绝事件更新/删除的触发器。MySQL 8.4 开启受控 `log_bin_trust_function_creators=1`；存在事件时不执行破坏性 downgrade，使用前滚修复。

## 后果

- 正向影响：重复请求、重复投递、进程中断、乱序和投影损坏均有明确行为与恢复证据。
- 代价/新约束：基础档增加一个 outbox worker；迁移需要 MySQL 触发器配置；投影 Schema 变化必须保持重放兼容或新建迁移/ADR。
- API、数据、授权影响：补偿、checkpoint、重放和 outbox 运维接口仅在家庭边界内执行；checkpoint 含 D2 状态，仍留在本地事实库。
- 模型/规则/知识影响：本 ADR 不允许模型确认事实或修改事件；后续消费者必须复用序号和幂等语义。

## 验证、复审与回滚

- SQLite 已有数据升级和 MySQL 8.4 空库升级必须同时通过。
- 自动测试覆盖相同/冲突幂等键、补偿、事务回滚、失败重试、重复投递、乱序、过期锁、空投影/checkpoint 重放和不可变触发器。
- 隔离 Compose 必须证明 API、MySQL、worker、Web 健康，worker 不记录健康正文。
- 回滚先停止 worker并保留事件/outbox/checkpoint；有事件时禁止降级丢字段，使用兼容应用或前滚修复。
- 若未来需要 Kafka/Redis Streams、跨家庭全局顺序或多主写入，必须新建 ADR，不在本方案中隐式扩展。
