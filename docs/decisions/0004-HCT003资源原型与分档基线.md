# ADR-0004：HCT-003 资源原型与基础/增强档基线

- 状态：已接受，后续正式模型固定集和部署验收仍可触发复审
- 日期：2026-08-07
- 决策人/复核人：Meyt1n；merge 记录为人工复核证据
- 关联需求、Issue、PR：NFR-04、NFR-05、NFR-06；Issue #40；PR（本分支）
- 替代/被替代：细化 ADR-0001 的环境可行性，不替代正式视觉模型、LLM、数据卡或部署 ADR

## 背景与当前事实

HCT-001 已通过 PR #75 冻结本地优先、证据和人工确认边界。后续工程、视觉和本地助手需要先知道团队设备能否复现 MySQL、视觉预处理和 Ollama，且增强依赖不可用时基础档不能伪造结果。

本次使用无健康语义的合成灰度矩阵作为固定视觉样例，不加载正式 YOLO/OCR 权重。MySQL 使用 `mysql:8.4` 镜像，Ollama 使用本机回环服务和已有 `qwen2.5:7b` Q4_K_M 模型。所有指标都是本机资源探针观测值，不是 P0 生产性能承诺。

## 决策驱动因素

- MySQL 必须保持唯一事实主库，迁移和字符集/时区结果可定位；
- 视觉必须先验证可复现的质量门控和资源采集，不把质量探针当成身份识别；
- Ollama 必须只走本地回环地址，结构化输出失败或服务不可用时只能退化为事实/规则卡；
- 依赖体积、显存、内存、许可证和启动失败必须被记录；
- W1 只建立可回滚的实验基线，不提前冻结正式模型和阈值。

## 候选方案

### 方案 A：MySQL 8.4 + OpenCV CPU 质量探针 + 回环 Ollama（采用）

保留 FastAPI/SQLAlchemy/Alembic/MySQL 事实主库；用 OpenCV/NumPy/psutil 完成固定合成样例质量指标；用 Ollama `/api/generate` 的 JSON Schema 能力验证本地结构化输出，并用 `/api/ps` 记录模型资源。优点是依赖边界小、可以在无正式权重时复现、故障降级清晰；代价是本 ADR 不证明 YOLO/OCR/LLM 业务质量。

### 方案 B：W1 直接引入 YOLO、PaddleOCR、向量库和云端模型

拒绝。权重、运行时体积、许可证、数据出网和 GPU 差异会让基础工程无法干净复现；云端模型也违反家庭版本地优先和默认不出网边界。

### 方案 C：只用 SQLite、固定 Mock 和字符串响应

拒绝。SQLite 不能证明 MySQL 迁移/字符集/时区；Mock 或固定回复不能证明视觉资源和结构化模型协议。

## 决策

### 已接受组件与版本

| 能力 | 选定基线 | 本机观测 | 约束 |
|---|---|---|---|
| 事实库 | MySQL `8.4` Docker 镜像 | Server `8.4.11`；镜像 digest `sha256:b3b90af2a6552ae30c266fdb7d5dd55f3afb72404bb78d37fe8a23eb857fd3fb` | `utf8mb4`、UTC、Alembic head；宿主机冲突时可临时映射 `3307` |
| 视觉资源探针 | `opencv-python-headless 4.14.0.94` + NumPy `2.4.6` | CPU backend；OpenCV CUDA device `0` | 只测解码/亮度/对比度/清晰度，不能入库或识别药品 |
| 资源采集 | psutil `7.2.2` | 记录探针 RSS、主机内存和耗时 | 不记录图片、OCR 正文或模型上下文 |
| 本地助手原型 | Ollama `0.20.2` + `qwen2.5:7b` Q4_K_M | 4.7 GiB 模型/VRAM；warm 墙钟约 `7.1 s` | 只允许回环 HTTP；模型未装或服务故障时结构化降级 |

### 分档与暂定资源下限

| 档位 | 进入条件 | 本次证据 | 不代表 |
|---|---|---|---|
| 基础档 | x64、4 个逻辑核、8 GiB RAM、20 GiB 可用磁盘、Docker/Compose；视觉先走 CPU | 当前设备 14 核/20 线程、约 16 GiB RAM，基础探针和 MySQL 通过 | 不代表正式模型实时性能 |
| 增强档 | 基础档 + 16 GiB RAM；7B Q4 模型约 5 GiB 显存/内存，建议 8 GiB 以上可用显存 | RTX 4060 Laptop 8,188 MiB；模型实际 4,696 MiB VRAM | 不代表 QLoRA 训练资源或全链路并发能力 |
| 研发档 | 独立训练设备、授权数据和模型制品存储 | 不在 HCT-003 验证 | 不得用家庭运行机自动训练 |

下限是团队开发准入的暂定值，不是统计学性能结论。任一成员设备低于下限时标记 `Blocked` 或选择基础档降级，不私自放宽门槛。

## 后果

- 正向影响：任何成员都能用固定命令得到相同结构化探针；AI 依赖离线时基础事实链不被伪造；后续正式模型可以独立替换。
- 代价/新约束：OpenCV headless 和 psutil 增加约 50 MiB wheel 下载与锁文件；增强档 7B 模型占用约 4.7 GiB，冷启动明显慢于 warm 调用；MySQL 宿主端口可能需要覆盖。
- API、数据、授权、模型/规则/知识影响：探针不新增业务 API/表，不绕过 FastAPI、授权、人工确认或规则边界。
- 必须补充的测试、监控和文档：HCT-201/202/203/204 必须基于许可数据、固定集、模型卡和真实失败样例重做视觉/模型验收；部署阶段需补备份、恢复和三档演练。

## 验证、复审与回滚

已验证命令和证据见 `docs/reviews/HCT-003-资源原型与技术选型评审记录.md`；契约、降级和输出格式由 `tests/unit/test_hct003_resource_probes.py` 保护。

触发复审的条件：

- 实际视觉全流程 CPU P95 超过测试方案的 8 秒目标，或 OpenCV/NumPy/许可证发生重大变化；
- Ollama 模型无法在 16 GiB RAM/8 GiB 显存设备上结构化返回，warm 延迟超过 30 秒，或输出 Schema/安全边界变化；
- MySQL 版本、字符集、时区、迁移恢复或 Docker Compose 在团队设备上无法复现；
- 需要引入 YOLO、PaddleOCR、FAISS/Qdrant、云端服务、真实数据或训练权重；
- 任一故障需要把健康上下文发送到回环之外。

回滚：回退本 ADR 对应提交、依赖锁、Compose UTC 参数和探针；保留业务事实库与已有迁移，不删除运行数据。正式能力在新的 ADR 被接受前保持禁用或使用基础档结构化降级。
