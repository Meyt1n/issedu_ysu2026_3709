# ADR-0006：不默认引入 Dify 或 RAGFlow 作为主 Agent / 主 RAG

- 状态：提议
- 日期：2026-08-26
- 决策人/复核人：项目负责人（merge 即复核）
- 关联需求、Issue、PR：FR-08、HCT-401、HCT-430；研判文档 `docs/reviews/Dify-RAGFlow与家健镜整合可行性-2026-08-26.md`
- 替代/被替代：无

## 背景与当前事实

家健镜已具备本地多智能体编排（HCT-430）与批准制本地 RAG（HCT-401），并在架构上要求：统一 FastAPI 校验、权限前置检索、家庭健康数据默认不出可信域、云端推理非默认回退。团队询问是否可用 Dify（编排/Agent）与 RAGFlow（文档 RAG）搭建多智能体与知识库。

## 决策驱动因素

- 家庭事实一致性、事件可追溯与回滚；
- 成员授权、敏感数据和医疗安全；
- 开放集拒识、证据契约和确定性规则边界；
- 八周 P0 的性能、算力、存储、许可证和维护成本。

## 候选方案

### 方案 A：不引入，强化自研本地 Agent + RAG

实现方式：继续以本仓库 `local_agents` 与 `knowledge` 为唯一产品路径。  
优点：符合已有隐私/分权规范；单栈可测可交付。  
缺点：复杂文档解析与可视化编排弱于专用产品。  
风险/成本：低。退出：无。

### 方案 B：自托管可选增强档，仅作公开文档预处理

实现方式：独立 Compose profile；禁止健康上下文；产出经人工批准后才可进入本仓库知识索引。  
优点：可对比行业工具。  
缺点：运维与误用风险。  
风险/成本：中高。退出：停 profile。

### 方案 C：用 Dify/RAGFlow 替换主链路

实现方式：外部平台承接问答与检索。  
优点：上手快、功能表面丰富。  
缺点：权限前置、引用校验、医疗拒答与默认拒绝出口难以等价保证。  
风险/成本：高。退出困难。

## 决策

**选择方案 A 为默认与 P0 路径。**  
方案 B 仅可作为未来单独 Story 的实验档提案，不得作为家庭版默认依赖，不得替换 FastAPI 校验器与权限前置 RAG。  
**拒绝方案 C** 作为产品主路径。

适用范围：全体家庭版/教学演示部署。  
禁止用途：将含成员健康事实的对话或工具上下文送入 Dify/RAGFlow 云服务；未审核外部索引直连助手回答。

## 后果

- 正向影响：架构边界清晰；避免双运行时；课程交付可维护。
- 代价/新约束：复杂 PDF 解析需继续用人工摘要或未来可选预处理，不承诺与商业 RAG 套件对等。
- API、数据、授权、模型/规则/知识影响：无强制变更；外部平台不进入默认依赖矩阵。
- 必须补充的测试、监控和文档：以本 ADR 与可行性研判为准；若启动方案 B 须先补威胁模型与数据流图。

## 回滚

本 ADR 为「不引入」决策，回滚意味着另立 ADR 接受方案 B/C；在此之前删除任何实验 profile 即可回到纯自研栈。
