# ADR-0008：Web 单一正式账号密码登录

- 状态：已接受（HCT-498，用户于 2026-08-29 明确要求）
- 日期：2026-08-29
- 关联：FR-01、HCT-417、HCT-423、HCT-425、HCT-439、HCT-453、HCT-455、ADR-0006（前后台分端口登录入口）

## 背景

桌面 Web 曾同时暴露开发 Actor ID、账号注册、密码、家庭 PIN、人脸和“其他登录方式”。这些入口混合了开发便利、账户开户、主身份认证、二次确认和生物识别实验能力，用户难以判断哪一个才是正式登录，也与 P0“不以人脸为身份入口”的需求基线不一致。

前后台两个端口解决的是角色语境和误入问题；它们不是两套身份系统，也不应因此拥有不同的主认证方式。

## 决策

1. 桌面 Web 只保留正式账号密码作为主登录方式；成员、管理员和 auto 入口使用同一表单与同一 `/auth/login` Bearer 会话契约。
2. 继续保留 ADR-0006 的两个端口、不同品牌、服务端角色事实和登录后入口锁。统一认证方式不等于合并门户或放宽授权。
3. 欢迎页不再提供开发身份、注册、PIN、人脸或其他登录方式。账户由受控 API/脚本预置，不在登录页开放自助注册。
4. Web 业务请求必须使用 Bearer 会话；不得在令牌缺失时回退到 `X-Actor-Id`。运行时和 Compose 的开发身份头默认关闭。
5. PIN/人脸后端契约和历史数据暂不删除。PIN 可继续承担敏感操作二次确认；人脸能力作为历史实验实现保留，但不作为正式 Web 身份入口。

本 ADR 覆盖 ADR-0006、HCT-423、HCT-425、HCT-453 和 HCT-455 中关于“成员前台以 PIN/人脸为主登录”的 UI 决定；双端口和服务端授权决定继续有效。

## 后果

- 用户只需理解一个正式登录流程，两个端口的区别只剩角色与工作区语境。
- 新账号必须在登录前由受控流程创建；部署与演示文档必须给出预置步骤。
- 旧 PIN/人脸浏览器回归改为断言这些入口不会重新出现；后端安全契约测试继续保留。
- 默认关闭开发身份会让依赖 `X-Actor-Id` 的本地脚本失败；测试夹具和诊断必须显式开启，不能依赖默认值。

## 回滚

本决策无数据库迁移。revert HCT-498 提交即可恢复旧欢迎页和默认开关；由于未删除账户、PIN、人脸表与端点，不需要数据恢复。
