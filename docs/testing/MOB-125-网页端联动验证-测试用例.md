# MOB-125 网页端联动验证测试用例

## 1. 测试信息

| 项目 | 内容 |
| --- | --- |
| 关联 Issue | #181（MOB-125） |
| 测试目标 | 验证移动端事件可在网页端可见；网页端复核结果仅按授权回写到移动端；虚构数据脚本可重复执行并得到可复核结果。 |
| 优先级 | P1 |
| 数据原则 | 仅使用标记为“演示”的合成家庭、成员、计划、事件和账号；不得录入、导出或截图真实健康数据、联系方式、令牌或 Cookie。 |
| 涉及端 | 移动端 H5/PWA 或 Android WebView、网页端、联动测试服务端与虚构数据脚本。 |

## 2. 前置条件与测试数据

1. 部署同一受控测试环境的网页端、移动端和服务端，并记录三端提交版本、API 版本及执行时间。
2. 执行虚构数据脚本，创建家庭 `demo-hct-125`、成员 `member-a`、照护者 `actor-caregiver` 和未授权观察者 `actor-observer`。脚本输出运行 ID、数据集版本和种子值。
3. `actor-caregiver` 对 `member-a` 具有 `family-care` 写入权限及“查看复核结果”权限；`actor-observer` 不具有该成员的读取或复核结果权限。
4. 准备一条待处理的合成计划 `plan-125-001`。移动端、网页端登录的账号均指向同一测试家庭；浏览器开发工具或服务端审计日志可查询脱敏请求 ID 和事件 ID。
5. 每个会改变数据的用例结束后，重新执行数据脚本或执行其 reset 参数，避免用例之间相互污染。

## 3. 移动端写入、网页端可见

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-125-001 | P0 | 在移动端以 `actor-caregiver` 确认 `plan-125-001`；记录返回的事件 ID 和请求 ID。 | 移动端仅在服务端确认成功后显示“已确认”；服务端创建一条 `plan_confirmed` 事件，包含正确家庭、成员、计划、执行者、发生时间和幂等键。 |
| TC-125-002 | P0 | 保持网页端已登录或重新登录后刷新该成员的时间线/计划详情。 | 网页端可见 TC-125-001 创建的同一事件；事件 ID、计划、成员、状态、发生时间与服务端一致，不显示为另一条本地推测记录。 |
| TC-125-003 | P0 | 在移动端对另一条合成计划执行“延后”，再执行“跳过”并填写合成原因；网页端刷新。 | 网页端分别展示服务端返回的延后和跳过结果；跳过原因完整一致；最终状态由事件顺序决定，不被旧缓存覆盖。 |
| TC-125-004 | P0 | 在移动端对同一操作连续点击或模拟网络重试，使用相同幂等键；网页端刷新。 | 服务端只保留一条有效写入事件；网页端只显示一次操作结果，计数、时间线和状态不重复。 |
| TC-125-005 | P1 | 移动端写入后不手工刷新网页端，等待其既有轮询/订阅周期；随后手工刷新一次。 | 若产品声明实时同步，网页端在约定窗口内更新；无实时机制时，刷新后必须更新。两种情况下均不得将旧状态标为最新。 |
| TC-125-006 | P1 | 移动端断网或服务端返回 5xx 时提交确认，然后恢复网络并刷新网页端。 | 移动端显示可恢复失败且不伪造成功；网页端没有该事件。只有后续服务端实际接受写入后，网页端才可见。 |
| TC-125-007 | P0 | 以 `actor-observer` 登录网页端，尝试访问 `member-a` 的计划详情、时间线及已知事件 ID。 | 返回既有的未授权/不可见状态；页面、接口响应、错误文案和缓存均不泄露事件内容、成员名称或是否存在该资源。 |

## 4. 网页端复核按授权回写移动端

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-125-008 | P0 | 网页端以具备复核权限的账号对 TC-125-001 事件提交“已复核”及合成备注；移动端打开对应计划并刷新。 | 服务端产生带复核者、复核结论、时间和关联事件 ID 的复核记录；移动端显示服务端返回的复核状态和允许展示的合成备注。 |
| TC-125-009 | P0 | 网页端提交“需更正/驳回”复核结果；移动端刷新。 | 移动端展示准确、可行动但非医疗化的复核状态，不把网页端复核结果误写为移动端已执行的计划动作。 |
| TC-125-010 | P0 | 移动端以仅有计划写入权限、没有复核结果查看权限的账号刷新同一计划。 | 移动端不显示复核结论、复核者、备注或任何可推断内容；接口按服务端授权拒绝或过滤，客户端不以缓存或默认值补齐。 |
| TC-125-011 | P0 | 网页端以无复核权限账号直接调用复核接口或操作复核控件。 | 复核控件不可操作或请求返回 403；不产生复核记录，移动端状态保持不变。 |
| TC-125-012 | P1 | 网页端两次提交同一复核结论，第一次正常、第二次重试或双击。 | 服务端按幂等规则处理；移动端只看到一个逻辑复核结果，不出现重复通知、重复时间线或状态抖动。 |
| TC-125-013 | P1 | 网页端和移动端分别基于同一旧版本修改相关状态，令网页端复核请求发生版本冲突。 | 服务端返回明确冲突结果且不静默覆盖；网页端提示重新加载。移动端最终只显示服务端已提交的版本。 |
| TC-125-014 | P1 | 网页端完成复核后，移动端离线打开旧缓存，再恢复网络。 | 离线期间明确标识数据可能非最新，不将旧状态作为新的复核结果；恢复连接后重新拉取授权范围内的服务端状态。 |

## 5. 虚构数据脚本可复现性

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-125-015 | P0 | 使用固定种子执行虚构数据脚本两次；两次执行前均清理或 reset 该脚本拥有的测试数据。 | 两次生成的家庭、成员、计划、事件顺序、授权关系和关键业务字段一致；输出数据集版本、种子和可比对摘要/哈希。 |
| TC-125-016 | P0 | 对同一固定种子重复执行脚本而不手动清库。 | 脚本安全幂等，或明确拒绝并给出 reset 指引；不得无提示地产生重复家庭、重复事件或污染非脚本数据。 |
| TC-125-017 | P0 | 使用不同种子执行脚本，并在网页端和移动端验证生成的数据。 | 标识符/合成内容可变化，但数据结构、授权矩阵和联动断言仍满足测试要求；两端看到的是同一服务端数据集。 |
| TC-125-018 | P0 | 检查脚本参数、输出、日志、导出文件和生成数据。 | 明确标记为演示/合成；不包含真实个人资料、健康正文、密钥、Token、Cookie 或生产地址。失败日志同样不得泄露敏感值。 |
| TC-125-019 | P1 | 中断脚本执行或模拟部分 API 失败后重新执行。 | 脚本输出失败位置和恢复方式；重新执行后恢复到完整且可验证的数据集，不留下半成品授权关系或孤立事件。 |

## 6. 术语与事实一致性核对

| ID | 优先级 | 核对项 | 预期结果 |
| --- | --- | --- | --- |
| TC-125-020 | P0 | 对照移动端、网页端和 API 的事件类型、状态枚举、成员/计划名称与时间。 | 同一事件使用同一事实来源和语义；展示名称可按端适配，但不得把“确认、延后、跳过、复核、驳回”混用。 |
| TC-125-021 | P1 | 对照两端的时间显示与服务端 `occurred_at`/`reviewed_at`。 | 显示可按产品时区规则格式化，但事件先后、日期归属和审计时间可追溯且一致。 |
| TC-125-022 | P0 | 核对无权限、网络失败、冲突和空数据文案。 | 两端均不暗示成功、不泄露受限资源，也不以演示数据替代联机失败；复核状态仅对有权用户可见。 |

## 7. 执行记录与通过准则

执行前后运行项目约定的检查命令：

```powershell
npm run check
npm run test
npm run build
# 涉及 Android 壳时
npm run android:sync
```

每次联动验收记录：移动端/网页端/API 版本，虚构数据脚本版本、种子、运行 ID，测试账号权限矩阵，事件 ID、脱敏请求 ID，以及两端脱敏截图或日志路径。

通过条件：所有 P0 用例通过；TC-125-001 至 TC-125-014 的服务端事件、授权过滤和最终状态可在两端与审计记录相互核对；TC-125-015 至 TC-125-019 证明虚构数据脚本可稳定复现且不会污染或泄露数据。未执行的真实联机、网页端或 Android 环境用例必须标记为 `Blocked`，不得以本地 mock 结果替代。
