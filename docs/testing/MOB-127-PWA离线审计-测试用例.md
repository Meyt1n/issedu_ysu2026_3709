# MOB-127 PWA 离线审计测试用例

## 1. 测试信息

| 项目 | 内容 |
| --- | --- |
| 关联 Issue | #182（MOB-127） |
| 被测对象 | PWA 应用外壳、Service Worker、Web App Manifest、静态资源和 Android WebView 容器。 |
| 测试目标 | 验证应用外壳和静态资源可离线使用；验证 `/api`、`/health` 及任何健康数据响应不进入 Cache Storage 或其他离线缓存。 |
| 数据原则 | 仅使用标记为“演示”的合成数据；不使用、导出或记录真实健康数据、Cookie、Bearer Token、密钥或生产地址。 |
| 优先级 | P1；涉及敏感数据缓存的用例按 P0 执行。 |

## 2. 前置条件

1. 部署受控 HTTPS 测试环境，记录 PWA 构建版本、Service Worker 版本、浏览器/Android WebView 版本和测试时间。
2. 使用独立浏览器配置文件或清理站点数据后的设备；可在浏览器开发工具中查看 Application、Network 和 Cache Storage。
3. 准备合成测试账号和演示家庭数据；准备可识别但不含敏感信息的静态资源版本标识。
4. 需要分别执行在线首次访问、安装后离线冷启动、离线恢复网络、更新 Service Worker 和注销后审计场景。
5. 每个验证缓存行为的用例结束后，清理站点数据、注销账号并记录缓存清单与脱敏请求 ID。

## 3. 应用外壳与静态资源

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-127-001 | P0 | HTTPS 在线首次访问应用，检查 manifest、Service Worker 注册状态和安装入口。 | Manifest、图标、启动页和 Service Worker 可用；注册成功无控制台错误；非 HTTPS 环境不得伪装为已安装 PWA。 |
| TC-127-002 | P0 | 完成在线首次加载后断网，关闭应用并从 PWA 图标或浏览器重新打开。 | 应用外壳可离线冷启动，显示导航、基础布局和明确的离线状态；不显示旧健康数据或伪造的在线内容。 |
| TC-127-003 | P0 | 断网后依次访问首页、设置等仅依赖应用外壳的入口。 | 已声明支持的壳层路由和静态资源可用；未缓存页面显示可恢复离线状态，不出现白屏、无限加载或脚本异常。 |
| TC-127-004 | P1 | 检查 Cache Storage 中的缓存键、静态资源和响应头。 | 仅包含版本化或明确允许的应用壳及静态资源；资源可正确加载，缓存名称与版本策略可追溯。 |
| TC-127-005 | P1 | 发布新静态资源或新 Service Worker 后，先在旧应用打开，再关闭重启。 | 更新按既有策略激活；新旧资源不混用导致白屏或脚本版本冲突；更新失败时保留可用旧壳或显示可恢复错误。 |
| TC-127-006 | P1 | 离线启动后恢复网络，执行刷新或等待既有更新策略。 | 网络恢复后重新验证 Service Worker 和静态资源版本；在线数据仅经正常网络请求获取，不从离线缓存伪造。 |

## 4. API、健康检查与健康数据缓存隔离

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-127-007 | P0 | 在线访问任意需调用 `/api` 的页面，检查 Network 的请求来源、响应头和 Cache Storage。 | `/api` 请求走网络；响应不写入 Cache Storage、IndexedDB、localStorage 或离线回退页面；离线时不得返回陈旧 API 成功响应。 |
| TC-127-008 | P0 | 在线访问 `/health`，再断网重复访问或刷新依赖健康检查的页面。 | `/health` 不进入缓存；断网时按实际网络失败或离线状态处理，不回放历史健康检查成功结果。 |
| TC-127-009 | P0 | 在线加载演示成员的任务、风险、用药或时间线等健康数据页面，随后检查所有浏览器存储。 | 健康数据响应、正文、成员名称及可推断内容不保存在 Cache Storage、IndexedDB、localStorage、sessionStorage 或 Service Worker 离线回退中。 |
| TC-127-010 | P0 | 登录后加载健康数据，注销、关闭应用、重新离线启动，再以另一合成账号登录。 | 不出现上个账号的健康数据、成员列表或摘要；注销清理范围覆盖缓存和本地状态，账号切换后仅显示新授权数据。 |
| TC-127-011 | P0 | 预先向 Cache Storage 写入模拟 `/api` 或 `/health` 响应，再离线访问应用。 | Service Worker 不匹配或读取这些响应；应用显示离线/失败状态，不使用恶意或遗留缓存作为接口结果。 |
| TC-127-012 | P1 | 服务端分别返回 401、403、404、409、429、5xx 与网络超时，检查缓存和重试。 | 错误响应及错误正文不被离线缓存；页面给出安全、可恢复提示，不泄露资源存在性或健康正文。 |

## 5. Service Worker 策略与离线恢复

| ID | 优先级 | 场景与操作 | 预期结果 |
| --- | --- | --- | --- |
| TC-127-013 | P0 | 审查 Service Worker 的 fetch 处理逻辑与实际网络行为。 | 静态壳资源遵循声明的缓存策略；`/api`、`/health`、认证及健康数据路径显式绕过缓存或使用网络失败策略。 |
| TC-127-014 | P1 | 模拟静态资源 404、缓存损坏、Service Worker 安装失败或激活失败。 | 不把失败资源标为可用；应用显示可恢复状态或回退到完整旧版本，不循环刷新或阻塞卸载/更新。 |
| TC-127-015 | P1 | 取消注册 Service Worker、清理站点数据后重新在线访问并重新安装。 | 可重新注册并构建正确的静态缓存；无孤立旧缓存、重复 worker 或跨版本残留。 |
| TC-127-016 | P1 | 在 Android WebView/Capacitor 壳中重复 TC-127-002、TC-127-007 至 TC-127-010。 | 壳内的离线启动、静态资源、接口排除和注销清理行为与 PWA 一致；记录设备、系统、WebView/APP 版本和脱敏结果。 |

## 6. 自动化命令、证据与通过准则

```powershell
npm run check
npm run test
npm run build
# 涉及 Android 壳时
npm run android:sync
```

每次审计至少保存：PWA/Service Worker 版本、浏览器或设备版本、离线切换时点、Cache Storage 清单、Network 请求类型、存储检查结论、脱敏截图或日志路径和已知限制。

通过条件：所有 P0 用例通过；Cache Storage 仅保留允许的应用壳与静态资源；`/api`、`/health`、认证响应和健康数据在任意离线存储中均无命中；离线状态不伪造在线成功或旧健康数据。真实 Android 环境未执行时必须标记为 `Blocked`，不得以桌面浏览器 mock 替代。
