## 减少动效修复与本地检查

真机检查时发现旧 APK 在应用内打开“减少动效”后，骨架卡片伪元素的计算动画仍为 `shimmer`（时长被全局压缩为 `0.00001s`）。原因是 `SkeletonCard.vue` 的根 `html[data-motion]` 选择器位于 `scoped` 样式内，无法匹配组件外的 `html` 节点。

本分支已将高对比与减少动效选择器改为完整 `:global(...)` 选择器，使构建产物明确包含 `html[data-motion=reduced] .skeleton-card:after { display:none }`。本次本地检查结果：

| 检查 | 结果 |
| --- | --- |
| `cd APP && npm run check` | 通过 |
| `cd APP && npm run test -- --reporter=dot` | 通过，39 个测试文件、355 项测试 |
| `cd APP && npm run build` | 通过；构建产物含静态占位规则 |
| `git diff --check` | 待提交前复跑 |

修复后的 APK 尚未能在本机重建（当前环境缺少脚本要求的 JDK 21–24），因此“减少动效”仍需在新 APK 安装后复验，不能将旧包观察结果写成修复通过。

## 发布边界与回滚

- 本记录不把演示延迟当成弱网证据；`npm run verify:weak-network-evidence` 仍应在空模板上按设计拒绝，直到设备持有人填完 12 条矩阵并提供可复核附件哈希。
- 本次代码改动只涉及 `SkeletonCard.vue` 的选择器作用域，回滚时移除该选择器修复即可，不影响 API 错误映射、请求去重和列表数据。
- MOB-171 继续保持“待验收”；需要受控后端、PWA、TalkBack、新 APK 和完整网络注入证据后才能改为“已验证”。
