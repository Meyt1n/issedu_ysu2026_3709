## 第一篇：数据划分规则

### 1. 划分原则

1. **按实体分组，非按样本随机**：同一物理药盒、同一成员的图像必须全部在同一集合
2. **按采集会话分组**：同一视频会话的所有帧必须在同一集合
3. **按设备分组**：不同设备拍摄的同一实体在不同集合中应有代表性分布
4. **时间隔离**：先采集的数据划分到训练集，后采集的划分到验证/测试集（模拟真实场景分布漂移）

### 2. 分组键定义

| 数据类型 | 分组键 | 说明 |
|---|---|---|
| 药品包装图像 | `physical_box_id` | 同一药盒多角度/多光照拍摄必须在同一集合 |
| 视频帧 | `video_session_id` | 同一拍摄会话的连续帧必须在同一集合 |
| 文档/报告 | `document_id` | 同一文档的多页扫描必须在同一集合 |
| 标注样本 | `annotation_batch_id` | 同批标注样本均衡分布在各集合 |

### 3. 禁止的泄露模式

| 模式 | 检测方法 | 严重度 |
|---|---|---|
| 相邻视频帧跨集 | 按 `video_session_id + frame_number` 分组，检查集合唯一性 | **S0** |
| 同一药盒跨集 | 按 `physical_box_id` 分组，检查集合唯一性 | **S0** |
| 同一文档跨集 | 按 `document_id` 分组，检查集合唯一性 | **S0** |
| 标注人泄露（训练集含标注人的测试样本） | 按 `annotator_id` 分层抽样 | S1 |
| 时间泄露（训练集含未来日期的样本） | 按 `created_at` 排序检查 | S1 |

### 4. 划分比例

| 阶段 | 训练 | 验证 | 测试 |
|---|---|---|---|
| V1（初始数据集） | 70% | 15% | 15% |
| V2（困难样本池追加） | 原训练 + 60%困难 | 原验证 + 20%困难 | 原测试 + 20%困难 |

## 第二篇：删除传播规则

### 1. 删除触发条件

| 条件 | 处理 |
|---|---|
| 用户主动请求删除 | 触发完整传播链 |
| 授权到期后数据过期 | 自动标记 → 缓冲期 → 删除 |
| 数据许可撤回 | 隔离数据 → 通知下游 → 删除 |
| 训练同意撤回 | 立即从训练集移除 → 重新划分 → 记录 |
| 课程结束归档 | 按留存策略执行 |

### 2. 传播链

```
用户删除请求
    │
    ▼
┌─────────────────┐
│ 1. 主数据库 (MySQL) │ ← 标记 deleted_at，不立即物理删除
└────────┬────────┘
         │ 30 天缓冲期
         ▼
┌─────────────────┐
│ 2. 关联文件        │ ← 删除 data/files/ 下的关联文件
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 向量索引        │ ← 删除 FAISS/Qdrant 中的关联向量
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 4. 缓存            │ ← 清理 Redis/内存缓存中的关联条目
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 5. 困难样本池      │ ← 移除困难样本池中的关联样本
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 6. 可控备份        │ ← 从最近一次备份中标记需跳过恢复的条目
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 7. 审计记录        │ ← 保留脱敏审计记录（操作者、时间、范围、请求 ID）
│                     │   不含原始健康数据正文
└─────────────────────┘
```

### 3. 各存储层的删除方法

| 存储层 | 删除方法 | 不可逆时间点 |
|---|---|---|
| MySQL | 软删除 `deleted_at` → 30 天后物理 `DELETE` | 物理 DELETE 后 |
| 文件系统 | `os.remove()` + 安全覆写（可选） | 覆写后 |
| FAISS 索引 | `Index.remove_ids()` + 重建索引 | 重建后 |
| 缓存 | `DEL key` 或 TTL 过期 | 过期后 |
| 困难样本池 | 从 JSON/DB 列表中移除条目 | 移除后 |
| 备份 | 标记 skip 条目，下次增量备份时不包含 | 下次备份后 |

### 4. 审计留存（最低要求）

删除完成后，仅保留以下脱敏记录：

```json
{
  "deletion_id": "uuid",
  "requested_by": "actor_id",
  "requested_at": "2026-08-08T12:00:00Z",
  "scope": {
    "member_id": "uuid",
    "tables_affected": ["health_event", "member_state_projection"],
    "files_deleted": 12,
    "vectors_deleted": 340,
    "cache_keys_deleted": 5
  },
  "propagation_completed_at": "2026-08-08T12:05:00Z",
  "status": "completed",
  "error_layers": []
}
```

**明确禁止记录：** `payload`、`evidence`、`state`、`display_name`、图像内容、OCR 文本、向量值。

### 5. 时间窗口

| 阶段 | 时间 | 说明 |
|---|---|---|
| 请求确认 | 即时 | 用户二次确认删除范围 |
| 软删除标记 | 即时 | 数据对业务不可见 |
| 缓冲期 | 30 天 | 支持撤销恢复 |
| 物理删除 | 缓冲期后 24h 内 | 各层物理清除 |
| 备份清除 | 下一个备份周期 | 增量备份不再包含 |

## 第三篇：验证脚本规格

### 划分泄露检查脚本 (`scripts/check_split_leak.py`)

```python
"""
检查训练/验证/测试集之间是否存在泄露。

检查项：
1. 同一 physical_box_id 是否跨集
2. 同一 video_session_id 是否跨集
3. 同一 document_id 是否跨集
4. 训练集中是否存在晚于测试集的样本（时间泄露）
5. 同一 annotator_id 是否过度集中于某一集合

用法：
  uv run python scripts/check_split_leak.py --split-file splits/drug_box_v1.json
"""
```

### 删除传播验证脚本 (`scripts/verify_deletion_propagation.py`)

```python
"""
验证删除传播是否完整。

检查项：
1. 主库中目标 member_id 的 health_event 是否已标记 deleted_at
2. 关联文件是否已删除
3. 向量索引中目标 member_id 的向量是否已移除
4. 缓存中目标 member_id 的条目是否已清除
5. 困难样本池中目标 member_id 的样本是否已移除
6. 审计记录是否已生成且不含 D3 敏感数据

用法：
  uv run python scripts/verify_deletion_propagation.py --member-id <id>
"""
```
