# HomeCare Twin 数据字典与敏感度分级

- 版本：v1
- 日期：2026-08-08
- 负责人：Shen-huang-123
- 关联：HCT-002、NFR-02
- 基线迁移：`migrations/versions/0001_initial_schema.py`

## 敏感度定义

| 等级 | 定义 | 处理要求 |
|---|---|---|
| **D1** | 非敏感：系统元数据、时间戳、版本号 | 无特殊限制 |
| **D2** | 个人身份：用户 ID、家庭成员信息 | 不可出网；日志仅记 ID，不记正文；导出需授权 |
| **D3** | 健康/生物特征：疾病、药品、过敏、报告正文、图像、视频、向量、对话 | 禁止进日志；禁止出网；禁止进公开 Issue；存储加密；删除需传播 |

## 表级数据字典

### 1. household（家庭）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `id` | VARCHAR(36) | 家庭唯一标识 | D2 | 日志可记 |
| `name` | VARCHAR(120) | 家庭名称 | D2 | 日志不可记全文，仅记长度 |
| `created_by` | VARCHAR(120) | 创建者 actor_id | D2 | 日志可记 |
| `created_at` | DATETIME | 创建时间 | D1 | 无限制 |

**风险提示：** `name` 可能包含真实姓氏或地址，不建议在日志/错误中输出。

---

### 2. member（家庭成员）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `id` | VARCHAR(36) | 成员唯一标识 | D2 | 日志可记 |
| `household_id` | VARCHAR(36) | 所属家庭 | D2 | 日志可记 |
| `display_name` | VARCHAR(120) | 显示名称 | D2 | **日志不可记全文**，仅记长度或 hash |
| `role` | VARCHAR(32) | 角色（PRIMARY_CAREGIVER / DEPENDENT / ...） | D1 | 无限制 |
| `actor_id` | VARCHAR(120) | 绑定的登录账号 | D2 | 日志可记 |
| `created_at` | DATETIME | 创建时间 | D1 | 无限制 |

**风险提示：** `display_name` 通常为真实姓名或亲属称谓（"妈妈""爷爷"），结合家庭 name 可推断真实身份。日志中替换为 `member:<id>`。

---

### 3. care_authorization（照护授权）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `id` | VARCHAR(36) | 授权唯一标识 | D2 | 日志可记 |
| `household_id` | VARCHAR(36) | 家庭 | D2 | 日志可记 |
| `member_id` | VARCHAR(36) | 被授权成员 | D2 | 日志可记 |
| `grantee_actor_id` | VARCHAR(120) | 被授权者 | D2 | 日志可记 |
| `data_fields` | JSON | 授权字段列表 | D2 | 日志可记字段名，不记字段值 |
| `actions` | JSON | 授权动作列表 | D1 | 无限制 |
| `purpose` | VARCHAR(200) | 授权目的 | D2 | 日志不可记全文（可能涉及疾病/照护原因） |
| `valid_from` | DATETIME | 生效时间 | D1 | 无限制 |
| `valid_until` | DATETIME | 失效时间 | D1 | 无限制 |
| `revoked_at` | DATETIME | 撤销时间 | D1 | 无限制 |
| `created_at` | DATETIME | 创建时间 | D1 | 无限制 |

**风险提示：** `purpose` 字段可能包含"照顾高血压爷爷"等健康信息，日志仅记长度。

---

### 4. health_event（健康事件）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `id` | VARCHAR(36) | 事件唯一标识 | D2 | 日志可记 |
| `household_id` | VARCHAR(36) | 家庭 | D2 | 日志可记 |
| `member_id` | VARCHAR(36) | 成员 | D2 | 日志可记 |
| `event_type` | VARCHAR(80) | 事件类型 | D1 | 无限制 |
| `source` | VARCHAR(40) | 来源 | D1 | 无限制 |
| `confirmation_status` | VARCHAR(32) | 确认状态 | D1 | 无限制 |
| `payload` | JSON | **事件载荷** | **D3** | **🚫 禁止进日志、禁止出网、禁止进公开 Issue** |
| `evidence` | JSON | **证据数据** | **D3** | **🚫 禁止进日志、禁止出网、禁止进公开 Issue** |
| `created_by` | VARCHAR(120) | 创建者 | D2 | 日志可记 |
| `confirmed_by` | VARCHAR(120) | 确认者 | D2 | 日志可记 |
| `created_at` | DATETIME | 创建时间 | D1 | 无限制 |

**最高风险：** `payload` 和 `evidence` 是 D3 核心敏感数据。任何代码路径不得将其完整输出到日志/错误/响应元数据。日志仅记 `event_id` + `event_type` + `confirmation_status`。

---

### 5. outbox_message（发件箱消息）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `id` | VARCHAR(36) | 消息唯一标识 | D1 | 无限制 |
| `event_id` | VARCHAR(36) | 关联事件 | D2 | 日志可记 |
| `topic` | VARCHAR(120) | 消息主题 | D1 | 无限制 |
| `payload` | JSON | 消息载荷 | D2 | 日志仅记键名，不记值（当前仅含 event_id/household_id/member_id） |
| `dispatched` | BOOLEAN | 是否已投递 | D1 | 无限制 |
| `created_at` | DATETIME | 创建时间 | D1 | 无限制 |

**风险提示：** 当前 payload 仅含 ID 引用（D2），若未来扩展包含事件摘要，需升级至 D3 处理。

---

### 6. member_state_projection（成员状态投影）

| 字段 | 类型 | 含义 | 敏感度 | 脱敏规则 |
|---|---|---|---|---|
| `member_id` | VARCHAR(36) | 成员 | D2 | 日志可记 |
| `household_id` | VARCHAR(36) | 家庭 | D2 | 日志可记 |
| `state` | JSON | 聚合状态 | D3 | **🚫 禁止进日志**（当前含 `last_event_payload`，即健康事件正文） |
| `last_event_id` | VARCHAR(36) | 最新事件 | D2 | 日志可记 |
| `updated_at` | DATETIME | 更新时间 | D1 | 无限制 |

**最高风险：** `state` 字段当前实现中直接复制了 `health_event.payload`（见 `routes.py:283-284`），因此 `state` 必须作为 D3 处理——禁止进日志、禁止出网。

## 日志脱敏规则汇总

```
# 密钥模式（gitleaks 已有，需补充这些）
[A-Za-z0-9_]{20,}key[A-Za-z0-9_]*
password\s*[:=]\s*\S+
token\s*[:=]\s*\S+
secret\s*[:=]\s*\S+

# 健康字段模式（HCT-004 新增）
"payload"\s*:\s*\{[^}]*(?:disease|drug|allergy|symptom|diagnosis|report|prescription)[^}]*\}
"evidence"\s*:\s*\{[^}]*(?:image|video|ocr_text|barcode|photo)[^}]*\}
"state"\s*:\s*\{[^}]*(?:last_event_payload)[^}]*\}

# 日志中允许的字段（白名单）
# 仅输出：request_id, event_id, member_id, household_id, event_type, confirmation_status, topic
```
