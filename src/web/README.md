# HomeCare Twin Web 用户端

计划使用 Vue 3、TypeScript、Vite 建设十个页面：家庭总览、成员健康档案、视觉扫描中心、人工复核中心、家庭健康图谱、用药安全中心、健康计划中心、本地健康助手、家庭健康大屏和模型实验室。

当前已建立 Vue/Vite 的一期 Web 工程，采用温馨纸感设计系统（`src/style.css`，无外部字体与资源请求，含极光背景、入场编排与滚动数字等动效），以侧边导航组织十二个已接通后端的视图：家庭总览、成员档案（含状态重放校验）、健康计划、视觉扫描（含 HCT-202 质量门控闭环）、人工复核、用药安全、家庭健康图谱（SVG 星轨投影，仅由已确认事件生成节点）、本地助手、家庭健康大屏（暗色非敏感聚合）、授权管理、知识文档（HCT-401 登记/检索/快照）和模型实验室（HCT-404 版本发布/回滚 + HCT-208 困难样本池与训练同意）（`src/views/`、`src/store.ts`）。成员当前事实卡片由 `src/ui/projection.ts` 按与后端 `build_relationship_graph` 一致的确定性规则，从 API 已授权返回的时间线在客户端推导，被补偿事件不进入当前事实。

界面提供五套可切换主题（顶栏调色盘或欢迎页色板，localStorage 记忆）：暖阳纸笺（默认）、晨雾简白（复刻第一版界面的扁平青碧风格）、青珀夜航（深色）、樱语粉黛、海盐晨风。主题以 `data-theme` 设计令牌实现（`src/ui/themes.ts` + `src/style.css`），新增主题只需覆盖一组 CSS 变量。

交互层包含：方向感页面过渡（含顶部进度条与滚动复位）、指针跟随的 3D 倾斜卡片（`src/ui/tilt.ts` 指令，触屏与减少动效偏好下自动禁用）、骨架屏加载态（`SkeletonList`）、Promise 式确认弹窗（`src/ui/confirm.ts` + `ConfirmDialog`，用于撤权、下线文档、取消任务等破坏性操作）、可折叠侧栏与图谱能量粒子。欢迎页主视觉为 AI 生成的教学插画（`src/assets/welcome-hero.jpg`，本地打包资源，运行时不发起任何外部请求，页面已标注来源）。

进入家庭空间后提供命令面板（顶栏「快速跳转」按钮或 `Ctrl+K` / `Cmd+K`）：统一检索十二个视图、成员档案直达、主题切换与常用动作（`src/components/CommandPalette.vue`，命令模型与过滤逻辑在 `src/ui/commands.ts`，零额外依赖）；无匹配时的空态同样不提供任何购药、问诊或广告入口。十二个业务视图按需拆包（欢迎页同步加载），进入家庭空间后在空闲时预取其余 chunk；切换视图时先展示骨架屏，避免空白舞台。

版式采用杂志式混合结构而非统一卡片网格：总览、成员档案、健康计划、用药安全使用开放式分区（编号分区头 `sec-head`、衬线大数字带 `stat-strip`、事实缎带 `fact-ribbon`、书页边栏 `side-rail`、竖排点题 `vertical-mark`），卡片仅保留给表单、风险项等需要操作表面的内容；扫描、复核、授权、知识、实验室等工作台页面维持表单卡片结构。

本地多人联调时，可用环境变量 `HCT_API_PROXY` 把 dev server 的 API 代理指向自己的后端实例（默认 `http://127.0.0.1:8000`），`HCT_WEB_PORT` 指定前端端口（默认 `5173`，`strictPort` 开启，端口被占用会直接报错而不是漂移）。

前端只通过 FastAPI 访问系统，不直连 MySQL、向量库或 Ollama。服务端负责权限、事件事务、风险规则和证据校验；前端负责输入校验、状态展示和人工确认。

页面必须明确展示：

- `MATCHED`、`CONFLICT`、`UNKNOWN`、`REVIEW` 及人工确认状态；
- 识别的 YOLO/OCR/条码/包装特征/本地主数据证据，以及人工修正的 before/after、原因和训练同意状态；
- 数据库事实、规则、文档引用、模型/规则/知识版本；
- 当前操作者可见的成员、数据域/字段、动作、用途和授权到期时间；
- INFO、GENERAL、HIGH、URGENT 等级、普通告警剩余预算和升级对象；
- 家庭版“健康数据默认不出网”的本地运行状态；
- 低置信、证据不足、依赖离线和越权等受控降级；
- “教学演示，不替代医疗诊断”，且不输出停药、换药或剂量决定。

页面信息架构与文案以[产品信息架构与页面设计](../../docs/vibe-coding/18-产品信息架构与页面设计.md)为准。产品不提供购药、问诊、广告或佣金导流入口。

开发命令：`npm ci` 后执行 `npm run dev:web`；生产构建执行 `npm run build:web`。

## 当前前端基础层

`src/api/types.ts` 定义当前 P0 API 的请求和响应类型，`src/api/client.ts` 提供统一请求入口。前端调用 API 时必须通过 `ApiClient`，不要在页面组件中重复实现请求、开发身份头、幂等键或错误解析。

当前客户端只封装仓库已有的接口：健康检查、能力查询、创建家庭、创建成员、创建/撤销授权、追加已确认手工事件、事件列表和成员状态投影。家庭列表、成员列表、授权列表、字段可见范围和统一 OpenAPI 错误信封仍需后端冻结后再接入；前端不得用假数据补齐这些接口。

网络不可用时客户端返回 `ApiClientError`，错误码为 `DEPENDENCY_UNAVAILABLE`；HTTP 错误同时兼容当前 FastAPI 的 `detail` 和目标契约的 `error.code/message/details/request_id` 结构。`X-Actor-Id` 仅用于开发环境演示，不能视为生产认证方案。

每个请求默认带 15 秒超时（`RequestOptions.timeoutMs` 可按请求覆盖）：本地 API 或 dev 代理偶发丢失响应时，挂起请求会被中止并归类为 `REQUEST_TIMEOUT`（与「连不上 API」的 `DEPENDENCY_UNAVAILABLE` 区分，界面据此给出不同的排障提示），而不是永远停在“正在保存”；写请求均携带幂等键，超时后重试不会重复写入。调用方主动传入的 `signal` 中止则按原样抛出，不会被误报为服务不可用。dev 代理侧同样配置了 30 秒转发超时（`vite.config.ts`）。

## 图片质量采集 Demo

`src/vision/VisionQualityPanel.vue` 提供 JPEG/PNG 拍照或选择、本地预览、质量检查、重拍提示和 PASS 后创建视觉任务的闭环。页面不会展示质量凭证、服务端路径或稳定文件摘要。

流程必须保持顺序：

1. 以 multipart 把用户当前选择的文件直接提交到 `/api/v1/vision-quality/check`；
2. `RETAKE` 只展示可执行提示，不上传文件、不创建任务；
3. `PASS` 后上传同一 `File`，核对上传 SHA-256 与质量结果一致；
4. 携带短期质量凭证创建视觉任务；失败时尽力删除刚上传的孤立文件。

换图、清除图片或切换开发身份会立即清除旧质量结果。质量通过只表示图片适合进入 OCR 队列，不表示已识别药品，更不表示可以自动写入健康记录。
